## Cost and limits

Benchmark `490dd9a8` held the GPU lock: macOS/aarch64, release, 640×360, each frame waited for.
CPU load 3.6 on 14 logical CPUs was **quiet**. First load copied 20.43 MiB in
three upload frames; each edit copied 1,398,528 bytes. Largest frame copy: 8 MiB; staging peak: 24 MiB
against four 8 MiB chunks. Existing tripwires passed. A passing predecessor run was appended to history;
the new leased metrics are still seeding, not a mature regression baseline.

Steady render CPU p50/max was 1.015/1.673 ms; upload p50/max was 1.393/4.203 ms. Upload frames are **not**
all inside the steady spread: the cold first scene frame includes host preparation and copy recording;
the first zero-copy switch creates the diagnostic's full set of output buffers and mip bind groups
(2.140 ms). The three copy-bearing edit frames were 1.209, 1.393 and 1.250 ms, within the steady spread.
The trace separates these cases. Whole-frame latency varied even in steady frames (24.09 ms maximum);
these waited offscreen measurements claim neither panel cadence nor physical residency. G5 closure and
reconstruction-motion qualification remain M3.

## Reproduction and identity

Run M1's done-when commands under the `gpu` lock. The benchmark is
`cargo bench --locked --offline -p v1-game --bench cooked_edit`; use an absolute `THRUM_G5_BENCH_OUT` path
and `THRUM_G5_BENCH_TRACE=1`. `scripts/content_loop_proof.py` records a clean revision before a run.
[Source identities](M1/source.json) equate functional revision `3b4d7df4` with rebased `eceb4c9a`, the
archived baseline revision. Final checks rerun after stronger byte assertions and documentation / error
context corrections. Fixtures are generated here; no external assets, build trees or bulk frames are inputs.

## Overlapping-edit repair

Revision `f3099f6d` fixes the review's M1.3 counterexample. Each prepared upload names the resident HEAD
whose resources it reused. After a protected ready publication switches, stale plans are discarded before
any copy is recorded and replanned against the committed resources, on native and fetched feeds alike.
[Metal regression log](M1/repair-native.log.gz): all three tests passed, including eight overlapping-edit
cases (portable/BC4, native/fetched, both contribution orders). They prepare a second edit behind a ready
publication, discard its switch recording, switch through capture, and assert retained hashes, textures,
views and serials for every unchanged product, only the edited product's padded upload bytes, unchanged
pipeline count, correct sampled texels and invalidation clearing after a history-advancing submission.
[Exact proof](M1/repair-exact-proof.json.gz): both native matrices and all four Chrome sets passed at that
revision in 977.48 seconds. These are function and exact-output proofs, with no new cadence claim.
