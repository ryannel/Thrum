## Scope and reproduction

I built the release game and web page at `f90bd8767d977c78e88dd1398143bbd334ca36f2` and used the generation-one exit store with root `3083a794f837963050dae3e566c788d6a9aad7fa7479309a46c1540cb0654643`. I relied on the script's clean automated checks on `a4afd52a6d4f`. For the visual inspection I used portable Metal and hardware Chrome WebGPU at 1280×720 SDR, with overlays off. The captures cover low Sun, night, near and far scatter, and the full authored camera travel. The six presets contain no storm. Physical panel refresh is a later attended exit item.

- The Mac stops used `scripts/capture_v1_runtime.py --case exit-stop --mode fixed` with each shipped preset. The native fixed route driver used `THRUM_CAPTURE_ROUTE=examples/v1-game/routes/exit-flythrough.json` with `THRUM_SCENE=exit`. Chrome's `exit-stops` case supplied the matched paused RGBA submissions.
- Mac motion used the same store and release binary with `--case exit-route --mode realtime` and the checked-in flythrough, then `--case exit-drift --mode realtime` with the noon preset unpaused. Chrome motion used `scripts/capture_v1_browser.mjs --scene exit --mode realtime --route-file examples/v1-game/routes/exit-flythrough.json` with the merged exit asset source.
- I inspected whole-frame sheets, native-size crops and consecutive source frames against their 1× submission times. The linked 30 fps previews preserve elapsed time at half resolution. The sample records identify the original consecutive submissions even where a preview frame spans more than one. These observations concern the engine's submitted output under capture.
