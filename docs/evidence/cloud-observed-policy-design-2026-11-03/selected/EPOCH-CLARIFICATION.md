# Clock epoch coupling clarification

Design addendum,3 November2026. The source model/world does not own or receive SourceClock.epoch during step. Raw observation records belong to the owning SourceModel instance; identity is `{cellID,localID,birthTick}` within that instance. Reference IDs are local within that same instance. Record capture/reference tick and actual source time, never a fabricated clock epoch or qualified ID.

Only `presentation(requestedTime,epoch)`/capture binds the existing supplied clock epoch to `[epoch,cellID,localID]`, including retained reference IDs. This derived qualification cannot mutate raw records or become a second source authority. Metadata without a supplied presentation epoch exposes raw local identities with explicit `identityScope:model-instance`; it does not default them to epoch0. The direct-model offline harness must provide an explicit test namespace and label its identities as test-qualified rather than clock-qualified.

`fresh()` creates another owner with no inherited raw observation records. Reset/seek replaces source objects through the existing clock/world path; the external test/observer journal records interruption of the abandoned object's pending observation before replacement. Do not change SourceClock solely to insert an epoch into model steps. Pausing and same-cell clear recovery retain the existing object and raw record. Policy/source/config pins remain independent of display epoch. This addendum replaces epoch/qualifiedID requirements for raw capture in Revision2; those fields are required only on publication/capture products.
