# P0/P1a source code review

2 November 2026. Independent read of `src/weather.js`, `src/scene.js`, `shaders/source.wgsl` and the narrow call sites in `src/bench.js`/`src/gpu.js`, against the selected runtime source baseline. Scope is the 96×80×80 dense, RGBA16F correctness pilot. Sparse allocation, all-five family acceptance, complete atmosphere and M2 budgets are outside this code review. I made no implementation changes. `node tests/weather.test.mjs` passed; it does not exercise WebGPU source state, provider-off time or front direction.

## Actionable findings

### [P1] CPU weather stops when the optical provider stops or GPU submit is full

`Scene.render` advances `Weather` only inside its source-tick loop (`src/scene.js:18`). `bench.js` sets `ticks=0` whenever the provider is shadow/clear, and `Scene.render` returns before the loop at three pending graphs. Therefore the supposedly CPU-owned world wind/front/cause clock pauses with optics/backpressure. Repro: select shadow provider, leave Play on and watch `weather.tick`/`scene.time`; both stay fixed. Returning to volume resumes the frozen source. This violates the selected independent E1 weather authority and makes main-hidden/provider-off tests unable to prove it. Advance weather on the committed world schedule independently, then let the visual source consume named WeatherFrame ticks with bounded catch-up or explicit unavailable/latency. The shader/source field must not decide whether CPU causes advance.

### [P1] The dry front initially covers the centered cloud and retreats as it moves left

`Weather.sendFront` sets `frontX=3800`; each weather step subtracts 18 (`src/weather.js:5–7`). `localSource` computes `dryFront=1-smoothstep(frontX-400,frontX+400,x.x)` (`shaders/source.wgsl:20`). At the cloud center `x=0`, this is already 1 immediately after Send Front; at `x=4000` it is 0. As `frontX` decreases, the dry region `x<frontX` shrinks rather than entering the cloud from the right. This can misattribute sudden breakup to a moving weather response. For a left-moving dry side originating at positive x, use the opposite half-space or reverse the front trajectory, then prove local onset at successive fixed world probes. An independent test can evaluate the front mask at x=0 and x=4000 before/after a known tick without using the rendering shader as its oracle.

### [P1] Reset and capture can claim an epoch/image that was never submitted

`Scene.reset` returns `false` at three pending GPU graphs before changing `epoch` or initializing q (`src/scene.js:17`), but `bench.js::reset` has already replaced the `Weather`, changed `scene.family` and camera and ignores that return. A reset click under load can therefore leave the old q field under new weather/family controls without the intended new optical epoch. `bench.js` capture likewise ignores a `false` return from `Scene.render(...,0)`, then waits and labels the canvas with `scene.time` and current controls even if the requested new view did not render. These are concrete source/image attribution errors, especially during fast 16×/64× or recovery. Queue/coalesce a reset until an epoch barrier can publish, or leave both weather and scene unchanged on refusal; require a successful render submission and its exact frame/source metadata before capture receipt. Keep submitted source time distinct from displayed canvas time. Tests should saturate three in-flight graphs, request family reset/capture, and verify no old-pixel/new-epoch receipt.

### [P2] Source injection ignores lift, and the mature pulse process is periodic fixed sites

`localSource` multiplies source by moist only (`shaders/source.wgsl:18–20`); lift affects `velocity` but does not gate new q. With `moist>0,lift=0`, the current source still creates/renews liquid at the fixed emitter sites, unlike the selected `lambda=lambda0*moistening*lift` producer. The eleven source centers remain fixed; sine windows repeat with a nonzero 0.12 floor, so this pilot does not yet implement bounded staggered pulse birth/expiration under one persistent body ID. It may show changing brightness at existing sites while the Eulerian structure settles or repeats. This is an **open P1a behaviour**, not a reason to add a parcel/physical solver. Gate source by the declared controls, implement/record deterministic finite pulse identities or explicitly narrow this diagnostic, and inspect connected-component births/losses at normal and accelerated time. A held-out proof should set lift to zero while moist stays positive, then restore it during a mature cloud and look for new local support, old loss and persistent body identity.

### [P2] MacCormack does not use its declared invalid-donor fallback

The selected algorithm says the corrected value reverts to first-order when donors are invalid/unknown. In `source.wgsl:25`, out-of-domain corners are filled with zero and included in `lo/hi`, then the corrected value is clamped; there is no invalid-donor branch that sets `adv=fwd.xy`. A backtrace crossing the finite source boundary can retain or create a nonzero corrected q in a partly valid donor cell even when `qAt` returned zero for the actual out-of-domain point. This matters for boundary occupation/halo evidence and any later sparse version. Track whether the traced point and all required donor corners are valid; on invalid/unknown support, take the first-order value and mark the boundary policy. Compare a translating 3D pulse across a known edge with an independent analytic zero-inflow reference and source=loss=0; inspect total, occupied support and no newly positive inflow voxels. The dense fixture need not implement P3 sparse halos now, but its MacCormack label should match the selected fallback.

### [P2] Weather command bounds and front replay are not enforced

`Weather.command` checks only finite values (`src/weather.js:4`), although the source reaction assumes nonnegative S/D and the authored controls have bounded domains. External `weather.command({dry:-100,moist:-100,lift:-100})` is accepted; the shader then has negative rates, so the exact positive reaction claim no longer applies. `sendFront` increments revision but does not append a command to `commands` (`src/weather.js:7`), so seed plus command log cannot reconstruct a front. The command ring silently drops entries after 256 without a checkpoint. For the pilot, validate field domains before mutation, record front events with their tick/trajectory, and state the bounded replay/checkpoint limit rather than treating this array as recoverable source history. Independently test rejected negative/nonfinite/out-of-range controls, rejected partial updates, and replay equality at a tick after a front command.

## Scoped positive observations and still-open proof

- The CPU scalar reaction test covers positivity and two half-steps for fixed rates, and the WGSL update uses the corresponding exponential form for the admitted positive rates. The q fields are ping-ponged; the 4 source passes and half-resolution rest pass are encoded before the same graph's light and view reads, so their normal queue order is coherent.
- `Scene.render` uses separate uniform buffers for its two allowed source ticks and a distinct view buffer, avoiding one buffer being overwritten between passes. The 96×80×80 dense field is deliberately a small source/optics pilot; its lack of page allocation, halos, occupancy mips and full-sky LOD is not itself a failed P3 implementation.
- The Cb band overlaps upward motion and radial outflow, with a bounded same-cell liquid→ice transfer (`source.wgsl:16,27`). Its visual anvil is unproved. The reset initializer prepopulates a tall Cb field (`source.wgsl:22`), so this reset state cannot by itself qualify continuous Cu→Cb development from inception; that later family proof needs a clear/low initial state and a controlled storm transition.
- The first image is reported faint; changing camera/optical calibration is in progress. This review makes no beauty verdict from that image. The source code and finite probe do not establish native Cu morphology, local mature renewal, front response, light/shadow/reflection agreement or browser performance.

## Independent verification targets

1. **World-clock/epoch oracle:** record CPU weather tick/revision and source submitted/completed/displayed time separately under volume, shadow, clear, GPU backlog and reset; compare against a CPU schedule driven by wall/world time, not a shader diagnostic.
2. **Advection oracle:** initialize a compact 3D pulse, set source/loss=0 and constant wind, and compare translated center, support and boundary loss with an analytic translated field at .25 s and multiple steps. Reverse wind and include a donor crossing; this rejects a limiter that merely stays bounded but transports incorrectly.
3. **Reaction/source oracle:** at zero velocity, check GPU q against the closed-form constant-rate solution from an independent scalar reference at selected voxels and `S=0`, `D=0`, `S,D>0`, plus a newly activated empty voxel. Compare positive-source support against exact zero, not only total q.
4. **Consumer-time oracle:** after a live front changes one source region, sample the same world ray/time through direct coefficient, light/receiver, fog/air and mirror paths. Hold main off. A stale reader must report its old source revision rather than match current timestamps by label.

The findings are defects/unfinished behaviour in the bounded pilot, not evidence that the selected live 3D architecture or M2 profile has failed. Resolve P1 attribution/authority errors before using captures or front motion as acceptance evidence; resolve P2 source/limiter cases before claiming P1a local renewal and bounded advection.
