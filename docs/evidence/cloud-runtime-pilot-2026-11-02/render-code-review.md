# P0/P1 render implementation audit

2 November 2026. Read-only audit of the current `tmp/cloud-production-proof` shaders and JS against `CLOUD-PRODUCTION-BASELINE.md` and `CLOUD-PROOF-ACCEPTANCE.md`. This is an early dense 3D source/view pilot. It does not qualify the full atmosphere, sparse source, BSM, environment cube, temporal reconstruction, art, or device targets. The inspected `cloud-0-11300` capture (build `2ab3ad2a942ae98e`) shows a faint cloud and ground shadow; its source receipt reports 5,943 occupied voxels, optical proxy sum 537.646, and no reported GPU errors. I did not run the proof or inspect a current device session.

## Verified working path

- `Scene.render` orders source update, current light cache, joint view with an independent reflected `trace`, then display in one command graph. Main and reflection read the same current `q`/carrier/light resources. `Scene.reset` creates a new optical epoch and source state. The clear-air transmittance LUT is built once at initialization.
- `coefficients` is a shared 3D sampler for view, point-light cache, direct receiver Sun, and local Sun samples. `cloudSun` samples two 100 m local segments and queries the cache at the 200 m endpoint, so it does not double-count a full-column map. Outside the cache domain it uses a complete source-box direct ray.
- The GPU wrapper checks shader compilation messages, records uncaptured errors/device loss, limits submitted graphs to three, and keeps three frame uniform sets. The recorded receipt alone establishes only that this particular run did not report a GPU error.

## Actionable gaps in the current slice

1. **The Sun second octave is not the selected one.** `view.wgsl` uses `phase(mu, ice, 0)` with coefficient `1.0`; `optics.wgsl` and `light.wgsl` use `exp(-.25*tau)`. The selected baseline is contribution `a=.5`, optical-depth multiplier `b=.5`, phase eccentricity multiplier `c=.5`. This materially changes the forward lobe and brightness and makes calibration against the chosen model misleading. Set all three factors coherently, including direct reference and cached channel.
2. **The light/reference integrals do not use the view's optical field.** The view and 200 m Sun prefix sample `coefficients(..., 1)`, while the cache and `directT` use detail `.25`, and ambient rays use detail `0`. `tauRay` places 32/20 uniformly spaced samples across the *whole source box*, not occupied intervals. A roughly 190–240 m source injection band within a several-kilometre Sun chord can fall between samples. This can yield clear Sun/ambient estimates in a visibly occupied cloud and defeats the claimed point-cache versus complete-ray comparison. For this dense pilot, use one declared coefficient/LOD convention and a support-aware or demonstrably resolved direct reference; occupancy acceleration can follow in P3.
3. **MacCormack has no invalid-donor fallback.** `source.wgsl` substitutes zero for out-of-domain donor corners and clamps the corrected value to extrema including those zeros. The baseline requires reverting to the first-order `fwd` value on invalid/unknown donors. At source boundaries and fresh birth support, zero-filled correction can erase or distort material. The source should detect invalid donors and take the first-order value, with a boundary/birth probe.
4. **The “finite GPU checks” do not test finiteness.** `bench.js` sets `sourceFinite` from `probe.errors.length===0`; `scene.probe` accumulates rounded sums and threshold counts, not explicit finite tests for all q/carrier components. A shader may produce a NaN/Inf without a WebGPU validation error; conversion to integer counters does not make that a reliable finite test. Add explicit nonfinite counts and report them separately from API errors before accepting P1a source validity.
5. **Camera gestures can move the eye below the ground with no body cut.** `bench.js` permits pitch down to `-.7`, distance up to 40 km, and unbounded vertical pan. With the fair-weather target at 2.2 km, default 7.5 km distance and pitch `-.7` already put the eye about 2.6 km below y=0. `view.wgsl` only detects ground for a downward ray from above it, so below-ground views can integrate through the planet. Clamp the navigation camera to admitted above-ground positions or terminate rays on the planet/ground consistently.
6. **Reset may be acknowledged without occurring.** `Scene.reset` returns false when three graphs are pending, but `bench.js` replaces the Weather authority and announces a new optical epoch without checking the return. On a busy GPU this leaves old q/time/epoch paired with new weather and UI controls. Defer/retry the reset before replacing the authority or report it as unavailable. This is a P0 generation/invalidity issue.
7. **The P0 no-consumer idle path is not implemented.** `Scene.render` dispatches the point-light cache and view/display every frame regardless of `main`, `mirror`, or clear-provider selection; the runner has no state that removes all optical demand. Thus a hidden main view cannot currently establish the required retained-consumer versus zero-consumer cost/queue distinction. Add an explicit demand gate and receipt before claiming P0 idle behavior; current graphs are valid as an always-on pilot only.

## Later-slice limitations to keep explicitly unqualified

- `fogSigma` occupies y=0–620 m, while the normal cloud box begins at y=400 m. Pre-box, post-box, and empty-box rays call `rayAir`, which omits fog. `fogSun` still attenuates ground/cloud Sun, so enabling the UI fog toggle does not produce a complete joint fog view. Resolve at P4 joint fog acceptance; do not use this toggle as present evidence of that path.
- Clear-air source outside the cloud box receives `airSun` but no cloud/geometry shadow. The current cache is only used for air/fog sources inside the cloud box. Moving cloud shadows through clear air remain P4 work.
- The current cache covers only the one dense source box and has no validity mask, per-corner validity test, multi-domain support, or demonstrated offscreen-source union. The fixed `skyMean` is a labelled placeholder. BSM, environment capture, sparse occupancy, near/far/history and full atmosphere are absent and must retain their existing unrun gates.
- The capture's `gpu.wholeMs=466.22` and `viewMs=11.27` are not a passing performance result; the pilot/IAB tier is separately labelled unqualified. The single receipt does not establish stable timings or explain the wall gap between GPU passes.
