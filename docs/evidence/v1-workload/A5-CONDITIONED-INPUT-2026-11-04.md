# A5 conditioned four-peer input, 4 November 2026

The same 10,000-entity/1,500-moving V1 simulation ran for 600 fixed ticks with four owned actors. A preallocated N1 window holds future frames; W1's existing next-tick `Simulation::admit_frame` remains the gameplay gate. The diagnostic sends one in-memory packet per peer/tick, each repeating up to four exact target-tick samples. Its fixed-seed conditioner drops packets at a 2% configured rate and delays delivered packets two to four 60 Hz ticks one way (33–67 ms, an approximation of 100 ms RTT with 20 ms jitter). Inputs target five ticks ahead. This run uses no socket, encoded bytes, client replica or prediction branch.

| --- | --- |
| One 600-tick process | 2,400 packets sent; 55 dropped (2.29% observed), 2,330 delivered and 15 still in flight. 2,380 due input frames admitted, exactly four per tick after the five-tick lead; zero due misses. Tick work p50/p95 47/50 µs; it includes the in-memory link and full 10k W1 step, without wall pacing, rendering or OS transport. |
| Divan, 20 complete 600-tick runs | Median 28.62 ms per run. The benchmark thread made 131 Rust allocations / 5.534 MB per complete run, including construction and teardown. This is an absolute baseline, not a one-peer speedup. |
| Counting-allocator assertion | Zero Rust heap allocations across 500 warmed consecutive ticks, including link delivery, future staging, W1 admission/step and timing collection. Setup and teardown allocations are outside the measured scope. |

The shared action validator was extracted from W1 admission and called before N1 reserves a future slot. Focused tests show that an invalid action cannot block a later valid frame for the same peer/tick; they also cover out-of-order arrival, duplicate and conflicting values, late/far-future targets, wrong actor/epoch, an undrained due slot and reconnect clearing. The read-only review found this invalid-first defect and found no remaining issue after the fix. `./dev check` and target Clippy results are recorded by the commit containing this evidence.

This is a partial A5 result. A deliberate burst-loss run, result identity/ACK closure, actual schema codec and transport, client prediction/reconciliation, visible correction behavior, browser/phone multiplayer and sustained device budgets remain open. The current diagnostic terminates on an unexpected W1 fault; a production session must retain pending input and resolve the exact outcome on retry or close.
