# G2 running-game qualification

4–5 November 2026. Apple M3 Max, Rust 1.99.1, release build. This is the actual `examples/v1-game` authority with 10k/1.5k or 100k/15k movers, four registered peers, game-owned fields and rules, engine-owned registered hecs storage, checked identity and leased publication. The bench warms 60 ticks, then uses `cargo bench -p v1-game --bench frame --offline game_tick -- --min-time 0.2 --max-time 1`. It admits no new frame in the timed loop; four-peer, failure, spawn churn and replay paths have separate tests. These are local diagnostics, not V1 device budgets.

| Complete game operation, median | 10k | 100k |
| --- | ---: | ---: |
| Serial tick and published page | 138.1 µs | 1.394 ms |
| Rayon schedule waves and mover jobs | 324.2 µs | 1.656 ms |
| Serial tick, page and rolling delta | 192.3 µs | 2.060 ms |

Serial remains the default. A counting allocator observed zero allocations in 100 warmed serial 10k ticks, 100 warmed spawn/despawn ticks, and 100 warmed tick-plus-history operations at both 10k and 100k. Divan observed about 0.03 occasional Rayon scheduler allocations per measured tick. The tick has no hard-coded core topology; platform policy can select a core-class-aware executor later. Two independent input callbacks execute in one conflict-free wave with private outputs under Rayon. The four-peer 10k test compares complete endpoint rows, accepted origins, dirty positions and structural events after refusal, churn and restore/replay. The game tests verify canonical order after swap-removal and replay.

The engine holds one full typed-column baseline and a reusable, bounded 64-tick chain of changed-component and structural deltas. Each delta is tied to its exact predecessor revision, so a divergent same-tick replay is refused. Restore clears abandoned change lists, journal and delta eligibility; a new committed tick creates a new revision. The history advances its baseline as old deltas leave the window. Retained storage measured before the deep-size callback change was about 7.45 MB at 10k and 64.7 MB at 100k for the 64-tick history, versus 1.49/14.88 MB full baselines. Component registration now supplies a nested-storage counter for non-Copy values; V1 components are Copy. Pending input SmallVec spill storage is counted. A non-Copy column test covers independent copy, replacement, insertion and removal through overlay. The earlier full-capture median was 93.81/951.1 µs and full restore 1.531/19.27 ms; the rolling path avoids a full capture each tick, while restore remains a cold rebuild.

Production engine declarations of V1 position, velocity, health, visual, ownership and action types: **zero**. The running game owns schema, actions, validation, rules and pages. Typed edits preflight an entire batch before mutation; post-commit callbacks have read-only world access. The engine owns per-component change ticks and actual structural events, captured for replay. A restore generation travels with each published page into `SourceTick`, preventing presentation from reusing poses on a divergent branch even if it skipped the replay baseline. The native Metal host test `committed_ticks_drive_latest_gpu_frame_and_overload_is_explicit` passed after the replay and presentation changes with native device access. Its 100 ms per-poll timeout was extended to the existing 10 s overall wait budget to allow normal GPU startup latency. `./dev check` passed after the replay fixes and the independent read-only review found no blocker. G2 closes the generic simulation boundary; G3 moves `FrameHost` into the engine and qualifies the executing renderer.
