# A0 representative fixture checkpoint

3 November 2026, local arm64 macOS, Rust 1.99.1, optimized Divan 0.1.21. This is a workload *scaffold*, not the W1 engine tick, real transport, physics, renderer or phone result. It holds 10,000 records, moves 1,500 each step, churns 100 spawn/despawn pairs per 60 steps, and sends four peer packets through a deterministic 100 ms nominal RTT / ±one-tick one-way jitter / 2% loss conditioner. The fixture's warmed 600-step test observed zero heap allocation requests in its scoped thread and verified churn, all-peer delivery, 2–4 tick one-way delay, 1–3% sampled loss and conservation of delivered/dropped/in-flight packets. It does not count other threads or prove an engine allocation gate.

| Divan fixture operation | Local median, 0.1 s minimum run |
| --- | ---: |
| 1,500 position updates + churn + four-peer conditioner | 131.2 ns |
| Four-peer conditioner alone | 45.64 ns |

The benchmark passes its full workload to `black_box` after each step to keep all 1,500 updates observable. These tiny medians are fixture overhead baselines only. A1 adds actual component queries, scheduling and publication; A5 adds a real codec/session. The 10% regression policy needs stable repeated baselines and an integrated named-device path before it can gate CI.
