# W1 callback to N1 peer-owned queue and sent storage — 2026-11-03

This no-socket integration fixture connects the real `HeadlessHost` callback and
immutable W1 snapshot to four match/peer/epoch-bound N1 queues and ordinary
sent-frame ledgers. A deliberately small game schema maps 128 inline cells to
four complete 32-actor partitions. Each peer controls the first actor in its
own partition (wire IDs 1, 33, 65, 97); the local validator checks every ID,
owner, mode, orientation and partition size before certifying complete state.
The fixture copies R4 payload bytes before dropping each host publication.
No peer queue or ledger retains a W1 snapshot lease.

The focused test changes the authoritative world on nine consecutive 60 Hz
ticks. Peer 1 submits one increment each tick and peer 4 submits one at tick 2.
The queue releases every three ticks. Peers 1–3 acknowledge their exact written
frames; peer 4 remains unacknowledged until after tick 9. The authority reaches
tick 9 with peer 4's result and frames still retained, beyond the eight-page
snapshot overlap. Mismatched match and stale connection-epoch callbacks refuse
without retiring the authority result. A valid peer 4 ledger ACK then retires
both its exact sent entries and the authority's result. `./dev check` passes.

`Authority::acknowledge_results_for_incarnation` and the corresponding host
method check current authority ID, peer and connection epoch before calling the
existing contiguous-result retirement. This closes the stale-incarnation
callback boundary for a future authenticated ACK owner. It does not itself
authenticate a wire receipt. The production N1 crate depends on no core crate;
its `thrum-core` dependency is limited to integration tests.

## Selected release cost

The ignored release probe runs 10 warmup and 2,000 measured three-tick windows
in each fresh process on Apple M3 Max with pinned Rust 1.99.1. Each tick calls
the real host, captures all four partitions for four peers from its snapshot,
and drops the publication. Each window transfers and writes 16 coalesced
state-only groups, reads every encoded frame byte into a rolling checksum and
ACKs the exact sent prefix. Frame and byte counts are asserted for the measured
windows: 16 frames and 30,208 bytes per window, 32,000 frames and 60,416,000
bytes in total. Seven fresh-process samples have a **49,767.4 ns median per
three-tick window** (49,212.9–55,137.0 ns). Four
queues plus four ordinary ledgers reserve **1,169,376 Rust bytes**; this is
their reported value/arena/Vec capacity, not process RSS. See the [raw samples]
(N1-W1-CAPTURE-COST-SAMPLES-2026-11-03.csv).

Run the functional fixture with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test -p
thrum-network --test w1_capture`. Run the local release probe with
`RUSTC_WRAPPER= rustup run 1.99.1 cargo test --release -p thrum-network --test
w1_capture measure_real_w1_to_n1_state_only_path -- --ignored --nocapture`.

This selected state-only shape has no rule changes during the measured windows,
so the ordinary ledger processes ACKs without invoking authority result-history
retirement. The nine-tick functional case exercises that callback.
It excludes mandatory outcome/lifecycle/event bursts, a general game manifest
and dependency closure, client replica admission, baseline/sync ownership,
authenticated ACKs, socket/TLS buffering, allocator-call counts, RSS and
whole-game/device tails. The nine-tick functional case exercises outcomes but
does not supply a timing claim. Its local schema projection is test-only; the
production W1 projection/journal and one multi-group session owner remain
open. No general N1 or multiplayer readiness is claimed.
