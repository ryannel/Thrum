# Official capability scan: Unreal, Unity, Stride

1 November 2026. Source inspection only: official feature/release pages and linked manuals were opened. This is a comparison of **advertised and documented capabilities**, not a build, device test, feature completeness audit, or ranking. Current engine coverage refers to [ARCHITECTURE-BRIEF](../../../design/ARCHITECTURE-BRIEF.md), [AUDIO-UI](../../../design/modules/AUDIO-UI.md), [TOOLS-DELIVERY](../../../design/modules/TOOLS-DELIVERY.md), [PLAY-SYSTEMS](../../../design/modules/PLAY-SYSTEMS.md), [ENGINE-EXPERIENCE](../../../design/ENGINE-EXPERIENCE.md), and [AI-DEVELOPMENT](../../../design/AI-DEVELOPMENT.md). Those describe a custom engine in design, not implemented features. A01–A05 remain open. Desktop Mac/PC, browser and native mobile are our goals; pure 2D/MMO are out, ordinary networking undecided. Do not infer that one cited engine or one of its advanced features works on every target.

## Comparison with our capability inventory and recommendations

The brief already names F1–F4, W1–W2, P1–P7, V1–V5, E1, A1, U1 and T1/T2. Many seemingly new competitor features are therefore **hidden under broad labels**, not absent. The table distinguishes a responsibility from a complete creator workflow.

| Priority / disposition | Current coverage and owner | Recommendation and game reason |
| --- | --- | --- |
| **Narrow addition: translation production and locale-specific assets** | [AUDIO-UI](../../../design/modules/AUDIO-UI.md) already specifies stable localization keys, plural/select rules, locale formatting, font fallback, missing-string cook policy, live locale switch and localized audio cue variants. This is **covered**, despite the brief's short “localization hooks” label. | Consider source-text extraction, translator interchange, pseudo-localization and validation for locale-specific art/model/audio assets as later T1/F4/T2 authoring/delivery refinements. Specify them only when a multilingual game/demo needs a translation production loop; no second localization authority. [Unity package](https://docs.unity.com/en-us/engine/6000.3/manual/packages-list/packages-all/pack-safe/com-unity-localization); [Unreal tools](https://dev.epicgames.com/documentation/unreal-engine/localization-tools-in-unreal-engine). |
| **Retain accessibility; no new capability gap** | [AUDIO-UI](../../../design/modules/AUDIO-UI.md) already designs U1's stable semantic tree, roles/names/values/actions, focus, captions, browser DOM/ARIA, provisional desktop AccessKit, separate iOS/Android native bridges and platform tests. P1 owns remapping/assistance. | Preserve its explicit platform limitations and qualification gates; the [Unity module](https://docs.unity.com/en-us/engine/6000.3/manual/accessibility/module-intro) independently reinforces that metadata needs authoring and device/screen-reader testing. The brief's shorthand should not be mistaken for absence. |
| **Retain build-content visibility; detail only if needed** | F4/T2 already specify dependency closure/manifests; [ENGINE-EXPERIENCE](../../../design/ENGINE-EXPERIENCE.md) explicitly says diagnostics show what is included and why, while [COMPOSITION](../../../design/COMPOSITION.md) says the lock shows why packages remain and which work is excluded. A03 still owns shader-demand closure. | When T1/T2 is implemented, ensure the existing diagnosis reaches individual asset/product/variant inclusion and gives approximate target size or download cost where available. This is a detailed UI/reporting acceptance criterion, not a newly missing capability. [Stride asset inclusion](https://doc.stride3d.net/latest/en/manual/get-started/assets.html). |
| **Retain named target build configurations** | [ENGINE-EXPERIENCE](../../../design/ENGINE-EXPERIENCE.md) already names versioned game-owned target profiles; F2/T2 have build/load plans and development/export/release distinctions. | Ensure the same selected profile/lock is invoked by CLI/CI and workbench when implemented. This is existing design, not a reason to copy Unity's build-profile asset type. [Unity build profiles](https://docs.unity.com/en-us/engine/6000.3/manual/building-and-publishing/build-settings/build-profiles), [CLI builds](https://docs.unity.com/en-us/engine/6000.3/manual/building-and-publishing/build-command-line). |
| **Retain and qualify creation/iteration, with A01/A02 as gates** | T1/T2 and AI-development already specify same source for humans/agents, typed operations, CLI, starter, capture, source/build identity and isolated play recommendation. | Keep these as core, define the pending source/edit/play isolation mechanism before claiming a working editor or live agent bridge. Unreal's Experimental Sandboxes and MCP plugin are examples, not mandates. Stride's code-only/CLI route confirms a full native GUI need not gate initial authoring, while its Mac editor gap warns that code-only is not artist usability. [Unreal 5.8](https://www.unrealengine.com/news/unreal-engine-5-8-is-now-available); [Stride platforms](https://doc.stride3d.net/latest/en/manual/platforms/index.html). |
| **Optional media/video playback; retain sequence capability** | P6 already has authored camera/animation/audio/game sequencing; the brief does not promise video decode. | Add video playback only for a named game/demo need (cutscene, screen in world, external footage). Keep P6 sequencing and asset/provenance hooks. Video brings codec, streaming, sync, accessibility/captions and platform packaging obligations that the present game range has not selected. [Unity video docs](https://docs.unity.com/en-us/engine/6000.3/manual/video). |
| **Defer genre-specific gameplay and high-end art packages** | P6 deliberately leaves combat, quests and inventory game-owned; P4/V3/E1 have optional providers. | Do not add Unreal's full ability framework, digital-human crowds, cloth, Nanite-style geometry, experimental mesh terrain or procedural vegetation as required engine modules. Demand a representative game and target budget first; keep extension seams. [Unreal ability scope](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-the-unreal-engine-gameplay-ability-system), [5.8 maturity labels](https://www.unrealengine.com/news/unreal-engine-5-8-is-now-available). |
| **Remove overclaims from comparison language** | Existing brief is mostly careful: web is separately qualified, ordinary networking undecided, runtime unbuilt. | Do not call a feature “cross-platform” merely because its engine ships on several platforms; distinguish editor OS, toolchain/build host, native/browser player, graphics backend and feature-specific support. Do not equate feature index, release claim, docs and measured behavior. Stride's no-web/Windows-editor split is a concrete counterexample. [Stride platform manual](https://doc.stride3d.net/latest/en/manual/platforms/index.html), [FAQ](https://www.stride3d.net/faq/). |

**Correction after owner-doc reconciliation:** semantic accessibility, runtime localization, named target profiles and creator-visible inclusion diagnosis are already designed. The remaining plausible addition is a scoped translation production loop (extraction/interchange/pseudo-localization and locale-specific asset validation); media/video is optional. The strongest unresolved creation mechanisms remain A01/A02, already tracked, not new survey findings. The survey found no reason to remove existing core responsibilities. Networking, XR/VR, LiveOps and real-time collaboration appear in competitor pages, but are not required by the confirmed game range; ordinary networking remains an open product question. No runtime, device result, popularity estimate or exhaustive competitor coverage was established.
