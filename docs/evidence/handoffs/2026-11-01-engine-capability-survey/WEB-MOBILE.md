# Browser and mobile engine capability survey

Official PlayCanvas, Babylon.js and Defold pages inspected 1 November 2026. This is a capability inventory comparison, not a proposal to use any of them as the host or to implement every advertised feature. The target is the custom 3D engine in `notes/engine-rebuild/ARCHITECTURE-BRIEF.md` (E01–E12); `AI-DEVELOPMENT.md` supplies the agent workflow. A01–A05 remain open. Claims below are vendor documentation, not independent quality or device certification.

## What the references actually cover

| Reference | Meaningful advertised capabilities | Scope or limit evident in the official pages |
| --- | --- | --- |
| PlayCanvas | Browser 3D engine with ECS, graphics, animation, physics, audio, UI, touch/gamepad, glTF/compressed assets; optional component-system registration and tree-shaken builds. Separate collaborative browser Editor with asset pipeline, scene tools and publishing. Editor MCP can mutate projects and inspect a running Launch instance. [Engine](https://developer.playcanvas.com/user-manual/engine/), [Editor](https://developer.playcanvas.com/user-manual/editor/), [MCP](https://developer.playcanvas.com/user-manual/editor/mcp-server/) | Engine targets WebGPU or WebGL 2 browsers, and its documented mobile app-store path wraps web content with Cordova or a WebView. WebGPU availability varies by browser/device. The Editor is a distinct product and its MCP depends on an open connected session. [Supported browsers](https://developer.playcanvas.com/user-manual/engine/supported-browsers/), [mobile publishing](https://developer.playcanvas.com/user-manual/editor/publishing/mobile/) |
| Babylon.js | Web 3D framework with WebGL/WebGPU, scene graph, cameras, animation, GUI/audio/physics, PBR, rendering techniques, LOD/instances, asset formats, inspector and separate node editors for material, geometry, particles and render graph. Specifications also advertise a native host, offline IndexedDB assets and incremental loading. [Specifications](https://www.babylonjs.com/specifications/) | A feature list demonstrates available methods, not equal quality or support across every backend and native target. Its tool set is not evidence of a single integrated game editor equivalent to a full production suite. [Specifications](https://www.babylonjs.com/specifications/) |
| Defold | Full editor and packaging toolchain for desktop, mobile and HTML5, 2D/3D scenes, GUI, scriptable rendering, Lua/native extensions, hot reload, debugger/profiler, build-time feature removal and on-demand Live Update content. [Product overview](https://defold.com/product/), [size optimization](https://defold.com/manuals/optimization-size/), [Live Update](https://defold.com/manuals/live-update/) | Defold says its strengths are especially in 2D even while supporting 3D. HTML5 hot reload is unsupported; threaded Wasm needs cross-origin isolation and compatible hosting, and a non-threaded bundle is a documented fallback. No Defold result establishes the target's intended 3D visual quality. [Product overview](https://defold.com/product/), [HTML5](https://defold.com/manuals/html5/) |

## Boundaries retained

The inventory should not absorb pure-2D tools, console/advertising SDKs, XR, massive multiplayer or an ordinary-networking commitment merely because surveyed engines advertise them. Defold's 2D production strengths and Babylon's extensive graphics list are useful evidence of available patterns, not requirements for this 3D engine. No source here proves visual quality, footprint or mobile performance on the target's eventual named devices; those stay in the D0/I4 qualification path. The proposed deltas do not close A01–A05.
