## Ranked integration findings

### 1. Session and source authority still block the D1 foundation contract — established A01/A02, high

The plan correctly separates durable files, desired edits, cooked products, active world state and checkpoints (`ENGINE-EXPERIENCE.md:15-22`; `CONTRACTS.md:23-26`; `modules/WORLD-CONTENT.md:95-109`). Yet it has not chosen play-world isolation/apply-back or a coherent external multi-file source admission boundary (`ARCHITECTURE-AUDIT.md:36-37`). These two decisions meet at world IDs, source pins, accepted-operation order and the `RecoveryRoot`: an external checkout during a disposable play session could otherwise be interpreted as either the next project revision or an unrelated branch while a saved play overlay still names the old source. That is a concrete route to replaying edits against the wrong base, not a complaint that a format or editor UI is unspecified. **Owners:** F1/F3/W1/P7/T1/F4/T2, with P3/P6 session state. **Earliest gate:** D1 identity/source/recovery API freeze (`CONSTRUCTION-PLAN.md:42-46`). Compare isolated world, checkpoint/restore and separate process for play; compare file-first, database/export-first and manifest-selected file revisions for source. Choose one source pin and conflict/restart rule before advertising typed edits or beginning I2. **Contrary evidence:** C10 already gives a coherent durable restore root and recovery rules *within a selected source lineage*; the content-lifecycle review closed its earlier publication counterexamples at high level (`research/CONTENT-LIFECYCLE-REVIEW.md:108-116`). This finding is the narrower, acknowledged A01/A02 boundary.

### 2. Preserve-world reparenting is not representable under the promised local transform — **new N01**, medium

W1 stores local transforms as `T * R * S`, then says a preserve-world reparent calculates `inverse(new_parent_world) * old_world` and rejects only singular parents and cycles (`modules/WORLD-CONTENT.md:27`). A nonsingular result need not be another `T * R * S`. For a parent with nonuniform scale `diag(2,1)` and a child whose old world rotation is 45 degrees, the required two-dimensional local block is `diag(1/2,1) * R(45°)`. Its columns have a nonzero dot product (magnitude 0.375), while columns of a rotation times diagonal scale are orthogonal. The missing component is shear. W1 can already produce sheared *world* matrices by composing valid local TRS nodes, so this is not an exotic imported matrix alone. An editor or agent could reparent a static prop to a scaled assembly, receive an accepted operation, and then find its visual and collider placement changed if the matrix is silently decomposed back to TRS. The dynamic-body restriction in the same paragraph helps P3 authority, but does not cover ordinary static, kinematic or authored attachment hierarchies. **Owners:** W1/T1, with F3 schema/validation and P3/V2 consumers. **Earliest gate:** D1 transform and typed-operation contract, before I2 scene editing. Choose explicitly between (a) affine/shear-capable local storage with downstream representation rules, and (b) TRS-only storage with a tested decomposition/round-trip tolerance that rejects a preserve-world operation when the result is not representable; preserving local remains a valid declared alternative. An analytical fixture should cover scaled rotated ancestry, prefab overrides and the same physics/render world matrix. This is a bounded contract correction, not a demand to adopt arbitrary transform algebra everywhere.

### 3. Render and environmental seams must close before the integrated scene, but need not enlarge the baseline — established A03–A05, high for their selected uses

A03 leaves cooked shader demand/readiness and profile transitions undefined at the point where F4 claims required-product admission (`ARCHITECTURE-AUDIT.md:38`); a valid material can select a stripped or unprepared variant on browser/mobile. A04 leaves cross-domain water level/flux/query ownership unspecified (`ARCHITECTURE-AUDIT.md:39`); a body crossing river–sea domains can receive incompatible physical heights even if the meshes meet. A05 is a direct representation inconsistency: independently preintegrated media pairs cannot in general yield the exact overlap combination required by C08 (`ARCHITECTURE-AUDIT.md:40,50-56`). **Owners/gates:** F2/F4/V1/V3/T1/T2 at the D1–D2 cooked render seam for A03; E1/P3/W2/P7/V2/V3 before a selected water-family API freezes for A04; E1/V3/V1 before overlapping media providers integrate for A05. The plan already scopes these to selected requirements rather than demanding every water regime or every atmospheric model (`ARCHITECTURE-AUDIT.md:75-102`). Use finite shader closures with explicit unavailable/loading behavior, declare each selected water adjacency's exchange policy, and either supply coefficients to a joint medium integrator, restrict preintegrated pairs to disjoint segments, or label layering approximate. **Contrary evidence:** The baseline renderer, material/transport and C05 product admission contracts are substantive; these are finite boundary decisions, not evidence that the full rendering stack should be replaced.

## Design judgment across the whole plan

**Keep.** The most useful simplicity choice is the recent explicit static game setup, direct typed game registration and finite target tiers (`COMPOSITION.md:8-14,27-33`; `CONSTRUCTION-PLAN.md:32-38`). It supports small games without assigning every rule its own package. Stable authored IDs versus runtime generations and product hashes, a single committed fixed-tick authority, specialized P3/P4/P5/V2 stores, pre-tick required activation, bounded snapshot/lease lifetimes and a recoverable content/save root form a coherent cross-module backbone (`modules/WORLD-CONTENT.md:19-29,95-109`; `CONTRACTS.md:9-33`; `modules/WORLD-CONTENT.md:111-118`). The independent content-lifecycle closure supports keeping this model rather than inventing a new universal transaction manager (`research/CONTENT-LIFECYCLE-REVIEW.md:108-116`). The world/physics/animation handoff explicitly returns solved motion to animation and avoids a second transform owner (`modules/PLAY-SYSTEMS.md:19-27`). Headless play and per-view presentation separate semantic state from quality (`modules/PLAY-SYSTEMS.md:7,68`). The construction plan has meaningful D0/D1/D2 and I1–I4 gates and labels paper predictions as unqualified (`CONSTRUCTION-PLAN.md:40-53`).

**Remove or defer by default.** Keep universal plugin descriptors, arbitrary provider search, executable hot loading, gameplay live removal and whole-renderer replacement outside the baseline unless a named distribution or style case selects them. The governing composition text already narrows those promises (`COMPOSITION.md:8-14,24-25,29-33`); older descriptor/lifecycle examples in that same document are contingent and should not become I1 work by inertia. The bounded W1 ECS/library comparison at D1 is legitimate; the no-Bevy-host selection does not force custom commodity storage (`ARCHITECTURE-AUDIT.md:63-69`; `modules/WORLD-CONTENT.md:25`). Do not make optional E1 domains or advanced animation/quality systems prerequisites for the first integrated scene (`CONSTRUCTION-PLAN.md:46-49`).

**Ledger precision.** `maturity.json` marks E1 as `reviewed_with_gaps` with A04/A05 (`maturity.json:650-684`), while its `E1.atmosphere` and `E1.water` child records still say `integration_review: reconciled` (`maturity.json:711-717,825-843`). Their `review_basis` explicitly calls the older family review historical, so this is not a new physical defect. It is a navigation risk if a reader filters only leaf records before D2. The ledger should expose inherited open findings on affected child rows or document that parent findings govern leaves. **Owner:** maturity coordinator/E1. **Gate:** before D2 work is assigned from the machine ledger. No separate architecture mechanism is needed.

## Open decisions and readiness

At D0, name representative scales and minimum device/browser/mobile configurations before treating symbolic budgets or the clustered-forward baseline as qualified (`CONSTRUCTION-PLAN.md:15-24,40-44`). Decide whether static scene admission is an essential W1/F4 path and W2 streaming is selectable, or whether every small game pays for the full region activation protocol; `WORLD-CONTENT.md:127` currently says all regions may simply stay active. This is a simplification question, not a proven contradiction. At D1, close A01/A02 and N01 together with identity, schema and source transaction boundaries. At D1–D2, close A03, and close A04/A05 for the water/media combinations actually selected for I3. Require each decision to identify the producer, consumer, tick/publication point and failure outcome, with one paper fixture before implementation. The existing `D0 → D1/D2 → I1/I2/I3/I4` order remains appropriate (`CONSTRUCTION-PLAN.md:40-53`).

**Recommendation:** ready to proceed with D0 and owner-coordinated detailed design; **not ready to freeze D1 interfaces or claim an integrated/portable engine**. The latter requires the named contract decisions, a first complete scene and device/runtime evidence. This is a design review; it does not certify implementation, performance or any target platform.
