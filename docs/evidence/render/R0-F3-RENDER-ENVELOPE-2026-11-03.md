# Render-v1 checked envelope and borrowed collections

3 November 2026. `thrum-source` now compiles a private inactive render-v1 envelope layer. `environment_json::CheckedRecord` ties the existing bounded, tree-free `record_header` result to its original byte slice. The render check consumes that opaque token; a caller cannot supply a header from A with bytes from B. F3 can pass the token created during dispatch, and F4 can request the same check after a complete accepted-pin copy, so typed preparation need not repeat the whole-record walk.

The second pass strictly decodes the `thrum.render.scene@1` envelope and fields map while borrowing six `RawValue` collection slices from the input. It allocates no collection-wide raw-value index. Ordinary root/active-camera UUID strings borrow source bytes; escaped equivalent spellings may own small decoded scratch. Both IDs become canonical 16-byte values. Unknown, missing and duplicate **decoded** envelope/fields keys refuse. Optional documentation is limited to 4096 decoded UTF-8 bytes; a raw-token ceiling of `6×4096+2` bytes bounds escape scratch before decoding, while permitted external whitespace does not change the result.

Three focused Rust tests cover `fields` before root identity, six actual in-input slice borrows, plain borrowed versus escaped owned text, escaped key/value equivalence, decoded duplicate/unknown/missing fields, null documentation and both sides of the documentation limit. Targeted Clippy with warnings denied, an independent defect-first review after the opaque-token correction, and the full repository gate pass. The reviewer found no remaining actionable issue in this slice.

The collection values are **raw and provisional**. This layer does not parse cameras, meshes, instances, materials, textures or lights; it does not check embedded UUIDs, numeric geometry, edges or global closure. It is not wired into F3 dispatch or F4 cook, and it issues no source-validity or ready-product receipt. The existing header's escaped-string scratch, second-pass cost, complete-record peak, charged work and admission latency remain unmeasured. Serde derive adds a build-time proc macro to `thrum-source`; no simulation runtime dependency or reflection is introduced.
