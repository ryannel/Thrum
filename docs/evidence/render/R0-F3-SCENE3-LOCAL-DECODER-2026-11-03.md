# Inactive scene@3 local source decoder

3 November 2026. The private `core.scene@3` decoder checks a strict map envelope and the required `render.source` UUID declaration, with optional existing `scene.label` and `environment.source`. Both references are binary canonical UUID facts; they are not resolved by this module. A byte entry performs the bounded whole-record header walk, while an entry accepting F3's opaque checked token reuses that walk. The module is absent from `builtin_schema` and F3 dispatch, so scene@3 is still unsupported for source admission. Existing scene@1/@2 parsing and the pinned scene@2 constant-light cooker remain unchanged.

Known decoded-key duplicates are reported before scene field meaning. The field order is label, environment source, render source, then unknown decoded keys. Optional means absent or present with the required type; explicit `null` refuses. Label and documentation have a 4096-byte decoded UTF-8 limit with raw escape-length checks before allocating escaped text. A canonical 36-byte UUID is raw-bounded at 218 bytes before unescaping. The separate immutable scene@3 descriptor has domain-separated SHA-256 `7671b216f8090e662bdf6f85c10026c835184f96b529082359b7b7f29dd222ea`; it is deliberately unregistered.

Nine focused tests cover minimal and complete facts; plain/escaped equivalence; known duplicates, unknown order and missing/bad UUIDs; strict map/null refusal; 4096-byte text boundaries; exact 16 MiB record, one-million-node and 64-level header boundaries; checked-token equivalence; and the golden descriptor digest. The selected [authored scene record](R0-AUTHORED-SCENE3-RECORD-2026-11-03.json) is byte-identical to the retained archive member (SHA-256 `214a3b9e98fafb2483dd479ed231d56e59337d54c89354e54e0319cd40e126e3`) and decodes to the expected three fields. Targeted tests and Clippy pass. Independent defect-first review found no blocker.

This local slice does not validate a target render record, source namespace, selected scene, F4 environment/render product, old/new pin overlap or any device result. The shared header can still allocate escaped parser scratch outside the first proposed indexed-work charge; near-limit CPU, allocation peak and RSS remain unmeasured.
