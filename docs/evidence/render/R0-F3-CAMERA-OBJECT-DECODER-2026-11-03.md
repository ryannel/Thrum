# Inactive render camera source decoder

3 November 2026. The private shared render object module now checks camera source meaning with the same strict map-only, decoded-key duplicate detection and fixed schema-field order as the inactive mesh slice. It returns canonical binary UUID and authored position, quaternion, projection and exposure facts without a persistent geometry allocation. A duplicate ID has no unique identity locator and uses the collection/ordinal fallback.

Decoded position components must be finite and within the closed ±1,000,000 m authored extent. The private exact transformed-box predicate validates the quaternion band using a zero local box and translation; the returned camera is not a runtime pose authority. The vertical FOV is positive and strictly below true π. Among binary64 values, the Rust PI constant is below true π and its successor is above, so the accepted upper comparison is inclusive at that constant. A local high-precision decimal bracket confirmed those adjacent binary64 values. Near is finite and positive, far is finite and greater than near, and exposure is finite and positive. An F4 device may still refuse valid authored values under its target certificate.

Two focused camera tests cover the authored fixture, both FOV boundary values, invalid quaternion and world position, reordered keys, repeated/escaped ID keys, positional-array refusal, and known-field versus unknown-key error priority. The adversarial camera review found the unknown-key priority defect in both camera and mesh; both now validate known fields before returning an unknown-field error. The eight focused object tests and the full repository gate pass on combined main.

This decoder is private and inactive. It does not validate the active-camera edge, complete namespace, other object kinds or admitted F3 source. Camera quaternion validation currently reuses the complete transformed-box predicate; a quaternion-only shared entry would save matrix/box work if many-camera cost proves material. Serde parser scratch remains outside the first owned indexed-work account. No F4 product, runtime pose, image quality or device cost is qualified.
