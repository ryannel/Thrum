# Inactive render texture stream decoder

3 November 2026. The private `thrum-source` candidate now validates one render-v1 texture object and replays its decoded bytes into a provisional callback. It is not wired to F3 admission or F4 publication.

The object parser borrows raw values and interprets fields in schema order, so `rgba8` can precede the dimensions. Positive `u64` dimensions determine checked `N = 4 × width × height` and padded `E = 4 × ceil(N/3)`; impossible counts refuse before body decoding. The borrowed JSON string is counted for semantic ASCII length, including equivalent JSON escapes, then decoded through pinned `base64` 0.23.1 in 16 KiB encoded / 12 KiB decoded chunks. The dependency has default features disabled, so this candidate uses the scalar path with no `std`, `alloc` or `simd-unsafe` base64 features. F3 can discard each checked chunk. A later F4 caller can replay the checked token from its verified pin into a provisional sink; callback refusal remains distinct from source refusal. Neither path builds a full texel vector here.

Five focused tests cover all three canonical padding lengths; plain/escaped equivalence; nonzero tail bits, early/excess padding, URL-safe alphabet and whitespace refusal; dimension overflow and field priority; callback refusal; and a 16,388-byte image across the chunk boundary. The large case compares decoded bytes and two hashes with independent Python `base64`/`hashlib` goldens, and places JSON escapes at semantic positions 0, 16,383, 16,384 and 16,385. Independent defect-first and followup reviews found no correctness or linear-time defect. The full repository gate passes.

An ignored release-mode local probe on Apple M3 Max used five fresh processes and five inner samples per process. For a 1×1 texture, median check cost ranged 528–589 ns. For 1280² RGBA8, plain check ranged 2.344–2.904 ms and replay 1.633–1.991 ms; a token with one early Unicode escape checked in 4.703–5.269 ms and replayed in 1.836–2.008 ms. This is a candidate CPU measurement, not an end-to-end F3/F4 latency or device result. It does not compare chunk sizes, scalar against accelerated base64, allocations, charged high-water, RSS, many-small workloads or near-record-limit payloads.

Activation still needs root-wide schema/error ordering, global UUID and typed-edge closure, a selected-pin F4 sink with atomic publication, combined source/work-account proof, and the performance comparisons above. The 16 KiB chunk remains a provisional measurement choice, not a contract limit.
