# Render-source JSON shape pass: inactive production slice

3 November 2026. `thrum-source` now compiles a private no-tree prewalk for the candidate shared render decoder. It checks the existing first-profile record-byte (16 MiB), JSON-value-node (1,000,000) and container-depth (64) bounds before typed object decoding. It consumes serde events without retaining a `serde_json::Value` tree or a collection-wide raw-object index. Its return is the observed node count, not a source-validity receipt.

The pass checks JSON syntax, finite decoded numeric values and trailing data. It deliberately does **not** decide decoded duplicate/unknown keys, UUIDs, field meanings or edges: the later strict typed grammar must check those. An escaped scalar can still require serde-owned string scratch bounded by the record bytes, and a future host charged-work account must include it. This slice adds a second linear pass over a render record; combined parse latency and peak memory have not been measured in production. The prior [typed-decoder prototype](R0-F3-TYPED-DECODER-PROTOTYPE-2026-11-03.md) is cost motivation, not this function's performance result.

Focused Rust tests check exactly one million nodes and the first excess token, 64 and 65 nested containers, escaped strings, trailing syntax, nonfinite numeric decoding and byte-limit refusal before parsing. An independent defect-first review found no actionable issue and confirmed byte/node/depth behavior against the existing JSON parser. Targeted Clippy with warnings denied and the full repository gate pass after integration. The module remains private and unused by admission or F4 until the complete shared decoder and global closure are implemented.
