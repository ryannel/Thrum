# V1 first Chrome WebGPU scene

4 November 2026. Chrome 156.0.8078.80 on the Apple M3 Max Mac, Rust 1.99.1, pinned `wgpu 30.0.1`, 1280×720 canvas, 640×360 synthetic source, 10k W1 entities with 1.5k moving. `web/build.sh` builds the `wasm32-unknown-unknown` library and runs `wasm-bindgen` for a local HTTP page. Chrome's WebGPU adapter withheld its name. The page uses the same `FrameHost`, `thrum-core` simulation and `thrum-render` passes as the native diagnostic. A full-page screenshot was visually inspected: the synthetic lit grid and fixed-aspect bars are present, with no V1 art-quality claim.

The pause-probe run lasted 12.040 s including two seconds paused yet committed only 601 world ticks; it resumed and reached 600 timed frames. The resize run ended at 960×540, kept world progress and reported three optional views shed while packets drained. A pre-recovery run stopped explicitly after one visible callback gap refused ten ticks; the new 250 ms probe then counted 15 refused ticks, resumed and reached 600 frames without representing them as committed updates. Additional runs completed: normal 603 ticks/one shed view, pause 606 ticks/four shed views, both zero overload. Every completed frame in the table had a timestamped scene and presentation pass; latest visual age was zero. Chrome's observed timestamp and browser CPU values are coarse/quantized, so these are diagnostic distributions, not a stable device budget. Strict native repository checks, Wasm Clippy and an overridden `CARGO_TARGET_DIR` build pass. Actual background-tab visibility, surface loss/device recreation, cooked hot reload, long-run memory, full browser callback cost, non-Chrome browsers and iPhone rendering remain open.
