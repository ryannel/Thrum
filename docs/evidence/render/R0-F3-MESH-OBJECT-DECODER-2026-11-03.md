# Inactive shared render mesh object decoder

3 November 2026. Thrum-source now compiles a private mesh slice of the proposed shared F3/F4 render decoder. The existing checked render envelope supplies borrowed collection bytes. A streaming array visitor passes one borrowed object at a time without an array-wide index. The object decoder accepts a JSON map only, records four field values in fixed slots, then validates by schema field order regardless of source key order. Decoded duplicate keys refuse before field interpretation; a repeated ID uses the anonymous collection/ordinal fallback because no unique object identity exists.

For each mesh, the decoder checks canonical UUID, ordered f64 position and UV arrays, matching lengths, finite UVs, every vertex against the exact local-radius predicate, and every triangle against the production exact indexed nondegeneracy predicate. Tight local extrema include unreferenced vertices; an empty mesh has origin extrema. It sends borrowed positions, UVs and triangles through a callback and releases those object vectors before visiting the next mesh. Callback refusal remains distinct from malformed source.

Six focused object tests cover the valid and empty cases, extrema, outlier and exact-triangle refusal, positional-array refusal, reordered fields, escaped duplicate keys, repeated-ID diagnostic stability and sequential collection visiting. The existing envelope suite checks borrowed array slices and callback refusal. A defect-first review found and led to fixes for positional struct acceptance, field encounter-order diagnostics and duplicate-ID locator instability. Targeted Clippy with warnings denied and the full repository gate passed after those corrections.

This is a **correctness and lifetime slice**, not an admitted F3 path. Serde currently allocates three object vectors without known-layout precharge. The callback is private; neither F3 nor F4 calls it, and no complete record, global UUID/edge closure, object diagnostic aggregator, charged work account, source admission, F4 product or latency/RSS claim follows. Before activation, the decoder needs charged object scratch and operation sinks, the remaining object grammars and deterministic complete-candidate closure.
