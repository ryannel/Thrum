# Production private transformed-box predicate slice

3 November 2026. A private `thrum-source` module now implements the [candidate exact transformed-box source rule](../../design/research/R0-F3-RENDER-SOURCE-GRAMMAR-2026-11-03.md#numeric-validation-and-refusal-boundary) with the certified interval filter and exponent-normalized 84-limb exact fallback selected by the [isolated optimization study](R0-F3-TRANSFORMED-BOUND-OPT-2026-11-03.md). It is compiled in production but has no caller until the shared render decoder is built; the module remains private and its unused-item lint is scoped at the module declaration. No scene@3/render@1 admission, F4 product, charged work account or runtime behavior is activated.

`transformed_box_within_world` accepts six tight extrema from **all** local mesh vertices, translation, XYZW quaternion and signed/zero scale. It checks finite input, ordered extrema and necessary component bounds, tests the quaternion norm against the exact rational `1±10⁻⁹` tolerance, then checks the entire affine image of the tight box against the closed ±10⁶ m world extent. `Ok(false)` means source extent refusal, including finite out-of-world translation; invalid source inputs and invalid quaternion are distinct errors. It does not itself prove each vertex's exact squared radius ≤10⁶ m² or construct the extrema; the future decoder must do both. An empty mesh supplies the local origin point. Box corners need not be actual vertices and can legitimately cause a conservative refusal.

The exact fallback uses fixed stack arrays and no heap or retained transform cache. It preserves the original 84×u64 width proof and checks finite source preconditions before arithmetic. The interval path requires IEEE binary64 round-to-nearest, gradual underflow and no semantics-changing reassociation; uncertain results fall back to exact dyadics. The local compile/test result is not a target/compiler-mode qualification of that filter for every build. One future shared decoder must also validate camera quaternions and exact per-vertex radius/triangle predicates; this module covers transformed instance bounds only.

Seven in-crate tests pass for closed equality and one decoded step across, negative/zero scale and quaternion sign, invalid-versus-extent refusal, unreferenced vertices and empty box, exact `N/Q` rotation, cancellation and 49 independent eight-corner rational vectors. Wrong-rule witnesses catch rounded tiny displacement, ignored scale sign, vertex-only bounds, ignored outlier and missing quaternion normalization. An independent defect-first review found no actionable code issue. The [standalone production-entry verifier](R0-F3-TRANSFORMED-BOUND-PRODUCTION-VERIFY.rs) also matched all **3,588** archived base-plus-extra rational-oracle vectors. To reproduce from the repository root, extract `base/cases.tsv` and `extra.tsv` from the [optimization archive](R0-F3-TRANSFORMED-BOUND-OPT-2026-11-03.tar.gz) into an owned temporary directory, compile the verifier with pinned Rust 1.99.1 `rustc --edition 2024 -O`, and pass those two paths. It asserts the exact vector count as well as every result.

`RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline -p thrum-source render_bound` passed seven tests, and targeted Clippy with `-D warnings` passed after private integration. The full repository gate is recorded after documentation integration. These are correctness checks on selected vectors, not a production F3 memory/latency or device measurement. The earlier **119–312 ms per 50,000** all-fallback timings belong to the isolated benchmark, not this module in a complete source admission path.
