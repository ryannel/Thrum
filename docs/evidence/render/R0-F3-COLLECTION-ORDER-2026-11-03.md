# Inactive canonical render collection scan

3 November 2026. A private F3/F4 candidate now walks borrowed camera and mesh object arrays without an array-wide raw-value index. The object decoders remain the single source grammar; the collection layer retains at most one structural error and a borrowed raw-object tie key. A complete valid collection emits provisional camera facts or mesh callbacks. The layer does not issue an admitted-source receipt.

The [shared decoder contract](../../design/research/R0-F3-F4-SHARED-DECODER-API-2026-11-03.md) now fixes the previously ambiguous local diagnostic order. Valid canonical IDs sort before anonymous objects, then by UUID and schema field. Distinct objects with the same ID and field sort by their borrowed raw bytes before array ordinal. Anonymous errors use ordinal, then field. A later lower-ID error can replace an earlier one without retaining all errors. When any structural error appears, later objects are still structurally decoded but their projection callbacks are suppressed; all earlier projection output is provisional and must be discarded. A projection refusal may end the scan as incomplete validation before later semantic errors are known. A collection JSON error outranks a held structural error.

Four focused tests cover UUID and field ordering under array reorder, a same-ID/same-field raw-byte tie, valid-ID priority over anonymous errors, projection suppression after an error, early callback refusal, camera ordering and non-array refusal. The scanner's successful path adds no collection-sized retained index and one branch per object; no complete-record latency, allocation high-water or RSS has been measured. Serde per-object scratch remains outside the first charged indexed-work tier. The complete root still needs the other object kinds, a collection-to-collection reducer, global collision/typed-edge closure, F3 dispatch and F4 selected-pin projection.

An independent code review found no lifetime or comparator defect and reproduced the focused tests and format check. It identified two activation limits: the private callback's generic error type permits an F4 caller to stop early with target Unsupported and hide a later source error unless the production wrapper restricts early aborts to operational incomplete/failure; and malformed unknown fields currently allocate an owned key for each rejected object before the reducer discards losing errors. The latter belongs in parser scratch measurement or a later borrowed-error optimization. Neither limit is claimed as solved by this inactive slice.
The scanners also accept an arbitrary raw value internally; the admitted entry must expose them only through the checked-record/envelope path that proves the existing byte, node and depth limits.
