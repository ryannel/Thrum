# A3 native extraction ABBA diagnostic

4 November 2026. Four fresh release processes in serial/worker/worker/serial order on Apple M3 Max/Metal, Rust 1.99.1. Each paced 600 completed **offscreen** frames at 640×360 with the 10k-entity, 1.5k-moving W1 scene and timestamp queries. No artificial competing load was imposed.

| --- | ---: | ---: | ---: | ---: | ---: |
| Serial A | 602 | 0.530/0.848 | 58.1/91.7 | 175.5/298.2 | 0 |
| Worker A | 1,203 | 0.198/0.417 | 57.9/114.8 | 172.7/380.9 | 1 |
| Worker B | 1,203 | 0.207/0.613 | 60.0/143.5 | 181.8/1,070.2 | 1 |
| Serial B | 602 | 0.534/0.898 | 57.5/92.7 | 185.3/329.9 | 0 |

All processes ran about 10.04 s, committed 602 ticks, produced the same 85,260 foreground pixels, and had zero catch-up callbacks, over-deadline callbacks, stale views, report drops and timing faults. Submitted samples had maximum visual age zero. Worker queue p50 was 6.1/6.8 µs and ready-to-submit p50 was 5.5/5.7 µs; serial values were zero by construction. GPU pass medians were stable across the four runs: near shadow 0.062–0.063 ms, far shadow 0.059–0.060 ms, forward 0.164–0.165 ms, display 0.082–0.083 ms.

The worker moves extraction out of the host callback, but needs a second wake for almost every frame. Callback percentiles cannot be summed into whole-process CPU or converted to a frame-time speedup. The Worker B extraction p95 tail is materially higher despite identical code and scene, so the next comparison needs controlled contention and an end-to-end latency/CPU measure. This run does not qualify visible-window pacing, phone/browser performance or the combined F1 graph.
