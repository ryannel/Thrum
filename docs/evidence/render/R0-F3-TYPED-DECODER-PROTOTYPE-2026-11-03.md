# R0 F3 typed render-root decoder prototype

3 November 2026. **Isolated implementation and cost evidence, not active F3 admission.** The [candidate grammar](../../design/research/R0-F3-RENDER-SOURCE-GRAMMAR-2026-11-03.md) requires one strict typed decoder shared by F3 summary extraction and F4 product preparation. The preceding [generic JSON index probe](R0-F3-EMBEDDED-INDEX-PROBE-2026-11-03.md) found that a `serde_json::Value` tree dominates memory on dense embedded identities. This experiment tests bounded no-tree prewalk and typed per-object decoding against that peak.

## Prototype and corrections

The standalone Rust program refuses records over 16 MiB, counts at most 1,000,000 JSON value nodes without a tree, and refuses container depth above 64 before typed decoding. It holds `RawValue` slices for the six identity-keyed arrays, then strictly decodes each camera, mesh, instance, material, texture and point light. Per-object geometry and texel scratch is released before the next object. It retains 24-byte identity and typed-edge vectors, sorts the IDs, and resolves target kind and render-root ownership. This is a two-stage raw-slice design, not a fully streaming visitor.

It checks unknown and duplicate fields, required material controls and present-null semantics, decoded canonical UUIDs and enum values, finite numeric domains, texture transfer/size and canonical padded base64, mesh indices, exact local-radius bounds and the earlier [exact dyadic triangle hook](R0-F3-EXACT-TRIANGLE-PROBE-2026-11-03.md). Text fields use borrowed `Cow<str>` when possible and an owned fallback for escaped spellings. This repaired an earlier prototype defect: borrowed `&str` rejected semantically valid `\\u` spellings. Serde also decodes escaped field names before duplicate and unknown checks. A legal re-encoding escapes every ID key and the first UUID character in four dense records; Python `json.loads` verifies all decoded trees equal the ordinary records, while source bytes differ. The typed prototype reports identical IDs, edges and checksum, with 332,016 owned ID strings and modestly higher peak RSS.

A second defect was rounded chained `hypot` accepting decoded `[600,800,1e-6]` even though its exact squared norm exceeds 1,000,000. The repaired rule compares exact decoded binary64 dyadics with 1000². An outward binary64 interval accepts/rejects clear cases; ambiguous cases use bounded 36-limb exact arithmetic. An independent Python `Fraction.from_float` oracle checks on-boundary, one-ULP and tiny-outside points. Rust tests compare the filter with the exact implementation on selected boundaries and 4,096 deterministic vectors. The interval argument assumes IEEE round-to-nearest, gradual underflow and no unsafe reassociation; cross-target/compiler qualification is still required.

The complete small record passes. Targeted mutants reject duplicate object key, escaped duplicate `id` key, escaped unknown `normal_texture` key, missing masked cutoff, null present texture reference, exact triangle degeneracy, noncanonical base64 tail bits, wrong base-slot transfer, duplicate embedded UUID, and exact-radius outside point. Legal controls include escaped UUID/type/enum/field/texture reference/format/base64 strings and a point exactly at radius 1000. Separate prewalk tests cover exactly one million nodes, one excess node, excessive depth and over 16 MiB. Four grouped `cargo test --offline` tests pass. These are selected distinctions, not a parser conformance suite.

The prior generic `Value` probe independently returns the same ID counts and checksums for generated large ordinary fixtures. For geometry/texture, it sees three edges; this prototype sees four because the generic comparator intentionally omits the material's base-texture edge. An independent Python traversal counts the generated records, geometry texture bytes, triangles and edges.

The escaped version of each has 13,031,750 bytes and the same node count; root zero SHA-256 is `cad5e04f1da072b47a84ddcc4fba221b34501f0e0603e826754b15a4cb8aa3c9`. Two mixed roots each have 11,985,709 bytes and 975,066 nodes; root zero SHA-256 is `f7ce59fcf4901fef9232345b9a97da052834c12e6cc4584588d345e1a42bc`.

The first prototype's rounded-radius geometry median was 43.83 ms. An intermediate exact-every-vertex version measured 52.30 ms in five processes. The repaired interval-plus-exact version is 44.63 ms on the same geometry fixture. These sequential local runs support the filter's cost rationale, but process variance and version differences do not establish a general speedup. The all-boundary variant's 49.49 ms median measures fallback-heavy behavior, though its source bytes differ. Generic four-root parse-plus-extract median was 162.77 ms and geometry was 25.66 ms; its work differs because it does not check full source semantics, exact triangles or base64. The evidence supports a large memory reduction for these fixtures, **not** a CPU speedup or an end-to-end admission latency claim. No numeric embedded-identity capacity is selected.

## Integration gates and limitations

The prototype remains outside `thrum-source`; it does not parse `core.scene@3`, join project/history/scene IDs, enforce global admission capacities, build source revisions, read authenticated pinned bytes or prepare an F4 product. It has no production typed diagnostics, serializer/cook-key canonicalization, W1 world binding or complete transformed-bound validation. Its old-index control omits accepted-store buffers, old and new source pins, SQLite stage, F4 input trees and product overlap. One large texture and one mesh are measured; multi-texture/multi-mesh adversarial peak remains open. The grammar/projection still needs full conformance and independent production review.

The next useful slice is one production versioned decoder API with summary and cook projections plus the `core.scene@3` typed edge. Resolve declared roots against the complete F3 UUID namespace and measure combined old/new admitted source, geometry, textures and concurrent F4 work before choosing embedded-ID capacity and edit-latency profile. Required-edge capacity is a distinct quantity.
