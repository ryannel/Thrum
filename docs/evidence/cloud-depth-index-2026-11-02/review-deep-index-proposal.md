# Independent review: exact deep-curve interval locator

2026-11-02. Root-authored proposal reviewed before implementation against current `deep-sun.js/.wgsl`, image/probe bindings and cloud contracts. No GPU, candidate code or canonical edit. The separate model reader is checking actual captured float32 endpoint arithmetic; this note does not claim those results.

**Design result:** the interval table can be an exact accelerator of the existing retained-curve lookup. No invalidating mathematical defect found, provided the following endpoint, fallback and ownership rules are explicit. It does not improve lateral light quality or permit a different Sun footprint/error allocation.

## Exactness and one necessary fallback distinction

Every retained anchor belongs to the same ordered513-endpoint input sequence. Thus each original half-open interval `[D_i,D_(i+1))` belongs to one compressed segment. A table entry can name that segment without storing/reconstructing a new tau. Query still interpolates the same two original stored depth/tau nodes using the same arithmetic expression. Before-first/after-last results stay unchanged.

Define canonical internal bracket as `[node[j].depth,node[j+1].depth)`: equality at an internal anchor selects its right segment, matching the existing binary search's `<=` rule. Generate entries by one monotone walk comparing the actual recomputed `D_i=f32(i)*h` values with the actual stored f32 anchor depths. Reuse exactly the builder's h/expression, or retain source endpoint ordinals while emitting. Do not assume dividing a rounded anchor depth by span and flooring recovers its ordinal.

`floor(depth/span*512)` is a tentative address, not proof of the correct bracket. Guard finite arithmetic, clamp a tentatively rounded512 to the final interval only after the existing actual-endpoint boundary handling, validate the decoded entry in `[0,count-2]` **before reading nodes**, then compare query depth with actual node depths. Apply at most one neighboring-segment correction and recheck the complete half-open bracket/finite positive span. This proves a successful hit uses exactly the old segment even if the tentative interval address was inaccurate. The safety proof does not require pretending that +/-1 always succeeds for every possible backend/input; unresolved cases must not guess.

**INDEX-R1, conditional exactness gap:** if unresolved hits invoke direct source integration, the result can differ from the old compressed curve. Direct integration is a separate approximation with different work; it cannot be called exact-equivalent to binary search. For an all-query exact accelerator, use the already bounded old binary search as the slow fallback on an otherwise valid column, and preserve direct/refined failure only for genuinely invalid columns/quality paths. Alternatively explicitly narrow the exactness claim to successfully resolved table hits and retain changed-result/fallback evidence. The former preserves the proposed optimization's intended no-quality-change boundary.

## Construction, bindings and lifecycle

- One column invocation owns128 packed u32 words; pack four interval indices locally before each word store, avoiding multiple byte writers/non-atomic OR races. Indices0..46 fit u8;255 can be an explicit diagnostic invalid sentinel. Invalid columns need not have meaningful table contents, but query must reject them before reading entries. Validity may be published only after all128 words and nodes are complete. A monotone512-interval/at-most48-anchor walk is bounded; do not reintroduce a per-interval K scan.
- Index buffer and format/step constants join the same immutable source/time/Sun/frame/crop generation as nodes and metadata. Rebuild/rebind/retire them together, including hot recipe replacement, camera-only reuse, failure cleanup and in-flight use. Quiescent existing ownership can provide this; no new physical authority or public Scene ABI is needed. Readback/probe product identities must distinguish the indexed shader/format from historical binary lookup.
- **Binding collision to resolve:** query binding13 is already used by both deep probe inputs (`capturedPoints`/`capturedColumns`), and14 by their outputs. Pick an unused table binding or move the probe bindings and all associated layouts/groups together. Build output table can have its own group1 binding. Image, query probe, replay/probe compilation, minBindingSize, shader stage visibility, usages and adapter storage-buffer limits all need the new buffer. The current local stages have room under ordinary storage-binding limits, but that does not follow merely from a numeric binding identifier being free.
- New allocation participates in create try/catch and idempotent destroy; unsupported table shape/stride/length must fail visibly. On an admitted data table, local range/bracket checks precede interpretation. Existing domain-invalid negative sentinel, metadata capacity rejection and4096 direct-request ceiling remain in force. Binary locator retries should have separate counters from expensive direct fallback so saved search work is observable.

## Cost and qualification boundary

4356 columns ×512 one-byte interval entries =2,230,272B, equivalently4356×128u32. Adding existing1,812,096B nodes/metadata gives4,042,368B local deep product, before staging, old/new overlap or backend residency. Each rebuild adds at most2,230,272 interval visits and209,088 retained-anchor advancements plus557,568 packed-word stores. Count actual query table hits, corrections, binary fallbacks and node/table accesses; theoretical elimination of a search is not a frame-time pass. Uniform512-entry tables over the separate344064-column whole-scene candidate would add168MiB by themselves; the local experiment must not silently promote that allocation.

Reasonable bounded acceptance is unchanged retained nodes/metadata and before/after primary+quarter values, endpoint/equality/nextafter cases, clear/opaque/K-overflow/invalid-domain behavior, stale or out-of-range index negatives and normal consumer images. Actual GPU bit parity/performance remains unrun here; compiler lowering and cache traffic can change even when source expressions match. Preserve the current compression/lateral/source/appearance qualifications and old failure evidence. This proposal is credible as a private exact locator optimization with these conditions; no new physical-perfectness or broad test campaign is requested.
