# SIM-2D M3: rule profile and creator guide

Target receipts and closing revision are recorded below after verification.
The retained Crowd and Mixed files are unchanged from M2.

The canonical profile configuration is `.config/sim2d-profile/clippy.toml`.
`scripts/sim2d_profile.py` discovers registered rule packages, compares configuration,
checks all dependency kinds and runs Clippy. Its controls start from one passing package;
each retained fixture changes only one prohibited operation, dependency, configuration
or component field. `./dev check` runs the guard and controls. The repository guard
also checks rule-package configuration and dependencies.

The registry supplies the conformance runner, sizes, vectors, traces, witness fields and
negative control. `--package` selects a registered rule package. The platform-sine control
uses the same registered runner and device adapter. Focused tests exercise a second schema
with different sizes, file paths and witness names and verify control dispatch. Engine
crates contain no reference-crowd types or constants. The generic `record` command refuses
to overwrite registered references; historical crowd retention commands remain explicit.

[Portable rules](../../SIM2D-RULES.md), linked from the creator guide, describes every
profile operation and refused class, random draws, state encoding, query order and domain,
rule-set cell size, adapter protocol, candidate recording and three-target reproduction.
W1 and P3 in the maturity ledger separate implementation, correctness, visuals and devices.
Physical iPhone, x86, Android and other browsers remain not run. Simulator function is
claimed separately from speed; this milestone makes no new performance or visual claim.

The negative fixtures are development guard controls, not a hostile-code security boundary.
Manual encodings and sort keys still require review; conformance covers recorded inputs.
Historical M1/M2 cost records remain measurements of their recorded source revisions.
