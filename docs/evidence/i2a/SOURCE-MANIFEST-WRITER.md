# Streaming canonical manifest writer

2 November 2026. `TreeManifest::revision` and the new `TreeManifest::write_jcs` use one emitter for the same RFC 8785 compatible bytes. The digest sink is infallible; the `Write` sink propagates I/O failure. A small manifest's emitted bytes match an independent `serde_json_canonicalizer` oracle and hash to the existing fixed revision; a deliberately short writer refuses without fabricating a successful output. The emitter traverses sorted entries once and retains no second whole-manifest JSON tree.

An ignored Rust 1.99.1 release probe writes **100,000 entries / 16,900,105 canonical bytes** to a hashing writer without buffering that output, then checks its digest against `SourceRevision`. Three fresh local macOS arm64 test processes took **10.499, 10.775 and 10.998 ms** for the writing pass and each peaked at **22,757,376 bytes RSS**. Process RSS includes fixture generation and the retained manifest metadata; the timing excludes that generation and the earlier `revision` call. This is a CPU sink, not SQLite/WAL or disk throughput. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_maximum_manifest_writer -- --ignored --nocapture` and a fresh-process `os.wait4(...).ru_maxrss` for isolated RSS.

The writer does not itself verify staged file bytes, persist a complete SQLite blob, authenticate prior source history or publish an accepted root.
