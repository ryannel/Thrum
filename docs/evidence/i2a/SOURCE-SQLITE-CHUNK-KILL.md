# Process kill after a committed source blob chunk

2 November 2026. A local two-process test now interrupts the test-only SQLite store at a precise point between blob transactions. The parent first commits one complete old blob as root generation 1. A child writes and commits the first 4 MiB chunk of a new 8 MiB-plus-one-byte blob, signals readiness and blocks. The parent kills that child, opens the same database, and observes root generation 1 with the old revision still selected. The new blob has state `incomplete` and exactly one stored chunk; trying to publish its hash as a root refuses. Restaging the full blob replaces the partial chunk, verifies all bytes, commits generation 2, and survives another reopen.

The readiness signal occurs after `append_blob_chunk` returns from its SQLite commit. The parent has a five-second startup deadline and an on-drop child kill/wait guard; the child receives native paths through environment variables without requiring UTF-8. The ordinary test helper exits immediately unless explicitly launched by the parent. `RUSTC_WRAPPER= ./dev check` passes on local macOS arm64, and a read-only review found and corrected the native-path issue before its final no-finding pass. Source SHA-256: `4995bd328e5b1d8c5da5235fbd4d17f656d2cc485e7c0f27649ddd763ebc3aaf` (`crates/thrum-source/src/sqlite_store.rs`). Reproduce the targeted test with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline -p thrum-source sqlite_store::process_kill_after_chunk_recovers_old_root_and_restages -- --exact --nocapture`.

This proves a process interruption **between** the chunk commit and the complete marker for one blob. It does not test a kill inside the final root/outcome transaction, an assembled candidate with source history, power loss, VFS flush honesty, GC pins or physical-space exhaustion. The source store remains test-only. [SQLite WAL commit and checkpoint semantics](https://www.sqlite.org/wal.html) are the underlying local transaction mechanism, subject to the selected filesystem/VFS assumptions in the [foundation specification](../../design/FOUNDATION-SPEC.md#3-native-admission-and-browser-runtime-persistence).
