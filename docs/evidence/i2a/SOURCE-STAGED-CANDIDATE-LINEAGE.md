# Rehashed staged candidate to stored-root lineage

2 November 2026. A test-only three-file project (`core.project` schema 2, one `core.scene`, and one `core.registry-history`) is captured and validated as a `StagedCandidate`. The store stages its exact file blobs and canonical manifest, commits a root, then compares the current stored history with history bytes reread and rehashed from the candidate's stage. A second validated stage is changed by one byte after validation, preserving length; both the candidate-history handoff and complete-blob reuse reject it. The root stays selected. This proves the narrow provenance handoff, not a public or complete admission operation. Independent read-only review found a 4 MiB allocation on every reused file; one lazily sized scratch buffer now serves both new and reused streams. The final review found no remaining issue, and `RUSTC_WRAPPER= ./dev check` passes.

On the same local macOS arm64 Rust 1.99.1 release fixture of **1,000 distinct eight-byte files**, three fresh-process alternating-order runs measured the one-file new-blob helper at **134.183, 122.832 and 192.839 ms**, the bounded batch helper at **9.252, 9.680 and 13.591 ms**, and complete-blob reuse with input rehash at **3.383, 3.354 and 3.672 ms**. The reuse scratch capacity was eight bytes in each run. Process peak RSS across these runs was **4,456,448–4,620,288 bytes**. Timed regions exclude fixture generation and database open; reuse staging is completed before its timer. These local helper measurements include SQLite work but not a full candidate edit-to-ready path, disk-reservation preflight or sustained tails. The prior [small-blob batch evidence](SOURCE-SMALL-BLOB-BATCH.md) records the pre-scratch implementation's exact binary and remains historical. Reproduce after `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source --no-run` by running `sqlite_store::measure_small_blob_transaction_cost`, `sqlite_store::measure_small_blob_batch_cost` and `sqlite_store::measure_small_blob_reuse_cost` with `--ignored --exact --nocapture` in fresh processes, collecting `wait4` peak RSS.
