# Opaque-preserving source text edit

2 November 2026. The native `thrum-source` tooling now exposes `replace_game_text_field` for one known text field under a parsed source-carried game descriptor. It validates the original record, checks that the selected field is text and that the replacement fits its UTF-8 bound, borrows the original top-level and field JSON values as `RawValue`, and serializes directly into one output buffer. Unchanged values keep their exact JSON spelling, including optional opaque nested objects. The output is bounded by the 16 MiB record limit and revalidated under the same descriptor; the stable record ID and required typed references must match the original. This function returns a proposed file's bytes. It does not write working files, admit a source revision or update a running world.

Tests cover a noncanonical optional value containing escaped Unicode and unusual spacing, an absent optional known field, wrong field kind, unknown field, overlong UTF-8 replacement, malformed duplicate input, two required references supplied in reverse field order, and an A/B staged candidate. In the staged test, the known caption edit changes the provisional `SourceRevision`, while the old stage and its revision remain unchanged; the optional value's internal bytes, stable record ID and required scene reference are preserved. The reference-order case came from independent review: the record parser emits references in source order, while the editor sorts field keys, so identity is compared by descriptor field index and target rather than vector position. `RUSTC_WRAPPER= ./dev check` runs these tests with the rest of the repository gate.

An ignored Rust 1.99.1 release probe edits a 4,197,928-byte record with 128 optional values of 32 KiB each. Three serial local macOS arm64 runs took **4.416, 2.820 and 1.901 ms**; the wide range makes these diagnostics rather than a latency bound. The operation borrows raw values and writes one output record buffer, avoiding an extra whole-record JSON value tree or serialized fields buffer. Peak RSS and allocator requests were not measured. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_large_opaque_text_edit -- --ignored --nocapture`.

The first bounded registry profile still needs a combined parser/graph physical memory reservation and a comparison against an authenticated admitted predecessor. The durable SQLite adapter must rehash every staged file and commit the root and outcome together before any revision can be called accepted. Broader editing operations, file application and source-to-run consumption remain separate work.
