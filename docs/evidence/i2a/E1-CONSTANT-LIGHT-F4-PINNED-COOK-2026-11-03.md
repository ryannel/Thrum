# First accepted-pin constant-light cook

3 November 2026. The selected [E1 constant-light product and binding](../../design/modules/ENVIRONMENT.md#selected-first-f4-constant-light-product-and-binding) now has a production selected-source adapter in [`thrum-cook/src/constant_light_source.rs`](../../../crates/thrum-cook/src/constant_light_source.rs). It feeds the previously checked pure 160-byte codec. This slice cooks one accepted source revision; it does not install a persistent product, compute the selected semantic `CookKey`, bind a ready build, or select a runtime.

`cook_pinned_constant_light` takes one mutable `PinnedSource`. It selects the authenticated `project.json` identity, requires exactly one entry scene, follows that scene's environment source and the environment Sun's light reference, and checks each selected ID, type and project-declared path against the accepted manifest. It makes four complete `copy_file_to` reads in project, scene, environment, light order. Only a successful full length/hash copy is decoded. The F3 strict typed parsers supply raw decoded numeric values; the codec normalizes and writes the immutable payload. The result carries the accepted root and four exact file length/digest records as provenance, plus typed input and payload. It owns no source pin or persistent cache entry; a future publisher must retain its own source lease through binding.

Six focused production-store tests pass. A held A pin cooks A after B admission and checkout edits, while a valid but incompatible C retains prior A. Unrelated source bytes and selected opaque/label edits preserve the payload while changing exact provenance where appropriate. Schema/entry count and incorrect selected type/path/ID refuse. Complete corrupt and truncated selected blobs refuse before decoding. A second-chunk fault after a 4 MiB valid JSON prefix proves the partial output is discarded rather than treated as source authority. An independent defect-first review of the adapter, F3 pin guarantees, strict parsers and codec found no actionable issue.

`RUSTC_WRAPPER= ./dev check` passed after this adapter, including the workspace Rust/doc tests, Clippy and documentation checks. The four selected file bodies are copied into temporary vectors one at a time, capped by F3's 16 MiB record limit; the manifest is scanned for three selected references without constructing a second whole-manifest index. This gives a bounded local strategy, not a measured peak RSS or edit-to-ready latency. Persistent `CookKey`/product manifest/cache integrity, exact-source build binding, stale-result admission, target/device work and experienced visuals remain open.
