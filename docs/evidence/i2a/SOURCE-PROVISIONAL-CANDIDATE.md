# Provisional source-candidate revision

2 November 2026. `validate_staged_candidate` checks one stage's project, source-carried schema/history and declared scene/game closure together. Its `provisional_manifest` labels those checked record paths with stable IDs and types, leaves ordinary staged files unlabeled, and derives the existing JCS/SHA-256 `SourceRevision` from captured exact-byte length/hash metadata. It builds a path-sorted borrowed label list, merges that with the already sorted stage files, and streams the manifest revision through the existing emitter. A candidate is **not** an accepted root: its manifest uses capture-time hashes for ordinary files, and the durable adapter still must reread all staged bytes, compare candidate history with an authenticated predecessor, and commit root plus outcome atomically.

An independent `serde_json_canonicalizer` oracle checks the six-file candidate's manifest digest, including its game, scene, schema, history and project labels and a nonrecord asset with null identity. Editing a game caption changes a fresh stage's revision while the old stage and revision stay unchanged. Invalid record and reference cases refuse in the preceding [closure proof](SOURCE-STAGED-RECORDS.md). The ignored Rust 1.99.1 release probe ran validation through revision 1,000 times in **99.089958 ms total** on the local macOS arm64 machine (about 99 µs per small candidate). This includes stage opens/hashes/parses and manifest work for five tiny records. It is not a 100,000-file, dense-schema, physical memory, whole-capture or device result. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_small_candidate_revision -- --ignored --nocapture`.

A separate ignored probe stages **4,096 declared records** (4,095 tiny scenes and one game, plus project, schema and history) and times validation through revision after staging. One local release run took **77.585083 ms**; the entire test process peaked at **7,290,880 bytes RSS**, versus **2,310,144 bytes** for the empty filtered test process, measured with macOS `getrusage(RUSAGE_CHILDREN)`. RSS includes fixture creation and staging, and the run still has just one descriptor, short history and tiny records. It therefore probes the declared-record count, not the maximum combined parser/graph memory or whole edit-to-ready time. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_4096_record_candidate_revision -- --ignored --nocapture`.

The first bounded source-carried profile remains open for a real editor's opaque optional round-trip, a selected maximum parser/graph memory reservation and an authenticated prior-root history comparison. Multi-schema game dispatch and external dependency roots also need a larger selected profile. No cook, save, restart or runtime consumer reads this provisional candidate yet.
