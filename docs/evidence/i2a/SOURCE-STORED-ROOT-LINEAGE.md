# Current stored root to source-carried history

2 November 2026. A test-only recovery proof reads the selected SQLite root generation and 32-byte revision, verifies the complete manifest blob's exact chunk layout, length and SHA-256, and decodes the first-profile canonical manifest into typed entries without a generic JSON value tree. The decoder refuses duplicate/unknown keys, alternate JCS spelling or file order, nonempty dependency roots and inputs over 64 MiB. It locates exactly one `core.registry-history` entry, rechecks that the root generation/revision still match, verifies that file blob's length/layout/hash, checks its record ID, and compares its permanent field and type-version history with a supplied candidate. SQL read transactions end before manifest/history JSON decoding. A later root advance is caught by the final generation compare-and-swap.

Tests cover reopen, valid extension, rejected stale lineage and wrong project, invalid candidate history, a competing root advance, corrupted stored manifest/history chunks, extra chunk refusal, oversized stored chunk and root-revision values, and a descriptor type requiring JSON escaping. Independent review found three resource/round-trip faults in the first implementation: escaped record types were not decodable, malformed chunks could allocate before length checks, and a malformed root revision could allocate before its 32-byte check. Those were corrected; the final read-only pass found no further issue. `RUSTC_WRAPPER= ./dev check` passes.

An ignored Rust 1.99.1 release probe decoded **100,000 entries / 16,400,094 canonical bytes** in **66.404, 64.853 and 64.129 ms**, with fresh-process peak RSS **55,738,368, 55,705,600 and 55,689,216 bytes**. A separate current-root resolution fixture with 100,000 entries and a shared one-byte ordinary blob took **62.242, 61.904 and 63.081 ms**, with peak RSS **72,450,048, 72,450,048 and 72,466,432 bytes**. The timed root path includes stored manifest/history reads, hash/layout checks, canonical decode and lineage comparison; it excludes fixture creation, blob staging and root commit. RSS includes those earlier fixture allocations and SQLite state. The fixtures ran in fresh local macOS arm64 processes with alternating order; these are development costs, not edit-to-ready or sustained disk/device qualification. Reproduce after `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source --no-run` by running `manifest_json::tests::measure_maximum_stored_manifest_decode` and `sqlite_store::measure_maximum_root_history_resolution` on the produced test binary with `--ignored --exact --nocapture`, collecting `wait4` peak RSS.

This does not yet bind the candidate history argument to a rehashed staged candidate in one admission operation. No GC pin protects the old root across the two read transactions, though this proof has no collector. The current store can still be reached through test-only generic publication fixtures, and it lacks physical parser/disk/WAL reservation, process-kill qualification and a production accepted-source API. The broader source-admission and editable-game boxes remain open.
