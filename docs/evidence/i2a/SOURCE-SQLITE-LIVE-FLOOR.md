# Live source-store free-space recheck, narrow proof

2 November 2026. After the test-only candidate path's initial unique-blob preflight, it now enables a live free-space check before each guarded SQLite write. The check reads current SQLite logical page count, main-file length and actual volume available space. It requires the configured free floor plus the next transaction's estimated WAL allowance plus uncheckpointed logical-to-physical main-file debt. It runs **before** `PASSIVE` or `TRUNCATE`, because checkpointing itself may grow the main file, and again after a checkpoint. Ordinary writes take one check. The guard clears when the candidate attempt finishes.

A deterministic test injects a 1 EiB floor immediately **after** a successful candidate preflight. The candidate refuses with `FreeSpace` before its first blob header and leaves root generation zero; retry with the normal fixture floor publishes successfully. A second test places the WAL guard at a truncate boundary, injects the same floor, and observes refusal with unchanged WAL length. The full `RUSTC_WRAPPER= ./dev check` gate and both focused tests pass. One local macOS arm64 Rust 1.99.1 release smoke run of a three-file edit from fixture write through source root took **2.754 ms**. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source sqlite_store::measure_small_candidate_edit_to_root -- --ignored --exact --nocapture`. Source SHA-256: `8b08479d720bf15a3f226448e0b51ac0e2335c426e2b91aab4b2021481d6daf2` (`crates/thrum-source/src/sqlite_store.rs`). This single run is not a regression/speedup or sustained performance claim.

This adds a live early-refusal boundary; it is **not** a physical peak guarantee. The next-write allowance and WAL guard are estimates, external actors may change free space after the check, and the test uses a zero floor for ordinary candidate admission so CI does not require 8 GiB free. Main-file growth, managed temporary use, reader-blocked sustained checkpointing, process loss and all owner pin classes still need the selected production protocol and qualification. The [physical-space contract](../../design/FOUNDATION-SPEC.md#4-working-files-crash-recovery-and-gc) remains open.
