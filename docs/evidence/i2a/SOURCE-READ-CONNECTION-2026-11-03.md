# Accepted pinned reads through a separate owner connection — 3 November 2026

The first append-only accepted source store now opens one read-only SQLite connection beside its one writer connection, under the same cooperating owner lock. Existing pins use the reader for short header and chunk queries, then hash and write output after releasing its mutex and read gate. No read transaction spans consumer output. Pin registration/release, admission, selected-root queries, checkpoints and the final root/outcome transaction remain on the writer. This adds one SQLite handle and page cache per owner, not one per pin. The read-only handle closes before the writer while the owner lock is still held; both handles enable `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE`. The writer still disables automatic WAL checkpoints.

The owner read gate is shared during pinned SQL. B checks every exact direct file in its final `IMMEDIATE` transaction while A may read on the other connection. Before writing root, outcome or GC epoch, B takes the gate exclusively and drains short reads. It holds the gate through COMMIT and, if COMMIT reports an uncertain error, marks the gate quarantined before releasing it. Every later pinned SQL sees `RecoveryRequired`; other owner methods still use the writer's recovery-required state. The reader never uses SQLite's `immutable` mode against this changing database. The bundled `libsqlite3-sys 0.38.2` contains SQLite **3.53.2**, later than SQLite's [3.51.3 WAL-reset fix](https://www.sqlite.org/wal.html#wal_reset_bug). SQLite's [WAL concurrency](https://www.sqlite.org/wal.html) and [separate-connection isolation](https://www.sqlite.org/isolation.html) are the basis for this path; the local tests below check Thrum's ownership and recovery behavior.

Two focused tests qualify the ordering. An A pin copies and hashes exact `project.json` bytes while B holds the writer mutex and an open final closure transaction; the test waits for A to finish before letting B publish. A second test starts an A read after B's root/outcome SQL while B holds the publication gate, injects a post-sync final-COMMIT I/O error, and checks that the waiting read refuses with `RecoveryRequired`. The post-fault tests also compare instrumented WAL/main write counts before and after both connections close; neither close adds a write. Existing public A/B, precommit process-kill, lost-response, SQLite-full, WAL pressure, live-lease quarantine and close/reopen tests pass with the second connection. This is not a power-loss or cross-platform filesystem proof.

The ignored optimized final-closure fixture stages all named blobs and the manifest before timing publication. With **100,000 distinct four-byte blobs**, three local macOS ARM64 runs measured B's exact final transaction at **110.659, 125.314 and 116.494 ms**. Coordinated A pinned copies took **0.221, 0.213 and 0.283 ms**. The previous one-connection fixture observed **97.171–117.654 ms** A waits with **97.122–117.581 ms** transactions. The concurrent reader may start before the closure loop in the timing fixture; the separate deterministic test proves an actual read inside that transaction. This result supports old-pin progress, not a p99 latency bound or faster closure. The 100,000-blob setup is synthetic and its multi-second staging is excluded from the commit timer.

Three fresh-process **64 MiB** public admission samples with an old A pin live measured 203–209 sampled A copies per run. Observed maxima were **3.254, 4.597 and 3.312 ms**, with writer wall times **317.514, 322.490 and 310.898 ms** and whole-process peak RSS **22,151,168; 22,347,776; and 22,183,936 bytes**. The earlier one-connection sample reported old-copy maxima **11.453–17.337 ms**, writer wall **293.102–302.708 ms**, and peak RSS **20,742,144–20,856,832 bytes**. Fixture, binary and host load differ; these are not a matched attribution of writer overhead or extra connection memory. They include staging, validation, SQLite, old pin and test harness, but not filesystem cache. The current 12 MiB pinned copy into an I/O sink took **7.924, 8.309 and 8.262 ms**, versus the historical **7.633–7.796 ms**. Three current ten-edit runs put median pin/copy/release at **7.935, 8.017 and 8.042 ms** and median reopen at **4.896, 4.947 and 4.973 ms**. This small local sample shows no gross ordinary-read regression; it does not isolate lock, cache or allocation cost.

A separate ignored local pressure probe kept **four A pins reading continuously without sleeps** while B admitted a 64 MiB source through the public API. Three optimized runs completed B in **330.624, 346.059 and 339.553 ms**, each before a five-second safety cutoff, while the readers completed **32,849; 36,148; and 36,491** verified A copies in total. The largest individual copy in each run was **4.680, 9.506 and 8.859 ms**. This exercises gate publication under heavy local reader traffic and shows progress on this macOS host; it is not a portable fairness guarantee. Four threads also compete for CPU and one read connection, so these B times cannot be compared directly with the one-reader runs. The probe stops readers before they release pins, preserving admission-permit order.

The release test binary for the initial metrics was SHA-256 `bdd39569cbe88215f06ce5092bff8c8559243a5a7896d8b9a33c3eedacac7f46` on Rust 1.99.1, bundled SQLite 3.53.2 and macOS 26.6.2; the four-reader probe required a later test-binary build. Reproduce the focused tests with `RUSTC_WRAPPER= cargo test -p thrum-source --lib accepted_old_pin_reads_during_final_closure_transaction` and the `accepted_reader_waiting_at_publication_sees_uncertain_commit_quarantine` filter. Reproduce the optimized local probes with `RUSTC_WRAPPER= cargo test -p thrum-source --release --lib <filter> -- --ignored --nocapture`, using `measure_maximum_manifest_closure_reader_wait` with `THRUM_TEST_UNIQUE_MANIFEST_CLOSURE=1`, `measure_native_phased_reader_progress` with `THRUM_TEST_SOURCE_PROBE_MIB=64`, `measure_native_continuous_multi_pin_admission`, and the small/large store filters. The focused tests and local probes passed, and `RUSTC_WRAPPER= ./dev check` passed after the four-reader fixture. The ignored admitted A/B headless consumer passed as well: 58 pinned files and 1,667,837 materialized bytes built a runnable A binary; invalid B did not replace it. This was a plain local compile, not the complete native sandbox qualification. Sustained checkpoint pressure with the new reader, representative mixed-source tails, allocation counts and other-platform behavior remain separate gates.
