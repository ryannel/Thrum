# I2a source validation checkpoint

2 November 2026. This is a **local syntax and identity proof**, not candidate capture or accepted-source admission. The owning [source specification](../../design/FOUNDATION-SPEC.md#1-source-format-and-identity--select-one-ordinary-file-language) and [capture design](SOURCE-CAPTURE-DESIGN.md) require further F3 semantic validation, immutable staging, physical-peak admission and the separate SQLite root/outcome transaction.

The native-only `thrum-source` crate is outside the game callback and portable core dependency graph. It checks relative NFC paths with `/` separators, cross-target reserved names, full Unicode case-fold aliases and file/directory prefix conflicts. The prefix check includes an intervening sibling such as `a`, `a-b`, `a/b`; the earlier adjacent-pair check incorrectly admitted that case and was corrected after read-only review. Directory aliases such as `Assets/a.bin` and `assets/b.bin` also reject. JSON parsing rejects duplicate keys at any depth, trailing data, nonfinite numbers, records above 16 MiB and nesting above 64 containers. The common envelope checks canonical lowercase UUID, nonempty ASCII type and field IDs and a positive schema version; the F3 registry owns the exact identifier grammar. Field units, known schema versions, required references, nested IDs and migrations still require that registry and are not claimed by these tests.

Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline -p thrum-source` or the repository gate `RUSTC_WRAPPER= ./dev check`. Three local tests exercise valid and adverse inputs; the workspace gate also checks crate/dependency policy, Clippy and formatting. There is no disk staging, accepted revision, durable root or device/performance result yet. Path validation allocates one folded string per declared path and a borrowed directory-prefix map, then sorts the folded strings once; each slash prefix uses a binary lookup. JSON validation is bounded by input bytes but its parsed `Value` tree and map allocations have not yet received a measured peak-memory bound, so the parser is not an activated admission boundary.
