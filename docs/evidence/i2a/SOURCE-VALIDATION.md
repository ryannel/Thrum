# I2a source validation checkpoint

2 November 2026. This is a **local syntax and identity proof**, not candidate capture or accepted-source admission. The owning [source specification](../../design/FOUNDATION-SPEC.md#1-source-format-and-identity--select-one-ordinary-file-language) and [capture design](SOURCE-CAPTURE-DESIGN.md) require further F3 semantic validation, immutable staging, physical-peak admission and the separate SQLite root/outcome transaction.

The native-only `thrum-source` crate is outside the game callback and portable core dependency graph. It checks relative NFC paths with `/` separators, cross-target reserved names, full Unicode case-fold aliases and file/directory prefix conflicts. The prefix check includes an intervening sibling such as `a`, `a-b`, `a/b`; the earlier adjacent-pair check incorrectly admitted that case and was corrected after read-only review. Directory aliases such as `Assets/a.bin` and `assets/b.bin` also reject. JSON parsing rejects duplicate keys at any depth, trailing data, nonfinite numbers, records above 16 MiB, nesting above 64 containers and more than 1,000,000 value nodes per record. The node check runs before deserializing each next value and adds one shared stack-local counter, with no per-node heap allocation. It bounds node count, not yet physical parser heap. The common envelope checks canonical lowercase UUID, nonempty ASCII type and field IDs and a positive schema version; the F3 registry owns the exact identifier grammar. Field units, known schema versions, required references, nested IDs and migrations still require that registry and are not claimed by these tests.

The manifest review also found that the independent JCS test dependency enabled serde_json's `float_roundtrip` feature only in tests. The production dependency now enables it explicitly, and a high-precision f64 source number has a regression check, so an ordinary source parser build keeps the same semantics.

Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline -p thrum-source` or the repository gate `RUSTC_WRAPPER= ./dev check`. The local parser fixtures exercise valid and adverse inputs, including an exceeded node cap in arrays and maps; the workspace gate also checks crate/dependency policy, Clippy and formatting. This record covers syntax and identity only; later provisional staging is tracked in the [staging proof](PROVISIONAL-STAGE.md), while semantic validation and accepted admission remain open. Path validation allocates one folded string per declared path and a borrowed directory-prefix map, then sorts the folded strings once; each slash prefix uses a binary lookup. The parsed `Value` tree and map allocations have not yet received a measured peak-memory bound, so the parser is not an activated semantic-admission boundary.

The selected one-million-value ceiling preserves room for a large single authored record while ruling out dense JSON that fits under 16 MiB but expands to several million `Value` nodes. Two ignored release fixtures build adversarial records at the ceiling and time only parsing. On this arm64 macOS 26.6.2 host, a 1,999,999-byte array parsed in 11.4 ms with 38.6 MB child-process maximum RSS; an 11,888,879-byte map of unique keys parsed in 183.8 ms with 134.8 MB maximum RSS. An empty filtered test process used 2.2 MB. The map's insertion and key allocations dominate the observed cost, so a byte bound alone would be misleading. Reproduce the elapsed probes with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_dense_array_at_value_limit -- --ignored --nocapture` and the matching `measure_dense_map_at_value_limit` filter. RSS was read from Python `resource.getrusage(resource.RUSAGE_CHILDREN).ru_maxrss` for each already-built release test process. These are local process peaks, not a proved maximum across all JSON shapes or a target-device result. The semantic validator still needs a physical heap reservation and an aggregate edge cap before admission.
