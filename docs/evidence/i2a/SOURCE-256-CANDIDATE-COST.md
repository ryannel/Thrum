# Dense 256-descriptor provisional candidate probe

2 November 2026. An ignored Rust 1.99.1 release fixture now carries 256 sorted source-carried `core.schema` records through the full staged candidate validator and canonical provisional manifest. It also contains 4,096 declared scene/game records (one `game.marker`, 4,095 scenes), 100,000 field-history entries, 1,024 version-history entries and a large optional opaque game value. The stage has **4,354 files** and **25,490,532 copied bytes**. The candidate check asserts 256 parsed descriptors, one descriptor-bound game record and one required game-to-scene edge. It exercises lookup under a large registry for the first sorted game type; other types remain unexercised in this fixture.

One local macOS arm64 release run took **140.127 ms** from the start of candidate validation through provisional manifest revision, after fixture generation and stage capture. A separate fresh-process run took **142.517 ms** for the same timed region and peaked at **40,124,416 B RSS** for the entire process, including fixture generation and staging. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source registry_stage::tests::measure_dense_256_descriptor_candidate -- --ignored --exact --nocapture`. For RSS, run that built test binary alone in a fresh process and read macOS `ru_maxrss` using `resource.getrusage(resource.RUSAGE_CHILDREN)` after completion. Source SHA-256: `47fd46d9584733426558ab4a052b19e43977ad1716cf51ecbac96d4b87f76bdd` (`crates/thrum-source/src/registry_stage.rs`). `RUSTC_WRAPPER= ./dev check` passes.

These are local observations, not a speedup or a hard process-memory bound. The fixture has only one game record among 256 registered types; it does not exercise records for every type, 65,536 simultaneous required edges, two live history buffers, a real editor, SQLite admission or a complete edit-to-ready path. It therefore does not close full multi-schema workload or device qualification.
