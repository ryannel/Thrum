# I2a source-carried registry-history record

2 November 2026. **One fixed history record, not staged F3 closure or admission.** `thrum-source::history_json::parse_registry_history` directly decodes a supplied `core.registry-history` schema 1 JSON record at most 16 MiB. Its `registry.fields` entries are strictly sorted by `(type ID, field ID)` and capped at 100,000; `registry.versions` entries are strictly sorted by `(type ID, target version)` and capped at 1,024. The parser accepts only fixed keys, game-owned portable IDs, versions from 1 through `u32::MAX`, 64 lowercase hex digit hashes and boolean retirement. It refuses duplicate keys and excess entries before parsing an extra value.

The stored entries use borrowed string slices for ordinary unescaped IDs, with owned fallback for escaped JSON strings. Known map keys also borrow on the common path, avoiding per-key string allocations. Unit fixtures cover direct decoding, escaped IDs/keys, duplicate and unknown keys, duplicate history entries, invalid hash spelling, invalid versions, trailing input and a malformed 1,025th version entry. An ignored 14,500,266-byte fixture parsed 100,000 field entries and one version entry in 17.5–17.6 ms in two local release runs on the arm64 macOS host. A prior implementation that allocated each known map key took 27.0 ms in one local run; this is a local paired indication, not a stable speedup claim. The fixture then inserts a malformed 100,001st field value and confirms count refusal before parsing it. A direct test-binary child run reported 36,356,096 bytes maximum process RSS via `getrusage`; that includes fixture construction, the retained input, the valid parse, the subsequent over-limit parse and test harness, and excludes filesystem cache. Reproduce the timing with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_maximum_field_history -- --ignored --nocapture`.

The parser alone does not compare entries to active descriptors or an admitted root, nor verify that its bytes came from a declared, rehashed staged path. Separate [consistency](SOURCE-REGISTRY-CONSISTENCY.md) and [carried-lineage](SOURCE-CARRIED-LINEAGE.md) proofs now perform pure joins on its output. Borrowed entries retain the complete input byte buffer while history is live. A future candidate/prior comparison may need both 16 MiB input buffers and a descriptor record buffer concurrently; the physical reservation must cover this combined peak and escaped/adversarial records, or a streaming comparison must prove a smaller one. `RUSTC_WRAPPER= ./dev check` and `RUSTC_WRAPPER= ./dev check-docs` are the repository gates for this checkpoint; the first source-carried registry profile remains unchecked in the [Build Plan](../../plans/BRIEF.md#parked-retained-in-git-history).
