# I2a first-profile schema definition hashes

2 November 2026. **Pure canonical hash proof, not parsed F3 source or admission.** `thrum-source::definition` accepts bounded first-profile values: game-owned type/field IDs, optional or required text up to 4,096 UTF-8 bytes, and required references to `core.scene`. It streams JCS-form attributes into SHA-256 with the versioned field domain. A type-version hash includes its version from 1 through `u32::MAX`, strictly sorted active field IDs and their signatures, and the optional opaque extension prefix. Invalid symbols, limits, duplicate or unsorted fields, and extension overlap refuse before returning a hash. The source-carried parser must later verify that each active field's signature and type-version hash match its history records.

Tests compare both streamed digest paths with an independent `serde_json_canonicalizer` oracle and show that changing the text bound, field set, version or extension policy changes the digest. Hash functions use stack-local SHA-256 and caller-owned slices, with no heap allocation in their own code. The ignored release probe prepares 256 type IDs and 128 field IDs before timing 32,768 field signatures and 256 type-version hashes, reusing one preallocated field vector. One local arm64 macOS run took 21.95 ms. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_definition_hashes_at_first_profile_bound -- --ignored --nocapture`. This excludes descriptor JSON parsing, stage I/O/hash verification, history comparison and durable admission; it is one local cost sample, not a platform latency distribution.

`RUSTC_WRAPPER= ./dev check` and `RUSTC_WRAPPER= ./dev check-docs` are the repository gates. The first source-carried registry profile and the larger F3 semantic gate remain unchecked in the [Build Plan](../../BUILD-PLAN.md#after-the-foundation).
