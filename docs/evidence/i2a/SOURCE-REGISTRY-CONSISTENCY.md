# I2a active registry and history consistency

2 November 2026. **Pure join over parsed records, not staged source admission.** `thrum-source::registry::validate_active_registry` requires active descriptors in strictly increasing type ID order, with one current version per type. It merge-scans each descriptor's sorted fields against source-carried `registry.fields`, then each current type/version against `registry.versions`. Every active field must have the same canonical signature in history and must not be retired; every nonretired history field must have an active descriptor. Retired entries may remain. The current type/version must have its exact canonical definition hash in history; prior versions may remain. The joins allocate no additional history and take O(active fields + field history + active versions + version history) time.

Fixtures build parsed `core.schema` and `core.registry-history` records, then cover a valid join, duplicate current type, missing/retired/changed active field, nonretired orphan history, retained retired field, and missing/changed current version. A two-type fixture places retired fields before, between and after active fields and retains an older type version. The parser and canonical hash proofs supply those values. This function does not compare candidate history with an admitted predecessor; a candidate can still delete an old retired field or type-version entry unless the future root adapter performs both monotonic history comparisons. It also does not prove staged paths, record classification, game-record references or durability. `RUSTC_WRAPPER= ./dev check` and `RUSTC_WRAPPER= ./dev check-docs` are the repository gates; no end-to-end latency or device result is claimed.
