# I2a field and type-version lineage comparisons

2 November 2026. **Pure registry-history proof, not F3 validation or durable source admission.** The [source-capture design](SOURCE-CAPTURE-DESIGN.md#general-registry-selection-before-implementation) calls for every admitted `(type ID, field ID)` and its mechanical meaning to remain in source-carried history. `thrum-source::compare_meaning_histories` checks two strictly sorted, duplicate-free slices. Every prior ID must remain with the same 32-byte signature; an active ID may retire, but a retired ID cannot revive. Candidate additions are allowed. A branch missing an admitted ID must merge the current history before admission.

The matching `compare_type_version_histories` requires every prior `(type ID, version)` and definition hash to remain. A new version may be added; a reused version with a changed field set or extension policy must refuse once a descriptor validator derives its canonical definition hash. Both comparators validate order, then use merge cursors. They take O(prior + candidate) comparisons and allocate no heap memory. Hashes are opaque to these functions; the separate [canonical hash proof](SOURCE-DEFINITION-HASHES.md) still needs a source-carried descriptor parser to derive and cross-check them against history. A later durable adapter must read both prior histories from the **current admitted root** under its generation compare-and-swap. No caller can establish those facts with these pure functions alone. Imported registries and their authority roots also remain future work.

Unit fixtures cover additions, retirement, missing prior IDs, changed signatures (including a changed-unit surrogate), revival, stale branch union, duplicate keys, unsorted input and reused type versions with changed definition hashes. `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_meaning_history_100k -- --ignored --nocapture` measured 1.689 ms for one 100,000-prior-entry **field** comparison with one added candidate entry on the local arm64 macOS host. This timer excludes fixture construction, parsing, staged-byte verification, descriptor/hash derivation, the type-version comparison and durable storage. It is one local cost sample, not a latency distribution or platform qualification. `RUSTC_WRAPPER= ./dev check` and `RUSTC_WRAPPER= ./dev check-docs` are the repository gates for this checkpoint.
