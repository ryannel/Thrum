# Bounded canonical manifest to SQLite chunks

2 November 2026. The test-only SQLite proof now accepts `TreeManifest::write_jcs` through a 4 MiB `Write` adapter. A first streaming pass obtains exact length and SHA-256 without retaining output; a second pass emits the same canonical bytes into fixed chunks. The adapter checks emitted length and digest, then the store rereads and hashes the stored chunks in its completion transaction. A 26,000-entry fixture spans two chunks, commits the root/outcome, reopens SQLite and checks the recovered stored digest. Shared blob staging helpers preserve incomplete retry, stale-writer and complete-blob reuse behavior. Independent read-only review found no actionable issue; `RUSTC_WRAPPER= ./dev check` passes.

An ignored Rust 1.99.1 release probe emits **100,000 entries / 16,400,094 canonical bytes / four chunks**. Three fresh local macOS arm64 processes measured **79.777, 79.051 and 81.361 ms** from the start of the two-pass manifest staging through stored-chunk verification and completion. Process peak RSS was **39,501,824, 39,518,208 and 39,583,744 bytes**. RSS includes manifest construction, SQLite and test process state; the timed region excludes fixture construction, the prior `revision()` check and database open, and includes SQLite/WAL work on this local disk. The 4 MiB writer buffer is not a claim about total peak memory.
