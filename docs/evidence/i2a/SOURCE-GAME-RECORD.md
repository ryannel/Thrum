# I2a first-profile game record validation

2 November 2026. **One descriptor-fed record, not staged source closure.** `thrum-source::game_json::parse_game_record` validates a supplied game record's stable ID, type and schema against a parsed source descriptor. Known fields are checked by sorted field ID lookup and a 128-bit presence mask; required text/reference fields must appear, text uses the descriptor's UTF-8 byte bound, and a present record reference must be a canonical stable UUID. The summary retains required reference IDs and descriptor field indices plus the exact descriptor definition hash. It does not resolve target records or use runtime/wire indices.

Unknown keys are accepted only under the descriptor's explicit optional prefix and never interpreted as gameplay, save or wire values. The validator checks duplicate keys even inside opaque nested JSON, while retaining the original supplied bytes as the value's round-trip authority. The first profile allows at most 128 opaque fields and 256 total fields; across opaque values it bounds 65,536 JSON nodes, 64 whole-record container levels including the record and `fields` objects, 1,024 members per nested object, 128 UTF-8 bytes per key and 65,536 decoded UTF-8 bytes per string. An extra node or object member refuses before its value or key is parsed. Escaped strings may still allocate before their decoded byte bound is known; the complete physical reservation remains open.

Fixtures cover a valid marker with typed scene reference, optional caption omission, opaque bytes unchanged between two manually constructed neighboring caption variants, missing required reference, wrong known value shape, multibyte text overflow, invalid reference spelling, unknown field, duplicate nested key, schema mismatch, trailing input, node/string/object/optional-field limits, and the global 62 accepted versus 63 rejected opaque-container boundary. The ignored release probes measured one 131,264-byte 65,536-node optional value at 393–581 microseconds with 3,866,624 bytes process peak in the latest direct run, and one 8,436,530-byte 62-level/1,024-member-per-level value at 11.4–13.3 ms with 32,555,008 bytes process peak, on the local arm64 macOS host. The direct test-binary RSS includes fixture construction and harness, including both generated and final strings for the deep/wide case; it excludes filesystem cache and is not a conservative worst-case bound or device qualification. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_dense_optional_record -- --ignored --nocapture` and `measure_deep_wide_optional_record`.

An authoring edit tool still must prove exact opaque-value preservation during a real file patch; the parser only checks supplied bytes. The follow-on [staged closure](SOURCE-STAGED-RECORDS.md) now rehashes declared scene/game bytes, resolves required local scene IDs and uses a descriptor already joined to candidate history. It still requires one active game descriptor; multi-schema dispatch, authenticated predecessor lineage and the combined memory-peak reservation remain open. `RUSTC_WRAPPER= ./dev check` and `RUSTC_WRAPPER= ./dev check-docs` are the repository gates. The first source-carried registry profile remains unchecked in the [Build Plan](../../BUILD-PLAN.md#after-the-foundation).
