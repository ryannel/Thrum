# Game-schema source candidate through the root proof

2 November 2026. The test-only candidate-to-root path now has an integrated five-file fixture: `core.project`, `core.scene`, one source-carried `core.schema`, its `core.registry-history`, and a `game.marker` record. The descriptor defines an optional caption, a required typed reference to `core.scene`, and an optional extension prefix. The history carries the descriptor's exact field signatures and type-version definition hash. Candidate validation checks one required edge and the stable game ID before the SQLite path rehashes every staged file, compares the prior root's carried history, stages complete file and canonical manifest blobs, and commits root plus retry outcome.

Changing only the game caption creates a second revision and generation. After reopen, the selected root is the second revision and the game blob equals the exact captured file bytes, including the untouched `\u0061` spelling and whitespace in an optional JSON value. A same-token retry returns generation 2. Changing the required game-to-scene target to the project ID is refused by candidate validation, leaving generation 2 selected. Independent read-only review found no issue with the descriptor/history relationship or root handoff. `RUSTC_WRAPPER= ./dev check` passes.

A local Rust 1.99.1 release probe times the second edit from fixture file writes through capture, semantic validation and SQLite root commit. Three separate runs took **4.832, 2.361 and 2.432 ms** on macOS arm64. The first run's tail is retained; these tiny files and warm local storage do not qualify a larger game, physical device, sustained edit latency or a speedup.
