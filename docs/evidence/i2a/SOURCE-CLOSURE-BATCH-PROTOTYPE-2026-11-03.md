# Accepted-source final closure batching prototype — 3 November 2026

The production accepted store still checks every direct manifest file in the final SQLite IMMEDIATE root/outcome transaction. A test-only alternative prepares sorted, deduplicated exact (SHA-256, length) pairs outside the SQLite-core mutex, then checks at most 128 pairs per parameterized VALUES/NOT EXISTS query inside that same transaction. It preserves the generation, complete-manifest, keyed-outcome and final-COMMIT code path. Equal hashes with different lengths remain distinct pairs. A focused fixture checks empty, 128- and 129-pair boundaries and refuses a missing hash, wrong length or incomplete header. This prototype adds no second connection or durable table.

The ignored optimized fixture stages all named complete blobs and the manifest before timing the final transaction. An old A pin then attempts a scene copy while B's closure runs. Three local 100,000-reference runs with 256 distinct one-byte blobs gave **5.030, 4.411 and 4.532 ms** batched final transaction time, plus **2.830, 2.500 and 2.326 ms** pair preparation. The corresponding old A waits were **5.081, 4.448 and 4.601 ms**. The unchanged per-file transaction had previously measured **38.783–39.859 ms**, and a later default-fixture repeat measured **40.842 ms**.

For 100,000 distinct four-byte blobs, three batched runs took **104.230, 102.356 and 104.846 ms** in the final transaction, with **3.571, 3.519 and 3.969 ms** preparation. The old A waits were **104.366, 102.446 and 104.955 ms**. The earlier per-file transaction took **97.122, 117.581 and 97.562 ms** on the same synthetic shape. The ranges overlap; batching does not establish a reduction for the distinct-blob case that caused the largest reader hold.

The result rejects batching as the general production solution for this parent gate. The code remains a test-only, reproducible performance probe; public admission keeps its original final closure path. A later profile with substantial exact-byte duplication could reconsider it. The next responsive-reader design must let an old pin progress during a large final closure or show a distinct-blob closure algorithm with a measured lower hold, while preserving the single accepted-source authority and post-uncertain-COMMIT quarantine. SQLite's [WAL model](https://www.sqlite.org/wal.html) permits readers and a writer on separate connections, but short read transactions and checkpoint backpressure need explicit proof.

Reproduce with the optimized thrum-source test filter measure_maximum_manifest_closure_reader_wait and the ignored flag. Set THRUM_TEST_BATCHED_MANIFEST_CLOSURE=1 for this prototype; also set THRUM_TEST_UNIQUE_MANIFEST_CLOSURE=1 for the 100,000-distinct shape. Unset the batch variable for the per-file control. These are isolated local samples, not a p95/p99, cross-machine, full-candidate or physical-memory result.
