# I2a narrow source-schema bootstrap proof

2 November 2026. **Provisional semantic check, not general F3 closure, a candidate manifest or accepted source.** This first proof follows the [capture design](SOURCE-CAPTURE-DESIGN.md#next-gate-f3-semantic-closure) and the [foundation source contract](../../design/FOUNDATION-SPEC.md#1-source-format-and-identity--select-one-ordinary-file-language). It runs in native source tooling and adds no game callback, network wire or runtime authority.

The validator rereads and hashes each engine record from the provisional stage before parsing it. `project.json` must have the stable `core.project` schema 1 envelope, project format 1, strictly sorted declared scene paths and a nonempty sorted list of entry-scene IDs. Each listed scene must exist and have a `core.scene` schema 1 envelope with only an optional string label. IDs are checked for duplicates and entry scenes resolve by stable ID to a scene record, not by filename. Reserved scene/prefab/asset/schema record paths omitted from the project list refuse; unsupported object fields, target/dynamic roots, record types and nonempty external dependency roots refuse. Ordinary unlisted game source and binary files remain in the staged tree. This narrow profile does not parse scene objects or assign runtime slots. `BootstrapProfile` borrows its stage and can derive a **provisional** manifest revision from its captured file hashes and checked record identities without another full byte read. It never labels source bytes admitted; durable admission must rehash every staged file, including binary masters, before publishing a root.

The pass decodes fixed project/scene JSON directly into bounded path/ID summaries, with no generic `Value` tree. Known-key visitors reject duplicates and unsupported fields; path and entry arrays stop at actual staged membership before accepting another element. It drops the project byte buffer before reading scenes, sorts borrowed scene IDs once, and resolves entry IDs by binary search. The 1,000-scene ignored release fixture includes stage creation but times only the semantic pass: the earlier generic-tree implementation reported 17–18.5 ms, while the direct parser reported 17.6–17.8 ms and manifest construction plus JCS revision about 0.74 ms on this local arm64 macOS 26.6.2 host. A direct-parser process had 4.4 MB maximum RSS according to Python child `getrusage`; this includes the fixture and test runner, excludes filesystem cache, and does not prove the 100,000-entry or 16 MiB-record peak. A separate 10.7 MB unsupported scene record with 900,000 unique fields refused on its first unknown key in 13–70 microseconds of **parser-only** time, with 14.9 MB process peak RSS including the input buffer. That sample excludes the public validator's staged-file read and SHA-256 verification. Reproduce with `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-source measure_bootstrap_validation_1000_scenes -- --ignored --nocapture` and `measure_dense_unsupported_scene_refusal`.

`RUSTC_WRAPPER= ./dev check` covers the small A/B stable-ID edit with different provisional revisions, an independently constructed expected manifest that pairs two scene IDs with their paths around an interleaved ordinary file, wrong or duplicate IDs, missing and unlisted records, unsupported object fields and dependency roots, impossible declaration counts and same-length staged-byte tampering. The broader [Build Plan item](../../plans/BRIEF.md#parked-retained-in-git-history) stays open: game-owned schema descriptors, nested objects/transforms, optional extension fields, external root resolution, parser heap reservation, aggregate reference bounds, general validated candidate capture and durable SQLite admission are not qualified here.
