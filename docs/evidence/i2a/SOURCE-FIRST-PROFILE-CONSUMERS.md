## First complete proof and cost account

The next vertical fixture should edit a known caption in an ordinary game record, preserve its opaque optional value, capture and durably admit revision B, cook a small target-ready product from only B's pinned bytes, start a new authority world, commit one action, checkpoint it and restore against B's exact build. A deliberately broken target build must leave A's running world and B's accepted source separately visible. Exercise stale generation, lost admission response, failed cook, corrupt save and mismatched restore. The authority and rule callbacks must be the same local/multiplayer path; no transport is needed for this first proof.

This fixture is intentionally smaller than the 256-type stress candidate. Capture and validation are offline; their edit-to-ready critical path includes source rereads, staged writes, missing-blob writes, SQLite sync/checkpoint, cook, and world construction. The 172–177 ms local validation runs measure only the post-stage candidate check and cannot be added into an edit-to-ready promise. Track bytes copied, manifest/record allocations, SQLite main/WAL/temporary physical peaks, sync count, source/build pin lifetimes, wall-time distributions and process RSS together. Reuse unchanged verified blobs, batch small missing files, stream the manifest and avoid retaining a second whole-tree JSON model. A physical free-space and WAL guard, collector-enforced pins and production accepted-source API are prerequisites to this runtime fixture. Do not weaken the selected disk reserve or describe test-only SQLite proofs as accepted source.

External dependency roots require a separately pinned resolver and closure/compatibility policy. Prefab/object schema, larger-source direct staging, live gameplay edits, save migration and server hot update each need their own selected profile and proof. Those remain open F3/F4/W1/P7/N1 work; this handoff does not change the whole-engine contracts.
