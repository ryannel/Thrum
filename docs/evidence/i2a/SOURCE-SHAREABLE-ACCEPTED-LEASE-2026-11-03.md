# Shareable accepted-source read lease — 3 November 2026

This is the first code step toward the [selected owner reconciliation](../../design/research/SOURCE-OWNER-RECOVERY-RECONCILIATION-2026-11-03.md). `NativeSourceStore` now keeps its SQLite core behind one shared owner and mutex. A `PinnedSource` retains that owner instead of borrowing the store handle, so the same owner can admit a new root while an old read lease remains live. The public cook and materialization consumers accept the owning lease type without changing their source identity checks.

The accepted-store fixture pins A, removes A's working master, and copies a 4 MiB plus 17 byte asset. Its consumer writer admits B through the **same** store during the first chunk write. The second chunk still reads A's exact retained bytes; the copied length and SHA-256 pass, B is selected, and A can be pinned again through its historical outcome. A separate fixture drops the store handle while a lease remains, removes its working source file, reads the exact pinned bytes, closes the lease, and reopens with the expected root and no remaining pin row. A test-only VFS injects an error after B's final WAL commit-frame sync while a real accepted lease is live: later lease read and close refuse without new WAL/main writes, then fresh open recovers B's exact key and the retained A pin row. This focused fault test uses the final commit helper after staging B's complete blobs; it does not exercise the entire public admission method under that fault. The focused tests, both affected crate suites and the opt-in native F4 A/B consumer build pass.

SQLite access is serialized for this owner. Pin registration and manifest reading use short transactions. Manifest decoding runs after its transaction and outside the mutex. File headers are checked once, then each at-most-4 MiB chunk is copied into one reusable lease buffer under the mutex; hashing and consumer output happen after releasing it. A later uncertain-commit latch is checked on every chunk, so a partial output refuses and must be discarded. This first append-only profile retains completed blobs while a lease is live. A poisoned owner refuses with `RecoveryRequired`, leaving durable pins for fresh-open recovery.

The cost shape is one `Arc` owner allocation at open, one reference increment per lease, a mutex acquisition for each short SQL phase and each chunk, and one SQLite statement preparation per chunk. The lease reuses its chunk buffer and adds no per-tick engine work. The old path held one prepared statement through the whole copy, including consumer writes; this change trades bounded query setup for shorter connection occupancy. At this checkpoint admission still held the owner mutex through staging and preflight, so a reader's wait behind a large edit was not measured here. The later [phased admission proof](SOURCE-PHASED-ACCEPTED-ADMISSION-2026-11-03.md) records the changed writer path and local contention sample. No allocation count or assembled source-to-build performance claim is made by these correctness tests.

At this checkpoint the accepted store still permitted other independent connections. The later [owner-lock proof](SOURCE-NATIVE-OWNER-LOCK-2026-11-03.md) closes that cooperative process boundary on the qualified Unix path. Format-2 intent reconciliation and collector deletion remain open. This lease slice alone does not check the source-store reconciliation or ready-build parent gates in the build plan.
