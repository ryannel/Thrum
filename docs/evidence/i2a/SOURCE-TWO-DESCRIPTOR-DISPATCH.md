# Two-descriptor staged game dispatch, narrow proof

2 November 2026. A game-bearing provisional source candidate can now carry two sorted source-carried descriptors and choose each game record's descriptor by its top-level `type` value. The common one-descriptor case still passes directly to full descriptor validation. With multiple descriptors, a bounded first pass reads only the record's known envelope keys and traverses `fields` without retaining a JSON tree. It enforces the selected depth, node, key and string limits before any descriptor lookup; unknown or duplicate envelope keys refuse. A binary search selects the checked descriptor, then the full parser verifies type, version, fields, optional opaque content and typed references against it. The rehashed staged-byte and local-reference closure remains the state owner.

A seven-file fixture carries `game.marker` and `game.signal` descriptors, their permanent field/version history, two game records and one scene. It validates both game types, one required marker-to-scene edge and the provisional manifest. A changed working file does not alter the older stage; fresh stages with an unknown game type or a wrong schema version refuse. Separate discriminator tests put a nested spoofed `type` before the top-level key, reject duplicate/missing keys and malformed JSON, and reject 65-level or more than 65,794-node fields before full validation. `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --offline -p thrum-source --lib registry_stage` and the focused discriminator tests pass.

Local Rust 1.99.1 release smoke runs after this change observed **89.716 ms** for 1,000 small one-descriptor candidate validations and **112.121 ms** for one dense 4,099-file one-descriptor validation. These runs are not paired with an identical baseline and do not qualify a speedup or the two-descriptor edit cost. Source SHA-256: `703788f83689890b44827714e022f74c7bf0fefd45cd378d9d4414e16b035377` (`crates/thrum-source/src/game_json.rs`) and `676fdfde36e7d809493f65a164ef87969bf7406cca72307f5b4dad7179ea4761` (`crates/thrum-source/src/registry_stage.rs`). The multi-descriptor path scans each game record's JSON twice, once to find the type and once for descriptor-bound validation; its CPU and allocation cost at 256 descriptors remains open. The candidate is provisional, with no external dependency roots, full F4/T1/W1/P7/N1 consumer qualification or production accepted-source API.
