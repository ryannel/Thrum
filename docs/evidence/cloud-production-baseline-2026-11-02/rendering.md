# Cloud rendering and lighting baseline — selected before migration review

2026-11-02. Scope: production **design selection**, not implementation, visual acceptance, or a measured WebGPU result. This is our assembly of published techniques; no source asserts that a single shipped engine uses this exact combination. The starting commission is five authored evolving cloud families (Cu, Cb, Sc, St, Ci), weather and Sun, clear air/fog, cloud and ground shadows, surfaces, ambient environment, and independent reflections. Target: M2 WebGPU 1280×720, cloud system ≤5 ms within ≤16 ms frame and ≤512 MiB total device resource target; native 3/10 targets remain unqualified. The numbers below are **selected initial defaults**, adjustable by profile only after evidence, not pending algorithm choices.

## Complete operating path

**One density authority.** The weather/content owner publishes a versioned `CloudField` at simulation time `t`: family records with stable ID, world transform/bounds, **time-varying authored 3D optical-density master**, velocity/deformation correspondence, extinction and scattering coefficients in m⁻¹, liquid/ice phase weights, and coverage. One `sampleCloud(p,t,mip)` returns the **sum of nonnegative extinction and phase-weighted scattering coefficients**, velocity/correspondence, conservative `maybeOccupied` and contributing group IDs. The source producer interpolates adjacent *final optical frames* channelwise at one unwarped cooked coordinate and one LOD; weather applies a shared height-wind transform once. Cu/Cb use artist-cooked low-frequency 3D voxel envelopes and 3D noise detail; Sc/St use broad layered 3D optical fields and bounded relief detail; Ci uses thin anisotropic 3D filament fields. All five are *true finite volumes*; broad layers stitch admitted adjacent cells from common source IDs with no exposed tile edges. Near and far read the same fields at footprint mips, so no mandatory 2D→3D handoff or novel far transfer algorithm. Prepared field frames and conservative max-density mips are shared by master revision/frame/LOD across instances; instances carry distinct event ID, phase and transform rather than duplicating full textures. Weather changes births/continuations and local support, not a sky alpha. Detail cannot substitute for genuine authored formation, renewal, deposition and breakup. No density has a second rendering-only formula. This uses Nubis³ authored voxels, procedural up-resolution, and distance mips as the content precedent; exact five-family masters must still be authored and admitted before production. [Nubis³, modelling/sampling and costs](https://advances.realtimerendering.com/s2023/Nubis%20Cubed%20%28Advances%202023%29.pdf#page=50), [Epic material and conservative-density practice](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-in-unreal-engine#conservativedensityevaluation).

**One atmosphere authority.** `AtmosphereState(t)` contains planet/local-up coordinates, Rayleigh/Mie/ozone profiles, Sun direction and spectral illuminance, and clear-air aerosol density. Hillaire's four LUT **families** are selected: 256×64 transmittance; 32×32 multiple scattering; 192×108 sky view; 32×32×32 aerial perspective. For aerial perspective store RGB in-scatter and **RGB transmittance in separate 3D targets**; the paper's mean-alpha transmittance is only a faster comparison path, not the selected RGB contract. The first two change only when atmosphere composition changes, sky view on Sun/camera-altitude change, aerial perspective on camera/Sun/composition change. Local fog is a bounded separate density/source in the *same view-ray integral* where it overlaps cloud/air; no independent finished fog image is blended. Horizon-sensitive sky mapping and a full-resolution analytic Sun disk follow the paper, with the disk filtered once by air/cloud optical depth. This is a selected RGB and local-fog adaptation of Hillaire's clear atmosphere method, not a published four-LUT proof of arbitrary fog. [Hillaire 2020, §§5.2–5.5 and Table 2](https://sebh.github.io/publications/egsr2020.pdf).

**Cloud optical depth and illumination.** Define `T(a,b)=exp(-∫a→b σt ds)` per RGB channel and HG phase `P(g,μ)=(1-g²)/(4π(1+g²-2gμ)^(3/2))`, μ=view-to-Sun cosine. Cloud extinction is scalar (grey); air/fog extinction is RGB. Default liquid cloud primary phase is two HG lobes `(g,w)=(0.8,0.8),(-0.2,0.2)`; ice family phase parameters are separate authored/admitted coefficients, not silently copied liquid constants. Set `P₀=0.8 P(0.8,μ)+0.2 P(-0.2,μ)` and `P₁=0.8 P(0.4,μ)+0.2 P(-0.1,μ)`; the selected one-octave Sun term is `j_sun=σs E_sun_clear T_fog_sun V_geometry_sun [P₀ exp(-τ_cloud)+0.5 P₁ exp(-0.5τ_cloud)]`. This is inexpensive Epic-style multiple-scatter look control, not energy-exact transport. Cloud ambient source is `j_sky=σs E_sky_clear/(4π) A_cloud`, where clear Sun/sky come from the **clear atmosphere** LUTs, fog Sun T is a bounded light-ray integral, and `A_cloud=exp(-τ_ambient)` from one coarse hemispherical/cloud-top optical-depth field generated from the same density. No cloud is included when generating `E_sky_clear`, so ambient cannot recursively re-light itself. Clouded ambient reaches surfaces through the environment product below. There is no arbitrary ground-bounce multiplier in the baseline; ground bounce is an optional later quality feature with its own evidence. In a camera segment Δs of locally constant **RGB** total σt and source j, add channelwise `T_view * j*(1-exp(-σt Δs))/σt`, then update `T_view *= exp(-σt Δs)`; use the σt→0 limit `jΔs` to avoid division near zero. Terminate when all T channels fall below 0.01. [Epic multiple-scatter and shadow recommendations](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-in-unreal-engine#lightmultiplescattering), [Nubis³ light decomposition](https://advances.realtimerendering.com/s2023/Nubis%20Cubed%20%28Advances%202023%29.pdf#page=19), [pinned Takram implementation of local ray, BSM and segment integration](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/clouds/src/shaders/clouds.frag#L440-L572).

**Sun shadow exactly once per path segment.** A camera-centred two-cascade Beer shadow map (BSM; 256² each, RGBA16F) is rendered from Sun to shadow-bottom through the current cloud density: near footprint 4 km, far footprint 20 km, snapped to texels. Each texel stores front depth, mean extinction, accumulated optical depth and bounded tail, as in the pinned Takram shader. On cloud samples, trace a **short local 4-step** Sun ray over `L=min(400 m, distance to cloud top)` for edges, then sample BSM optical depth *starting at the local ray end*, not at x: `τ_cloud_sun(x)=τ_local[x,x+L]+τ_BSM[x+L,top]`. If BSM has no valid footprint, finish the same ray with coarser samples to top rather than assume a lit cloud. For ground and surface direct Sun use BSM `[ground,top]` only, plus ordinary opaque geometry shadow factor; do not also apply a cloud-screen shadow. Atmospheric/aerial/fog Sun in-scatter samples this same BSM at its own view samples and a separate local-fog light ray where fog exists, so shafts and shaded surfaces agree. BSM represents cloud extinction only; clear-air Sun transmittance, local fog and geometry factors are applied once each in the light path. BSM is scalar extinction, intentionally grey; color comes from Sun spectrum and cloud scattering. BSM construction/approximate point lookup and offset are shown in Takram; Epic recommends shadow maps for constrained platforms and documents cloud shadowing of terrain and atmosphere. [Takram BSM writer](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/clouds/src/shaders/shadow.frag#L33-L116), [Takram offset lookup](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/clouds/src/shaders/clouds.frag#L157-L232), [Epic shadow modes and interactions](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-in-unreal-engine#volumeraymarchingandshadowmaps).

**Cloud view pass.** Depth-clipped ray intervals intersect all active family bounds, sorted front to back; overlapping coefficients sum before a segment is lit. The same integrator serves main and independently projected reflected views. At 1280×720, far cloud rays are **320×180 every frame**; a separately masked near pass is 640×360 only for projected cloud intervals within 200 m. Each pass writes RGB scene-linear radiance/RGB transmittance, first/weighted depth, velocity and source ID; near samples replace, never add to, the corresponding far source interval. Jitter by a fixed blue-noise sequence, march up to 64 occupied steps with 12 m minimum near step and perspective/distance growth capped at 250 m; conservative max-density mip skips empty intervals and chooses detail LOD from ray footprint. These are selected starting bounds, not certified adequate for every camera or family. Reconstruct to full resolution using per-view depth/velocity reprojection, 3×3 neighborhood clamp and current-frame blend 0.15; reject on disocclusion, changed local source correspondence/optical coefficients, incompatible light generation, camera cut, or >2% depth disagreement. A global source clock advance alone does not reject valid moving history. Outside history, use current-frame bilateral spatial upscale, with native fresh sampling at newly born high-contrast silhouettes. No sparse 1/16 refresh or novel far transfer is on the critical path. [Nubis³ split resolutions and 2.1–4 ms **console** reports](https://advances.realtimerendering.com/s2023/Nubis%20Cubed%20%28Advances%202023%29.pdf#page=93), [Takram pinned temporal reconstruction and rejection](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/clouds/src/shaders/cloudsResolve.frag#L45-L155), [Hillaire jitter/reprojection discussion](https://sebh.github.io/publications/egsr2020.pdf).

**One joint view integral in scene-linear HDR.** Build sorted intervals from camera to opaque terminal/sky boundary for air, fog and all cloud supports. On intervals containing cloud, local fog or spatial Sun shadow, sample **summed** RGB extinction and RGB source coefficients (air single scatter, bounded Hillaire higher-order air term, fog, clouds) at the same x and apply one homogeneous Beer step. Thus fog crossing a cloud and air inside a cloud are integrated with one common view throughput. On clear, unshadowed intervals use Hillaire's aerial prefix LUT as an affine segment; `A∘B=(L_A+T_A L_B,T_A*T_B)` for premultiplied RGB source L and RGB transmittance T. Derive a clear segment by `T_ab=T_b/T_a`, `L_ab=(L_b-L_a)/T_a` only where T_a is well conditioned; otherwise directly march the bounded segment. Opaque radiance is direct Sun filtered by clear-air/cloud/opaque Sun optical depth once plus environment ambient; sky LUT is the terminal for clear sky, not another full-camera overlay. Local clouds and fog are integrated before that terminal. Transparent/reflective interfaces use their own terminal depth, and a reflected ray starts from the interface with its own projection/world sample; the eye→interface operator is applied once. The cloud renderer can use weighted depth for temporal reprojection, but that depth cannot replace the joint coefficient integral. Hillaire's aerial LUT and mixed media transport algebra support this selected join; Smolder's **public 2026 abstract** establishes the production need to integrate volumes with opaque, transparent and fog, but its 30 MB slide PDF was unavailable under this task's 5 MiB download cap, so no detailed algorithm is attributed to it here. [Hillaire §5.4](https://sebh.github.io/publications/egsr2020.pdf), [Smolder course abstract](https://www.realtimerendering.com/advances/s2026/index.html).

**Environment and reflections close independently.** Ambient owner captures a 32² cube of clouded sky at a stable region anchor with **all six faces from one current source/Sun/air generation in the same frame**, then derives SH9 diffuse irradiance and a roughness-prefiltered specular cube; publication is atomic. The capture transport terminal is clear sky, ground or direct-only surface and does **not** read the clouded environment it is producing. Surfaces sample that clouded environment once for indirect lighting; no additional cloud AO multiplier. Ground direct remains BSM-shadowed. Mirror and low-roughness reflection requests render the same joint cloud/air/fog integral along their **own reflected rays** and geometry terminal, using an independently budgeted 320×180 reflected view/history when requested; the main view's color/depth is never mirrored as cloud radiance. Rougher surfaces use the current environment cube plus standard BRDF/SSR weighting and an independently captured probe where needed; water/refraction applies eye-to-interface medium once. This is our nonrecursive closure based on Epic's sky-light capture and established independent-view transport. Epic's time slicing is a later possible quality/cost trade, **not** the default while current-generation coherence is required. [Epic real-time sky capture and reflection limitations](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-in-unreal-engine#realtimeskylightcapture), [Epic time slicing](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-in-unreal-engine#budgetingwiththeskylightrealtimecapturemode).

## Pass and resource contract

Per frame: (1) sample one weather/source epoch/time and origin-relative transforms; (2) prepare dirty resident source endpoints/occupancy mips into a **candidate generation**; (3) update invalid atmosphere LUTs; (4) update dirty BSM/ambient regions using that candidate and Sun; (5) render all six environment faces and derive irradiance from the same candidate; (6) extract opaque/main/reflection requests and render their own depth/transport terminals; (7) main and requested reflected cloud/joint-medium view passes; (8) per-view temporal reconstruction; (9) transparent/interface composition; (10) publish the complete compatible frame graph and tone-map once. BSM, ambient, environment and view passes use **the same candidate field generation and Sun**; source regional read sets may reuse only unchanged data, not relabel a stale tile. If work cannot complete, retain the last complete image with its old timestamp and count a missed frame; do not silently combine stale shadow/environment with new density or freeze source time. Camera movement only invalidates/reprojects its view history and moves cascade centre; source/weather/Sun changes invalidate affected BSM, ambient and cube. Device loss recreates derived resources from recoverable CPU masters and clears view histories. Visible-main-cloud-disabled still retains BSM, environment and reflection work if those consumers request them; no optical consumer drops all cloud GPU work while semantic weather remains. Reflections-disabled drops reflected view, while environment capture remains if surface ambient uses it. CPU gameplay queries read source/weather state, not temporally reconstructed pixels or filtered BSM.

At 720p the **selected reservation**, counting simultaneous CPU+GPU copies, is 184 MiB: encoded source masters 64, decoded endpoint/occupancy pool 48, bounds/index 8, shared shadow/ambient 8, main/reflected histories and reconstruction 32, staging 16, air/environment 8. This leaves 328 MiB of the ≤512 MiB **whole-browser** target for scene, browser, pipelines, driver and peak overlap; it is arithmetic headroom, not measured available memory. Source admission rejects a library whose real retained masters/endpoints/old+new overlap exceed the reservation. Cloud 5 ms ledger target includes source ≤0.45, BSM ≤0.55, cloud light/ambient ≤0.45, main ray work ≤1.90, reflected rays ≤0.35, current environment ≤0.25, reconstruction ≤0.65, reserve ≤0.40 ms. Clear-air/composition ≤0.8 ms is additional within the 16 ms whole-frame target. These are **allocation objectives, not predictions**. At 320×180, 64 primary samples already imply 3.69 million density visits before local Sun rays; near and reflected requests increase it. The first reductions remove duplicate prep and tighten conservative occupancy, then use validated mips and shared low-frequency light; only then reduce near/high-frequency cloud ray footprint or sample ceiling with held/motion comparison. Slower shadow/environment cadence is excluded until an explicit age/error budget and changed-region gate pass. No M2 timing, bandwidth, browser residency, native 3/10, or visual beauty is claimed from papers' console timings.

## Selection and provenance

Published: Hillaire's LUT architecture; Epic's Beer shadow-map, one-octave cloud scattering, cloud/atmosphere/sky-light integration and time-sliced capture; Nubis³ voxel authored density, mip/up-resolution, adaptive marching and production performance on its hardware; pinned MIT Takram implementation demonstrates local Sun ray + offset BSM, finite segment integration and temporal resolve. Our assembly: five-family density interface, exact field-to-pass schedule, numeric defaults, nonrecursive environment closure, local fog in the same aerial operator, version/invalidation policy, and M2 cost allocations. Smolder 2026 abstract supports cross-layer integration as an experience constraint only. The pinned Takram shader is a readable MIT reference; do not copy restricted Unity or Epic runtime code, and port equations/ideas with source attribution rather than copying Takram source wholesale.

**Required proof after design, not choices deferred:** paired full-scene sun/cloud/ground/atmosphere/fog/reflection captures for each family and weather transition; high-resolution reference renders for near/far overlap, grazing sun, disocclusion, opacity and camera flight; verify `τ_local + τ_BSM_tail` against an independent full Sun ray; check one aerial operator and no doubled ambient; inspect 60 s motion and 30 min churn; M2 WebGPU GPU pass timings and residency at 720p with all consumers enabled; native 3/10 separately. Rejection: missing family form/evolution, doubled/absent cloud blocker, inconsistent Sun/air/ground, history trails, reflected cloud feedback, >5 ms cloud or >512 MiB total on target. None of these has run.

## Post-selection comparison with existing migration plan

This section was written **after** saving the selection above. I read `docs/design/modules/CLOUD-MIGRATION.md`, `CLOUD-CAPABILITIES.md`, `CLOUD-PERFORMANCE.md` and `docs/design/research/ATMOSPHERICS-TECHNIQUES.md`; it is a scoped self-review, not independent reviewer sign-off. The original first draft exposed three defects during comparison, now corrected above: scalar aerial T despite the RGB contract; separate finished cloud/air layers despite required joint overlap; and a cube-only reflection route despite required independent reflected rays. It also used stale time-sliced environment by default and omitted reflection from the 5 ms ledger; both are corrected. The changes are material and remain unproven until implementation/visual/device gates.

The old plan already selected most sound **principles**: Hillaire four LUTs, authored evolving optical masters, shared all-layer depth, bounded local Sun rays, joint C08 integration, nonrecursive environment, independent reflected views, and atomically compatible generations. This baseline narrows the still-open implementation shape to one practical renderer: shared final-optical-frame source sampling; one fixed 3D field path with mips for near and far; 2×256² BSM plus four local steps; one cloud MS octave; 320×180 far and near-only 640×360 current rays; same V3 integrator for main/reflection/environment; RGB aerial T; current-generation 32² all-face environment; explicit per-view history and allocation. The **choice** is locked for the first implementation, while its beauty/cost/support evidence is not. A failure against an explicit gate calls for a revised design, not an invisible parameter tweak.

The critical path should **exclude** developing a coverage-conditioned far transfer summary, Smolder-style per-pixel selective-light sharing, a novel lighting cache/occupancy format, optical-flow frame reconstruction, neural cloud shading, async-compute scheduling, time-sliced stale environment, and extra multiple-scatter/ground-bounce refinements. None is required to implement the selected baseline; they may be measured as bounded challengers after the common-source spatial/lighting/consumer sentinel reveals a specific error or bottleneck. Standard max-density mips and empty-space skipping are part of the baseline, not experimental research. The pinned Takram GLSL path is a method reference, not a WebGPU-ready dependency or cost proof. Smolder's detailed slide findings in the older source map were retained by other reviewers, but this bounded study directly inspected only its public abstract; it does not claim a fresh reading of the 30 MB deck.

Review conditions before calling the baseline build-ready: the content owner must produce recoverable phase-complete optical masters for each family, especially Cu/Cb renewal and Ci tails; the two-cascade BSM must prove offscreen/far blocker coverage at 5° Sun; the 320×180 far/640×360 near split must prove silhouettes and no source double-count at 200 m; current six-face capture must meet its allocation under rapidly changing weather; and source endpoints plus old/new/staging must fit 184 MiB without peak overrun. The previous one-source **12.976/17.075 ms p50/p95 GPU** local graph makes the 5 ms target high risk; it is evidence about that old graph, not a measurement of this baseline. The selected design is not accepted merely because similar components shipped elsewhere.
