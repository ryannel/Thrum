# System review of selected cloud baseline (2 November 2026)

Read `CLOUD-PRODUCTION-BASELINE.md` and the rewritten `CLOUD-MIGRATION.md` against the original commission, governing `CLOUDS.md`, capability ledger, POC acceptance and performance contract. This is design review only; no source build, art inspection or target timing. The baseline's explicit unrun status is appropriate.

## Blocking design/cross-document findings

1. **BSM self-shadow tail is underdefined.** Baseline lines127–139 specify a 2D cascade texel containing front depth, mean extinction, whole-column tau and validity, then query its `tau_tail_column` from an arbitrary cloud sample after a400m local march. These four numbers do not determine directional optical depth from that interior endpoint to the Sun for two separated layers, holes or varying cloud depth. A receiver-map total may include material behind the sample or omit a nearer upstream blocker. The local four samples do not repair a far gap. Define a depth-conditioned cumulative Beer representation with an admitted depth domain, or use a bounded direct remaining-ray evaluation with a demonstrated complete-cost route. Keep conventional 2D BSM for receivers where it is valid. Add same-source opposing-depth-layer counterexamples and current/filtered shadow comparisons at cloud, air/fog, surface and reflection samples before saying the light path is closed. This is an optical producer/consumer contract gap, not a shadow-resolution tuning issue.
2. **The two evidence contracts still order retired techniques.** At review time, `CLOUD-PROOF-ACCEPTANCE.md` P1a/P1b requires midlife control/branch/shear edits, P6 asks to perturb shear, and P3a requires the coverage-conditioned far transfer test. `CLOUD-PERFORMANCE.md` still mandates16/64-subray far-transfer comparisons, selective-light comparisons and encoded64/source48MiB. The selected baseline instead uses finite authored episodes, ordinary far mips, fixed light and encoded48/source64MiB. Update these before D2 marks alignment complete. Preserve the *observable* continuity, far gap, light quality and cost adversaries, but test them through the selected method. An optional challenger may be recorded without blocking a stage.

## Significant unresolved qualification, not design blockers

- The source/cook contract is concrete: the same world episode owns time/IDs/wind, density already contains shear, runtime poses apply it once, and all five family recipes export3D optical fields. P1b's Cu/Cb, low deck, Ci and weather-survivor pilots arrive before P3b source freeze. Still, 4×10-minute stories at4Hz with per-frame bricks and baked per-source16³ accessibility can be large. If512 independently animated events each had a16³ R8 accessibility grid for all2,400 frames, this channel alone would be about5.0GB uncompressed before VDB density, even though the active window could be far smaller. P1b/P3b must estimate actual event lifetimes, sharing, changed bricks, compressed durable bytes, requested mip/window bytes, IO/decode/upload rate and old/new peak; the184MiB reservation is a target, not proof. A source that misses current time at16×/64× or exceeds resident caps is failed for that profile, not silently downgraded.
- The selected every-frame32² cube and main/reflected volume work are plausible consumer categories but not an M2 cost demonstration. The old one-Cu12.976/17.075ms p50/p95 M3 result makes the selected5ms target an adverse gate. P4a and P3b should model combined sampled work and transfer; P7 must measure full fixture and P8 real Thrum/water. Parameter adjustment can stay within baseline if retained cues and budgets pass; required algorithm changes should revise D2 explicitly.
- Finite authored episodes satisfy the four commissioned weather progressions if births, renewals, survivors and joint shadow/reflection response are observed. Full ongoing use beyond an episode needs a declared looping/chaining boundary with stable IDs and matched cause fields or an explicit supported-duration limit. This is a product-domain choice to pin before full-sky acceptance, not a demand for live weather simulation.
- Houdini22 FX license/install is an external prerequisite. The plan candidly marks it unavailable and does not claim source qualification. The selected version and VDB route can be a locked specification while P1a remains blocked until the tool is actually usable.
