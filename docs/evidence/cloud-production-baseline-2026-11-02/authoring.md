# Selected cloud production authoring baseline — 2 November 2026

**Status:** first independent recommendation, before comparison with `CLOUD-MIGRATION.md` or the old technical plan. This selects the content production route for the five-family cloud commission. It is a design, not a claim that authored assets, runtime viability, or appearance have passed. No download, license purchase, bulk bake, or new asset was made for this note.

## Decision and prerequisite

Use **Houdini 22.0 production build, native SOP/VDB and sparse Pyro tools, plus one versioned Thrum cooker that converts selected VDB sequences and scene tracks to compact runtime pages**. Use the 22.0.459 production build as the initial pin; require a compatible commercial or Indie production license, as appropriate for the actual content owner's eligibility, before producing deliverable assets. SideFX lists 22.0 as current, and its staff announced 22.0.459 as a production build on 1 October 2026. The local Mac currently has Blender but no discoverable Houdini executable or application. Apprentice is for noncommercial learning and its `.hipnc` chain is not a production source. This is a real provision/eligibility gate, not an instruction to purchase anything. Do not claim a build can begin until an eligible seat and exact build are recorded. [H22 release](https://www.sidefx.com/forum/topic/104182/), [22.0.459 production build](https://www.sidefx.com/forum/topic/104614/), [SideFX licensing](https://www.sidefx.com/Support/licensing/), [Indie limits](https://www.sidefx.com/products/houdini-indie/).

The chosen workflow is: **author and simulate a finite weather episode in Houdini → cache exact frame dependent VDB and control tracks → review native animated volumes and representative cloud/light render → cook bounded sparse spatial/time pages with identities and optical coefficients → stage a complete versioned delivery → inspect the actual Thrum renderer, receiver shadows, reflected rays and air/fog together → pin the selected package**. No EmberGen or Blender fallback is in the production chain. EmberGen's documented VDB export is useful corroboration of offline volume export, but it is not selected because one Houdini scene needs to own both field feedback and all layer/weather control. [SideFX File Cache](https://www.sidefx.com/docs/houdini/nodes/sop/filecache.html), [SideFX cache formats](https://www.sidefx.com/docs/houdini/dyno/cache), [EmberGen VDB export](https://docs.jangafx.com/embergen/pages/references/How-To%20Guides/exportVDB.html).

## Fixed domain and content contract

- One named **episode** is a finite 10 minute world-time sequence, with a fixed 3D world frame, metre units, absolute UTC-independent episode seconds, Sun/air binding, deterministic seed and one versioned altitude-dependent wind table `W(x,z,h,t)` in metres/second. Four episodes are authored: `FAIR`, `BROKEN`, `OVERCAST`, `STORM`. Shared wind is sampled by all Houdini source networks at the same times. The runtime reads the baked tracks/volumes; it does not re-advect clouds or promise arbitrary live wind, branch, or shear edits. A game may select an episode at a documented boundary; cross-episode instant arbitrary blending is outside this baseline.
- Every persistent formation/layer patch has a stable `source_id`, family, birth/death support interval, source revision, world bounds, parent/child IDs where a cell splits or merges, and local material region IDs. Birth, renewed lobes, holes, anvil and decaying tails are represented by actual changing density support. Time interpolation between adjacent authored samples is allowed only inside a continuous ID/region interval. A topology change carries both endpoint volumes and explicit validity/invalidation; it is never treated as unchanged material for temporal history.
- Author in Houdini at a fixed simulation step (initially 1/24 s). Cache source samples at an adaptive **maximum 1 s spacing** in smooth intervals and tighter where density support or silhouette changes exceed measured thresholds. The cook interpolates within each same-ID segment and quantizes tested coefficients. This is a selected representation, not a forecast of final storage size. Fixed steps, export cadence, page dimensions and thresholds are recorded per package and tightened where motion/lighting witnesses fail.
- Store Cu/Cb/Ci local volumes relative to a baked source anchor track; export that track with world positions at the same sample times. The renderer interpolates the **authored pose** and then samples the local field. It does not numerically integrate or add wind again. Sc/St regional columns remain in the fixed world tile frame. A frame interval is admitted only if residual feature displacement after applying the authored anchor is below half a source voxel **and** quarter/mid/three-quarter checks against Houdini's finer cache preserve silhouette, optical depth and changing connectivity. Otherwise add frames; the 1 s cap is never a quality guarantee. The time-varying 3D fields retain local rise, shear, renewal and erosion after the anchor is removed.
- Store extinction and scattering/albedo fields in scene-linear, metre-based optical units, not a prelit image. The cooker writes one canonical density/coefficient sample representation and conservative nonempty bounds; nearby and distant renderer paths derive from it. A family may have distinct detail channels, but no per-consumer independent cloud. Sun direction and sky state are evaluated at runtime against the same authored volume/time, so time of day remains live within the admitted air/light profile. The weather source may provide a clouded diffuse irradiance input and storm event seams; surface, water, audio and precipitation implementations remain their own owners.
- Runtime delivery is a **streamed sparse page set**: per-family source packages and episode-scoped indices/tracks, quantized 3D density pages for Cu/Cb and localized relief, 2D column/height pages with vertical profiles for broad Sc/St, and 3D thin filament pages for Ci. Pages include conservative majorants, full physical bounds, mips/guards, exact format/byte counts and temporal neighbours. The loader admits an entire compatible generation before swap, keeps old pages until readers retire, and fails explicitly if a required page is absent. Source identity and optical time are shared across main, shadow, reflection, environment and air/fog queries. One cache budget covers them; no invisible copy is free. This packaging and the 2D/3D split are **our design inference**, not an exported Houdini or Nubis³ feature.
- Quality profiles may change spatial/time sampling and reconstructed light rate only after moving acceptance. They do not replace the current episode, its IDs, density support, age or downstream shadow/reflection source. The 512 MiB fixture peak includes CPU/GPU copies, staging, old/new overlap and browser process scope; 5 ms cloud and 16 ms full GPU p95 at 720p on M2 WebGPU, 3/10 ms native, are admission targets, not achieved numbers.

## Executable Houdini 22 source recipes

These are **specific authoring recipes to build and test**, not claims that SideFX ships a cloud life-cycle preset. In each network cache the *time-varying* density, the state/ID tracks and full-resolution comparison render. A stationary Cloud Shape followed only by noise-offset animation fails the required growth/renewal/breakup even if it moves beautifully. SideFX's current cloud modeler documents Cloud Shape Generate/from Line/from Polygon, VDB from Particles/Polygons, Cloud Billowy Noise, Cloud Wispy Noise, Density Profile and Clip; its deprecated `Cloud` SOP explicitly describes non-simulated shape/noise-offset animation and points to sparse smoke for simulation. [Cloud modeling](https://www.sidefx.com/docs/houdini/model/cloud.html), [deprecated Cloud SOP](https://www.sidefx.com/docs/houdini/nodes/sop/cloud.html), [sparse Pyro Solver](https://www.sidefx.com/docs/houdini/nodes/sop/pyrosolver.html).

| Family | Construct the finite evolving source in Houdini | Distinctive exported state and failure witness |
| --- | --- | --- |
| **Cu** fair-weather cumulus | Seed heterogeneous low-base lobes with `Cloud Shape Generate`/`Cloud Shape from Polygon` → `VDB from Particles` fog `density`; feed a **sparse Pyro Solver** with independently time-windowed base emitters, buoyancy, moderate turbulence and density dissipation. The episode wind drives solver advection. Apply restrained `Cloud Billowy Noise` to *each cooked frame*, with material/rest coordinates carried by the evolving solver rather than replacing its support; use Density Profile for a common condensation base. At maturity, overlap new base-fed cells with older eroding cells; stop sources asynchronously so individual lobes detach and vanish. | Changing occupied support, lobe IDs and real mature renewal; reject scale inflation, whole-cloud opacity fades, or unchanged silhouette plus noise scroll. |
| **Towering Cu/Cb** | Start from the Cu network, but key a sustained, stronger rising core and several staggered feeder towers in the same `source_id`. Cache solver density and velocity. At a pinned stable cap altitude, divert the upper density into a height-dependent lateral outflow/shear field in a connected upper solver region; cool/erode the core and anvil on different timescales. Add wispy density only to the upper ice/outflow material, while the core retains billowy treatment. Keep the cap/anvil child regions tied to the parent cell ID. | Actual upward development and continuing lower feeder growth, a flattened spreading/sheared fibrous anvil, then core decay with anvil persistence. Reject vertically stretched Cu or a separate pasted disk. The precise cap/ice operator is an authored adaptation to prove, not a documented meteorological solver result. |
| **Sc** broken stratocumulus | Paint/seed a 2D regional column field `q(x,z)` with cell/roll masks and a shared low base. Use a SOP Solver feedback loop on the VDB/volume column at each source step: semi-Lagrangian sample at `x−W_low Δt`; add local, per-cell source and renewal; subtract local dry erosion; diffuse only enough to join banks. Lift `q` into a shallow 3D slab with base/top profiles, cellular relief and patch-local billowy detail using a Volume Wrangle/VDB composition. | Real connected banks and gaps that advect, close, reopen, merge and erode without tile reset. Export column amount, slab bounds, patch IDs and sparse local 3D relief. Reject isolated Cu balls or static holes under moving noise. |
| **St / overcast** | Reuse the *same low-layer feedback field and surviving IDs* as Sc. Author a broad moistening front and spatially variable source/drying fields; lower cellular relief and widen the connected column support. As overcast develops, source grows/joins existing banks and fills gaps locally. During breakup, spatial drying opens holes and fractus at edges; never crossfade to a separately inserted sheet. Lift to a low-relief, varying-thickness slab with 3D fringe pages. | Broad continuous deck with local thickness and underside variation, visible regional edge, real hole closure and opening. Reject a grey overlay, infinite plane or a wholly replaced Sc sky. `Sc→St` is a coverage/state transition of this one low-layer authority. |
| **Ci** high cirrus | Build parent head paths with `Cloud Shape from Line`/curves and seeded strand emitters at high altitude. In a SOP Solver, emit tagged points/strands continuously from each head; advect each by the shared upper wind plus specified settling, stretch under vertical/horizontal shear and reduce density by age/local drying. `VDB from Particles` with velocity trails plus `Cloud Wispy Noise` creates a thin field; retain older trailing points after the head weakens. | Directional fine fibres, tapering fall streaks, persisting tails and local sublimation gaps; reject flattened Cu or an opaque static bar. Keep this as a thin volume, not screen-space paint. |

The low-layer feedback operator is explicitly `q_next = clamp( Advect(q, W_low, dt) + dt [ S(x,z,t)(1−q) − D(x,z,t)q + κ ∇²q ], 0, 1 )`, with a stable bounded timestep and authored source/dry maps. `q` is a *design control field*, not atmospheric humidity or scientific conservation. This exact operation can be expressed through SOP Solver plus Volume Wrangle and VDB sampling; SideFX documents feedback SOP Solver and voxel-level Volume Wrangle/VDB sampling. `S`/`D` fields are themselves episode tracks, rather than whole-sky alpha. [Solver SOP](https://www.sidefx.com/docs/houdini/nodes/sop/solver.html), [Volume Wrangle](https://www.sidefx.com/docs/houdini/nodes/sop/volumewrangle.html), [VDB from Particles](https://www.sidefx.com/docs/houdini/nodes/sop/vdbfromparticles.html).

## Weather episode construction and consumer handoff

Build each episode in **one Houdini scene** with one clock and wind control. In `FAIR`, stagger Cu births from local source windows with high clear-sky gaps; allow a Ci witness. `BROKEN` carries existing Cu/low-layer IDs while Sc cells form, merge and open gaps. `OVERCAST` continues the same Sc/St layer and increases local source behind a front until coverage connects, with a trailing dry edge revealing holes. `STORM` tracks one Cu parent from base growth through Cb tower and anvil while nearby Sc/St and Ci continue under the same wind profile; an approaching mature Cb can also enter view, but cannot replace the growth witness. A scene may contain several episodes of different absolute start state, but required **within-episode transitions do not reset source IDs**. No hard-coded preset alpha blend stands in for changing support.

The Houdini export manifest records sample times, wind table version, stable IDs, optical domains, layer/source bounds, storm activity/precipitation/lightning **events and support/time seams** (not rain/lightning visuals), field names and units. The Thrum cooker validates density nonnegativity, finite bounds, monotone time, ID continuity, endpoint overlap, conservative majorants and cross-product hash consistency before writing pages. Its import is not an engine weather authority; the source episode owns the weather cause, while rendered pages are one derived view. At runtime, main, independent reflected rays, receiver/within-cloud Sun attenuation, diffuse cloudy irradiance and air/fog integrate the same sampled extinction and authored time. No view may cull a source needed by another consumer. Source-off retains explicit clear/attenuation-only/reflection-only semantics. These are architectural contracts to integrate with C08 and prove, not Houdini features.

**Production package:** retain `.hip`/`.hiplc` master, custom HDA/VEX/Python source, scene input controls/seeds, exact Houdini build/license class, source VDB sequence or an exactly recoverable durable master, cooker version/hash, quantization profile, package manifest, selected runtime pages and native normal/accelerated visual witnesses. Version the small recipe/manifest in Git; before any bulk generation, estimate peak disk, identify a configured LFS/durable location for required masters, and test restoration. Never call an ignored local cache a backup. Stage complete generation, validate all consumers, then change a pinned package ID. This follows [Thrum asset lifecycle](../../ASSET-LIFECYCLE.md). No bulk outputs are created here.

## What primary precedents establish, and what they do not

- **SideFX Houdini 22 tools** establish an available tool vocabulary for cloud shapes, fog VDBs, billowy/wispy detail, voxel edits, feedback and sparse smoke simulation; `File Cache` can write simulation-dependent sequences. They do **not** supply these five recipes, a real atmospheric weather model, the Thrum cooker, or a WebGPU renderer. Houdini's older `Cloud` SOP noise offsets are explicitly a fast non-simulated animation route, unsuitable alone for structural lifecycle. [Cloud modeling](https://www.sidefx.com/docs/houdini/model/cloud.html), [Pyro Solver](https://www.sidefx.com/docs/houdini/nodes/sop/pyrosolver.html), [File Cache](https://www.sidefx.com/docs/houdini/nodes/sop/filecache.html), [Cloud SOP](https://www.sidefx.com/docs/houdini/nodes/sop/cloud.html).
- **Guerrilla Nubis³** explicitly reports fluid-simulation cloud modeling, Houdini/Atlas or Aero solver sources, edit/compositing tools, voxel storage, compressed signed-distance ray acceleration and lighting approximations. In its 2023 SIGGRAPH slides, the voxel-modeling section (roughly slides at PDF lines 473–588) describes growing clouds using fluid simulations then composing them into stored voxel cloudscapes. This supports selecting authored volumetric masters and compact runtime rendering. Its shown storage is a cloudscape and does **not** prove that Thrum's multi-family 10 minute time-varying lifecycle fits its or our budgets. [Guerrilla overview](https://www.guerrilla-games.com/read/nubis-cubed), [SIGGRAPH 2023 slides](https://advances.realtimerendering.com/s2023/Nubis%20Cubed%20%28Advances%202023%29.pdf).
- **IOI Smolder (2026)** describes a shipped integrated real-time volumetric VFX framework coupled to opaque, transparent, volumetric fog and lighting layers. It supports a unified runtime light/composition expectation, not any claimed Houdini source pipeline, cloud lifecycle algorithm or M2/WebGPU timing. Only the official course abstract was inspected; the 30 MiB talk PDF was not downloaded under this task's 5 MiB download limit. [SIGGRAPH 2026 course](https://www.advances.realtimerendering.com/s2026/).
- **EmberGen** officially exports frame-ranged VDB channels and volume processing but not its lighting. It could make animated source volumes, yet it is deliberately not a second toolchain in this baseline. Its documentation does not establish all-five weather-authority/ID logic. [JangaFX VDB export](https://docs.jangafx.com/embergen/pages/references/How-To%20Guides/exportVDB.html).

## Qualification and stop rules

The selected architecture is buildable only after the license/build prerequisite. The first production proof is one Cu episode and one Sc/St changing-coverage episode with real source sequences and common wind, rendered through the **same** runtime optical query in main, independent reflection, receiver shadow and air/fog. Reject if native normal/accelerated motion lacks birth, mature renewal or breakup, if source IDs/support reset, or if consumers disagree at the same world time. Then qualify Cb and Ci, mixed weather, and full skies. Check content disk/page counts before committing to broad variations.

The runtime plan needs an early combined-workload lower bound using real pages, all retained consumers, cold load and transition overlap. If 720p M2 WebGPU cannot plausibly reach the 5 ms cloud / 16 ms total and 512 MiB fixture limits at accepted appearance, revise the page/index/light representation before authoring a large library. Native 3/10 ms is independently qualified. Shadow, reflection, air/fog, family lifecycle and moving quality are never waived by a beautiful still or a fast isolated sample. Experiments may optimize or reject this selected route; they are not an invitation to leave the toolchain or content mechanism unchosen.

The active queue has three foundational content choices still open or over-scoped for the user's now-bounded authoring brief:

1. **Close P1a's tool decision now.** Replace the tool menu (`Houdini/EmberGen/Blender`) with this Houdini 22.0.459 production chain and the license/seat gate. Keep one recoverable sample and appearance/memory checks; do not start a large library. A paid product's unverified seat is a blocked production prerequisite, not grounds to quietly switch to a different authoring model.
2. **Replace required live wind-free-master mapping with baked episode wind.** `CLOUD-MIGRATION` currently requires removing bake wind and applying a runtime affine shear transform, inverse/Jacobian/support qualification, plus a midlife wind-ramp control. That is a defensible *separate responsive-weather profile*, but the user's brief here permits finite authored sequences with shared wind and persistent IDs. In the baseline, bake one common height wind into every family and export the local source anchor poses and exact world-time volumes; consumers query the same world density. Eliminate the P1b affine-warp gate from the critical path, not the requirement for visible height shear and coherent shadows/reflections. Preserve the affine test as optional follow-on if a game later requires arbitrary midlife wind edits.
3. **Replace the required Cu→Cb continuation branch with a single continuous baked cell episode.** The current P1b asks for compatible branch states and a permitted midlife driver change. The commissioned outcome is a tracked cell that genuinely deepens into tower/anvil and decays, amid changing weather. A preauthored same-ID source schedule supplies that outcome without runtime branch switching. Keep branch continuity as an optional control extension, with a separate acceptance gate if requested. Do not use a separate faded disk or a scene preset crossfade.

Corresponding queue edits: P0 reads an authored finite world episode and IDs from the package; P1a verifies the selected Houdini source, optical cook, cadence and storage; P3a/P4a continue as the early unified-consumer and scaling sentinel; P1b proves Cb deepening/anvil from the same baked source and upper wind (the runtime affine-map checkbox moves out of the required path); P5/P6 evaluate the five recipes and four authored weather episodes; P7/P8 retain all complete-sky/device/engine gates. Do not change C08 transport, air/fog, independent reflections, shadow/irradiance, publication, or performance targets. The current plan's frame coefficient interpolation and old/new support union remain mandatory; this baseline adds local pose tracks and an explicit residual-displacement/cadence test.

The essential added production deliverables are a real `.hip`/`.hiplc` recipe with per-family networks, a one-scene common wind/episode control file, VDB and ID/pose tracks, a versioned cooker, recoverable selected masters, a staged package manifest, and watched native motion plus full consumer measurements.
