# CULLING M2 evidence

13 November 2026. Sources: `2303f661098ae49b4d039eb53abadb863db14cda` for the first
Metal, simulator and Chrome runs. `f0bd3851` only makes the integration test's Metal
assertion conditional on macOS; production and benchmark sources are unchanged.
M2 remains `in_progress`; the lead owns the review.

- **M2.1, device selection:** [Metal log](M2/selection.log.gz) passes the prepared-path
  test. Both culled requests resolve to Direct for unknown and indirect-masked records,
  and their readbacks equal the complete Direct image. Supported records prepare the
  requested pipelines. `CullingSelection::resolve` reads only the immutable capability
  record before pipeline preparation. The original scene retains the request, so device
  replacement resolves it against the replacement record. Native frame reports, Chrome's
  report and the simulator witness expose the request, resolved mode and reason. Native
  cube/bucket oracle helpers and the field route assert the prepared mode; Chrome also
  asserts its reported mode and read-back hidden counts.
- **M2.2, iPhone simulator:** [report](M2/simulator.json.gz) records eight progressing
  samples, from 117 to 957 presentations, with requested Occlusion, resolved Direct and
  `MissingIndirectExecution`. Its adapter-read flags lack indirect execution. I inspected
  the [screenshot](M2/simulator.png): the diagnostic cube grid and foreground cubes draw.
  This is simulator function evidence, with no device-speed or cadence claim.
- **M2.3, Chrome mixed meshes:** [oracle](M2/chrome-oracle.json.gz),
  [run identity](M2/chrome-run.json.gz) and [GPU facts](M2/chrome-gpu.json.gz).
  All 16 fixed views at tick zero and 1280×720 match Chrome's bucket-ordered Direct
  exactly for both Frustum and Occlusion. Frustum draws 20,789 of 100,513 slots and
  Occlusion draws 1,369. Actual Wasm SHA-256:
  `ad234c0abf0fed802f3dfe97bc23b8a1b5be72844880ad492fc318379c78ac76`.
- **M2.4, default decision:** [run one](M2/bench-run-1.log.gz) and
  [run two](M2/bench-run-2.log.gz) favour Occlusion in both groups, so the mixed-mesh
  field now defaults to Occlusion on native and Chrome launches. The cube field keeps
  Frustum and the grid keeps Direct; explicit requests remain available.
  [Measurement identity](M2/measurement-identity.json) pins their shared executable and
  source. Each run measures 1,800 ticks after 60 warm-up ticks, at 1920×1080 with shadows,
  rotating the order of all three modes. The view pitches from 0 to 0.6 radians after
  900 measured ticks. Groups use actual counts: behind cover means Occlusion draws at
  most half of Frustum; open means more than half. Both runs have 920 cover and 880 open
  samples, 1,800 non-empty prepasses and 1,065 ticks with hiding. Every row is contended,
  with load recorded per 300-tick segment. Whole GPU includes all timed scene passes,
  including tone, but excludes untimed transfer/query work and physical presentation.
  The open-group gain is small; this is a bounded field result, not a general speed claim.
