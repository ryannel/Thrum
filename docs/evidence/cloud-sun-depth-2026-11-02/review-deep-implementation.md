## Concrete initial findings

**DEEP-R1 — P1: point-only lateral early-clear disagrees with the actual four-curve footprint.** `deepSunTerms` initially returns1 when the query's projected U/V lies outside `raw`, before considering the four neighboring curves. Its admitted path otherwise bilinearly averages branch transmittances at those curves. This creates a boundary discontinuity and violates the complete-footprint outside proof. For aligned512m bounds/grid128, raw half-width258m, padded H275.2m and curve pitch8.6m, the query at x258m uses interior253.7m and clear262.3m curves at half weight. A thick filled slab can give approximatelyT=.5 there. Just outside258m the initial early-clear suddenly returns1, although the same interpolation footprint still reaches the interior curve. Correct by evaluating the outer zero curves inside padded H, and declaring outside clear only where the complete participating footprint is provably outside, or use an equivalent complete-footprint bounds test. Keep lateral total-error qualification separate even after the seam is removed.

**DEEP-R2 — P1: Scene grid and physical packed texture can disagree while compression admits.** JS `configure` only checks format/dimension/minimum3x3x3. WGSL checks grid components positive but does not compare `textureDimensions(deepDensity)` to `[grid.x+2,grid.y+2,ceil(grid.z/4)+2]`. A3cube texture can be accepted with a Scene grid128cube; sampling then uses wrong world-to-physical coordinates/channels yet the resulting monotone curve can still get `compressionValid=1`. An independent mocked `configure` call confirms it accepts3cube without any relation to Scene grid. Correct by checking exact packed shape before any builder source read and making that domain failure visible to queries even before an outside-clear fast path. Since the mutable Scene uniform is the grid authority, JS texture-only checks cannot replace that shader admission. `GPUTexture.depthOrArrayLayers` is the correct actual texture descriptor property used by configure; no issue was found with that getter itself.

**DEEP-R3 — P3: debug schema overwritten by GPU buffer.** `create` assigns human-readable `.metadata` schema, then overwrites that property with the GPU buffer. Root independently identified this. Rename the schema (e.g. `.metadataSchema`) while keeping the actual buffer property/bindings coherent. This is a reporting/API defect, not an image corruption claim.

The author was notified of R1/R2; root already knew R3. Corrections were in progress when this initial review section was written.

## Verified algorithm and assembly properties

- Builder checks the prospective actual endpoint slope against the previous intersection, adds its constraint only on acceptance, commits the previous accepted endpoint on failure and reprocesses the same already-integrated current point. The first endpoint is `(0,0)` and final accepted endpoint is stored. Final-store capacity is counted; overflow marks invalid rather than silently truncating an admitted curve. I found no off-by-one/reprocess/capacity defect in that loop.
- The opaque sentinel delta=-1 disables constraints only when both transformed anchor terms are already<=working epsilon. It does not stop integrating or hide coefficient/tau failures. Ordinary endpoint taus remain nondecreasing and original to the supplied integration curve.
- Working epsilon.004998 plus a labelled nominal2e-6 reserve matches the selected reference's numerical-policy distinction. The eight-term small-r log series truncates positively and its stated real-arithmetic tail is correct. Neither that series nor a reserve proves uniform hardware exp/log/slope/interpolation error. Metadata admission/bounds are expressly compression-only and nominal, not the full .02 result.
- U/V/W projection signs agree with the current Scene: W=-Sun, builder begins at the Sun-facing side, and positive query depth accumulates from that side. Raw support includes the scalar half-cell reconstruction collar. Saturated last-depth constant extension is geometrically justified only by the bounded single-field support; this helper does not establish all-layer/world projection coverage by itself.
- Each curve is interpolated in ordinary tau, then primary/reduced transmittances are formed separately and bilinearly blended. It does not exponentiate bilinearly averaged tau or derive the reduced branch from primary. Whole required tap invalidity invokes the explicit fallback instead of averaging an invalid tap as clear.
- Query bindings11/12 do not collide with the current image Scene/density/errors/bank bindings0/1/2/3/4/5/7 or scatter table/axes/profile8/9/10. The source probe's10/11 are a separate shader/pipeline. Section extraction shares constants/functions without importing the build Scene/texture declarations into the query section. Existing caller Scene ABI is192B.
- Metadata is a32B struct of two vec4f records, not the old16B reservation. Node/metadata buffer byte sizes and query/build minBindingSize agree. The create failure path destroys allocated node/metadata buffers; destroy is idempotent. configure preserves the old binding if creating the new group throws. Caller still owns quiescence, source/Scene/light generation keys, encoding cadence, error reset/readback and device-level lifecycle.
- Direct fallback atomically budgets4096 requests; request4097 and later return a negative sentinel and increment unsupported errors rather than fabricate clear. Invalid direct tau also returns negative. This is safe only if the integrated caller checks all4 counters and rejects the entire unsupported graph; current helper alone cannot enforce that. `tauDirect` is finite512-step single-field integration, not an already-qualified full .02 or complete finite-footprint oracle. A fallback may be the right refinement path, but its quadrature/footprint error remains separate.
