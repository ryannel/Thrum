## Remaining contract clarifications

1. **GPU visual-state recovery is still underspecified as a bounded guarantee.** The baseline saves recipe/seed, weather commands/state and update count, plus an *optional* visual checkpoint, while disallowing unbounded replay from world start. CLOUD-PROVIDERS says re-enable reconstructs from an admitted checkpoint/forcing and device recovery may report progress/unavailable. Those statements need one explicit selectable policy: either (a) pin a compatible CPU/durable checkpoint with a maximum replay interval and counted capture/storage/restore peak, or (b) declare visual cloud reset on restore/seek as an admitted discontinuity, with a new source epoch, invalidated light/environment/reflection/history, visible recovery status and a bounded time-to-useful-source target. A checkpoint existing only in lost GPU memory cannot recover after device loss. The provider can choose per profile; the contract must reject a profile promising continuity without a recoverable closure. This does not require bit-identical GPU replay or cross-provider state conversion.
2. **Headless cloud attenuation needs a precise capability split.** The GPU q design is valid for visual optics; C08 requires headless physical irradiance/thermal to use an E1 provider and shared source facts rather than rendered pixels. CLOUD-PROVIDERS says headless visibility never needs q readback, but the meaning of “visibility” could be confused with cloud optical attenuation. State that gameplay visibility facts and physical thermal/cloud-irradiance queries use an explicitly selected CPU/analytic E1 approximation or are unsupported, with its relation/error versus visual q declared. If a headless profile specifically requires cloud shadow or radiative attenuation, F2 must bind a headless capable provider (for example the independent 2D attenuation source) and must not interpret absent GPU q as clear. This avoids making every visual voxel a CPU authority and preserves one weather cause owner.
3. **Source time and lease publication should stay explicit in the eventual API.** The design already names a complete source/occupancy snapshot before readers, actual prior sample time, product leases, device epochs and fenced retirement. The implementation contract should pin the WeatherFrame revision used by each q update, the corresponding SourceSnapshot/light-cache generation, and a single publication boundary for all retained consumers. Old-generation GPU work can finish but cannot publish current handles; a missed deadline reports old time/unavailable. This is an implementation precision item, not a reason to reopen the model or demand hot swap.

## Scope verdict

The revised atmosphere map now accounts for the complete *interaction* without claiming the cloud commission implements rain particles, lightning bolts/thunder, night stars/Moon, water dynamics, persistent wetness or gameplay effects. The selected GPU q is a derived optical state under E1 CPU weather and wind; this is compatible with C09 if the headless physical/semantic substitutions above are made explicit. Full 3D and shadow-only 2D are compatible only with their declared profiles. The remaining recovery and headless-query wording is actionable design closure; no new meteorological feature or competing full-sky implementation is required.

## Final delta verification after contract and queue revision

Read the later revisions of `CLOUD-PROVIDERS.md`, `CLOUD-PRODUCTION-BASELINE.md`, `CLOUD-MIGRATION.md`, `CLOUD-PROOF-ACCEPTANCE.md`, `CLOUD-PERFORMANCE.md` and `CLOUD-CAPABILITIES.md`. This pass still makes no implementation, image or device claim.

- **Recovery finding closed in design.** The default `reset-optics` policy now explicitly preserves CPU weather/event identity while starting a new optical epoch after discarded all-off state, device loss or incompatible seek. It initializes from current seeded controls, invalidates optical products/histories and reports unavailable/progress without claiming uninterrupted material continuity. `continuous-optics` retains update work and requires completed recoverable q/carrier checkpoints at intervals of at most 60 source seconds and bounded forcing history of at most 60 seconds; missed capacity is unavailable or rejects continuity. Asynchronous capture, durable chunks, staging and load work are charged. This is a valid choice of guarantees; no universal hot migration or bitwise GPU replay is needed. Qualification must still measure recovery latency and retention/peak on an actual host.
- **Headless finding closed in design.** The documents distinguish CPU E1 weather/causes and gameplay visibility from a headless physical cloud optical-depth request. The latter selects a CPU/analytic coefficient provider with accuracy/cost, rather than reading GPU q or treating weather potential as transmittance. This permits GPU q to remain derived visual optical state under C09. F2 must reject the headless optical request if that provider is absent.
- **Source-time/lease finding closed in design.** Each `SourceSnapshot` records the actual WeatherFrame revision, source tick and presentation interpolation interval. `FrameOptics` and leases bind those revisions. The baseline specifies complete source/occupancy publication before readers and one retained source interval for every optical view. Old work cannot be relabelled as the latest tick. Correctness/device proof remains unrun.
- **G5 sequence closed in the active queue.** P0 validates full versus independent shadow-only setup; P1a forces live Cu source response to changed wind/shear and a new drying/lift front after development begins; P3a binds same-source main, mirror, receiver and environment; P4a combines two live cells/layers, clear air, fog, hidden-main perturbation, offscreen blocker and cause stubs *before* representative families and the full variant library. P1b then checks Cb, Sc/St and Ci source regimes before format/library freeze. P6 expands to four weather stories and reset/continuous recovery. This order exercises the least-established runtime/cross-consumer claim early and does not require building three competing full systems.

**Minor acceptance-text mismatch:** `CLOUD-MIGRATION.md` P4a and `CLOUD-PROVIDERS.md` require two live cells/layers, hidden-main wind/drying perturbation and rain/lightning cause receipts. The `CLOUD-PROOF-ACCEPTANCE.md` P4a table row still describes one renewing Cu and does not explicitly list the hidden-main perturbation or cause IDs. Make that row match the queue before freezing P4a's proof card; otherwise a narrower POC could be marked done. This is document alignment, not an unresolved atmosphere architecture.

**Final design verdict:** G1–G7 now have an adequate written direction at this commission stage, with the P4a acceptance wording above the only remaining bounded correction found in this read. The plan continues to label actual family visuals, continuous runtime behavior, coupled optics, complete workload, engine integration and device admission unproven. The whole-atmosphere map continues to state rain/lightning presentation, Moon/stars, water, wetness, audio and gameplay effects as neighbouring implementations with required typed seams, not delivered cloud features.
