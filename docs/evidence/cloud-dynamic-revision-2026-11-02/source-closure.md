## Assessment

The integrated default is directionally sound for the revised commission: a production-supported 3D optical/render shell; repo-native reusable detail inputs; fixed-tick, weather-driven optical controls; spatial source/loss; distinct warm/ice morphology; common time/source queries for light, fog, shadows and reflections; and explicit unrun visual/device gates. The exact positive reaction is a good correction to an Euler source/loss update. These are **design statements**, not demonstrated clouds.

Four causal contracts remain underdefined enough that an implementer could build a cloud that never forms, an anvil that appears by an unstated source, or a provider that cannot recover its visual state. Close them in the governing source specification before treating the pilot as build-ready. They do not require a physical meteorology solver.

### S1 — Activate empty source support before occupancy work (foundational)

The source currently updates sparse 3D bricks and counts work against active physical voxels, but it does not define how a front or new emitter allocates a region where all previous `q_l=q_i=0`. An occupancy-driven worklist alone would never evaluate `S>0` there. A conservative **prospective source-support producer** must run from E1 front/emitter/strand controls and recipe bounds before each fixed source step. Its worklist is the union of (a) old occupied support swept by the backtrace and erosion/detail halo, (b) all cells/bricks where `S_l` or `S_i` can become positive during this step, including an empty Cu seed or Ci head, (c) cap/outflow destinations, and (d) neighboring donor/limiter/guard support. Source-support bounds must cover the full step and chart/region boundary exchange; zero occupancy is not proof of zero future source. If admission/capacity fails, publish unavailable/missed current source rather than silently suppressing births. This operator is necessary to prove clear→scattered and live front response.

A minimal test starts from a completely clear allocated state, moves a new moist/lift front into an unallocated world region, and requires a new same-time 3D source plus receiver/reflection response. A second test moves the source across a tile/chart edge with no clipped, duplicated or delayed cloud.

### S2 — Close the Cb cap-to-anvil producer and centerline velocity (foundational)

The baseline names `u_z=w_core*fade_below_cap` and `u_h=W_h+v_out*r_hat*radial_falloff` above a detrainment band, then says a liquid amount is partitioned into ice. This leaves a possible zero-flux gap: if upward motion has faded before material reaches the upper outflow, no source actually populates the anvil. It also leaves `r_hat` undefined on the tower centerline unless `radial_falloff(r)=O(r)` as `r→0`. Semi-Lagrangian advection through a divergent field is not conservative, so the words “matching subtraction/addition” do not by themselves balance deposited optical proxy across the cap.

Specify a single overlapping cap band `B=[z_c-δ,z_c+δ]` where `u_z>0` at its lower entry, smoothly decreases across B, and radial outflow grows continuously while source material is present. Use a regular vector form such as `u_out=α B(z)(x_h-x_core) f(r)` with bounded `f(0)`, and define the phase transfer on the *same advected cap-band state*: `Δ = min(q_l, k_ice Δt χ_B q_l)`; `q_l←q_l-Δ`, `q_i←q_i+g(Δ)` with an explicit shared optical-unit rule. If lateral expansion needs an independent detrainment source beyond transported q, define its paired removal from the tower and deposit into upper cells with a kernel whose weights sum to one. Apply loss only after this transfer according to a declared order. Mark the transferred source's support and IDs for light/history invalidation. A broad anvil then follows continued tower flux, wind/shear and upper loss, not an inserted disk or phase label. Check a core that reaches the cap, a weak core that never does, a stalled core, a moving/sheared cap and post-core anvil persistence.

### S3 — Define `q_cap` and phase units with the exact reaction (necessary math clarification)

With `q_adv≥0`, `S,D≥0`, `q_cap≥0` and `k=S+D`, the selected update is positive and tends to `S q_cap/k` for fixed coefficients; when `k=0`, `q_next=q_adv`. The text should explicitly name `q_adv` as the **limited corrected MacCormack value** (or first-order fallback), not an unbounded provisional value. It should define `q_cap` as a bounded local *source equilibrium capacity* for `q`, not a hard spatial clipping mask. In particular `q_cap=0` must suppress new source while incoming advected q survives until `D` removes it; hard-clipping q to q_cap would make a weather front cut a cloud instantly. If q is normalized to `[0,1]`, state the clamp of `q_adv`, `q_cap` and final q to that range and guard the `k→0` evaluation numerically (e.g. `expm1`). The exact formula assumes frozen S/D/q_cap within the substep; changing E1 controls are sampled/interpolated at the named substep time.

The two RG16F channels are called optical proxies, while liquid/ice use class-dependent calibration. Equal numeric subtraction/addition preserves `q_l+q_i` only if both q channels share the same extinction-equivalent unit. Choose and state that common unit, or use `g(Δ)=κ_l Δ/κ_i` so the intended optical quantity partitions once. If changing phase intentionally changes total extinction, state the allowed conversion rule and resulting optical gain/loss explicitly. This prevents a Cb cap/anvil double count or an unexplained brightness jump, without claiming physical mass conservation.

### S4 — Guarantee bounded visual-state recovery, especially after all-off (foundational)

`q` is history-dependent. Current weather fields, seed and fixed update count do not reconstruct its current value unless the complete earlier forcing/time path is available and replayed. The baseline calls a visual checkpoint “optional” and rejects an unbounded log/full-world replay, while the provider contract retires all visual updates/pages when no optical consumer remains and promises restoration. These conditions do not yet name a guaranteed producer of a current source after a long all-off interval, device loss or seek.

Select an explicit admissible recovery policy: for ordinary save/device recovery, a **mandatory recoverable visual checkpoint** with exact source/recipe/format/world epoch and a bounded forcing segment from its time to the target; bound both retained bytes and replay steps/latency. If checkpoint creation fails, the provider must report visual state unavailable or enter a declared new visual epoch/reset policy; it cannot claim seamless continuation. For all-off, either retain a compact source state/advance it at a stated cheap cadence while expensive optical products retire, or accept a declared restoration interval and appearance discontinuity with history invalidation. If continuity of existing formations is required after all-off, the latter cannot silently count as a pass. A GPU readback can be asynchronous, but a save/seek cannot complete with a checkpoint that is only queued and may be lost on device failure. CPU E1 causes and rain/lightning remain independent and do not wait for this visual checkpoint.

A proof should run a cloud through mature renewal, turn all optical consumers off for many source times while weather changes, then restore and compare source IDs/shape/time against a continuously updated oracle; repeat with device loss, failed checkpoint and a seek. Record bytes and time to first compatible current source. No held old frame may acquire a new timestamp.

## Smaller source-readiness notes

- **Material/rest coordinates:** the source says detail uses advected material/rest coordinates, but the state/update/storage of those coordinates is not yet fixed. Choose a concrete near-field carrier or bounded analytic flow map, and charge its channels/scratch/correspondence. Otherwise a shared `q` can evolve while detail visibly slides across it or prior-view history invents motion. This belongs with P1 native motion, not a later renderer polish pass.
- **Headless visibility:** `CLOUD-PROVIDERS.md` says CPU E1 causes and “headless visibility” do not need GPU pixels. Define whether that is an authored weather visibility field or actual cloud optical `tau/T`. If the latter is required for gameplay/headless queries, it needs a CPU/coarse source producer and an error/domain contract; the GPU visual state alone cannot supply it without readback. Do not silently equate the two.
- **Source/cache timing:** fixed 1 s E1 controls and 0.25 s source steps are compatible if each source step samples the committed E1 trajectory at its own world time. The cache key must include actual source tick/revision and old/new swept support. The plan already calls for this; the first coupled test should confirm offscreen front changes update Sun, fog/air, ambient, environment and independent reflection rather than only the main view.
- **Cost qualification:** the 2M-voxel×4B×5=40 MiB example is correct planning arithmetic for base storage/scratch, with the named omitted lifetimes. It is not an M2 pass. The earlier one-Cu M3 17.075 ms p95 is adverse for its old graph only. Neither unrun native beauty nor unrun budget is classified here as a plan-level mathematical defect.

None calls for Houdini, baked lifecycles, a parcel solver or a full meteorological simulation.
