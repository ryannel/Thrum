# Dynamic cloud source review — initial independent recommendation

2 November 2026. **D0, saved before reading `CLOUD-PRODUCTION-BASELINE.md`, `CLOUDS.md`, or `CLOUD-MIGRATION.md`.** Scope: written source/model review, not a runtime implementation, measured performance claim, or user acceptance. I had seen their titles and a short baseline summary in the retained research index; this is independent selection against the commission and external source methods, not blind discovery.

## Selected target

**Select a live, weather-driven hybrid density producer:** use the production-proven Nubis/Unreal *runtime volumetric density/control and ray-marched optical architecture* as the rendering shell, but make the authoritative changing cloud matter a bounded moist-state simulation rather than a scrolling/static weather-mask evaluation. Use the published Goswami–Neyret parcel model for individual convective cores and the published Stormscapes warm-cloud advection/phase/buoyancy mechanism as the basis for a reduced, layered grid for Sc/St and background weather. Both feed one optical extinction contract with procedural detail in the Nubis sense. Cb uses the same live convective state plus explicit anvil detrainment; Ci uses a distinct high-altitude ice tracer/filament state. This is one proposed runtime *hybrid* source architecture with interchangeable producers at the optical-field seam, not a claim that any one publication shipped this complete combination.

The production support is for the runtime density/material/lighting/control shell, not for five-family local lifecycle simulation. Guerrilla's Nubis decks and Epic's Volumetric Cloud documentation support dynamic parameterized cloud density, weather/type controls, volume materials, ray marching, shadows and reflected/environment consumers. The 2017 Nubis notes explicitly limit ordinary motion to detail and weather-state changes; the user-visible local matter source below is a Thrum integration of published simulations. Stormscapes demonstrates interactive warm-cloud formation and transitions (Cu, Sc, St, Cb) over a large domain, but its reported interactive platform is not M2 browser evidence and it excludes cirrus ice. Goswami–Neyret demonstrates real-time landscape convective parcels with entrainment/detrainment and volumetric amplification, but not layered and ice families. This distinction governs every claim below.

### State, controls and operators

At weather tick `n`, E1 owns spatial/time-dependent ambient fields `A(x,z,t) = {T_a,p_a,q_v,a,u,u_z, uplift, inversion, ice-supersaturation, frontal lift}` and authored front trajectories. These are declared atmospheric drivers (units, support, interpolation, validity), not a cloud image, weather label, or prerecorded episode. A front changes humidity, lift and height wind locally while existing condensate keeps its identity. The cloud source owns fixed-step, stable-ID active parcels/columns and shallow layer grids with vapor, liquid and ice amounts; V3 only reads an immutable optical snapshot at a named source time. Authoring supplies boundary/forcing trajectories and parameter ranges, not complete lifecycle frames. Steady fair conditions must still drive a birth/renewal/death balance.

**Convective Cu/Cb.** A lifted source region injects parcels at cloud base when environmental vapor and lift yield saturation. Each parcel has `x,v,m,T,q_v,q_l` and a compact neighbor grid. At each fixed step, sample ambient `A`; apply the published parcel pressure, drag, buoyancy and entrainment/detrainment/mixing operators, then condensation/evaporation against `q_sat(T,p)`. In reduced notation, `d q_l/dt = C(q_v-q_sat,T,p) - E(q_sat-q_v,T,p) - P`, `d q_v/dt = -C+E+mix`, and `d v_z/dt = g(ρ_a-ρ_p)/ρ_a + pressure/drag`. Existing condensate is advected and evaporates under changed ambient air; new saturated parcels continuously add lobes. The optical base field deposits each parcel's liquid amount with a mass-normalized kernel of its current radius and uses conservatively bounded procedural edge detail, never using detail animation as the lifecycle source. Merge/split of connected occupied components follows overlapping/rising parcels and localized evaporation; neither an age scalar nor whole-volume opacity fade counts as local breakup. The specific closure rates, nucleation distribution, kernel/detail mapping and parcel count are **Thrum design choices requiring proof**, not claimed exact equations or production values from Goswami–Neyret.

For **Cb**, a sustained strong source drives buoyant cores upward into a stable/inversion cap. Near level of neutral buoyancy, the source diverts/detrains liquid/ice into a thin horizontally advected anvil reservoir; the horizontal wind shear spreads the outflow, an ice-rich rim tapers through sublimation/precipitation sinks, and continued core births renew the tower below it. Overshooting tops require transient core momentum above the cap, not an added stationary dome. The anvil reservoir has `∂q_i/∂t + ∇·(u_h q_i) = D_i(core,cap) - S_i(ambient) - P_i`, with bounded positivity and source/sink accounting. Stormscapes supports inversion-limited anvil formation in warm-cloud simulation; the ice tracer, exact cap transfer and optical mapping are necessary Thrum extensions. Do not claim a cloud's darkness emits rain or lightning; E1 receives typed precipitation/electrical event seams from source diagnostics, with later owners deciding those phenomena.

**Sc/St.** A shallow 2.5D layer carries vapor/liquid (and vertical class profile) under Stormscapes-style advection, phase exchange and buoyancy/entrainment reduced to a shallow layer. `∂q_l/∂t+∇_h·(u_h q_l)=C(q_v,T,p,uplift)-E(q_l,ambient)-P + D_h∇²q_l` is the explicit scalar closure; humidity/lift fronts add local cloud, dry intrusions erode openings, and advection carries existing banks. Sc has cellular/roll-varying lift and a bounded, uneven top/base profile, so cells coalesce and break while retaining low-bank identity. St uses broad, low-gradient condensation and a coherent sheet; erosion opens transparent gaps and redevelopment fills them without detached puffs. A coarse field and structured, materially advected detail share the same source time, and fine detail only refines an occupied base field. The reduced 2.5D projection and cell forcing are authored extensions, not a demonstrated Stormscapes performance reduction.

**Ci.** A separate high-level ice amount `q_i(x_h,z,t)` is emitted where high-altitude supersaturation/frontal lift or Cb detrainment supplies ice, advected by height-dependent wind and stretched by shear. Positive deposition at filament tips and sublimation/dispersion behind them create new, tapered wisps and broken tails; a bounded anisotropic filament basis supplies shape while amplitude comes from live ice. Anvil-generated Ci inherits its source identity and time; independent Ci can form under a high front. `∂q_i/∂t+∇·(u q_i)=N_i(supersaturation,lift)+D_i(Cb)-S_i-P_i`. The ice mechanism is a necessary authored extension: Stormscapes excludes cirrus and neither a static cirrus texture nor noise scroll proves it.

At each render sample, producers provide nonnegative `σ_t(x,t)` plus material class/phase and conservative occupancy; shared extinction is derived from condensate and class-specific optical conversion, with detail constrained to preserve occupied support and finite optical depth. One optical time/snapshot feeds primary view, direct Sun/sky attenuation, cloud-to-scene and cloud-to-air/fog shadows, environmental light, mirror and rough/water reflections. V3 integrates overlapping media in depth order and supplies scene-linear `(T,S)` under a declared light closure; no cloud screen overlay becomes a second authority. Consumers can choose sampled/cached fidelity and independent update cadence, but must name source time, error/freshness and invalidation from changed matter/front/Sun/view. Topology change invalidates motion/history locally rather than inventing correspondence. Disable the visual provider without retaining its GPU work; E1 can still publish required semantic weather drivers.

### Why this model, and what is not selected

The deciding requirement is **local matter creation, renewal, deformation and destruction under changing weather**, observed in both close cloud and full sky. A live moist state is a defensible causal source for this; a prepared full-density sequence cannot react to arbitrary runtime fronts and wind without a new retiming/transport mechanism. A pure Nubis/Unreal weather map is production practical and remains the optical/control shell, but its public evolution method does not establish local structural lifecycle. A full Stormscapes 3D grid is the strongest published all-warm-family dynamic alternative, yet its all-domain update/residency and browser cost have no demonstrated fit to M2, and it still omits ice. A parcel-only solution is efficient for Cu/Cb and has explicit entrainment, but its own paper does not establish St/Sc/Ci. Procedural Cloudscapes (2018) offers weather-aware continuous density morphing and useful family authoring, yet its keyframe/optimal-transport route does not replace live causal growth under arbitrary weather changes. A reduced layered-grid + parcel + ice state is therefore selected provisionally. A provider can be replaced at the optical seam if it fails, while consumers keep shared transport semantics.

### Cost hypothesis and proof order

No figure here is a measured pass. The M2 browser fixture's proposed targets are p95 cloud GPU ≤5 ms, full GPU ≤16 ms and process peak ≤512 MiB, with all consumers active. Limit authoritative updates to occupied regional cells/parcels at a fixed lower frequency than rendering; keep stable packed IDs, dirty bounds and reusable storage. Render a shared current optical representation once per source tick/revision, with footprint LOD and conservative occupancy; avoid re-evaluating parcel/light operators per ray or per view. Dirty propagation covers old/new swept support and all Sun-shadow influence. Budget includes layered fields, parcel neighbor work, source raster/update, cloud light, view rays, cloud receiver shadows, fog/air, environment/reflection, histories, uploads, CPU/JS/Wasm heaps and device recovery overlap. Regional/LOD reductions are admissible only if they preserve the defining lifecycle and all required consumers. Full 3D moist-grid reference and direct density/light evaluation remain correctness oracles for the reduced source; no assumed speedup substitutes for measurement.

Prove in dependency order: (1) Cu local source: births during a mature steady interval, same-ID local renewal and breakup under a moving dry front, direct optical snapshots at normal and accelerated time; (2) Cb cap/anvil and Ci ice source including shear reversal, independent Ci; (3) Sc/St sheet/cell transitions; (4) five-family shared Sun/air/fog/shadow/reflection witnesses and clear→broken→overcast→storm; (5) full fixture cold/warm/burst cost and M2 device admission. A false solution based on moving noise, whole-cloud scale/opacity or a finite clip must fail component-topology and source-response checks even if stills look plausible. A pass in this worktree cannot be inferred from the papers.

## Final recommendation after challenge

Retain D0's **live moist-state hybrid**, with a stronger explicit 3D visual rule: near and oblique warm clouds are queried from a **runtime-generated sparse 3D optical field**, not the 2.5D Sc/St state or parcel kernels alone. Parcels and shallow layer grids are *controls and coarse dynamics*; their local liquid/ice is deposited into 3D occupied tiles and shaped by material-following volumetric detail, in the production Nubis³ spirit of base morphology plus up-resolution. Cb tower, cap, overshoot and anvil remain 3D at every view where their thickness/parallax matters. A 2.5D/column representation is only an admitted far or broad layer control/LOD whose projected optical depth and silhouettes are qualified against the same 3D source. Do not call it a visual equivalent to Nubis³ prepared cubic clouds.

The exact **3D density construction** must be selected before implementation: (a) deposit nonnegative phase water from active parcels/layer cells into occupied world-anchored bricks at named time; (b) use a bounded, materially advected 3D morphology field to displace/erode the isodensity edge while preserving a separate conservative support bound and nonnegative phase totals; (c) make source/loss visible by updating coarse matter before detail, so a dry-front breakup removes occupied connected components rather than merely shifting noise; (d) carry material coordinates and explicit birth/death/reactive masks for motion history; (e) generate a stable hierarchy of scales, with broad coherent body, intermediate lobes/rolls and fine turbulent edge, selected against actual photographic/motion references. The procedural detail may be precomputed as a stationary *basis* texture, but the cloud's complete frame sequence is never baked. This is an authored Thrum morphology/up-rez extension, not a claimed recovered Nubis³ algorithm. The old Q1 detailed source had faint birth, frozen maturity and rounded late remnants; the later surface hierarchy was rejected visually. Thus the previous appearance result directly warns against treating parcel kernels plus noise as accepted morphology. The earliest Cu proof must first show native close/oblique shape and mature renewal under live controls. If it fails, revise the 3D source, not the light or reconstruction to mask it.

A published **full 3D Stormscapes warm solver** is the strongest whole-source alternative, including Cu/Sc/St/Cb dynamics and inversion behavior. I do not select an all-sky 3D grid for the browser baseline: the proof concerns interactive simulation on its published hardware, while the required full-sky source/light/view/reflection graph and M2 browser memory/5 ms allocation have no such demonstration. Its operators and 3D reference scenes should challenge the reduced hybrid. This choice prioritizes visual success by preserving genuine 3D near morphology and early native visual rejection, while bounding the dynamic work to active regions. If the reduced source cannot make credible 3D Cu/Cb/Sc/St under the required weather variation, the founding approximation fails; a full 3D warm solver is then the specific revision candidate, with explicit cost requalification. That is a rejection path, not an open-ended menu or permission to ship weak visuals.

# D2 — superseding recommendation after visual-first challenge

The D0/D1 moist parcel + reduced thermodynamic layer choice above is **superseded as the default**. The user relaxed physical fidelity and prioritizes a credible, critically acclaimed *visible* atmosphere that changes under live weather. A parcel-neighbor/phase/thermodynamic solver adds an unproven browser dependency and does not itself solve the earlier rounded/frozen Cu appearance failure. Keep Goswami–Neyret and Stormscapes as scientific/reference challengers, not critical-path packages or required physics. The final recommendation is a **native, reproducible, sparse 3D optical-control field with live authored advection, local source and loss**, sampled through a Nubis³-style 3D density/up-rez renderer. Its runtime lifecycle operator is a **Thrum extension**; production support covers the voxel/procedural morphology, weather control, optical sampling, lighting/consumer architecture, not our exact dynamic field update. This is one target, with an early falsification gate for visual morphology and cost.

## Runtime source in executable terms

**Authoritative inputs.** At a fixed world tick, E1 publishes regional weather `W(X,z,t)={coverage, moist-potential, uplift, drying, wind_h(z), shear, cap-height, frontal convergence, high-ice-potential}` in world metres/seconds, plus persistent front IDs and interpolation validity. These are authored/game-driven scalar/vector controls, *not* meteorological vapor/temperature or a sky preset. CPU packed, reproducible controls and stable source IDs are saved/replayed. The cloud module owns one visual source state per active sparse world region: bounded liquid-control `q_l∈[0,1]`, ice-control `q_i∈[0,1]`, source activation `a∈[0,1]` and validity/support; all are 3D at the admitted near fidelity. A same-time immutable snapshot/lease is published to V3. Optical controls are not physical water masses; no conservation or rain-flux claim follows.

**One selected update operator.** On occupied 3D bricks plus a conservative growth halo, construct velocity `v(X,t)=wind_h(z,t)+v_local` and backtrace `X_b=X-Δt v(X,t)` through the previous snapshot. Use bounded MacCormack-corrected semi-Lagrangian advection with local extrema clamping (or revert to the first-order traced value where correction violates bounds/enters unknown support), following [Selle et al.'s author paper](https://physbam.stanford.edu/~fedkiw/papers/stanford2006-09.pdf). Then update each phase control by

`q_j^{n+1}=clamp(A_v(q_j^n)(X)+Δt[S_j(X,W,a,n)(1-A_v(q_j^n)(X))-D_j(X,W,q_j^n,n) A_v(q_j^n)(X)+κ_j∇² A_v(q_j^n)(X)],0,1)`.

`A_v` is that selected advection operator; `S_j,D_j≥0` are spatially local, world-time functions; diffusion is bounded/explicit only within a named stability range. Source is inhibited where the same phase is full, preserving bounded controls. A dry front raises `D` only over its moving support; cloud vanishes locally and holes open. The source activation field `a` is itself advected and relaxes toward a deterministic, band-limited, weather/seed-controlled spatial lift pattern: `a' = clamp(A_v(a)+Δt k_a(a_target(W,seed,X,t)-A_v(a)),0,1)`. `a_target` evolves by translating/deforming seeded regional 3D noise and staggered local activation knots; it is not a whole-cloud age value or finite frame track. The exact fixed tick, field resolution, coefficients and knot scales are design inputs to qualify, not a missing choice of governing operator. `q_l/q_i` can exchange at the Cb cap by an explicit partition transfer; absent transfer, they are independent source fields.

**Native 3D morphology.** Initialize and refresh `a_target` from deterministic generated 3D band-limited basis volumes (low-frequency Perlin/Worley-type body, independent intermediate lobe/roll, high-frequency erosion/filament bands), genus height profiles and region/control seeds. Retain their generator source, seeds, versions and hashes in the repository; the basis is reusable and compact, with no baked complete cloud lifecycle. At each source time, a low/mid-frequency 3D `q` field represents actual broad occupied structure; a material-following 3D detail coordinate/field refines *that* density only near occupied edges. A single density query is `σ_t=κ_l R_l(q_l,N_l,z,footprint)+κ_i R_i(q_i,N_i,z,footprint)`, with `R_j(0,...)=0`, `R_j≥0`, conservative occupancy enclosing any detail expansion and separate liquid/ice fractions. `R` uses smooth thresholded/warped 3D bands rather than a sum of round distance kernels. Different bands have controlled world metre wavelengths; high frequency never creates isolated condensate outside the coarse support. Detail is advected with the same named velocity/material clock or its correspondence is invalidated; arbitrary UV scroll over stationary `q` is not credited as growth. This construction is proposed, **not visually accepted**: the previous rejected hierarchy warns that plausible rules can still yield poor Cu. An early native close/oblique, normal/accelerated movie decides it before population work.

**Cu, including maturity and breakup.** Regional low-altitude moist potential and local uplift seed separate, uneven source activation maxima under a stable formation ID. `v_local,z=U(x_h,t) B_base(z) B_cap(z)` lifts existing 3D liquid; `S_l` injects at saturated-looking lower/side source bands and renews rising heads under active maxima; `D_l` increases on entraining flanks, in downdraft pockets and as the moving dry front passes. For a mature Cu, several updraft maxima continue to source new connected billows while older lobes advect upward/downwind and erode, with persistent base/body and changing topology. Changing wind bends/shears the same body; a subsequent dry front removes local lobes before the whole event dies. The source pattern is a continuous 3D field with changing lift maxima and base-to-head transport, **not** ellipsoid cohorts summed into balls, a global scale ramp, a density fade or detail-only pseudomotion. The Cu acceptance witness must track at least two simultaneous local births and losses under one identity, then connected-component merge/split and irregular edge change at normal speed.

**Cb tower, overshoot and anvil.** A Cb uses stronger sustained `U`, multiple neighboring source maxima, and a height cap `z_c(X,t)` from E1. Below the cap, vertical transport and localized replenishment grow a connected 3D tower. A compact updraft-momentum control `m` relaxes under cap damping, so only strong cores overshoot transiently: `m'=clamp(m+Δt(force_up-λ_cap m),0,m_max)`, `v_z∝m` above `z_c` until decay. At the cap, remove a bounded fraction of the *arriving upward* liquid control flux and deposit the same optical-control contribution into a thin, irregular upper ice/anvil source band: `F_cap = k_cap max(v_z,0) q_l|_{z_c^-}` with explicit liquid decrement/ice increment (partition, not duplicate density). Upper `q_i` uses the same 3D advection/source/loss operator with height shear, lateral divergence from the core and anisotropic spreading along the local wind; source stays tied to current tower flux. Filamentary 3D detail and uneven source knots break the rim; dry upper air raises local loss. When the updraft weakens, the tower contracts while the already released anvil persists, spreads and thins at a different rate. A static disk glued atop a tower fails. The term *ice* here denotes optical class/transfer, not physically solved microphysics.

**Sc and St.** Each is a **connected, shallow 3D regional field**, not repeated cloud actors. `v_local,z` is weak and bounded; `q_l` occupies a finite height interval with a genus vertical profile. Sc's `a_target` has coherent cellular/roll bands of varied size/orientation plus broad shared banks; local source/loss opens, closes and shifts gaps while rounded tops form above a connected low base. St has a lower spectral bandwidth, a largely continuous sheet and subtle uneven thickness/base; localized drying opens tears, moist-front source refills them, and the sheet's edge advances coherently. Neither is a grey alpha overlay or a puff ceiling. A 2D weather field drives where sources occur; the 3D field supplies actual thickness/parallax and evolving shape. Far 2.5D/column LOD is admitted only after comparing optical depth, gaps and silhouettes to this same 3D source from the required angles.

**Ci.** High-ice potential/front shear spawns persistent **head/strand controls** with stable IDs, position, tangent and width. They are advected by `wind_h(z)` and different heights separate under shear. Each live head emits a narrow 3D ice source ribbon along its recent trajectory, with irregular spatial source variation; old portions thin by local sublimation/dispersion loss and lateral anisotropic diffusion. In terms of the common update, `S_i` is supported around current strand heads and recent trails, `D_i` rises with age/dry high air, and `v` includes fall/shear. New heads can form while older tails vanish; Cb anvil strands can supply heads but independent Ci does not require a storm. An age-dependent loss is local to emitted strands, not a whole-Ci opacity fade. A static high texture with moving UVs or beaded curves fails the motion witness.

**Consumers and causality.** Source publication carries `(world epoch, tick/time, source/control revision, region, support, phase, quality/error)` and a current/previous valid material mapping only where topology survived. The same `σ_t` time and liquid/ice interpretation serve main and independent reflected rays, Sun/receiver shadows, clouded air/fog, environment/ambient capture and any optical query. V3 retains the existing air LUT, joint overlapping-media transport and scene-linear light semantics. Main-hidden must not suppress shadow/environment work; source-off must release its visual allocations while E1 weather remains available. Every changed brick, including offscreen Cb or newly opened Sc hole, dirties its swept old/new support plus Sun/ambient/reflection influence before a cached product can claim current time. Update source once, then derive all consumers; no extra runtime wind in individual shaders. Prior-view reprojection invalidates locally at births/losses and globally on cut/epoch/quality incompatibility.

## Bounded cost account and rejection

The structure is viable only if sparse state is bounded by *occupied regional 3D tiles*, not one high-resolution cube per named event. One 64³ `R16F` channel is 0.5 MiB before guards/mips; 512 such per-event fields are 256 MiB **for one generation/channel**, already incompatible with the source pool. For a planning arithmetic example, 16 near 64³ liquid tiles with current+previous cost 16 MiB; 512 far 16³ scalar tiles with current+previous cost 8 MiB. A second phase/detail/velocity field, guards, mips, Sc/St regional coverage, Cb anisotropic tiles, CPU recovery and old/new leases multiply this; the example is *not* an allocation promise or sufficient visual density. Use regional shared tiles for connected decks, coarse far 3D LOD and high-detail bricks only where projected footprint or oblique parallax demands. A coherent far summary must be derived from the same source state and carry error/freshness; do not invent distant clouds per camera. GPU compute updates only dirty/occupied tiles at a fixed source cadence; rendering may interpolate a valid source pair or require fresh samples for births/cuts. CPU packed E1 controls are small and fixed-tick; a CPU reference evaluates exact selected source rules for conformance, but high-resolution source work is not on the main JS input thread. No per-ray simulation update.

Profile P7 must count source compute/reads, two-way advection, source/erosion/detail generation, occupancy/mips, dirty discovery, complete light and ambient updates, main/reflected/environment rays, clouded air/fog and receiver shadows, resolve, upload, all leases and process memory. Compare p95 cloud GPU 5 ms, total 16 ms and process 512 MiB on the actual M2 fixture; these are unrun targets. An unbounded rate of live full-sky changes or a low-frequency source that visibly freezes between updates invalidates the model. If the near source cannot pass native Cu/Cb structure and local renewal at budget-relevant tile size, or far LOD loses cloud topology/consumer agreement, revise the representation before broad family authoring. This is a foundational visual/cost gate, not routine parameter polishing. Preserve the current renderer/light contracts where they prove equal-density behavior, but the old one-Cu M3 result remains adverse scoped evidence rather than this design's timing.
