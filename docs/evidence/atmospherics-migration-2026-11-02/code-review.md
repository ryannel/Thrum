# Cloud/atmospherics proof → Thrum: code migration audit

2 November 2026. Research/design only. This inspects the current standalone source, including uncommitted Sun-air work; it does not certify that work or commission runtime implementation. [CLOUDS](../../design/modules/CLOUDS.md) and [capabilities](../../design/modules/CLOUD-CAPABILITIES.md) are the selected target and acceptance authority. The five families Cu/Cb/Sc/St/Ci, actual formation/renewal/breakup, weather and complete skies remain required. Existing code is a reconciliation candidate, not a target.

## Coupling and leakage that migration must remove

1. `scene()` combines world shift `[3*(t-origin), route?0:900, t-origin]`, camera, Sun, source bounds, HDR inputs `[90000,85000,75000]`, sky `[6000,9000,15000]`, exposure `.00006`, grid/light mode and view toggles in one `ArrayBuffer(208)`. Event motion is a viewer fixture, not shared E1 wind; no other family/weather authority exists.
2. `renderFrame()` serializes source → fit/Sun/ambient → image in one per-canvas graph. A JSON `wantedLightKey` covers selected parameters but has no complete air/fog/world/source-group/product generation; the Sun-air switch is deliberately omitted because only direct lookup changes. Engine products need complete dependency keys, atomic publication and all-consumer lifetime.
3. The `Scene`/WGSL `grid.w` bitfield (`16` deep, `32` reference patches, `128` air) and `switches` couple quality, diagnostics and consumer presence. `image()` contains V3 media, reflected leg, analytic geometry, and V4 tone/gamma. Main omission still executes source/light work. Runtime composition must retire actually unused closures while retaining shadows/reflection/environment/semantic demand.
4. `cu-preview.wgsl` assumes one finite box, `tauDirect(...,512)`, at most 1024 view steps, constant external sky, a plane, one sphere, and one perfect mirror. `surface()` has constant diffuse receiver term; `buildAmbient()` samples only five axes. These do not express spherical horizon, many layers, clouded diffuse surface irradiance, fog or a rough reflection provider.
5. `deepSunShaderSections()` extracts WGSL between comment markers and expects ambient `Scene`, `tauDirect`, and `errors` names; `deep-sun.js` binds fixed texture/buffer slots. This is private source coupling. The selected K48 product needs typed producer inputs, explicit query validity/error and stable shader ABI owned with V3/F4.
6. `PreparedCu` and `CuSourceField` each own a `ScalarField`; `chooseRecipe()` creates replacement products, waits for queue, then swaps/destroys. This protects a single paused proof but cannot serve multi-view/in-flight atlas residency, overlapping sources or device loss. `ScalarField.buildFromHalfBits()` submits internally, unlike pass-encoded field builds; production scheduling must not hide a second queue authority.
7. `ScatterFit.createProducts()` is dimension-bound to one field and `DeepSun` owns one global set of columns. Source-only body thickness and ordinary all-layer light depth have different aggregation/reuse domains. A separate per-cloud light cache can double-count blockers or omit offscreen layers.
8. `AirSun` loads immutable external direct transmittance, while `cu-preview.wgsl` still supplies authored sky and computes cloud march separately. This is a valid narrow diagnostic, not a complete air/fog/cloud integrator; adding sky LUT output over the current terminal would count air twice.

## Proposed ownership and migration order (not existing Rust code)

Use existing F2 composition, W1/E1 source authority, F4 cooked products/leases, V1 GPU resources, V2 view extraction, V3 transport and V4 display from `docs/design/CONTRACTS.md` C05/C07/C08/C09. Do not invent cloud crates or a second service locator before real public boundaries/consumers are fixed. A cloud package may register authoring schemas, E1 source provider, F4 cook inputs and V3 coefficient/source provider; its internal family evaluators, packing, indexes and caches stay private. Public queries expose source/time/epoch, support, metres and m^-1 coefficients, liquid/ice weights, validity/error, source group/partition and optional correspondence. A separate all-cloud path query returns ordinary tau to main, reflection, surface and air/fog/light consumers. Valid zero and unavailable must differ.

Performance work should first count source groups, fresh field evaluations, light columns, view samples, environment rays, memory peaks and invalid/fallback paths in the assembled graph; optimize measured work without shrinking the accepted scene.

## Independent review of the saved migration plan and technique selection

Reviewed `docs/design/modules/CLOUD-MIGRATION.md` (304 lines) and `docs/design/research/ATMOSPHERICS-TECHNIQUES.md` against the actual proof files and retained cost/failure evidence. Severity means execution risk, not a verdict on the selected target. Proposed fixes belong in the governing plan/contract before the indicated build stage; POC measurements remain legitimate where noted.

1. **High — generation publication is underspecified and internally inconsistent.** `CLOUD-MIGRATION.md` “Required handoffs” says complete compatible generations swap atomically, but “One frame and one weather transition” step 2 publishes source before steps 3–4 build air/Sun/ambient, and the storm paragraph permits current density versus cached light mismatch under an unspecified latency bound. This can give new visible births with old shadows, environment or mirror, exactly the defect the plan rejects. Before P0, define the frame-visible generation transaction: dependency tuple for source, air profile, Sun/light, fog, shadow, A0, environment and each view; atomic publication of mutually compatible products; invalid/old-generation behavior; allowable reuse only when exact inputs match. If latency is an intentional approximation, specify maximum age/error, affected consumers and a measurable fallback, with birth/seek/cut/epoch as immediate invalidations. The old `cu-preview.js::wantedLightKey` is a concrete incomplete-key regression witness.
2. **High — shared GPU residency has two apparent owners.** “Target system and code ownership” assigns `source` atlas residency, `gpu/schedule` leases/generations/retirement, V1 resources and F4 admission. P0/P3 cannot implement safe old/new overlap, multi-view references or no-consumer release from that table alone. Clarify that source selects representations/demand and provides coefficient/index data; F4 owns admitted cooked bytes/source leases; V1 owns GPU allocation/page/fence/device epoch; the proof scheduler requests and publishes complete product graphs. Add an owner/key/readers/dirty-region/retirement table for field atlas, Sun depth, ambient/A0, reflection/environment, per-view history and staging. State whether CPU copies are retained for recovery and how device loss/resize/quality swap invalidates each. This is a design decision; exact pool size/page policy remains P1/P3 measurement.
3. **High — scaling risk reaches the queue too late.** “Budget account and reductions” correctly labels its 5ms split and 184MiB reservations as objectives, not predictions, and acknowledges peaks. But P3 has only two Cu ages, P4 one cheap low layer, and the first regional/full-coverage and many-source scaling is P7 after all families/weather. The current single-source crop already costs GPU p50 12.976ms; 512 independently aged Cu, overcast occupancy, many Sun blockers and full environment demand can invalidate the representation before P5 content expansion. Add an early P3/P4 synthetic but semantically faithful stress matrix (1, 2, 16, 64 and regional groups; same versus independent ages; sparse versus full cover; overlapping layers; low Sun; all main/reflection/shadow/env consumers) with actual unique evaluated groups, voxel updates, light columns, view steps, GPU p95 and residency peaks. Synthetic shapes can screen cost but cannot pass family appearance. Require a representation correction before bulk variant production if the assembled scaling slope is structurally incompatible with the targets.
4. **High — update cadence/fast-time cost has no explicit admission condition.** “One frame and one weather transition” promises dirty-only updates, and P1/P4/P7 mention 1×/16×/64×, but neither the work model nor source policy specifies master frame interval, interpolation error/correspondence, decoded-cache miss rate, number of simultaneously changing sources or source-seconds advanced per display frame. At 64×, even a perfect view cache cannot help if every source and dependent light product becomes dirty every callback; holding an old phase would violate the timeline. Add representative 1×/16×/64× timelines to P1/P3/P4 with moving source time, measured decoded/upload bytes per display frame, cache hit/miss, dirty product area, light rebuilds, missed cadence and visual error. Choose bounded residency/paging/seek deadlines and a deterministic degradation or explicit capacity failure before declaring a source route viable. Do not turn the 0.45ms source objective into a forecast.
5. **High — four-LUT clear air is not yet a clouded-air composition algorithm.** `ATMOSPHERICS-TECHNIQUES.md` “Selection” correctly limits altitude-only LUTs, while `CLOUD-MIGRATION.md` P2 calls the LUT family “complete clear air” and P4 requires two fogs, offscreen blockers, clouded irradiance and environment. The join is described only as “correctly placed clear-air tails” and local shadow integration. Specify before P4 which exact disjoint ray intervals use clear LUT affine `S/T`, which occupied intervals sum sampled air/fog/cloud coefficients and sources, and how cloud/geometry attenuation of air scattering and all-layer direct light is evaluated without adding a second sky-view/aerial contribution. Include horizon/planet/near-interface boundaries and a reference integrated ray for clear, cloud-shadowed air and fog overlap. P2 isolated LUT quality can be measured separately; it cannot be promoted as the joint graph pass.
6. **Medium — exact point service remains a contractual branch, not a K48 tuning option.** “Required handoffs” and P3 distinguish filtered from point shadow queries, but the chosen all-layer Sun-depth product has no explicit source/receiver domain or fallback ownership. The retained K48 lateral point error reaches .121507 T (versus .008 target); lowering its compression error cannot fix that. Specify a point/path query provider that evaluates current all-layer coefficients at the requested footprint and returns exact/qualified error/unavailable status, while the filtered radiance product advertises its own footprint. Test offscreen blockers and many layers before binding ground shadows, semantics or precipitation to the filtered product. The algorithm/performance of point service is a legitimate P3 choice; the semantic split must exist in D1.
7. **Medium — memory reservation needs per-lifetime peak arithmetic before calling it headroom.** The “Budget account” explicitly says 184MiB is a reservation and actual process residency is unmeasured; the derived “remaining328MiB” is therefore only an accounting remainder, not available browser headroom. P1 should inventory retained compressed masters, decoded CPU cache, GPU current fields/mips, old+new generation overlap, source uploads/staging, 3D light products, independently retained per-view histories and browser/driver/compiler/scene cost at cold load, seek, quality switch and device recovery. Use physical allocated texture dimensions/format and simultaneous lifetimes, not logical voxels alone. Keep 512MiB qualification for P7 on target browser/device; use the early inventory to reject a content/pool policy that already exceeds its reservation.
8. **Medium — source contract abbreviations can drift from the canonical multi-family semantics.** “Required handoffs” lists `MediumSample` coefficients and phase but omits support, footprint/representation/error, source group partition and correspondence details stated in `CLOUDS.md`; “Target system” calls `source` a coefficient owner, while “Mathematical and content closure” says every genus's source is a `sigma=k*rho` master. For Sc/St connected sheets, Ci tails and Cb core/anvil overlap, define in the proof handoff how group partitions sum one condensate once, how independent groups add, how near/far representations substitute rather than add, and which coefficients remain valid for headless/point queries. A fixed `k*rho` remap is a content calibration route, not evidence that all family source/phase semantics are identical. Test an overlapping core/anvil and Sc/St transition with coefficient accounting before P5/P6.
9. **Medium — scientific/source support is properly limited, but the selected production route has a tool gate that belongs to P1.** `ATMOSPHERICS-TECHNIQUES.md` distinguishes inspected papers/code from watched motion and does not claim a ready VDB library; `CLOUD-MIGRATION.md` explicitly requires one executable licensed authoring chain and recoverable sample. Keep that gate before committing to library-scale content or format assumptions. In the D1 review disposition, label the VDB/flow-assisted transition and offline optical remap as proposed synthesis; require the first sample to expose actual source frames, velocities/branch/correspondence data, export precision, cook time and license/source chain. The exact tool and artistic quality are P1 findings, not a reason to weaken the five-family goal now.

Two exact corrections remain useful before the D1 checkpoint; neither asks for a GPU test or changes the selected architecture:

1. **Optical interpolation semantics.** In “Prepared-content control contract,” `rho(a)=(1-a)rho0+a rho1` follows text selecting *final optical frames*, while “Mathematical and content closure” allows mixed liquid/ice extinction/scattering channels. State the baseline per nonnegative optical coefficient channel, with `a∈[0,1]` and the same unwarped source coordinate/LOD/filter for both endpoints: e.g. interpolate `sigma_t` and each phase-weighted `sigma_s` component, then evaluate the phase mixture. Do not interpolate a normalized phase parameter separately or infer a mixed optical sample by applying one `k` to a scalar `rho`. The linear-filter/mix commutation claim holds for these linear channel samples under the same linear filter and transform; half rounding, varying LOD/footprint, endpoint flow maps, Beer/T/S and per-event nonlinear remaps require their own error checks. Existing text acknowledges quantization/flow limits; this pins the missing mixed-channel case.
2. **Far-bin marginal versus path composition.** “Far-source candidate” gives correct single-bin marginal identities `Tbar=(1-c)+c exp(-tau_occ)` and `Sbar=c S_occ` only when `c`, `tau_occ` and `S_occ` describe the same conditional footprint/interval, with `S_occ` the already integrated conditional source. Averaged bins cannot generally be chained as independent affine segments: `E[T_A T_B]≠E[T_A]E[T_B]` for correlated clear channels, and `E[T L_terminal]≠E[T]E[L_terminal]` when geometry/sky/reflection terminals vary across the footprint. Add P3a reference cases with aligned versus staggered multi-depth gaps, mixed layer correlation and changing terminal/depth at a silhouette; retain per-subray path correlation or bound the approximation before adopting a summary. The current explicit P3a gate is the right place to reject the candidate if those cases fail; no far-product quality pass is presently implied.

No other unresolved *planning* blocker found in this bounded delta. Remaining source appearance, LUT joint error, point/shadow fidelity, full workload, M2/browser residency and native targets are correctly labelled POC or device gates rather than checked results. The 5ms/184MiB splits are still objectives/reservations, not forecasts or admission evidence.

### Final narrow math-text verification

Both remaining clarifications are now **addressed in the plan text**. “Prepared-content control contract” defines channel-wise `q_j` interpolation for extinction and phase-weighted liquid/ice scattering at the same unwarped coordinate/LOD, derives albedo after mixing and retains endpoint-support union; “Selected multi-instance sampling baseline” explicitly limits filter/mix commutation to the same linear channel/filter and excludes Beer, half rounding, flow and changing LOD. “Far-source candidate” now uses conditional occupied-subray mean `T_occ=mean(exp(-tau_j))`, conditional premultiplied `S_occ`, separate clear/cloud cases and joint per-subray composition before averaging across correlated depth or varying terminals. P3a requires counterexample tests and cost admission. These are mathematically appropriate **candidate definitions**, not measured quality or performance passes. One copy typo remains at the sampling baseline: “Thus so independent ages” should read “Thus independent ages”; it is editorial, not a design blocker.
