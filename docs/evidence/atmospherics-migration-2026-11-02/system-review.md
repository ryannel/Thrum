# Independent atmospherics system challenge — 2026-11-02

This note records an initial recommendation before auditing Thrum's cloud design. I had seen the worktree's file names and README cloud handoff, so this is independent in derivation, not blind to the existence or maturity of the existing work.

## A. Independent target and selection (saved before current design audit)

**Required experience.** A player can recognize fair-weather cumulus (Cu), towering cumulonimbus with anvil (Cb), stratocumulus (Sc), stratus (St), and cirrus (Ci) by silhouette, vertical placement, texture and characteristic development, from below, inside where relevant, and above. Cloud identity survives wind transport and camera motion. Birth, growth, mature state and breakup change topology and density distribution, not merely UV phase, scale or opacity. Clear, scattered, overcast and incoming storm conditions transition in space and time; Sun, sky, haze, cloud light, cloud shadows, surface irradiance and reflections refer to the same event and time. Browser and native hosts may use different quality/cost choices with the same weather/source semantics.

**Selected architecture, provisional until combined proof:** a *weather/feature/optics* hierarchy. One authoritative world-space weather state provides synoptic controls (humidity, stability, wind by altitude, frontal lift, cloud-base/freezing/tropopause proxies) and artist/mission overrides. A persistent feature graph identifies individual convective cells, stratiform patches and cirrus filaments; it records trajectory, family, phase, parent/child, seed and source-content references. Source builders turn this into coarse time-varying **extinction-density fields**; a separate sampler adds bounded spatial detail and yields density, optical type, support/distance and velocity. A shared radiometric service provides atmospheric transmittance and radiance, cloud Sun optical depth, sky irradiance/occlusion, cloud shadow projection and aerial perspective. The renderer integrates this field for the camera and reflection views. This is an authored-phenomenological system, not a claim to simulate weather forecasting.

**Why this combination.** Guerrilla's [2017 authoring talk](https://www.guerrilla-games.com/read/nubis-authoring-real-time-volumetric-cloudscapes-with-the-decima-engine) treats regional maps, weather states/scheduler, artist modifications and transitions as production essentials; its 2015 prototype alone did not. The [2023 Nubis³ slides](https://d3d3g8mu99pzk9.cloudfront.net/AndrewSchneider/Nubis%20Cubed.pdf) report that moving shape generation from the sample shader into authored voxel data changes the cost/authoring balance, but dense full-region grids become hundreds of MiB. [Webanck et al. 2018](https://perso.liris.cnrs.fr/egalin/Articles/2018-cloudscapes.pdf) give a controlled primitive-field and wind-aware correspondence/morphing path, explicitly separate from fluid simulation. [Stormscapes 2020](https://wp.faculty.wmi.amu.edu.pl/papers/Haedrich.etal-2020-Stormscapes.pdf) and [Weatherscapes 2021](https://research.google/pubs/weatherscapes-nowcasting-heat-transfer-and-water-continuity/) show that thermodynamic evolution can produce diverse morphology, but their interactive research simulations do not establish a browser game cost. Thus use prepared fluid-growth and decay sequences as *source examples*, controlled runtime feature events and procedural interpolation for open-world variability; reserve live thermodynamics for a later competing path if it wins a whole-workload comparison. Source creation, optical rendering, and ray sampling are separate decisions.

### Source producer, not just density vocabulary

1. **Weather control.** A slow 2D world-space field with several vertical bands is advected by the corresponding wind and driven by a scheduled state/front boundary. Bounded source/sink terms change moisture/coverage potential, convective potential, layer heights and wind shear. Author-painted masks/curves may add or override an incoming front, clearing, a storm corridor or the Sun opening; their priority, blend interval and world coordinates are explicit. The schedule is the causal input, not a crossfade between unrelated rendered skies. A front propagates at a defined speed so observers see arrival in order.
2. **Feature lifecycle.** At fixed source ticks, candidate seeds are admitted where lift/moisture and cell-spacing criteria hold. Each feature has persistent ID and world trajectory integrating altitude-dependent wind; phase timers are *gates* on operators, not an opacity animation. A feature can branch, merge, shed fragments and die. Occupancy/shape correspondences are retained through those events. An old feature exits by dilution/erosion while new ones condense at independently advected locations. Avoid re-seeding from camera coordinates.
3. **Cu/Cb.** Use a small library of artist-selected, offline fluid-grown *time sequences* of coarse 3D extinction, skeleton/height envelope and velocity (birth, tower, mature, decay) with varied bases and aspect ratios. Runtime takes weather-driven phase, applies a smooth wind/shear deformation to each source sequence, maps density between key times by velocity-guided backward transport and a matched feature correspondence, then adds phase-dependent condensation/evaporation residuals. The source must exhibit new lobes and voids at different places; optical-flow interpolation alone cannot create them. Cb requires a rising tower whose top reaches a modeled stable layer/tropopause, then lateral detrainment along shear to create a flat spreading anvil; separate precipitation shaft/dark core and evaporating underside are source outputs. A fallback analytic feature grammar can create nonhero Cu but must prove the same growth cues, not borrow validation from prepared sequences.
4. **Sc/St.** A 2D cloud-water/coverage field with finite thickness, vertical profile and altitude is advected with wind. Spatially varying condensation and evaporation, finite-width dilation/erosion, and fragment connectivity produce joining Sc cells and a St deck that can thicken, lower, tear or open. A stationary coverage mask that only scrolls/fades fails the transition requirement. Weather fronts can feed a new deck from an edge while existing cells persist.
5. **Ci.** High-altitude 2D/2.5D filament sources follow upper winds and shear with persistent streak IDs. Stretching, deposition and sublimation alter length, width, holes and fiber orientation. A single lower-layer cloud-type blend cannot carry the altitude, thin optical depth or wind distinction.

These are authored algorithm choices/inferences, not algorithms claimed from any one publication. *Before build*, specify the exact sequence encoding, feature correspondence and creation/destruction residual for prepared Cu/Cb, and the source/sink/transport update for stratiform and cirrus fields. A still, a looping clip or uniform density crossfade cannot prove structural evolution. If the intended engine supports arbitrary weather, specify the library's interpolation domain and what happens outside it; do not call a few hero clips a general storm system.

### Radiometry and shared consumers

Use a single Sun direction/spectrum or RGB radiance, atmosphere medium and physical-time snapshot. Hillaire's [EGSR 2020 atmosphere method](https://sebh.github.io/publications/egsr2020.pdf) is the baseline for transmittance, multi-scattering, sky-view and aerial-perspective LUTs, with explicit near-camera/volumetric shadow treatment where LUT assumptions fail. Cloud extinction/scattering are in reciprocal length units; camera integration computes **premultiplied cloud in-scatter L and transmittance T**, not an opaque color/alpha. Composition is `L_total = L_near + T_near * L_far`; sky/ground behind the cloud is attenuated once. Cloud illumination uses atmospheric Sun transmittance at the cloud location, cloud Sun-direction optical depth and a controlled multiple-scattering approximation; atmospheric aerial perspective is integrated exactly once before/after a cloud segment according to depth. Sun disk attenuation by clouds uses the same optical-depth field and solar angular footprint.

Publish a world-space cloud-Sun optical-depth/visibility service to sky, fog, water/ground irradiance and shadowed direct light. Sky ambient occlusion is a *different hemispherical integral* with a separate low-frequency approximation and update cadence; it must not be substituted by the Sun shadow map or multiplied twice. Aerial haze/fog uses atmosphere-owned coefficients and cloud shadows only if the chosen volumetric-lighting mode accounts for that optical depth. Surface direct light is Sun radiance times atmosphere and cloud transmittance once; environment reflection uses the rendered sky/cloud radiance for its camera/time/roughness budget. Reflection cameras must sample the same source epoch, though lower spatial/temporal resolution is allowed. Explicitly define transparency/occlusion boundaries for below-cloud, in-cloud, above-cloud and space/long-distance cameras. Camera frustum culling must never disable world-space source/lighting queries needed elsewhere.

### Sampling, scheduling and residency

The density sampler exposes a coarse conservative support/distance representation for empty-space skipping, then samples family-specific coarse structure and only requests high-frequency 3D detail near occupied regions. Distances used to step must be **lower bounds after deformation, temporal interpolation, filtering and quantization**; otherwise silhouettes are skipped. Use a bounded active 3D atlas/clipmap for nearby or hero evolving features, 2D/2.5D layers for broad stratiform/Ci, and analytic or prepared distant proxies that preserve integrated optical depth and silhouette. A single 2048²×256 8-bit full sky already costs 1 GiB before mips; even BC4 is about 512 MiB, consuming the whole stated browser envelope. Nubis³ reports that dense grids and sparse indirection each have costly tradeoffs; its chosen compressed 512²×64 modeling/field data is production evidence, not a direct browser allocation recommendation.

Cache keys include source feature ID and epoch, weather/front epoch, Sun direction and spectrum, altitude/atmosphere coefficients, content hash, quality/profile, and (for view resources) camera transform/projection/viewport and history origin. Separate invalidation for density, Sun-depth, ambient, sky LUT, aerial LUT, shadow projection, reflection and temporal history; a new source tick should not rebuild atmosphere molecular LUTs, while a new Sun angle must invalidate Sun-dependent lighting. Double-buffer source epochs, tag derived maps, and avoid mixing a shadow from tick n with density at n+1 beyond an explicit tolerated latency. On teleport, time jump, weather edit, device loss or tier switch, invalidate/reseed history and repopulate from the same authoritative feature graph; no old ghost clouds.

At 1280×720, 5 ms cloud GPU on an M2/WebGPU candidate leaves ~11 ms for the entire rest of the 16 ms frame; native 3/10 leaves ~7 ms. A quarter-resolution cloud target is 320×180 = 57,600 rays. At 64 occupied samples plus 6 Sun/ambient samples, that is ~4.0 million density/lighting evaluations per view before empty-space work, reflections, cloud shadow maps, history, composites and updates. This is a workload estimate, not measured viability. Two 320×180 RGBA16F history targets cost ~0.88 MiB together; 512³ R8 is 128 MiB before mips; 256³ R8 is 16 MiB. Bandwidth, random 3D texture reads and several cameras can dominate before nominal VRAM does. Allocate explicit per-pass and peak-memory budgets, including cloud source preparation, shadow/ambient updates, LUTs, reflections, upsampling, upload/staging and device-resident copies. Preserve the physical/source tick across quality tiers; reduce view rays/detail, light query accuracy, reflection frequency and active volume resolution in that order, only after visual/cost comparison. Browser fallback may use prepared sky/cloud proxies for a low tier, but may not silently claim the full required experience.

**Initial proof gate.** One prepared Cu transitions through four phases with observable lobe/void changes while translating in wind, in a scene with one St/Sc deck and an approaching Cb anvil/front; the Sun crosses cloud edges and the same moving shadow/irradiance change appears on opaque ground and reflective water. Run below/above/reflection cameras, weather transition, teleport and quality switch. Reject if feature tracking loses IDs, phase change is explainable by scroll/scale/fade alone, cloud/ground/Sun timing disagrees, reflection sees different weather, source updates spike beyond budget or combined cloud work exceeds the candidate budgets. Measure warm frame distributions/tails and actual logical/resident bytes; component kernels alone cannot certify this assembly.

## B. Audit of the current Thrum design and evidence

Inspected on 2 November 2026: `docs/design/modules/CLOUDS.md` (working-tree revision, including its new air-profile pointer), `CLOUD-CAPABILITIES.md`, `CLOUD-LOCAL-CLIP.md`, `CLOUD-SYSTEM-SOURCES.md`, `CLOUD-SKY-SOURCES.md`, C08/C09 of `CONTRACTS.md`, the cloud maturity entry and the cloud-sky design, R0, Cu-correction, Sun-depth and depth-index evidence READMEs. The Sun-profile discussion below comes from `CLOUDS.md` and the evidence summary, not a full read of its separate profile file. This was a design/evidence read, not a shader-wide code audit or an independent rerun of GPU receipts; no recorded motion or native image was watched in this challenge. The worktree contains concurrent uncommitted air/profile and preview edits, so the audit is a dated read, not a frozen release certification.

### What the existing design already gets right

The current design is more complete than its prototype: [CLOUDS.md](../../design/modules/CLOUDS.md) already separates E1 cause, F4 product, V3 transport and V4 display; supplies stable world IDs, a storyboard/front, height-dependent wind, five distinct source families, a common coefficient seam, ordered `(T,S)` composition and separate main/shadow/reflection/environment consumers. It calls out exactly-once overlap/LOD, clear versus unavailable, source/headless lifecycle, ambient recursion and cloud-shadow double-counting. [CLOUD-CAPABILITIES.md](../../design/modules/CLOUD-CAPABILITIES.md) correctly marks all five full-family gates and full skies incomplete. These are not omissions and should survive a source/renderer replacement.

The R0 proof established finite scalar packing/operator behavior and a rejected first Cu still; later hierarchy stills were rejected. The [Cu correction record](../cloud-cu-correction-2026-11-02/README.md) reports a better held-source light comparison, but the old finite clip has faint birth/static mature arrangement and no accepted family. Its fresh-source/light 330-frame GPU bracket p50/p95/p99 is 11.96/15.07/17.89 ms at native 1280×720, above the 5 ms browser cloud allocation; the device is not the M2 target. The [depth-index record](../cloud-depth-index-2026-11-02/README.md) rejects a new index for lack of repeatable whole-graph speedup. The [Sun-depth record](../cloud-sun-depth-2026-11-02/README.md) still reports a lateral point-query failure. The current design labels these limits honestly; none demonstrates a complete atmospheric system.

### Ranked selection challenges

**1 — Source/appearance is the critical path.** `CLOUDS.md` now chooses a prepared-master fallback for failed sphere/hierarchy Cu, but has not selected a complete *time-varying* production master contract for Cu/Cb at the 1–14 km family scale. The historical local 512 m/240 s Q1 clip has one detailed but static mature topology, and a finite source does not establish a renewable sky population. The current Cb emitter kernel, Sc/St column formula and Ci strand kernel are mathematically specified authored candidates, yet no prepared morphology, characteristic time sequence or appearance gate has accepted them. Guerrilla's 2023 volume method deliberately uses offline fluid-grown/editor-composited shape, and its slides explicitly distinguish actual evolution from pseudomotion in other representations. Stop treating a finer lobe grammar as the default rescue. Select content families with actual formation/mature/decay samples, controls, variants and recoverable master inputs; define interpolation, looping/nonlooping lifetime, residual creation/loss and mature renewal before more shape code. The old Q1 clip remains a transport comparator. This finding does not dispute the current design's candid failure labels; it challenges which mechanism receives the next implementation effort.

**2 — Cost model must select representation, not merely cap enormous work.** The canonical `CLOUDS.md` reserves up to 58.7/117.4/234.9 million Sun-column endpoint visits across fair/broken/storm skies, plus up to 402.7 million ambient endpoints and 25.2 million environment endpoints, before camera/reflection samples, source-field builds and fallbacks. These are correctly called ceilings, but a design offering them as admissible paths alongside a 5 ms GPU goal has not yet selected an economically credible schedule. The existing one-source 11.96 ms median is already >2× that goal. Separate source-update frequency from frame frequency, dirty *regions* of shadows/ambient, rate-limit probes with a declared stale-error/time bound, and derive expected occupied/rebuilt work in every FS scene. Put a representative two-family plus air/shadow/reflection workload ahead of further global deep-curve optimization. A simple production cloud shadow map/secondary-trace tier should be a measured comparator to the custom all-layer deep-tube graph; Epic documents both modes and platform-specific choices. The chosen curve may win, but the current numerical fit alone does not establish that.

**3 — An unconstrained global virtual population is not a free far-field solution.** The design says stable cells cover the sphere and every requested view, Sun, ambient and probe path can materialize intersecting birth cells. This is internally coherent and avoids an incorrect camera-centered source, but can make each coarse sky/ambient query pay source/event enumeration over a very large support. The source-index ceilings of 512 node and 256 candidate tests per coefficient request are failure guards, not an efficient algorithm. Derive a hierarchical world/weather tile cache with occupancy and a *transfer/coverage summary* for distant subpixel clouds, plus conservative validity across front motion and horizon direction; measure candidate tests, point failures and fallback rate. Retain canonical IDs and coefficient access for close/semantic rays. The needed far product is not simply an average density mip, since clear/cloud mixtures change `E[exp(-tau)]`; the current document already recognizes that trap but does not choose a costed transfer representation.

**4 — The prepared library needs a hard scaling equation.** The current notes discuss 128³ versus 256³ current fields but not a full five-family, multi-variant, multi-phase clip inventory with CPU/GPU residency, upload and in-flight swaps. At raw R8, 30 frames of one 128³ clip are 60 MiB and 30 frames of one 256³ clip are 480 MiB, before velocity, mips and recovery copies; compression ratios are content dependent. Reusing a master at different ages saves immutable bytes but does not make its evaluated fields or shadow updates identical. Set a source library residency policy: shared encoded masters, per-feature current-field pages only for perceptually near/high-impact features, bounded asynchronously loaded segments or procedural far proxies, and explicit seek/teleport fallback. Define an actual variant count/content-production workload rather than promising both fully individualized frames and 512 near Cu sources under 512 MiB.

**5 — Integrated atmosphere fidelity needs a production comparator.** `CLOUDS.md` explicitly handles air/cloud/fog ordering and the new `CLOUD-AIR-PROFILE.md` is bounded Sun-only CPU work; this is a strength. But the selected end state requires a sky-view and aerial product with clear atmospheric multiple scattering, diffuse sky irradiance and shadow response. A single-scatter first proof is valid only as a stepping stone, since overcast and low Sun appearance depend strongly on diffuse illumination. Compare a recognizable Hillaire 2020 LUT implementation and its author code against the new joint integrator's pixels/cost for clear, low Sun, blocked Sun and two fog volumes. Choose where a preintegrated clear-air segment ends and full joint air/fog/cloud integration begins, with exact boundary radiance/T; ensure clouded ambient and surface probes do not get a second clear-sky aerial pass. The proposed A0 24-direction field is nonrecursive, but its 32,768-anchor ceiling and interpolation error need a specific spatial/temporal reuse rule.

**6 — Weather authoring is a real input, not a free procedural consequence.** The current 60-minute storyboard and deterministic cell seeds specify chronology, but production cloudscapes in Nubis 2017 use regional maps, authored overrides and weather scheduler states, including intentional openings. Our selected approach likewise requires a curated atlas of front shapes, source/emission timing, morphology variants, lower-layer holes, persistent survivors and camera-relevant composition. A seed hash and one potential field may produce a mechanically homogeneous 512-cell sky. Define the authoring schema, controls and variation/override precedence, inspect weather maps at world scale and a filmed transition, and record asset provenance. This is a missing content-selection dependency, not a request for a bulk asset campaign now.

**7 — Claim boundaries in the capability ledger are accurate, but the proof sequence can expose system faults earlier.** The commission requires accepting isolated families before full assembly; keep that acceptance order. In parallel, a small *nonacceptance architecture probe* with prepared Cu + cheap low deck + Sun/air/shadow/reflection would test source epochs, producer/consumer scheduling and combined cost. It must not promote F1/F3 or a full sky. If it fails, the defect can change the representation while content authoring is still cheap. The current single-source Q2/Q3 proof already did this at local scale and found the budget failure; the next probe should challenge the new source and full-air/far/multi-family path, not repeat local single-Cu transport.

### Derivations required before another build slice

1. Choose a specific selected Cu/Cb prepared sequence family: master provenance and recovery, extent/voxel/detail scales, phase markers, velocity/correspondence, topology creation/loss rule, variant knobs, branch/renewal behavior and fixed optical calibration. Include one characteristic authored sample and its visual acceptance criteria; the current failed procedural alternatives may remain as explicit comparators.
2. Give the full-sky 5 ms cloud ledger in expected terms for FAIR, BROKEN, OVERCAST and STORM: source rebuild bytes/voxels per source tick; active unique fields; shadow columns actually dirty; ambient anchors/rays; main/reflection steps; probe cadence; temporary/peak CPU/GPU bytes and upload. Quantify a tier that changes actual work yet preserves the five-family/transition experience, or explicitly declare the target presently infeasible.
3. Specify world-space far transfer/coverage summary, optical-depth and silhouette error, source-cell admission and stale/front invalidation. Test a camera movement and low Sun where offscreen blockers matter. Do not confuse a cap with a cost prediction.
4. Choose the atmosphere integration split and shared producer order for Sun transmittance, clear sky multiple scattering, cloud shadow in air/fog, cloud ambient, surface irradiance and reflection. State units, geometric boundaries, cache keys and acceptable update latency for each. A mixed-epoch product must be rejected or explicitly bounded.
5. Pin a minimal authored weather/front/feature schedule containing real survivors and local growth, with inspection references at ordinary and accelerated pace. The coherent story is part of the source artifact, not a post-process blend.
