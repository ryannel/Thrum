# Mobile lifecycle and touch gate — first local slice

2 November 2026. The selected [platform design](../../design/modules/PLATFORM-RUNTIME.md#i1-phone-shell-lifecycle-slice--selected-target-implementation-pending) adds a separate `thrum-mobile-shell` crate. It has no third-party dependencies, GPU resource or world authority. The app adapter must reconcile its Android lifecycle signal before clock, input and presentation work; winit remains the only Android event-loop owner. This slice implements the reusable state gate and leaves JNI, winit packages and visible game integration open.

`AndroidLifecycleSignal` packs foreground state and a 63-bit Activity pause generation into one atomic word. A pause/resume pair between Rust callbacks still changes the generation; `MobileGate::observe_android` requests a clock pause and clears touches even if the latest foreground state is already active. The adapter must call `HeadlessHost::pause` before `mark_host_paused`, drain already queued ticks through bounded callbacks, then call `resume` and `mark_host_active` only when the queue is empty and surface/foreground gates are open. The maximum generation returns a terminal signal rather than wrapping. Focus loss cancels gestures but is a separate input gate, not a claim about Android Activity pause.

The gate stores at most 16 `(touch ID, surface epoch)` starts in a fixed array. A duplicate start does not replace one; the first matching end consumes it, and another end yields no action. Cancel, focus loss, foreground loss and surface loss clear starts. Surface loss advances its generation; redundant loss and ready callbacks are inert. The 17th simultaneous touch returns explicit `Capacity`. A surface generation exhaustion returns false for terminal handling. These paths contain no heap allocation; this is source-level inspection of the crate, not whole-process allocation evidence.

`RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline -p thrum-mobile-shell` passed six local tests (one cost probe ignored). They cover compressed Android pause before the next input callback, foreground/focus and duplicate/cancelled/stale release, finite touch capacity, pause-generation exhaustion, and the actual `thrum-core::TickClock` draining five queued updates during a 610-second hidden interval before a fresh-origin resume. The clock test admitted zero hidden ticks and one new tick after resume; it is a fake-surface local integration, not a `HeadlessHost` or phone run. The portable crate also passed locked offline `cargo check -p thrum-mobile-shell --target` separately for `aarch64-apple-ios`, `aarch64-apple-ios-sim` and `aarch64-linux-android` with the pinned compiler. These compile checks do not link an app. A read-only review found and corrected the 63-bit generation overflow, then reported no remaining findings within this partial gate.

The ignored release probe runs one million Android signal reconciliations plus one touch start/end pair per run, five serial runs, on the local Apple silicon macOS host with Rust 1.99.1. Command: `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-mobile-shell bench_android_reconcile_touch_pair -- --ignored --nocapture`. The observed times were 6.42, 6.40, 6.36, 6.23 and 5.90 ns per combined cycle; `size_of::<MobileGate>()` was 408 B and the signal 8 B. `black_box` protects input and outputs. This is one synthetic, in-cache kernel that excludes winit dispatch, JNI, touch normalization, action submission, host callback, acknowledgement, rendering and actual device contention. It supports the fixed-cost representation but no mobile frame-rate or battery claim.

The [separate local receipt proof](MOBILE-LOCAL-RECEIPTS.md) now connects returned host publications (including rejections) through more than 256 results and paused-tick drain. Next, connect the actual GameActivity pause bridge and iOS/winit event flow to this gate and receipt path, then build and run packaged shells. The package and device boxes remain unchecked.
