# I1 review fixes and idle-publication check

1 November 2026. A read-only review of the uncommitted headless and clock slice found four actionable issues. This record covers their fixes and local verification; it does not qualify the full I1 host or devices.

The idle world publication scanned every dirty-page flag even when nothing changed. `World` now maintains a dirty-page count, updated once on each clean-to-dirty transition and cleared after publication. The unchanged path tests that count in O(1) time; changed publication still traverses its page references and clones touched pages. This adds one branch to mutation marking and one `usize` per world. It does not remove the per-publication snapshot lease allocation.

The replica now checks that each event belongs to exactly one committed result with matching action origin and resolution tick, in both baseline and incremental admission. It rejects orphaned or misattributed events before changing replica state. Result acknowledgements now remove all completed sequences through a contiguous watermark even when a timed lower sequence finished after a higher one; retained capacity recovers after acknowledgement. `CommittedEvent` and `AdmittedGroup` are re-exported so external adapters can name the public boundary types. Regression tests cover these cases and the unchanged/dirty publication cycle.

Run `RUSTC_WRAPPER= ./dev check` and `RUSTC_WRAPPER= ./dev check-web`. For the cost fixture, run `RUSTC_WRAPPER= cargo run --release --locked --offline -p thrum-core --example i1_cost`. The prior world implementation is identified by the original [qualification record](QUALIFICATION.md). All measurements below are local release-profile synthetic CPU runs, not target-device results.

The [before run](review-before.txt) recorded idle `World::publish` p50 of 42 ns for 4,096 objects and 125 ns for 16,384 objects; [after A](review-after-a.txt) and [after B](review-after-b.txt) recorded 41 ns and 41 ns respectively for 4,096, and 41–42 ns for 16,384. The structural change removes the page-count-dependent scan; the tiny absolute timings are near timer resolution and do not support a precise speedup factor. At 16,384 objects with 25% churn, publication p50 remained about 123 µs in these runs, while tails varied. This is local attribution to the idle path, not a whole-game frame-rate claim.

The original reviewer did not run tests. The author ran the full local checks after integrating the findings. Process-wide snapshot byte admission, real callback budgets, multi-peer match behavior and device qualification remain open.
