# Charged authority peer registry

1 November 2026. The authority's canonical peer set now uses a private sorted vector. Lookup uses binary search; tick and baseline scans walk peers in stable `PeerId` order. The ordinary prototype and sealed path share that ordering and one rule implementation. The sealed path charges the requested vector storage before a new peer is visible. Capacity grows geometrically, starting at two slots, and both old and replacement buffers remain charged while peer headers move. This removes the peer tree's hidden node allocations from the qualified authority path and improves scan locality. A join can be refused when the next geometric buffer will not fit even if a single peer slot might have fit; this trades bounded admission granularity for amortized growth.

New-peer registration builds its charged pending queue and prepares an empty replacement registry buffer first. It then attempts the fallible due-key scratch growth. Only after all requests succeed does it move the old registry entries, insert the new peer at its sorted position and invalidate cached watermarks. A failed request drops its temporary owners without making a peer visible. Reconnect takes the existing entry and reuses buffers without registry growth. The registry's requested capacity stays charged until the authority retires; a peer reconnect does not retire the registry.

The [unit proof](../../../crates/thrum-core/src/authority.rs) inserts peers 8 and 3, forces a failed two-to-four-slot growth while another owner fills the pool, then retries and inserts peer 5. It checks sorted order, lookup, overlapping charge and final release. The [integration proof](../../../crates/thrum-core/tests/i1_game.rs) registers peers 9 and 3, fills the pool, rejects peer 5 without changing the baseline peer list, reconnects peer 9 under contention, then releases the competing owner and admits peer 5 in canonical order. Existing simultaneous-action, late-input, duplicate, baseline and replica tests pass. `RUSTC_WRAPPER= ./dev check` passes.

The local [two-peer release fixture](../../../crates/thrum-core/examples/i1_two_peer_cost.rs) ran against previous commit `cf84180` and this source on macOS/aarch64, with 1,000 warmup and 10,000 measured ticks. One paired run gave p50 authority-step 375 ns for both and p50 admission-through-replica-and-acknowledgement 708 ns for both. The p95 complete path was 833 ns before and 791 ns after; tails and run-to-run scheduler noise remain material. This shows no measurable two-peer speedup in that run, and does not measure join cost, large peer counts, devices or sustained load.

The registry charge is for requested vector storage, not allocator metadata or surplus capacity. The result does not close future output byte credits, replica progress scratch, mutable world indexes or the whole-process memory gate.
