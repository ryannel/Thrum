# Bounded rule-scratch proof and local cost

2 November 2026. This record qualifies the [selected reusable byte-scratch design](RULE-SCRATCH-DESIGN.md) for the sealed headless authority. `Authority::try_enable_rule_scratch(K)` reserves `K` logical bytes from its existing pool, initializes one retained buffer, and refuses a one-byte-short available pool without installing it. Setup can retry after the competing owner releases capacity. Capacity is fixed before accepted work; already configured and active authorities refuse a second setup. A zero-capacity configuration requests no buffer bytes. Allocation layouts are checked before allocation.

Each action gets a fresh checked generation and a reset cursor. Rules allocate zeroed ranges, access them through private-field owner/generation/range handles and may pass a handle from `decide` to `prepare`. The cumulative allocated range length across both callbacks cannot exceed `K`; ending a view does not refund space. Later views of a range preserve its contents until the next action. A stale handle, a foreign authority's handle, a handle from a retired owner, an oversized request or arithmetic overflow is rejected. Limit and invalid-handle errors set an engine-owned sticky fault; returning `Ok` after catching one cannot commit that action's edits. `try_copy_scratch_payload` copies a range directly into the separate preadmitted output allowance, without an intermediate game-owned buffer. The result retains its normal shared publication charge. The implementation adds no unsafe code and makes no scratch allocation during a callback.

The local two-peer protected host test queues simultaneous peer actions, a game rejection and a later action. With every unreserved pool byte held by a competitor, all due actions and a clean interim tick advance in canonical order through the required replica. The rejected action's scratch does not leak into the next peer's action, and the delayed action reads its own decision-time range during preparation. A later deliberate overrun faults the host before world edits, leaving the prior authority tick and replica state intact. A separate caught callback unwind faults the host, preserves tick-zero replica state and releases the scratch charge on owner drop. Focused unit tests cover exact-end/zero-length requests, zeroing, retained range contents, stale/foreign/retired handles, sticky overrun, invalid allocation layout and direct scratch-to-payload copy. A second two-peer host test creates a 32-byte payload directly from scratch during preparation, shares it into state and an event, and confirms both through the replica while the other peer's charged rejection, an older snapshot and a competitor occupying all remaining pool bytes stay live. The payload and scratch charges release after final owners drop. `RUSTC_WRAPPER= ./dev check` passed after this slice, and `RUSTC_WRAPPER= ./dev check-web` compiled the portable core for `wasm32-unknown-unknown`; neither is a device runtime test.

Local Apple Silicon release-mode fixture: `RUSTC_WRAPPER= cargo test -p thrum-core --lib --release compare_protected_callback_with_and_without_rule_scratch -- --ignored --nocapture`. The same one-object, one-peer, one-replacement action runs through submission, protected callback, required replica and acknowledgement at exact 60 Hz timestamps. The scratch variant allocates and writes four temporary bytes in `decide`, then reads them in `prepare`; the plain variant uses the same rule type and skips those operations. Each variant has 100 warm-up ticks and 500 sorted samples. Three serial pairings ran plain first:

| Variant | p50 (three runs) | p95 (three runs) | Retained logical owner bytes |
| --- | ---: | ---: | ---: |
| Plain | 708 / 583 / 584 ns | 1,541 / 708 / 750 ns | 4,605 B |
| Four-byte scratch | 708 / 625 / 667 ns | 750 / 833 / 875 ns | 4,609 B |

The clock often quantizes nearby values by about 42 ns; the first run has a noisy plain p95. This supports a small local overhead and an exact four-byte retained difference, not a stable speed ratio or device guarantee. It does not measure larger scratch buffers, typed structures, allocation outside `RuleContext`, the submission-time `spawn_bound` classifier, remote queues, allocator metadata or process RSS. These remain outside the general memory gate. The scratch profile is optional and costs no retained buffer bytes when disabled.
