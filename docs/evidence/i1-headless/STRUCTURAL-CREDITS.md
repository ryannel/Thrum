# Bounded structural admission and host proof

1 November 2026. This is a **selected inline-edit structural host profile**, extending the [world-owner slice](STRUCTURAL-WORLD-STORAGE.md). It connects the existing charged authority, required in-memory replica, shared local/multiplayer rule callbacks and sealed host. It does not qualify arbitrary game-private allocations, remote queues, allocator metadata, OS RSS or named devices.

Each accepted input stores the pure `GameRules::spawn_bound` result, checked against the configured maximum. Prepared spawns above that stored bound fault the authority before the action's world edit. The authority caches total pending spawns and count. With slot high-water `H`, reusable slots `F` and pending spawn sum `S`, the admitted absolute horizon is `max(H, H - F + S)`; admission refuses a horizon beyond physical cap `M`, live objects plus `S` beyond `L`, or required replica headroom beyond its cap. The bound is conservative across canonical action decisions: an input never relies on an uncommitted future despawn for space. Zero-spawn reclamation remains admissible at both caps.

An admission that raises the per-input page/root price reserves the candidate's whole snapshot/group and output allowance plus **every older pending credit top-up in one pool reservation**. Completed-history growth finishes before any top-up transfer or sequence consumption. No top-up scan runs if the funded price does not rise. Credits may remain conservatively overfunded while any pending input remains; the funded threshold resets when the last pending input resolves or reconnect cancellation empties the set. Due preflight transfers only snapshot/group partitions, verifies the aggregate bound and prices the admitted absolute horizon. A clean idle tick uses zero snapshot bytes even if a future spawn is pending. The touched-page count follows due edits, not the horizon's slot difference.

Local correctness proof: a two-peer host holds a delayed zero-spawn input, then admits a same-tick despawn and spawn whose possible horizon crosses a 32-slot page boundary. With enough free capacity for the new candidate **but not the required old-credit top-ups**, admission refuses before sequence consumption and preserves both older credit sizes; the same sequence succeeds after release. A fourth-tick spawn stays pending through a clean fully occupied idle tick, then commits exactly once. The required replica sees the same-slot replacement and later growth. A fresh charged baseline builds a matching replica after growth. A direct authority reconnect cancels a positive-spawn pending credit and permits a new-epoch spawn-capable input at the same cap. Another case admits zero-spawn reclamation at physical and live caps, then admits a spawn into the free slot; a false per-action spawn bound faults before edit and leaves the prior committed tick intact. A second two-peer case creates a charged state payload and event during a structural spawn while the other peer produces a charged rejection; the full pool, old snapshot and last-owner release preserve all three outputs. The [world proof](STRUCTURAL-WORLD-STORAGE.md) covers generation retirement, neutral journal entries, old snapshot readers, long churn and a one-byte-short activation refusal. `RUSTC_WRAPPER= ./dev check` passed: 72 core tests with 4 opt-in cost fixtures ignored, 6 clock tests and 56 game tests.

Local Apple Silicon release-mode complete-path fixture: `cargo test -p thrum-core --lib --release measure_structural_churn_complete_callback_cost -- --ignored --nocapture`. One peer alternates a despawn and a new-ID spawn at full live capacity, through submit, host callback, charged authority publication, required replica admission and result acknowledgement. Each size runs 100 warm-up pairs and 500 measured pairs using exact 60 Hz timestamps; samples are separately sorted for p50/p95. Three serial runs yielded:

| Objects | Despawn p50 | Despawn p95 | Spawn p50 | Spawn p95 |
| --- | ---: | ---: | ---: | ---: |
| 4,096 | 1,000 / 1,000 / 1,000 ns | 1,333 / 1,083 / 1,083 ns | 1,042 / 1,083 / 1,083 ns | 1,375 / 1,125 / 1,125 ns |
| 16,384 | 1,833 / 2,041 / 1,916 ns | 2,209 / 2,125 / 2,000 ns | 1,875 / 2,125 / 2,000 ns | 2,333 / 2,292 / 2,125 ns |

These are local diagnostic timings, not cross-device guarantees. The fixture tests one active peer and one changed object per tick, with full group and replica handoff. It reuses slots at a fixed high-water (`M = L = objects`), so it does **not** measure horizon increases, credit top-up scans, page-count growth, multi-input batches or table rehash. The separate two-peer case proves ordering and liveness but was not timed as a distribution. Hashbrown and vector requested storage are charged by the selected owner-byte policy, while allocator overhead, rule-private scratch and RSS remain outside it. The top-up path scans registered peers and pending inputs, O(`P + Q`) when the funded price rises (`P` peers, `Q ≤ 8P` pending inputs); ordinary admission uses cached counts and no old-credit scan. Resolved upgrade-cost measurement, larger structural batches, platform qualification and arbitrary game-private work remain before the broader memory/performance gate can close.

An isolated admission fixture, `measure_structural_credit_upgrade_cost`, compared an ordinary 16th input with one that raises a page horizon and tops up 15 older inputs. It verified the older credit changes on every measured upgrade. On this machine the timer quantized most single admissions to roughly 42 ns; three serial runs showed ordinary means 37–38 ns and upgrade means 47–52 ns, with overlapping medians. That resolution is too coarse for a stable upgrade-cost claim. The O(`P + Q`) bound is analytical until a batched or higher-resolution measurement resolves this path.

A paired complete-path fixture, `compare_fixed_and_structural_protected_callbacks`, runs the **same no-spawn one-replacement action** through submit, protected host callback, required replica and acknowledgement in 4,096- and 16,384-object worlds. Each sample checks one committed result and the confirmed replica state. Each profile gets 100 warm-up ticks and 500 measured ticks at exact 60 Hz; three serial pairings kept fixed first. At 4,096 objects, fixed p50 was 959/917/875 ns and structural p50 was 1,000/1,000/1,042 ns. At 16,384, fixed p50 was 1,792/1,958/1,917 ns and structural p50 was 1,875/1,917/1,958 ns. The larger-world timing ranges overlap and p95 varied between runs. Selected retained owner bytes after host construction were stable across runs: fixed 1,367,248 B versus structural 1,634,424 B at 4,096, and fixed 5,456,464 B versus structural 6,522,360 B at 16,384. The structural profile spends about 19.5% more retained owner bytes here, primarily on the larger churn-safe live-ID table. This is an explicit cost of enabling growth; the fixed-slot profile remains the selected specialization for games that never spawn. These ordered local pairings do not prove a frame deadline or a cross-device speed ratio.

2 November 2026 addendum: a maximum due-batch fixture admits eight inputs from each of two peers, each preparing two distinct spawns. All 32 new identities extend an initial 32-object world to 64 physical slots and live objects in one tick while a competitor holds every unreserved pool byte. The published snapshot contains all 64 states, the required replica preserves the original 32 and confirms all 32 new states, all 16 results are committed, and watermarks reach `(peer 1, 8)` and `(peer 2, 8)`. An older snapshot still contains only the initial 32 records, and final owner release returns the pool to zero. This closes the scoped maximum-batch **correctness** case for the two-peer, two-inline-edit profile.

The release-mode `measure_maximum_structural_batch_callback_cost` fixture uses the same 16-input, 32-spawn due workload with 4,096 or 16,384 initial objects. Each sample creates a fresh charged world and host, submits all inputs and fills every unreserved pool byte **before** starting the timer. The timed interval includes the host callback, charged authority publication, required replica admission, callback publication release and both result acknowledgements. It excludes world/host construction, input submission, pool occupation, post-run assertions and final host teardown. The 32 contiguous new IDs dirty one new page. Twenty warm-up runs precede 100 sorted samples per size; three serial runs on local Apple Silicon yielded:

| Initial objects | p50 (three runs) | p95 (three runs) |
| --- | ---: | ---: |
| 4,096 | 8,041 / 7,291 / 7,250 ns | 9,833 / 8,375 / 8,416 ns |
| 16,384 | 8,625 / 8,542 / 8,583 ns | 10,708 / 10,292 / 10,375 ns |

These are diagnostics for one native machine and a bounded, inline-value game, not a worst-case latency bound. They do not establish a frame deadline or general process memory bound. The batch measurement exercises page/root growth, both peers' maximum pending queues and 32 unique spawns, but it does not time admission top-ups during submission, retention by an older snapshot reader, large variable payload creation, larger peer counts or remote transport. The separate correctness case covers an older reader. The fixed-slot profile remains available for games without structural growth. The selected bounded structural profile has now passed its local correctness and complete-path cost gates; game-private scratch, allocator metadata, OS RSS, named-device measurements and wider multiplayer/transport qualification remain open.
