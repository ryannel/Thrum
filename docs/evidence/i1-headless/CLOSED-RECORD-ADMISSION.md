# I1 closed record authority admission

1 November 2026. `Authority::try_new_closed_snapshot_charged` accepts only a sealed engine-owned `ClosedPublicationValue`. It checks every live initial state against its selected `PublicationPool` before reserving or publishing tick zero. The qualified authority stores a function pointer for the same provenance check and checks each prepared spawn or replacement before applying any edit. This reuses the same `GameRules::decide` and `prepare` callbacks as standalone and match authorities. The older generic charged constructor remains a prototype path and does not claim this value gate.

The `i1_game` fixture now runs its fixed-counter plus charged-payload authority through the qualified entry path and replica. A second fixture rejects an initial foreign payload with `WrongPool`, then executes a two-edit batch whose first replacement is valid and second spawn carries a foreign payload. The authority reports `TerminalGameContract`, retains tick zero, and refuses replay. The provenance check precedes `World::apply_edits`, so neither edit is applied. `RUSTC_WRAPPER= ./dev check` runs these fixtures and the repository gates.

Initial validation scans the contiguous slot array once, with work proportional to slot high-water plus live states times the record's payload slots. Each prepared action checks only its new states and payload slots; a no-input tick performs no record scan. The check borrows values, uses no validation vector, and makes no payload copy. These are code-path bounds, not a measured latency result. Record const sizes still lack profile maxima. The gate does not bound other authority allocations, group output, replica state, baseline delivery, or private game scratch, so the parent publication-memory task stays open.
