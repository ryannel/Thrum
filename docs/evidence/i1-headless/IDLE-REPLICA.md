# I1 idle replica progress path

1 November 2026. An empty complete group whose sorted peer watermarks exactly match confirmed progress, with no buffered result above a prefix gap, now advances the replica tick without cloning its peer-progress map or allocating temporary changed-ID, event or advertised-watermark maps. Any changed state, result, event, new/reordered peer or differing watermark takes the original full validation path. Authority ordering, commit tick and nondecreasing event cursor are checked before the shortcut.

`RUSTC_WRAPPER= ./dev check` passes. The focused tests admit an ordinary idle group, accept a reordered peer list through the full path, reject a duplicate peer watermark without advancing the replica, and then accept the valid replacement group at the same expected ID. Review found that a baseline may contain a result buffered above its contiguous prefix; a regression test proves that such an empty group still takes full gap normalization, rejects a stale watermark, and accepts the corrected one. Existing delayed-result, gap, baseline and two-peer tests remain green.

The release fixture uses 64 fixed-size objects, one registered peer, no input, 1,000 warmup and 10,000 measured authority steps plus replica admissions on local macOS arm64. One baseline run (`tmp/publication-memory/replica-idle-before.txt`) measured 125/167/208 ns p50/p95/p99; two runs after the first change (`replica-idle-after-a.txt`, `-b.txt`) measured 83/84/84 and 83/84/125 ns. The final reviewed guard (`replica-idle-final.txt`) measured 83/125/250 ns. The 42 ns timing steps, single baseline and variable tails limit precision. The source-level reduction in temporary maps is certain; the local median change is an indication, not a device latency guarantee or a whole callback result. The authority-only idle fixture still measured 42 ns p50 in the baseline and one after run, so the changed work is on the replica side.

The shortcut does not solve the whole memory gate. Authority still creates a per-tick lease and peer-watermark vector, and other replica groups may allocate progress and validation maps. The [whole-tick owner plan](../../design/I1-HEADLESS.md#whole-tick-byte-gate-bounded-profile-and-owner-plan) requires a precharged idle delivery floor and bounded non-idle buffers before publication bytes are qualified.
