# I1 closed game output admission

1 November 2026. The sealed authority entry path now takes separate `ClosedValueLimits` for entity, event and game-rejection values. It rejects an oversized fixed output type before tick-zero publication, even when the world is empty. At execution, a game rejection from `decide` is checked before it enters an `ActionResult` or duplicate history. A prepared event is checked with all entity edits before `World::apply_edits`. Engine timing rejections carry no game value. An invalid output is a terminal game-contract fault; no part of that tick is published or replayed.

The `i1_game` fixture uses closed records for all three retained game value kinds. It tests a foreign-pool and an oversized rejection, plus a foreign-pool and an oversized event. Each case faults at tick zero; the event cases leave the live world’s prepared replacement unapplied. Empty-world cases reject an event type and, independently, a rejection type whose payload-slot shape exceeds its selected limit. A valid rejection reaches the replica, duplicate lookup and baseline, then its exact payload charge releases after acknowledgement and the final reader. A valid event accompanies a committed replacement and likewise releases after acknowledgement and the final output owner. `RUSTC_WRAPPER= ./dev check` covers the fixture and repository gates.

Shape checks are constant time at construction. Runtime checks visit only the payload handles in the produced rejection or event, use no new collection, and do not copy payload bytes. The release `i1_record_cost` fixture measured 4,096 repeated `validate_for_pool` calls per sample on local macOS/aarch64: fixed-only p50 1,167 and 1,417 ns in two runs, and one shared 512-byte payload p50 2,792 and 3,500 ns. This microprobe is too small to establish callback latency or a stable regression threshold; it confirms the check is tiny relative to a full tick on this host. The game callback can still allocate a payload before the check, and action values, result/history/group buffers, required replica storage and host delivery remain outside a complete pre-edit byte reservation. The [whole-tick design](../../design/I1-HEADLESS.md#whole-tick-byte-gate-bounded-profile-and-owner-plan) and parent memory box stay open.
