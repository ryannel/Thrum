# I1 process-memory boundary and next proof

2 November 2026. **Status: scope analysis, not a process-memory qualification.** The selected fixed-slot and bounded structural profiles precharge engine-managed world, snapshot, group, result, required-replica and callback owners before accepted inputs can require them. Their tests include two peers, maximum pending work, old readers, complete competing pool occupation and final release. The current `PublicationPool` limit is a checked **logical requested-owner-byte** limit for those selected paths. C02's wider whole-process admission target remains open.

| Owner | Current authority and evidence | What a process claim still needs |
| --- | --- | --- |
| Engine-managed protected owners | `PublicationPool` charges retained and transient requested bytes in the selected profiles; [protected-path audit](PROTECTED-PATH-AUDIT.md) and [structural proof](STRUCTURAL-CREDITS.md) cover their declared limits. | A combined peak worksheet spanning every enabled engine owner and future input, including remote queue and content/GPU providers when present. A selected profile must refuse before sequencing or edits when that peak cannot fit. |
| Game rules and typed values | `ClosedPublicationValue` seals admitted value storage; `RuleContext` charges cooperating output and one reusable scratch buffer. `GameRules::spawn_bound`, `decide` and `prepare` remain arbitrary native Rust callbacks. | A finite game-work domain that makes **all** allocations and temporary work in the qualified callback path auditable or enforceable, including typed game-facing projections. A rule allocating a private `Vec` is outside the current pool even if its returned value is closed. |
| Allocator and process | The pool reports its fixed Arc control allocation separately; requested vector/table sizes exclude allocator metadata and surplus. | Process resident/peak measurements and explicit overhead margin on named runtimes. Logical owner bytes and physical RSS must be recorded as different quantities; shared CPU/GPU memory cannot be inferred by adding owner counters. |
| Platform and transport | The I1 phone shell is compiled for iOS and has Android package source; no device run. I2n remote queues do not exist yet. | Device/API allocation and sustained memory observations, plus bounded network queues and reconnect/baseline peaks under the same authority/replica policy. |

An allocation-counting `GlobalAlloc` wrapper alone cannot turn unrestricted rules into a precommit memory guarantee: it is an unsafe implementation boundary, the optimizer may elide or move allocations, some standard-library activity can bypass it, and infallible allocation failure can abort a `std` process. [Rust `GlobalAlloc` contract](https://doc.rust-lang.org/core/alloc/trait.GlobalAlloc.html), [allocation failure behavior](https://doc.rust-lang.org/std/alloc/fn.handle_alloc_error.html). A sandboxed guest is a possible separate policy, but even Wasmtime's resource limiter does not account for all host/store allocations and needs a distinct CPU policy; it is not selected as a silent replacement for native rules. [Wasmtime resource limiter](https://docs.wasmtime.dev/api/wasmtime/trait.ResourceLimiter.html).

The [standalone allocation audit](PROCESS-ALLOCATION-AUDIT.md) measures the selected one/two-peer protected path and a deliberate game-private allocation that leaves pool charge unchanged. The [typed projection proof](TYPED-PROJECTION.md) now uses one borrowed view over closed state/action records in standalone and two-peer rules, with charged outputs, accepted delayed work, maximum due batch, old reader, competing full-pool user, acknowledgement, fresh baseline and final release. It records requested engine-owner bytes, Rust allocator requests and isolated whole-process RSS. It does not complete a host reconnect or enforce native rule allocation behavior. These are diagnostics, not a hard process cap.

**Next architectural decision:** the [provisional game-work choice](GAME-WORK-BOUNDARY.md) separates direct native rule performance from an enforceable cap on arbitrary authored work. Select a finite domain and mechanism for all callback-private allocation and temporary work, including `spawn_bound`, typed temporary containers and projection construction. Then derive and test the combined authority/replica/host/remote-queue peak, including baseline/reconnect and device-specific allocator/RSS margin. A separate transport design is needed before remote queue cost can be included. Until those choices are implemented and qualified, keep the mature claim scoped to selected engine-owned profiles and leave C02's full target unchanged.
