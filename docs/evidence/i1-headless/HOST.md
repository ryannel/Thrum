# I1 native headless host callback: local qualification

1 November 2026. This is the bounded F1 callback proof for the initial headless authority/replica path. It uses a real monotonic native host loop and measures elapsed service time with `Instant`; this includes blocking and scheduling time and is not CPU usage. It does not qualify a window, renderer, phone lifecycle, browser callback or online server. Source at measurement: `host.rs` SHA-256 `35a444b8b8853c584b28f7bba1c1547d7fa96fcf6cb67a1e0ea93f714cf85319`, `clock.rs` `ab0b1a2527d9890f7e1222d70456814bb7c05198d99f59cff274444161a9f581`, and fixture `i1_host_cost.rs` `8802d467bcb194d380dc3678e31d20b68df1b69681939e11f19ccaccac5baa2e`. Rust 1.99.1 release build on local macOS arm64. Hardware model, thermal state and CPU counters were unavailable.

## Correctness and admission

`RUSTC_WRAPPER= ./dev check` covers the host with a game-owned collect rule. The prepared two-stage schedule owns authority mutation/publication before replica admission; validation rejects missing/backward dependencies, cycles, unordered conflicting access and cross-role world access. It runs the same authority rule path used by direct local and in-memory match play. A due callback publishes the committed state and returns its results/events to the caller, either as a local full group or as an admitted replica outcome. The caller explicitly acknowledges handled results; the host never retires them before delivery. An initial replica baseline also returns outstanding outcomes. A repeated callback timestamp cannot commit an action twice. Local result capacity recovers after explicit acknowledgement, including after 256 retained results. Hosted pause/resume ignores hidden time and closes input admission while paused. A deliberately slow rule callback completes its single valid tick, reports a step-budget overrun, stops additional queued work and rejects new input until explicit recovery. A failed authority publication remains an uncommitted due tick in the underlying clock. Post-commit replica failure is a terminal host fault, not an instruction to retry the committed tick.

At construction, the host derives its maximum admitted tick count from `(callback time budget − other-work reserve) / conservative tick-cost bound` and validates its finite stage plan once. Each callback measures actual elapsed wall time; after each committed tick it checks the world-step budget remaining after the other-work reserve and stops further catch-up if the budget is spent. The clock's four-tick-per-call and eight-queued-tick defaults remain independent safety caps. The host does not preempt a slow native rule, predict a true worst-case tick cost, or set a rendered-frame ceiling.

## Real-time local cost fixture

Run `RUSTC_WRAPPER= cargo run --release --locked --offline -p thrum-core --example i1_host_cost`. The native loop sleeps toward 120 callback deadlines per second for four seconds, then calls the host with `Instant::now()`. Two independent peers each submit one action per callback against two counter objects; the authority commits at 60 Hz, and the in-memory replica admits every committed group and the fixture handles and acknowledges its delivered outcomes. This exercises input admission through confirmed state without actual network or rendering. The normal callback time budget is 2 ms, with 0.5 ms reserved for other work and a conservative 0.2 ms cost admission per tick. A separate intentionally slow rule sleeps for 3 ms under a 10 ms total callback budget with 8 ms reserved for other work, leaving 2 ms for world steps.

Two selected same-binary runs are [A](host-real-a.txt) and [B](host-real-b.txt). Both completed 480 scheduled callbacks, 241 world ticks including the final drain, with zero step-budget overruns; authority and replica ended at the same tick and both counters matched every admitted input. The real callback interval p50 was about 8.33 ms and p99 varied from 10.70 to 12.31 ms. Two submissions plus host service and acknowledgement per callback had p50 4–7 µs and p99 36–42 µs; host callback elapsed time alone had p99 30–38 µs. Those service samples include callbacks with no committed tick. All 960 inputs reached a confirmed result; their submit-to-confirmation elapsed p50 was 51–52 µs and p99 10.37–12.19 ms. The bimodal latency reflects 120 Hz submission against 60 Hz authority and host scheduling jitter. These are local short-run observations, not device latency bounds. The intentionally slow callback measured about 4.52 ms, exceeded the 2 ms world-step budget while staying within the 10 ms total budget, completed one tick, entered `Overloaded`, and closed new input admission. No silent clock stretch, duplicate effect or second tick within that over-budget callback occurred.

The headless loop's sleep jitter is host scheduling, not render frame pacing. No GPU, audio, real WSS, process-wide publication-byte admission, long-run thermal response or phone surface lifecycle was measured. The general F1 system registry and its typed component views remain broader foundation work; this proof validates the initial authority/replica stage path only.

## Read-only review and resolution

A read-only review found that the first host version lost observable results in the replica path, could never release local retained results, compared measured work against the total budget instead of the reserved step budget, and labelled per-callback service time as completed-input time. The final code returns local publications and admitted replica outcomes, exposes explicit acknowledgement for both paths, applies the reserved step budget to admission and measured overload, and records confirmed-input latency separately. Regression cases cover local capacity release, outcome delivery, a two-tick queue with one slow callback, and a nonzero other-work reserve. The evidence also labels `Instant` measurements as elapsed time rather than CPU usage. The first pre-review timing files were replaced by the final-build runs linked above.
