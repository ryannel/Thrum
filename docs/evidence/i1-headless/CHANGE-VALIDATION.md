# Sorted live change validation

> Status after the code-quality cleanup: the I1 timing examples cited here were removed from the active tree. Their historical measurements and source remain in Git; quoted example commands are no longer current commands.

1 November 2026. `World` records changed objects in a `BTreeMap<StableId, ChangeKind>`, so its live publication already emits distinct changes in increasing stable-ID order. The sealed group wrapper preserves that vector. The charged replica now checks adjacent IDs and lifecycle in one pass, before touching confirmed objects or progress. An equal ID reports `DuplicateObject`; descending order reports a malformed group. The prototype path still accepts arbitrary change order and uses its duplicate-ID tree. Charged baselines can arrive in snapshot slot order and keep their separate object-index duplicate check. This changes no gameplay authority, outcome, event or multiplayer publication contract.

The new tests prove producer order from out-of-order spawns, rejection of a reversed two-object charged update without partial mutation, and a corrected retry. Existing duplicate-change, two-peer and sealed-host cases pass under `RUSTC_WRAPPER= ./dev check`. The review-agent found no scoped semantic issue. Live charged duplicate-ID validation no longer allocates tree nodes; the mutable world change journal and charged baseline key validation remain outside this result.

The isolated `ID fixture` (historical `git show 84d7673:crates/thrum-core/examples/i1_change_validation_cost.rs`) compares the old `BTreeSet` insertion with the sorted scan over 1, 64, 1,024 and 4,096 IDs on macOS/aarch64, release mode, with 200 warmups and 1,000 timed samples per case. Its single run measured p50 83/1,709/31,000/138,083 ns for the tree and 41/83/542/1,667 ns for the scan. It measures only duplicate-ID validation, excluding object lookup and admission.

The `many-change fixture` (historical `git show 84d7673:crates/thrum-core/examples/i1_changed_group_cost.rs`) applies 4,096 updates from one action through a sealed authority and charged replica for 100 warmups and 1,000 measured ticks. The identical fixture source was run sequentially against previous commit `49b8e9d` and this change, then in reverse order. Replica admission plus acknowledgement p50 was 286,875/287,875 ns before and 94,083/93,125 ns after. Complete submit/authority/replica/ack p50 was 687,083/692,208 ns before and 473,791/465,958 ns after. p99 complete times were 1,034,459/807,292 ns before and 566,208/557,917 ns after. The fixture verifies final object state. This is local CPU elapsed evidence under an unlimited logical pool, not phone or network qualification.

The existing `single-change fixture` (historical `git show 84d7673:crates/thrum-core/examples/i1_charged_replica_cost.rs`) ran before/after and reverse order over two peers, 64 and 4,096 objects, 1,000 warmups and 10,000 samples. Its charged replica-plus-ack p50 at 4,096 objects was 125 ns in all four runs; complete host p50 ranges overlapped. The isolated scan therefore explains a material many-change gain without a separately attributable one-change whole-path gain. Baseline peer/result temporary keys, mutable world indexes, future input/output byte credits, and named-device costs remain open.
