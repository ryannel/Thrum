# I1 two-player in-memory match: local qualification

1 November 2026. This qualifies a bounded two-controlled-player fixture through the existing headless match authority and in-memory replica. It is not a network session, wire protocol or device test. The test fixture was `i1_game.rs` SHA-256 `bfe205d06a733d40ba580b74d293f9f44043d57472acbb2c36fd977d1f89a33c`; the cost fixture was `i1_two_peer_cost.rs` `24685a55bc93c7f929a4e56b535e22783b88e7f3d2eb7cd7441b9fba0af756c1`. It used `authority.rs` `765ed5126c42e06789daa2e5e40af2d077e10fdcfaca62eb20fc0c62ae9229d8`, `world.rs` `67687ba24750b7f8ee2d5485ba3dbc8b5953b4ee445f15dfacbcab02f814d5fd`, and `replica.rs` `dc8d898f131dd8289d624173400cfa3b994d09a6173fc07acfe057f212b4e525`.

`RUSTC_WRAPPER= ./dev check` runs the integration case. Two peers control distinct actors with independent connection epochs and sequences. Both try to collect the same item in one authority tick: one commits, the other gets the game-owned `AlreadyTaken` result, and exactly one event appears. Actor impersonation is rejected before sequence consumption. Both duplicate submissions return their original result without a second effect. One peer's timed sequence is resolved after a higher immediate sequence; its contiguous watermark advances only when the gap closes. A late one-shot is rejected. A second replica holds the tick groups and applies them later in order, then has the same four object states as the promptly updated replica. A newly joining replica admits the complete tick-five baseline, two retained event identities and each peer's progress; an old connection epoch fails after one peer reconnects.

Run `RUSTC_WRAPPER= cargo run --release --locked --offline -p thrum-core --example i1_two_peer_cost` for the synthetic CPU cost case. It uses 64 fixed-size counter objects; both peers submit one accepted action per tick, then an in-memory replica admits the group and both outcomes are acknowledged. After 1,000 warmup ticks, each of two release-profile runs measured 10,000 ticks on local macOS arm64. [Run A](two-peer-a.txt) and [run B](two-peer-b.txt) recorded 0.83–1.21 µs p50 from both admissions through replica and acknowledgement, and 1.08–1.92 µs p99. Each tick copies two page references, one 32-object page and two full group objects. The runs varied enough that this is a local cost baseline, not a stable latency bound or a comparison with the one-peer fixture. No allocation counter, actual network encoding/transport, display, device or sustained thermal result is included.

This completes the Build Plan's **in-memory two-player** box only. Real secure transport, four-player fault handling and whole-game latency remain in the committed later multiplayer path.
