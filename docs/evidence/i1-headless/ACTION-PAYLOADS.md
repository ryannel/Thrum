# Precharged variable action payloads

1 November 2026. The selected protected fixed-slot host now accepts a closed action containing immutable variable payloads already charged to its publication pool. Entity, event and rejection values remain inline-only. Submission still validates action shape, provenance and each payload length before consuming a sequence. The payload's existing owner charge follows the pending input into completed history; future snapshot/group execution credit neither duplicates nor spends that charge.

A host test uses a 1,024-byte action payload and two input sequences from one peer. The first is due at tick 3; the second resolves at tick 1 while a competing owner holds every remaining pool byte. Both tick publications and the required replica succeed. Pending and resolved duplicates retain their original answer and schedule no extra work. Foreign and oversized payloads are refused before sequence 1 is consumed. Full-pool credit refusal also leaves that sequence available for retry. Acknowledgement releases the second payload, while an external clone keeps the first charged until its final drop. Final host, baseline and reader release returns pool use to zero. The existing fixed-slot proofs cover two-peer output credits and old snapshot readers; this test specifically combines charged actions with a delayed sequence and full pool contention. `RUSTC_WRAPPER= ./dev check` passed.

Shared-owner duplicate checks previously compared every payload byte. `PublicationBytes` equality now first compares owner identity, then compares bytes for distinct owners. Value equality remains unchanged, including separately allocated equal values. The [release record fixture](../../../crates/thrum-core/examples/i1_record_cost.rs) performs 4,096 equality checks per sample, with 50 warmups and 250 timed samples. A/B/B/A local macOS/aarch64 runs compared commit `cc2395f` with this change, using separate Cargo target directories and distinct binaries: before SHA-256 `a245833394fbb1fb1db7e9f83424d80d28cb212e409d9ed294a36010ebffa8df`, after `fd7a6a8acc3512f8d353fba6a4ae93a7baf7ba8f1ae3ce7646a9b9377662c77c`. | --- | ---: | ---: |
| Same shared owner | 85,958 / 84,584 | 3,166 / 2,542 |
| Distinct owners, equal bytes | 103,625 / 85,000 | 84,500 / 78,958 |

The shared-owner kernel is much cheaper in these local runs. Distinct-owner value comparison still scans bytes; the small, variable local samples do not establish a reliable speed change there. These are isolated equality costs, not a measured whole callback gain or a named-device ceiling. Payload copying occurs before input submission and is outside the measured equality loop. Rule-created output payloads, arbitrary game-private allocation, structural growth, remote queues and process RSS remain open.
