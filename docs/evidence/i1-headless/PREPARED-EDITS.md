# I1 prepared world edits: bounded admission prerequisite

1 November 2026. This is a local correctness proof for an edit batch, **not** the publication byte gate. `World::apply_prepared` validates every ordered edit before changing the authoritative world. Existing-object edits carry checked generation/epoch handles; a distinct `DespawnNew` can retire only an object spawned earlier in the same batch. The single-edit `apply_one` path does not allocate a validation map. Multi-edit validation touches only IDs in the batch: for C commands, U distinct IDs and D pending changed IDs, its expected lookup cost is O(C + U log(D+1)) because the changed-ID ledger is a `BTreeMap`. A full free-list simulation runs only if the ordinary conservative check cannot prove u32 slot capacity.

`RUSTC_WRAPPER= ./dev check` covers invalid later edits after a proposed replacement or spawn, stale handles after slot reuse and same-batch respawn, retirement at maximum handle generation, successful single edits, old-snapshot isolation, and 65 spawns followed by 65 despawns. The last case has zero final live objects and zero lifecycle changes but still publishes three dirty pages because slot high-water reached 65. The existing authority/replica tests remain green. A read-only review found and resolved a stale-handle-after-respawn partial-mutation path, an overly conservative slot-capacity rejection, and an understated validation-cost claim. The reviewed implementation had no remaining actionable code finding.

Measured source identity: `world.rs` SHA-256 `294e50453b0cb464594501edc643c05954d3bcdc2422f12a9f8ca735197a1eb1`. No speed or residency claim follows from these tests. The authority's current `GameRules::commit` still mutates `World` directly, and no byte reservation is attached to prepared edits, input history, snapshots, groups, baselines or replica state. The [remaining gate](../../design/I1-HEADLESS.md#publication-memory-admission-gate) must connect those owners before the parent memory item can be checked.
