# I1 closed action admission

1 November 2026. The sealed authority entry path now selects a separate action `ClosedValueLimits`. It validates the action type’s fixed shape at construction, then checks each new input’s charged owners and per-payload length after identity, actor, sequence and queue checks but before scheduling, insertion or sequence increment. A wrong-pool action returns `AdmissionError::WrongPool`; an oversized value returns `AdmissionError::ValueProfile`. Neither is a terminal authority fault. Exact duplicates still take the existing duplicate path and never create second execution work. The prototype constructors remain available for unqualified game action types.

The `i1_game` fixture rejects an oversized action type before activation, then rejects a foreign-pool and an oversized action at sequence 1 without consuming it. A valid action at sequence 1 is queued once; both its own duplicate and an equal-content duplicate from another pool are recognized without retaining another payload. The committed state reaches the in-memory replica. The charged action payload remains held while pending and in completed history, then its exact charge releases after acknowledgement and the final caller-owned input drops. A second pending action releases on reconnect, and an old-epoch foreign action still gets the stale-epoch result before value validation. `RUSTC_WRAPPER= ./dev check` runs this proof and the existing multi-peer/reconnect tests.

The check inspects fixed record shape once and visits only present payload handles at admission; it does not copy payload bytes or allocate a validation collection. The action source or decoder can allocate before calling `submit`, and this gate does not charge B-tree nodes, pending/history inline storage, or protect future execution/output credit. Those are required before the whole publication-memory box can close.
