# Local phone-result delivery through the headless host

2 November 2026. `crates/thrum-mobile-shell/src/receipts.rs` adds an infallible one-peer local delivery cursor for `HeadlessHost`. It borrows each callback report so the caller can still inspect clock overload and backpressure. Before observing a publication it checks the world epoch, consecutive snapshot tick, and that all results, events and peer watermarks belong to the local peer. It then presents the complete publication to the caller and acknowledges only a higher contiguous local sequence watermark. A report cannot be replayed or delivered out of order. If the observer unwinds or acknowledgement fails after observation, the cursor remains poisoned and will not replay a possible side effect. A terminal callback may contain earlier committed publications; it delivers them once, skips acknowledgement because the host is already faulted, and leaves terminal teardown to the caller. `acknowledged_through` intentionally means **acknowledged**, not merely seen.

`RUSTC_WRAPPER= ./dev check` passed, including ten active mobile-shell tests (two cost probes ignored), the existing core and game suites, repository guard, rustfmt and Clippy. The sustained integration fixture uses the actual in-memory replica host and game-owned rejecting rule. It submits 258 actions, observes all 258 results, including five stale-observation timing rejections and game rejections, and acknowledges each handled prefix. Result 258 resolves from already queued ticks during a 600-second pause; no hidden elapsed ticks are admitted. The fixture passes the authority's 256 retained-result boundary without permanent `Busy`. Held tick-two delivery before tick one is refused before observation; in-order delivery then succeeds and replay is refused. Another test faults the host after a report was held: acknowledgement fails, the cursor poisons, and observation cannot repeat. A terminal report with one earlier committed publication delivers it once and correctly leaves its acknowledgement at zero.

The helper performs no heap allocation of its own and scans only that publication's result, event and peer rows to enforce one-peer scope. The local minimal-path release probe ran 10,000 one-result rejected actions per run, three serial runs on the local Apple silicon macOS host with Rust 1.99.1. Command: `RUSTC_WRAPPER= rustup run 1.99.1 cargo test --locked --offline --release -p thrum-mobile-shell bench_minimal_local_receipt_path -- --ignored --nocapture`. Submit + headless callback + in-memory replica + borrowed delivery + acknowledgement measured 355.1, 350.7 and 342.4 ns per action. The probe uses an empty world, synthetic 60 Hz timestamps, one peer and no rendering, JNI, winit or OS event dispatch. It has no paired baseline and does not establish a device frame rate or relative speedup. Locked offline library checks also passed separately for ARM64 iOS device, iOS simulator and Android.

A read-only review found the initial watermark-only acknowledgement could delete an unseen earlier result if reports were delivered out of order. Epoch/tick continuity and the held-report test resolve that. It also found that a late acknowledgement error could replay an observer side effect; poison-before-observe and the host-fault test resolve it. The terminal report test and explicit `acknowledged_through` name resolve the terminal prefix wording. The reviewer reported no remaining findings for this partial local receipt path. A future multiplayer transport must acknowledge to its own remote receipt contract, not to local view observation. Game-specific view handling, finite input retry queue, winit/JNI shell integration, native packages and devices remain open.
