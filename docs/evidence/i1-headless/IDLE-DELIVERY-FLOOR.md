# Sealed-host idle delivery floor

1 November 2026. The sealed host now primes one charged two-peer watermark column before its baseline and reserves eight callback buffer permits before activation. A clean tick shares the unchanged watermark owner; it does not request another pool allocation for the group. The host acquires one callback permit before the first authority step, then requests a vector of at most `D = min(max_ticks_per_call, CPU-admitted ticks, 8)` publication slots. One shared floor charge covers eight such buffers, their permit owners and the floor owner. The directory itself is fixed inline storage. Each callback or consuming iterator keeps its permit until its buffer drops, even after iteration is exhausted. A retained permit keeps the floor charge alive after the host drops. An empty failed callback returns its unused permit.

This is a logical requested-capacity charge. Allocator metadata and surplus allocator capacity remain outside the pool, as elsewhere in the qualified storage path. A permit can be acquired under full pool contention because its bytes were protected at host construction. Eight independent permits are needed even when `D > 1`: eight old callbacks may each hold one publication. A ninth live buffer returns `PublicationBackpressure` before the authority step; the clock retains that tick for one retry. This finite-reader condition cannot be relieved by another world's pool release.

The [unit fixture](../../../crates/thrum-core/src/host.rs) constructs a sealed two-peer host with a zero-object world, fills all remaining pool bytes with a competing reservation, and runs 16 clean callbacks. It holds the first callback while the later ones complete. The test runs with configured per-call limits of 1 and 16; all 16 authority and replica ticks commit once, both peer watermarks remain valid, and pool usage stays at its limit. A separate test consumes eight callback publications into exhausted iterators, then holds those iterators while their snapshots are gone. The ninth callback reports backpressure without advancing tick 8; releasing one iterator lets the same clock timestamp commit tick 9 exactly once. A nine-tick catch-up with a configured limit of 16 stops explicitly at eight retained snapshots before the eight-slot callback vector can overflow, then retries the ninth tick after release. Dropping the host before the remaining iterators retains the floor charge until the last iterator drops. An unqualified authority still reports `Unqualified` during sealed-host setup. The existing two-peer changed-group test still checks an actual due action blocked by a full competing pool before edits, then retries once after release.

`RUSTC_WRAPPER= cargo test --locked --offline -p thrum-core` passes. The local [release fixture](../../../crates/thrum-core/examples/i1_charged_replica_cost.rs) runs 1,000 warmups and 10,000 measured one-action callbacks per profile. Two macOS/aarch64 release runs, with prototype then charged paths in each run, gave these submit/callback/acknowledge p50 nanoseconds:

| Objects | Prototype, runs 1 / 2 | Charged, runs 1 / 2 |
| ---: | ---: | ---: |
| 64 | 1,083 / 709 | 1,084 / 833 |
| 4,096 | 1,042 / 1,083 | 1,125 / 1,167 |

The run-to-run variation is larger than the small differences in some comparisons. This fixture tests one replacement action per callback with immediate acknowledgement, not long-lived callback buffers, real device scheduling or the process-wide byte gate. It does not qualify the remaining replica progress scratch, completed history, future input execution credits or mutable world indexes.
