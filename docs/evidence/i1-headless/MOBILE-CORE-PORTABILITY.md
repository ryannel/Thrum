# Portable headless core on mobile Rust targets

2 November 2026. The pinned Rust 1.99.1 toolchain cross-compiles `thrum-core` for `aarch64-apple-ios`, `aarch64-apple-ios-sim` and `aarch64-linux-android` with `RUSTC_WRAPPER= ./dev check-mobile-core`. The command uses locked offline Cargo resolution and the repository's pinned compiler path. Xcode 27.2 and iPhoneOS SDK 27.2 were present on the local macOS 26.6.2 host; the three Rust target libraries were installed for the pinned toolchain. The standalone target checks passed. This is a **library compile proof**, not a linked app, simulator run or phone test.

The initial direct `rustup run 1.99.1 cargo check` invocation resolved a Homebrew `rustc` from `PATH`, which could not see the rustup-installed target libraries and reported a missing `core` crate. The repository's `./dev` wrapper prepends the pinned rustc directory before invoking Cargo; running the three target checks through it passed. The `check-mobile-core` contributor command makes that compiler selection reproducible. It is opt-in because these targets and Xcode are not installed on every contributor machine.

The selected I1 shell target remains an iPhone 13 on iOS 18+ and a Pixel 7 on Android 14+, with bundled initial content, basic input, pause/resume and surface recovery. Those are [design targets](../../design/BASELINE-SPEC.md), not tested configurations. This checkout has no iOS Xcode app target, Android GameActivity/Gradle package, Android SDK/NDK, or physical phone result. A portable Rust compile cannot exercise OS lifecycle, input, native library linking, UI, surface destruction/recreation or sustained cost. The [winit 0.30.13 iOS integration guide](https://docs.rs/winit/0.30.13/winit/platform/ios/) and [Android glue guide](https://docs.rs/winit/0.30.13/winit/platform/android/) define the selected host boundary; the actual shell must still be built and qualified.
