# I1 memory direction

2 November 2026. The engine will pursue low and stable memory use through ownership discipline, measured workloads and pressure response. A hard whole-process memory ceiling is no longer the target for the general native runtime or arbitrary game-authored rule work. The user explicitly selected this direction because a universal cap could obstruct useful games and force fragile preadmission machinery. This supersedes the earlier proposed whole-process gate in I1, while preserving the checked results of the existing bounded publication-pool profile.

The current pool still proves exact lifetime charges, old-reader retention, selected precommit refusal and two-peer progress under deliberately saturated pool fixtures. Those are scoped correctness and cost experiments, not a promise that the OS process or every game allocation is capped. Keep this specialized path available where a game selects a finite profile; do not require its output credits or scratch allowance for ordinary native rules. Count limits for queued ticks, retained readers and protocol windows still protect ordering and overload semantics. Format/file/graph bounds in source validation protect finite parser work and are a separate input contract.

For the general runtime, the next evidence should include complete game and multiplayer callback p50/p95/p99 cost, allocation requests, retained owner bytes, process RSS, long-running growth and pressure/eviction behavior on named devices. A targeted budget may remain appropriate for a specific platform, provider, optional effect or service process. Select it from measured workload and quality needs, with an explicit fallback, rather than treating one global cap as an engine invariant. No new general-memory maturity claim follows from this decision alone.
