# I1 charged snapshot authority bridge

1 November 2026. `Authority::try_new_snapshot_charged` now publishes tick zero through a process-shared pool and reserves a conservative immutable page/root peak before later tick mutation. Each due action contributes declared maximum edit and spawn counts. Actual prepared batches are checked against those declarations before application; a violation is terminal. The `World` charged publication mode then spends the reservation, so the authority cannot silently fall back to uncharged pages. This is a **snapshot-only bridge**, not whole-process memory qualification.

`RUSTC_WRAPPER= ./dev check` covers two authorities in one pool, a required old reader, host/clock backpressure before a two-edit `Collect`, retry after held capacity releases, replica convergence, and charge release only after the old snapshot reader drops. It also covers a two-edit/one-edit-bound terminal fault before those edits apply, 65 transient spawns and 65 retirements through a charged authority, sequential `Collect` then `Open` in one tick, and two peers competing for one collectible. The first peer commits and the second receives the same game rejection as the uncharged path. Existing old-snapshot, handle, clock and replica tests stay green.

The release fixture used macOS arm64, 64 fixed-size `Counter(u64)` objects, 1,000 warmup and 10,000 measured one-edit ticks per path, with input admission, publication, in-memory replica and acknowledgement. Three order-varied local runs (`tmp/publication-memory/charged-authority-a.txt`, `-b.txt`, `-reverse.txt`) gave charged tick p50 417–541 ns and prototype tick p50 375–542 ns. Complete p50 ranges were 708–875 ns charged and 666–958 ns prototype. Both copied one 32-object page and one group object per tick. The charged fixture retained 4,256 logical page/root bytes at the end. A later fixture (`charged-authority-idle.txt`) measured 10,000 no-action ticks: both paths had a 42 ns p50, zero page copies and the same shared 4,096-byte logical snapshot view. Zero-byte reservations avoid atomic pool counter updates. These overlapping measurements support only local non-regression within timing noise; they do not certify a device budget or general memory bound.

The pool accounts for its own page/root owners and in-flight snapshot reservation, not allocator metadata or OS resident memory. It does not charge mutable slots and indexes, game-owned heap inside `Entity: Clone`, input history, group/result/event buffers, baseline deep copies or replica maps. The declared edit counts are game-contract bounds; `prepare` may still allocate before they are checked. The [remaining memory gate](../../design/I1-HEADLESS.md#publication-memory-admission-gate) must enforce finite payload/output profiles and reserve the complete authority-plus-required-replica peak before closing the parent work item.
