## Consequential findings

1. **[P1] A motion file can be labelled `fixed-fixture` despite mid-clip changes or a stopped source.** The recorder keeps rendering while `motionActive` guards Probe, Capture, GPU checks, and quiet timing. Its validity check compares only start/end optical epoch, play flag, options, weather input sliders, and camera. A Front click changes CPU weather without changing those compared inputs. Pause→Play, rate changes, or an input/camera change reverted before the end can also leave the endpoints equal. A device/source fault can stop new images while the endpoint settings remain equal; the nonempty WebM blob does not prove image or source progress. Record a monotone fixture-mutation/fault generation across all control, camera, playback, rate, front, reset, configuration and device-loss events, and require a healthy end with source and submitted-image progression appropriate to the selected rate. Keep the start/end frames and explicit `fixture-changed`/`unavailable` result. Actual canvas recording is useful evidence, but this label currently overstates its stability.

2. **[P1] Long background return needs a declared optical epoch recovery, not a stale-history fault left as the default user path.** Weather remains CPU-owned and correctly advances independently. `Scene.render` preflights the named source times against only ~66 committed WeatherFrames. With reported world ≈720 s and source ≈36.75 s, those old inputs are gone, so the preflight throws and `fail()` leaves optics unavailable; q cannot be reconstructed continuously from that history. The smallest default reset-optics path is: detect `scene.time < weather.history[0].time` before source mutation, stop using the old q, let the bounded `WorldClock` finish its catch-up to the requested current time, drain in-flight GPU work, then seed `Scene.reset(weather, currentUi, false, clock.time)` as a **new optical epoch** while retaining CPU Weather, world epoch, events and commands. Record the reason, old/new source times, lost-continuity flag and new optical epoch. Waiting for weather catch-up matters because `WorldClock.step` commits at most 128 seconds per animation frame; immediately reseeding at each intermediate time during a 720-second return could produce repeated optical resets. If reset cannot complete, expose optical unavailable while CPU weather continues. Do not describe the new q as uninterrupted matter or as a replay of unavailable forcing.

3. **[P2] A current-time Cb reset needs a coherent moving chart and seed location.** The Cb seed in `source.wgsl` uses `length(x.xz)` around world origin; Cb local emitters, broad updraft, thermal heads and curl phase use current `windIntegral` (and z drift), while `Scene.bounds()` and camera target remain fixed near origin. After a long optical gap, a fresh body at origin can be detached from current source/thermal controls; at sufficiently large integrated wind, the live source exits the fixed ±12 km chart. For a reset-optics Cb epoch, derive one chart origin from the same current WeatherFrame (`I_W`, declared z drift), apply it consistently to the reset seed, storage bounds, camera/target and current source coordinates, or refuse the reset with an explicit out-of-chart status. This is a reset chart concern, not a request for physics or continuous q state conversion. The reported Cirrus case can recover its optical source without claiming Cb acceptance.

## Resource and ownership check

- The full-volume scene allocates 24 per-tick thermal head/band pairs (three in-flight frame slots × eight source ticks) plus zero bindings. Buffer sizes match 48 `ThermalHead` records ×48 bytes and 32 bands ×49 `u32` entries. Source-less providers create none of these thermal buffers. Their cost is part of `Gpu.allocations`/logical bytes, including when thermals are disabled in a full-volume scene.
- Each fixed tick writes its own frame/tick thermal pair before the velocity and q passes; all four q/carrier stage uniforms for that tick map to that pair. Cached source and velocity bind-group keys include both head and band buffer labels, so reuse cannot silently bind a prior tick's table. Three submitted graphs are the existing in-flight cap. Thermal bindings and cached groups live within the Scene and are released with its device on provider retirement. This static check found no unbounded per-frame thermal allocation or source-less provider leak.
- `recordCanvas` owns its canvas stream tracks and stops them in `finally`, including failure. MediaRecorder errors reject, and save responses are checked. It intentionally does not set `busy`, so source/world rendering continues during the clip; the endpoint test must therefore carry the burden of honest clip attribution. Capture output is a real canvas stream at a requested 15 fps, not verified displayed cadence or GPU timing.

Suggested narrow witnesses: simulate a long background gap and verify one reset-optics epoch at current committed weather after catch-up, unchanged CPU world/cause IDs and no stale q claim; record a Front click, Pause→Play, and device fault during three short diagnostic clips and confirm none is accepted as fixed-fixture; run one immediate Cb optical reset at nonzero integrated wind and check seed/emitters/chart/camera alignment before using its motion as family evidence.
