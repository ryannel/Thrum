# SESSION M2 deterministic in-memory match

The Mac runs use the registered reference crowd and one host plus four independently restored client worlds. The host sends admitted sets after the runtime commits. Clients verify the contiguous set stream before acknowledging it, then commit the same sets on their own playout clocks. The Rust harness compares each client's independently computed digest at every digest tick.

The clock preserves the slope from a frame already sampled at the committed edge. When a later poll can commit the next set, it carries on from the sampled position using only elapsed time since that sample. The lead test uses independently offset client clocks, including one at 1.0001 times host rate. The harsh conditioner is 125 ms one way with 50 ms of jitter each way and 5% loss.

On the steady harsh link the controller adjusted 24 to 43 times per client during the 65 seconds sampled after warm-up. That adjustment frequency remains visible in the record alongside the admission floor.

Warmed costs sample single-tick advances whose starting tick is a multiple of 16 after tick 600. Engine time covers input preparation and the registered runtime step. Allocation counts cover the session thread during the sampled advance, including its link calls. The carrier records the virtual network separately.

Mean warmed host engine time was 14.79 ms at A0 and 14.26 ms on the harsh profile under load. Mean session work in those samples was 38.85 µs and 34.78 µs, with about four allocation calls per host advance. Per-peer host output was about 15.2 and 23.8 kB/s, respectively, and triggered the 64 kbit/s tripwire in both runs. Repeat-depth rows are separate clients with independent seeded paths and clocks.

One release invocation recorded Git state while the implementation checkpoint was being committed. Another recorded test edits in progress. An independent clean release build reproduced the executable used by all three proofs byte for byte. The raw receipts keep their original invocation metadata.
