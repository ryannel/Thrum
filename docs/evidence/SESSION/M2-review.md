# SESSION M2 review

**FAIL. Seven items pass and five fail.** The five worlds agree through both full matches. The host nevertheless accepts an expired negotiation, the playout clock undercounts a real stall, and some measurements describe the wrong player.

Reviewed at `a319249fb549`. The script ran the workspace gate and all eleven item checks on `5f49c732c3de`. The session implementation, transport, match harness and proof scripts are unchanged between those revisions. The supplied `git show 8067b526ebb1` concerns CLOUDS graph snapshots. I traced the SESSION implementation and tests through the module's own commits. M2 has no visual inspection or human-feedback item. Its target is the headless Mac match. The project’s lighting, camera and display conditions apply to rendered scenes.

## Findings

1. **M2.6 — Must Fix, verified. An expired hello renews its own deadline.** With the default 4,000 ms response timeout, I polled the host at 3,999 ms, then had a normal client send its first hello at 4,001 ms. It received a welcome and slot zero. The 3,999 ms control also joined. In `session/host.rs`, `receive` dispatches messages before testing the deadline at line 432. A valid hello moves the deadline to the join timeout at line 514. Enforce the expired phase's deadline before a message can advance it. The existing silent-peer test covers the empty queue. [Probe](M2-review/deadline.rs) · [Observed states](M2-review/deadline.txt)
2. **M2.9 — Must Fix, verified in source. A session call can wait on the carrier's loss observer.** The session itself schedules from caller time, uses the feature-free transport dependency registered in the architecture manifest, and contains no socket, game rule, sleep or await. The host encodes each committed set once and shares those bytes across peers. However, the new `Memory::advance_observed` takes the sending endpoint's state mutex at `crates/thrum-transport/src/memory.rs:227`, calls `schedule` under that guard, and invokes caller-provided code on datagram loss at lines 375 and 380. A concurrent session poll needs that same mutex to drain events or messages. Its wait can therefore last as long as an arbitrary observer runs. Move observer execution outside the guard. This is a lock-lifetime finding. I did not measure contention or exercise socket adapters. [Carrier](../../../crates/thrum-transport/src/memory.rs) · [Link queue operations](../../../crates/thrum-transport/src/link.rs)
3. **M2.8 — Must Fix, verified against both cost records. Held counts are attributed to the wrong repeat depth.** In the harsh run, player 0 uses depth one and owns slot 1. Player 1 uses depth two and owns slot 0. At `examples/match-proof/src/memory.rs:482` the probe indexes host admissions by player index. It reports 968 held ticks for depth one and 3,333 for depth two. The host slot counts imply **3,333 for depth one and 968 for depth two**. Three A0 slots are also permuted. Line 495 makes the same attribution error for per-player admission fractions in the lead record. Use the negotiated slot whenever joining a host counter to a client row and verify the mapping in a run with reordered hellos. [Builder cost record](M2/memory-costs.json) · [Clean check rows](M2-review/checked-cost-rows.json)
4. **M2.8 — Must Fix, verified. The cost command never compares a previous comparable row.** `scripts/session_memory.py:128` labels every invocation an initial measurement. For example, the retained harsh player 1 mean session time is 6.57 µs and the clean check measured 16.62 µs for the same workload. Host load differed. That qualifies for investigation under the quarter-worse tripwire, with the loads attached. Neither the change nor the absolute time should fail the command. The code has no previous-record lookup even when that record exists. [Retained costs](M2/memory-costs.json) · [Clean check rows](M2-review/checked-cost-rows.json)
5. **M2.8 — Must Fix, verified in source. The image tripwire measures only serialization.** The design flags a host tick that runs long while writing the image. `session_memory.py:123` compares the writer alone with a full tick period. All four images in the cost harness are written in the lobby before `host.start`. There is no measurement of a running tick that both writes an image and performs its ordinary work. Record the whole image-writing tick so that two individually short operations whose sum overruns the period are visible. I inspected the timers and recorded samples. I did not infer an overrun from unrelated maximum values. [World instrumentation](../../../examples/match-proof/src/memory/world.rs) · [Match harness](../../../examples/match-proof/src/memory.rs)
6. **M2.12 — Must Fix, verified. The stall duration omits the interval ending at recovery.** On the in-memory link, the client stalled at position 24. I resumed the carrier and kept polling the host while sampling the client's held position before its next advance. Position 24 held for at least 202,500 µs. The client resumed at 24 without a skip and emitted a 2,500 µs stall. `session/clock.rs:177` counts elapsed time only if the current poll ends blocked. Account for the elapsed interval actually spent held, including the recovery poll. The cost record consumes the same public duration. [Probe](M2-review/playout.rs) · [Observed positions and duration](M2-review/playout.txt)
7. **M2.12 — Must Fix, verified in source. The match cannot set its playout rates.** Mechanism 6 specifies both rates as match settings and the M2 plan assigns the complete playout clock to this milestone. `session/clock.rs:144` and line 146 fix the rates at 1.1 and 0.85. Neither `Settings` nor its welcome codec carries either value. The current movement assertions exercise only the defaults. Verify the same promise with a different negotiated rate. [Playout design](../../plans/SESSION/DESIGN.md#6-the-playout-clock) · [Clock](../../../crates/thrum-network/src/session/clock.rs)
8. **M2.3 — Must Fix, verified in source. The initial authoring tick uses half the specified round trip.** Mechanism 5 places the starting authoring tick at the newest set tick plus the handshake round trip in ticks plus the starting lead. `Lead::new` adds `half_rtt` plus the starting lead at `session/clock.rs:210`. The half-trip estimate also used later for reporting is appropriate there. The check drops the first 600 ticks before evaluating the admission floor, so it allows the adaptive controller to compensate for this startup discrepancy. Check the first target against the design as well as the settled floor. [Input lead design](../../plans/SESSION/DESIGN.md#5-the-input-lead) · [Lead implementation](../../../crates/thrum-network/src/session/clock.rs)
