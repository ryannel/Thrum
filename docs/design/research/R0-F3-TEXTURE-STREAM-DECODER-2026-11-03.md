# R0 texture source bytes without an F3 texel copy

3 November 2026. **Selected decoder representation, pending implementation and measurement.** A reviewed candidate replaces the earlier object-wide decoded texture scratch assumption in the [shared F3/F4 decoder API](R0-F3-F4-SHARED-DECODER-API-2026-11-03.md). This changes no source meaning or active F3/F4 path. The one versioned source grammar remains in thrum-source; F3 and F4 use different projections over the same validated bytes.

## Field and byte path

The texture map borrows raw field values before interpretation, so JSON may place the rgba8 token before dimensions. Validate in fixed schema order: canonical ID; positive integer width; positive integer height; transfer format; then rgba8. Checked u64 arithmetic computes decoded byte count N = 4 × width × height and canonical padded encoded character count E = 4 × ceil(N/3). Reject overflow or a count incompatible with the already checked record-byte limit before any variable heap output is allocated. These are source constraints, not an F4 target texture-size limit.

The rgba8 token is a JSON string. Plain ASCII content can borrow the bytes between quotes and compare its length directly with E. Escaped spellings must have the same decoded meaning: an allocation-free JSON string reader emits ASCII base64 characters, counting E before decode and rejecting any decoded non-ASCII character. It accepts equivalent escapes such as escaped slash and Unicode escapes for ASCII symbols. Neither path builds a whole decoded String or texel Vec. A checked-header token must precede this decoder; the raw object function alone does not prove the 16 MiB, node or depth limits.

Pin and register the already cached base64 0.23.1 as a real thrum-source workspace dependency when implementing this slice. Its standard engine provides allocation-free decode-into-slice, requires canonical padding and rejects nonzero tail bits under its default configuration, matching [RFC 4648 canonical encoding](https://www.rfc-editor.org/rfc/rfc4648.html) and the [base64 engine API](https://docs.rs/base64/0.23.1/base64/engine/trait.Engine.html). Feed four-character-aligned encoded chunks into fixed decoded scratch. Every nonfinal chunk must contain no padding and produce exactly three bytes per four symbols; the final chunk must complete exactly N decoded bytes. A 16 KiB encoded / 12 KiB decoded chunk is a **measurement candidate**, not a frozen size. Compare the crate's scalar and default accelerated feature profiles before selecting its build configuration.

F3 validates every declared texture and discards each decoded chunk immediately, retaining compact ID/dimensions/format and required graph facts only. F4 repeats the same validation from a completely verified accepted-pin copy, then emits borrowed decoded chunks into a provisional product sink; it cannot publish a partial texture if source, sink, edge closure or later target checks fail. The semantic product key uses decoded bytes and typed meaning, so plain versus escaped JSON spelling does not force a different texture product. Exact source revision still binds the original file bytes. F4 target Unsupported is decided after source structural/global closure and never passed as an early projection error.

## Proof and cost gate

Use independent encode/re-encode oracles for N mod 3 = 0, 1 and 2; missing, early and excess padding; nonzero pad bits; URL-safe alphabet and whitespace refusal; ordinary and escaped equivalent strings; base64 before dimensions; zero/overflowed dimensions; malformed JSON string escapes; callback refusal and discarded provisional output. Check F3 and F4 decoded-byte/product hashes against each other, including a large ordinary and escaped image. Measure parse CPU, allocation count, charged high-water and sampled RSS on small, 1280² and near-record-limit textures; compare 4/16/64 KiB chunk candidates and an object-wide Vec baseline on the named host. Include many-small-texture workloads, where per-object setup can dominate. Select the chunk and dependency feature profile from these measurements before activation.

This design does not charge Serde's private parser scratch, prove full operation memory or make any device texture-support promise. The first work-account tier remains explicitly scoped to F3-owned indexed buffers; texture scratch is fixed stack work when implemented.
