3 November 2026. **Implementation sequence, partly executed and still pending complete closure and measurement.** The [inactive complete render-root structural scan](../../evidence/render/R0-F3-RENDER-ROOT-STRUCTURAL-SCAN-2026-11-03.md) proves only one record's local grammar. The [registry structure](../../evidence/render/R0-F3-REGISTRY-STRUCTURE-ORDER-2026-11-03.md) and [required-edge barrier](../../evidence/render/R0-F3-REQUIRED-EDGE-BARRIER-2026-11-03.md) checkpoints now execute in the complete-candidate path. This note reconciles the remaining F3 steps with the [shared decoder phases](R0-F3-F4-SHARED-DECODER-API-2026-11-03.md), the [indexed-work policy](F3-RENDER-IDENTITY-WORK-POLICY-2026-11-03.md) and the [holistic limit policy](HOLISTIC-LIMIT-POLICY-2026-11-03.md). It selects no host byte allowance and activates no schema.

## Why the current candidate path cannot just call the root scanner

The exported `validate_staged_registry` still retains its registry-only collision check; the complete path now bypasses that early check. `validate_staged_records` completes declared local grammar before reporting required-edge capacity, but still sorts top-level IDs without source locators and resolves edge categories in separate loops. Adding render callbacks inside those loops would preserve the wrong global error order and could turn a semantic capacity refusal into a generic operational callback abort. The current scene@2 constant-light pinned cooker also hardcodes scene schema 2; scene@3 admission must not silently break that consumer.

The selected complete-candidate order is:

1. Registry structure: project, schemas by canonical path, carried history and registry consistency.
2. Every declared record's local structure by canonical path, including unselected render roots. Preserve provisional outputs only until this phase succeeds. A bounded header token from dispatch feeds `scan_checked_render_root` without a second whole-record walk.
3. Required-reference *capacity* barrier. Count the existing charged unit, saturating at 65,537; project entry selection remains uncharged, and containment creates no edge. After the 65,537th charged edge, drop no-longer-useful retained identity/edge/deferred slabs and continue every remaining local grammar check with no-op projections. Then report the existing source-profile capacity refusal after complete structural parsing. The root callback may not return this as `Projection(E)`. An already incomplete operational attempt has no semantic source result. The grammar's “before appending” rule is kept: never retain the edge that crosses the capacity boundary.
4. One complete namespace collision pass across project, history, schemas, scenes, games, all built-ins and every embedded render ID. The first equal-UUID pair uses one total locator key, independent of discovery or slab order. Consume `PreparedCandidate` into `NamespaceCheckedCandidate`, which owns both this namespace and the exact prepared roots/edges; neither input can be swapped from another attempt.
5. One operation-wide sorted typed-edge pass, including project entry, game/scene/environment, active camera, instance mesh/material and all present material texture slots. Check target kind, owning render root and texture transfer format. A zero factor does not erase a present texture edge. Retain the existing source rule that an entry environment scene requires exactly one project entry: evaluate it at that selected scene's `environment.source` edge locator before resolving that edge. Its count contributes no additional required-edge charge. Test its new deterministic position against dangling project/game/environment edges; do not silently drop the scene@2 rule. Only after **every** edge closes may `close_candidate_edges` consume `NamespaceCheckedCandidate` and produce a private `EdgeClosedCandidate`.
6. `finish_render_v1` consumes that same edge-closed candidate, checks mesh-dependent transformed bounds over all its roots and chooses the first deferred error by canonical locator. It cannot pair A's successful edge check with B's unchecked or omitted roots. Then release indexed work and construct the candidate summary. F4 target and device support run later.

Each phase is a barrier. A missing mesh edge beats a bound needing that mesh; a duplicate beats any edge; a malformed later declared record beats an earlier duplicate or edge. An operational reservation refusal may stop early as `ValidationIncomplete(ResourcePressure)` and makes no later semantic claim. The original source-capacity, disk-space and operational-pressure outcomes retain distinct types and units.

The identity and edge row layout is deliberately not frozen by this note. It must encode a canonical path/object/field locator without allocating a `SourcePath` or formatted string per embedded object. Use a compact path index into the already owned staged manifest and a fixed kind/owner/field discriminator; define equal-key tie handling before selecting a slab size. Only then can sort order, charged layout, diagnostics and worst-case memory be measured together. The prototype's 332,016 IDs and 24 MiB RSS are evidence of scale, not a validity cap or host allowance.

## Resource owner and guarantee scope

A host-owned attempt should begin before capture and live through final outcome resolution, so its phase and retry diagnostics have one identity. Its **first enforceable charged tier** is only the audited known-layout identity, edge, merge and compact deferred buffers used in validation. Charge checked requested layout bytes before each slab allocation, charge unused reserved slots, and refund after the final owner drops. A cooperative shared reservation owner accounts for concurrent attempts. Safe `Box` allocation may still fail or abort for OS reasons; allocator overhead, Serde/escaped-text scratch, mesh vectors, record buffers, staging, SQLite, F4/T2 and process RSS remain outside this first tier. Do not call the tier a total validation-memory bound. Add other allocations only after their ownership and fallible/allocation behavior are audited.

`ResourcePressure` is a retryable incomplete validation result with owner, phase, profile, requested/charged/available bytes and a useful action. It is not invalid source, disk `SpacePressure`, or a terminal keyed rejection. Preserve the old selected root and the same `(epoch, key, request_hash)` retry contract, binding the captured candidate hash after capture. An uncertain store commit still requires exact-outcome lookup before retry. The host allowance, free-space target and performance evidence do not enter `SourceRevision` or semantic cook keys. A changed built-in definition does enter the dependent cook-key closure.

## Qualification before claiming an admitted render source

Run semantic precedence mutants across registry, record, duplicate, capacity, edge and deferred phases. Exercise every edge kind in an unselected root, shared base/emissive sRGB textures, incompatible ORM aliases, zero-factor present textures and the authored fixture's 16 graph edges/15 charged required summaries. Pair edge-cap overflow with a malformed later record; assert the no-op projection retains no crossing edge, frees prior indexed slabs and makes no further indexed allocation. Include scene@2 multiple-entry/environment cardinality against a dangling edge, plus cross-attempt and omitted-root edge-closed owner mutants. Inject reservation refusal at each indexed-work phase and verify complete refund, concurrent ownership, no partial candidate, A pin survival and B retry with a raised allowance. Measure charged high-water separately from allocator estimates and sampled RSS, with old/new pin overlap and concurrent F4/T2 work. Compare small and dense 16 MiB roots, escaped IDs, all-fallback numerical cases and the actual accepted-pin F4 copy/cook path. The many-root fixture must state aggregate declared roots, total encoded bytes and JSON nodes as well as per-record maxima; isolated 16 MiB records do not qualify the complete candidate. A sufficiently funded selected profile must complete its stated finite source dimensions without an invented embedded-ID count cap.

No current repository check proves those integrated outcomes, a physical APFS floor, an F4 ready product or a device frame budget.
