# Rendering and environment evidence, 31 October 2026

This is the source ledger for the proposed [rendering](../modules/RENDERING.md) and [environment](../modules/ENVIRONMENT.md) contracts. It records material inspected, its maturity, and the design consequence. Links are to primary author, vendor, specification, or production documentation. Published results are evidence for candidate mechanisms, not measured results for this engine. Current code and older water experiments did not select the target.

The focused [temporal and composition study](TEMPORAL-COMPOSITION.md) records additional AMD, Apple, Epic, NVIDIA and Hillaire sections and their precise motion/transport consequences.

## Execution, GPUs, portability

| Source and inspected material | Maturity and consequence |
| --- | --- |
| Epic, [Render Dependency Graph](https://dev.epicgames.com/documentation/unreal-engine/render-dependency-graph-in-unreal-engine), “Render Graph Builder,” transient/external resources, async compute and Insights (UE 5.8 docs) | Shipped engine practice: declared pass resources enable lifetime analysis, culling, barriers and visualization. We propose these semantics; an independently packaged graph library and async queue are not automatically required. |
| Unity, [URP render graph](https://docs.unity.com/en-us/engine/6000.0/manual/render-pipelines/universal-render-pipeline/customizing-urp/render-graph/introduction), introduction/resource management | Shipped alternative: temporary textures are graph managed, imported persistent textures retain external ownership. Confirms the transient/history boundary. |
| Apple, [Tailor apps for tile based deferred rendering](https://developer.apple.com/documentation/metal/tailor-your-apps-for-apple-gpus-and-tile-based-deferred-rendering), tile shading, imageblocks and deferred sections; [Metal deferred sample](https://developer.apple.com/documentation/metal/rendering-a-scene-with-deferred-lighting-in-c%2B%2B), single versus two pass | Platform architecture and sample: preserving tile locality can avoid external G buffer traffic on Apple silicon; a two pass fallback is used on other Mac GPUs. This challenges an always-deferred portable renderer. Metal-only tile paths cannot be assumed available through WebGPU. |
| Arm, [Mali OpenGL ES developer guide](https://developer.arm.com/-/media/developer/Graphics%20and%20Multimedia/Developer%20Guides%20-%20PDFs/arm_mali_gpu_opengl_es_3-x_developer_guide_en.pdf), pixel local storage and bandwidth examples | Vendor guidance, older API: mobile tile bandwidth is a first-order cost. Use as architectural warning, then benchmark current devices and selected API. |
| W3C GPU for the Web, [WebGPU specification](https://gpuweb.github.io/gpuweb/), feature names/limits, device and resource validation | Evolving normative API: optional features and limits must be queried; native GPU/Metal features do not automatically appear in the browser. Browser coverage and performance remain unmeasured. |
| Apple, [Metal capability tables](https://developer.apple.com/metal/capabilities/), family feature matrix | Platform reference: ray tracing, mesh shading, sparse resources and advanced Metal features vary by family. “Mac” and “mobile” cannot be a single capability tier. |

## Visibility, surfaces, light, reconstruction

| Source and inspected material | Maturity and consequence |
| --- | --- |
| Olsson, Billeter and Assarsson, [Clustered Deferred and Forward Shading](https://highperformancegraphics.org/previous/www_2012/media/Papers/HPG2012_Papers_Olsson.pdf), cluster algorithm, forward discussion and results slides | Primary academic presentation, inspected as PDF slides, not watched. Derives light-list motivation and demonstrates forward/deferred cluster variants under its scenes; slides' performance ratios are not transferable to our cameras, shadows or mobile hardware. |
| Walter et al., [Microfacet Models for Refraction through Rough Surfaces](https://www.cs.cornell.edu/~srm/publications/EGSR07-btdf.pdf), §5.2 GGX/Smith equations and §5.3 sampling | Peer-reviewed material model, not an engine material system. Supports a physically interpretable reflection/transmission closure; diffuse, layering, texture conventions and energy compensation still need an authored contract. |
| Epic, [Nanite virtualized geometry](https://dev.epicgames.com/documentation/unreal-engine/nanite-virtualized-geometry-in-unreal-engine), supported geometry/materials; [Nanite SIGGRAPH 2021 slides](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf), virtual geometry/streaming | Shipped specialized path and disclosed design: virtual geometry requires cooked clusters, residency, coverage and fallback representations. It is a possible later provider, not the geometry baseline. Transparency, deformation, skinned forms and browser constraints need qualification independently. Slides inspected as slides, not a recording. |
| Epic, [Virtual Shadow Maps](https://dev.epicgames.com/documentation/unreal-engine/virtual-shadow-maps-in-unreal-engine), caching, invalidation and foliage | Shipped practice: deformation, moving lights and streamed casters can erase cached-page savings. Shadow quality and invalidation must be measured together. |
| Epic, [Lumen technical details](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine), platform, geometry and hardware/software modes | Shipped high-end system with explicit limitations and costs, including representation mismatches, skinned geometry updates and platform distinctions. It supports provider isolation, not adopting Lumen or promising its fidelity. |
| Unity, [URP Forward+](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@15.0/manual/rendering/forward-plus-rendering-path.html), benefits and limitations | Shipped rendering path; its documented orthographic-camera exclusion is a useful counterexample. Our selected path must prove both perspective and orthographic rather than inherit this limitation. |
| AMD, [FSR 3 upscaler integration](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-upscaler/), inputs, motion vectors, reactive and transparency/composition masks; [GDC 2024 integration slides](https://gpuopen.com/presentations/2024/FidelityFX_Super_Resolution_3-1_Release-Overview_and_Integration.pdf), motion vectors around slide 80 | Production SDK guidance: temporal reconstruction needs depth, correctly scaled motion, exposure and reactive data for particles/alpha/transparency. The exact AMD masks are provider specific; the engine must supply semantic inputs. Slides inspected as PDF, not watched. |
| Apple, [MetalFX](https://developer.apple.com/documentation/MetalFX), temporal versus spatial input requirements | Platform SDK: color/depth/motion are required for temporal scaling; spatial scaling offers a fallback. Compatibility and visual quality on our content remain untested. |

## Sky, clouds, world content

| Source and inspected material | Maturity and consequence |
| --- | --- |
| Hillaire, [A Scalable and Production Ready Sky and Atmosphere Rendering Technique](https://sebh.github.io/publications/egsr2020.pdf), abstract, scattering/LUT architecture and quality discussion | Peer-reviewed production-oriented paper: dynamic atmosphere with compact LUTs is a candidate for high quality sky and aerial perspective. It does not alone specify cloud weather, local fog, or all opaque/transparent composition. |
| Bruneton, [Precomputed Atmospheric Scattering: a New Implementation](https://ebruneton.github.io/precomputed_atmospheric_scattering/index.html), introduction, tests and implementation choices; [BSD source](https://github.com/ebruneton/precomputed_atmospheric_scattering) | Author implementation with tests; useful reference for validation and alternate precomputation. Its static/precomputed structure carries different update cost than rapidly changing atmosphere. License and code provenance must be audited before borrowing. |
| Guerrilla, [Real-time Volumetric Cloudscapes of Horizon Zero Dawn](https://advances.realtimerendering.com/s2015/The%20Real-time%20Volumetric%20Cloudscapes%20of%20Horizon%20-%20Zero%20Dawn%20-%20ARTR.pdf), layered 2D/3D clouds and rendering slides | Production presentation: mixed representations can fit cloud types/altitudes. The engine still needs its own causal weather field and light/occlusion contracts. Slides inspected as PDF, not watched. |
| Epic, [Volumetric Cloud component](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-in-unreal-engine), shadow modes, quality and supported platforms; [properties](https://dev.epicgames.com/documentation/unreal-engine/volumetric-cloud-component-properties-in-unreal-engine), directional light interactions | Shipped examples: cloud shadow maps versus secondary march trade accuracy for reach/cost; visible cloud rendering can be separate from attenuation. Its mobile table lists no volumetric cloud support, so mobile requires an alternate visual representation. |
| Epic, [Volumetric Fog](https://dev.epicgames.com/documentation/unreal-engine/volumetric-fog-in-unreal-engine), scalability and cost | Shipped screen-space volume example: froxel resolution strongly affects cost. Do not assume a full view volume is cheap for every camera or mobile profile. |
| Epic, [World Partition](https://dev.epicgames.com/documentation/unreal-engine/world-partition-in-unreal-engine), grid, streaming sources and level lifecycle; [PCG overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-overview), points/authoring | Shipped world tooling: authored cells and procedural recipes can share stable identities and streaming. The render scene consumes activated content; it must not own canonical world cells or procedural truth. |
| Epic, [PCG GPU processing](https://dev.epicgames.com/documentation/unreal-engine/using-pcg-with-gpu-processing-in-unreal-engine), beta note and supported nodes | Beta shipping feature: GPU procedural generation is useful for some workloads but is not a baseline content or authority requirement. |

## Evidence limits and next reads

These documents were inspected as linked pages or PDF text, not by running their sample projects. Qualcomm/Adreno current architecture guidance, current mobile browser GPU support and packaging, and a full native Metal versus portable WebGPU feature comparison need specialist verification. No source measures this engine’s visual quality, memory, frame time or app-store acceptance. The documents below therefore mark mechanisms provisional and put representative cross-platform comparisons ahead of selection.
