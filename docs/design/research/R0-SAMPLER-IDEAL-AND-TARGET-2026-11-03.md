# R0 material sampler: ideal source meaning and target realization

3 November 2026. **Source-meaning selection, pending F4/V3 device proof.** The [render-v1 grammar](R0-F3-RENDER-SOURCE-GRAMMAR-2026-11-03.md) needs one mathematical interpretation of `nearest`, `linear`, three address modes, RGBA8 transfer and masked alpha. WebGPU specifies their broad behavior but leaves precise filtering implementation dependent; a device sampler is therefore an implementation candidate, not the source oracle. [WebGPU samplers](https://gpuweb.github.io/gpuweb/#samplers), [WebGPU texture formats](https://gpuweb.github.io/gpuweb/#texture-formats).

## Ideal source law

Texture bytes are straight (unassociated) RGBA8, upper-left-origin rows with one level. Dimensions `W,H≥1`. Normalized UV `(0,0)` is the top-left *edge*; texel `(i,j)` has center `((i+1/2)/W,(j+1/2)/H)`. The ideal products, floors and weights below use exact real arithmetic and mathematically unbounded integer tap indices, even for a very large finite authored UV. For one selected filter mode and finite UV `(u,v)`:

- Nearest uses unaddressed integer coordinates `i=floor(Wu)`, `j=floor(Hv)`, then applies the selected address operation per axis. An exact midpoint tie chooses the higher unaddressed index. This is **Thrum's** rule, not a WebGPU precision guarantee.
- Linear uses `x=Wu−1/2`, `i=floor(x)`, `a=x−i` and likewise `y=Hv−1/2`, `j=floor(y)`, `b=y−j`. Address each of the four integer taps independently; bilinearly combine with real weights `(1−a)(1−b)`, `a(1−b)`, `(1−a)b`, `ab`.
- For extent `N`, clamp maps `k` to `[0,N−1]`; repeat maps by mathematical modulo `N`; mirror maps `r=k mod 2N` to `r` when `r<N`, otherwise `2N−1−r`. This defines negative UVs and seam/turn behavior without a hidden prewrap step.
- Convert each stored byte to `c=byte/255`. For sRGB RGB, apply the ideal sRGB EOTF `c/12.92` when `c≤0.04045`, otherwise `((c+0.055)/1.055)^2.4`, **before** filtering. Alpha and `rgba8-linear` data channels stay in their linear stored unit interval. Filter RGB and alpha independently.

All material slots use `uv0` and one authored sampler. Missing maps bind the typed neutral values in RENDER-SPEC. The selected min/mag mode depends on the evaluator's footprint/LOD policy, which must be versioned and qualified in F4/V3; either authored mode remains valid F3 source. For `mask`, coverage is `sampledBaseAlpha × baseFactor.a ≥ alphaCutoff`, including equality, for the **same surface sample** in depth, shadow and forward roles. Shadow and camera images generally sample different surface points; whole-image bit identity is not the contract. The [glTF texture convention](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#images) supports the chosen origin and transfer-before-filtering intent but does not supply this exact Thrum tie rule.

## Finite target proof and performance choice

F4/V3 revisions bind source-f64 to product precision, UV interpolation and range reduction, mode/LOD selection, arithmetic order and contraction, transfer implementation, texture/view formats, sampler/shader bytes, compiler/backend and device support. A change to that evaluator changes the dependent product key, not admitted source meaning. Quantify error against the ideal sampler and define cutoff-boundary classification: an ambiguous error interval needs a robust path or typed `Unsupported`, not a silent alpha flip. Equal min/mag modes remove one masked pass difference but do not prove exact samples. The first R0 target may require equal masked modes, one mip and anisotropy one as a support rule while F3 accepts all valid modes.

Prefer qualified hardware sampling when its measured error and frame cost meet the selected workload. Compare an explicit `textureLoad` four-tap path and predecoded linear-light texture only where needed; both add ALU, preparation, residency or bandwidth and neither alone proves identical arithmetic across devices. [WGSL texture built-ins](https://www.w3.org/TR/WGSL/#texture-builtin-functions), [Direct3D sampling precision](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm#PointSampleAddressing).

The conformance set needs 1×1, 2×2, odd/non-square textures, every center and tie, negative UVs, repeat seams and mirror turns with adjacent values. In particular, for `N=2` and mirror repeat, nearest `u=0.5` selects texel `1`, while `u=−0.5` selects texel `0`; test immediate neighbors of both. Cover all 256 sRGB byte decodes; black/white midpoint proving decode-before-filter; linear alpha/data; and factor/cutoff equality neighbors in each pass at the same surface sample. Then test perspective, minification, oblique and moving views with separate interpolation diagnostics. A nearest discontinuity can turn an arbitrarily small UV error into an order-one alpha error: F4 must state a UV/interpolation domain and a discontinuity-aware boundary mechanism, robust path or typed refusal. Finite fixtures and a scalar sample-ULP bound cannot certify every legal source. Measure whole R0 shadow/depth/forward cost, resource overlap and sustained frame tails on named devices. No such device proof is claimed here.
