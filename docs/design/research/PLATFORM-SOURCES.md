# Platform/runtime primary-source evidence

Inspected 31 October 2026. This is a source record for [the platform/runtime design](../modules/PLATFORM-RUNTIME.md), not device certification. Version labels are those displayed by the source pages when inspected; pages without a stable version are dated by inspection. Summaries are paraphrases. No comparative build, device trace or store-submission test was performed. The scheduling DAG, generation invariants, frame/deadline relation and memory peak equation in the design are deductions from dependency and ownership constraints; they are not claims that a source prescribes this exact engine architecture.

## Derived design decisions and remaining qualification

The callback/lifecycle sources imply that a continuously polled desktop loop cannot be the shared host contract. The design therefore gives the platform callback thread surface ownership and feeds a separate world-step coordinator. Surface/device loss sources imply that transient presentation resources and durable world/content identity have different lifetimes; the design uses separate generations and publication barriers. Browser background/audio/thread restrictions imply a single-thread-capable baseline with explicit pause/resume and user-gesture audio. Apple tile and Android pacing sources imply that pass traffic, frame deadline tails and sustained thermal behavior belong in the cost model, rather than a renderer-only median benchmark. These are reasoned architectural commitments. Numeric costs and specific SDK bridge compatibility remain unmeasured.

1. **Portable GPU qualification:** first derive pass graph, resource lifetime, shader feature requirements and predicted attachment/bandwidth costs for the representative material/light/transparency/environment/reconstruction path. Then check API representability and predicted cost on actual Mac, Windows, browser, iOS and Android targets. A raw path is warranted only for a named failure or measured gain with a maintenance estimate.
2. **Mobile bridge qualification:** retain the designed lifecycle and ownership state machine; use SDK inspection to specify the minimal winit/android-activity or GameActivity bridge, then validate lifecycle, touch/controller/IME, frame pacing, packaging and thermal response on devices. The experiment checks bridge compatibility, not whether the runtime should have one world clock.
3. **Clock/residency validation:** derive the maximum concurrent tick work, queue byte limits and peak overlap for a specific scene. Exercise two cameras, async stream-in/out, background/resume, device recreation and headless replay against explicit predictions: one tick authority, zero stale publications, bounded queue/memory, predictable resource retirement and reported overload. A failed invariant forces a design correction before extension.
