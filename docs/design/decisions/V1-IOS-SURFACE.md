# V1 decision: thin iOS simulator surface shell

4 November 2026. **Selected for the first simulator diagnostic; physical iPhone qualification follows V1 on rented devices.** The iOS app runs the existing V1 `FrameHost`, fixed-step W1 simulation and `thrum-render` scene. UIKit and Winit own only the process/window/surface lifecycle. No phone-specific game rules, world or renderer are introduced. This follows [C02/C06](../CONTRACTS.md), the [bounded frame host](V1-BOUNDED-FRAME-HOST.md) and the [phone foundation](../../evidence/i1-headless/MOBILE-APP-SHELL.md).

The separate `v1-scene-ios` static library is a packaging boundary: Swift links the Rust library and implements UIKit's required scene delegate, while `v1-scene` retains its Chrome `cdylib`. Winit 0.30 creates its `UIWindow` using `init(frame:)`; on the installed iOS 27.2 simulator that window did not receive redraw events until attached to the active `UIWindowScene`. The Swift delegate receives a borrowed `UIView` pointer from Winit's raw handle, takes no ownership of that pointer, assigns the view's owning window to the scene, and retains the window for that scene. The Rust call is synchronous on UIKit's main thread while its `Arc<Window>` owns the view. The one narrowly expected `unsafe_code` block and exported C entry point are the complete ABI exception. See the upstream [Winit iOS scene issue](https://github.com/rust-windowing/winit/issues/4224) and [Apple's scene delegate contract](https://developer.apple.com/documentation/uikit/uiwindowscenedelegate).

The shell acquires a drawable only when a world update is due and a GPU slot is free, then passes that view to the shared host. A surface failure sheds only the view. Hidden/paused time does not enter W1; accepted queued ticks drain before resume. Visible overload counts refused elapsed ticks, pauses, drains and restarts from a fresh time origin. The first diagnostic used a 640×360 prepared image with a fixed-aspect surface pass, producing large portrait bars. [G3b iOS M7](../modules/PLATFORM-RUNTIME-IOS.md) now selects current full-bounds oriented pixel extent for the iOS scene, internal targets and presenter, with preserved vertical camera field of view. This supersedes that framing deferral; implementation and simulator proof remain owed. G4 retains later reconstruction/governor policy. The iOS simulator adapter exposes 15 interstage shader variables, below wgpu's default request of 16; requesting downlevel limits with the adapter's resolution limit prepares this scene without asking for unsupported capacity.

The [first named simulator result](../../evidence/render/V1-IOS-SIM-2026-11-04.md) proves process launch, one scene attachment, shared rendering and 600 completed surface frames. It does not qualify a physical iPhone, power/thermal behaviour, GPU pass timing, background/resume/device-loss recovery, input, cooked visual replacement or visual quality. Keep these as separate gates. The per-frame Swift bridge cost is zero: it runs only when a Winit window is created. Scene preparation remains a startup cost and must be measured on a physical target before a shipping shell is selected.
