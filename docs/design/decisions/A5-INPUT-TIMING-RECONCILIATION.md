# A5 decision: timed input staging and controlled prediction

4 November 2026. **Selected for the V1 four-peer fixture; preallocated staging and an encoded no-socket 600-tick input run pass, while state deltas, client prediction/reconciliation and device qualification remain open.** This refines [the N1 transport/codec decision](A0-N1-TRANSPORT-CODEC.md), [the input packet](A5-INPUT-WIRE.md) and [C02/C13](../CONTRACTS.md). The existing W1 `Simulation::admit_frame` accepts only the next authoritative tick and must remain the sole gameplay admission gate. N1 may hold future input bytes and frames, but a transport receipt neither commits gameplay nor changes a world component.

## Timing and ownership

At 60 Hz, the selected conditioner delivers one direction in two to four ticks: roughly 50 ms one-way within a 100 ms RTT and 20 ms jitter envelope. The first fixture sends controls for estimated authority tick **current tick + 5**. This gives each sample at least one tick of arrival margin under the conditioner's four-tick maximum. It is a fixture policy, not a universal game latency setting. Sessions negotiate tick rate, lead and maximum future window before play; different rates require a compatible recipe. Clients batch the new frame with recent exact frames to recover isolated loss, never inventing a new sequence for a retransmission.

N1 owns a preallocated per-peer, per-target-tick staging window. A frame is copied or moved into exactly one future slot after sender, connection epoch, actor, finite normalized axes, message size and target window checks. The first valid frame for a peer/tick wins; an exact resend is idempotent, a conflicting frame is rejected. Arrival order may differ from tick order. Late, too-far-future and old-epoch frames refuse before changing the window. A slot is never silently overwritten. At each W1 pre-tick barrier, N1 moves at most one due frame per peer to `Simulation::admit_frame`, in stable peer order. W1 rechecks authority, actions and current ownership. If no frame is due, W1 holds the previous axes and never repeats one-shot actions. A rejected due frame leaves the world unchanged and produces a typed result; all admitted due origins are reported committed only **after** `Simulation::step` commits. W1 now exposes that exact committed-origin slice in its borrowed tick outcome; a failed tick emits no outcome and retains the same pending frames. The retained N1 result/ACK owner remains open. A reconnect flushes the old staging and prediction branch before binding a new epoch.

The selected initial client prediction closure is one owned kinematic controller against immutable static collision. It captures pose, velocity/contact/controller state, exact input sequence/tick and collision revision in a 64-tick, at-most-256-KiB ring. Confirmed replica state stays separate. The client predicts through its current input horizon for immediate local response. A complete authoritative state/result group at tick `t` retires every individually resolved input represented by that state, restores the controller at `t`, and replays only unresolved later inputs. A matching state within the declared position/rotation tolerance can keep the branch; a correction beyond 2 mm or 0.05° resets affected render/effect histories. Replay is capped at eight ticks or 1 ms per presented frame, with a partial result kept unpublished. If it cannot catch up in four frames or the collision revision differs, discard the branch and show confirmed state. Prediction cannot commit authority or irreversible effects. The 10k fixture has empty static collision initially; this does not qualify a collision provider.

## Cost and first executable gate

Four peers × eight future slots are 32 retained input owners; direct tick-indexed access avoids sorting and per-tick queue allocation. Four × 64 prediction records store only owned controller state and exact input payload, not 10k world snapshots. At most four due frames enter one W1 tick. The link conditioner and codec record sent/delivered application bytes, dropped packets, duplicate/late frames, due misses, CPU encode/decode and allocations; W1 now reports the exact committed input origins at its successful tick barrier. Packet reorder counts, rejected-result retention, correction distance, replay steps and visual age remain open. The first executable gate runs the same 10k/1.5k-moving world for 600 ticks under the fixed-seed four-peer conditioner, including a deliberate burst-loss and separate reconnect case; it compares authoritative ticks, identity and held axes against an independent trace. The first [schema-declared input packet](A5-INPUT-WIRE.md) now runs in that diagnostic; an acked-baseline state delta still must replace the provisional full-record R4 path. No 64-kbit/s, no-snap or sustained device claim follows from a local input-byte proof.
