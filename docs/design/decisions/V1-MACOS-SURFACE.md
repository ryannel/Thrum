# V1 macOS surface handoff

4 November 2026. **Selected first diagnostic surface adapter.** This extends the [bounded frame host](V1-BOUNDED-FRAME-HOST.md) under [C02, C05, C06 and C07](../CONTRACTS.md). The fixed-step world is the only game-state authority. The macOS event loop owns one window, one `wgpu::Surface`, its configuration and each acquired texture. The host owns the prepared scene, three in-flight GPU targets and timestamp batches. A surface is optional; the offscreen profile allocates no surface pipeline or binding.

## Frame transaction and recovery

The platform requests a redraw at the next clock deadline. A zero-capacity request/result handshake gives one worker ownership of `get_current_texture` and surface reconfiguration because the pinned Metal backend can block in `nextDrawable` with no timeout. The worker cannot accept a new extent until the event-loop callback has presented or dropped the prior acquired texture; wgpu rejects reconfiguration with a live surface texture. The event loop takes a ready texture without waiting, then calls the host with monotonic time and its view. The host first commits every admitted world update, then extracts and submits one latest-complete view if a GPU slot and valid surface are available. The fifth prepared pass reads the encoded SDR output directly and writes the acquired 8-bit attachment in the same queue submission. Only a report of `surface_presented` permits the platform to call `Queue::present`; an unavailable, late or stale surface skips the optional view with counters while world ticks continue. No ordinary callback waits for GPU completion or drawable acquisition. The platform counts occlusion, waiting and stale acquisitions separately from host view and report drops.

The source is a 640×360 diagnostic, displayed with an integer aspect-preserving viewport and black bars. A non-sRGB surface receives encoded bytes directly; an sRGB surface decodes before hardware encoding. Source texture/bind group, pipeline and graph closure are prepared once per device generation. Resize or Lost/Outdated recovery waits until all host GPU packets have completed before allowing the worker to reconfigure the platform surface; this avoids concurrent queue submissions during wgpu's configure wait. The host then recompiles only its extent-dependent one-pass graph when a current-size texture arrives. A stale acquired texture is dropped. Zero extent defers acquisition. Device loss requires a new generation and host; that recovery remains open. The worker may remain blocked in Metal acquisition at process shutdown, so this bounded diagnostic does not establish a reusable cancellable surface lifecycle. An explicit GPU validation or fixed-clock fault stops this diagnostic rather than presenting an unvalidated frame.

## Cost and rejection conditions

The added per-present work is one full-screen texture load/write and a fifth timestamped pass. There is no CPU pixel copy, per-frame pipeline creation or intermediate render texture. Three existing 640×360 source targets remain GPU-owned until completion; the platform swapchain is additional, driver-owned memory. One bounded 600-frame window run must report complete callback CPU time, world ticks, surface failures, view/report drops and scene/surface GPU timings. The native Metal readback separately checks linear/sRGB byte equivalence and letterbox pixels. Reject this handoff if world ticks depend on drawable availability, an old target is reused before completion, a presented frame lacks the fifth pass, resize uses a stale extent or the callback waits for an ordinary GPU fence. Visual quality and sustained frame budget require an unlocked display and a named-device run; Chrome WebGPU and iPhone adapters remain later V1 work.
