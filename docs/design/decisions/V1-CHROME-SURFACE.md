# V1 Chrome WebGPU surface handoff

4 November 2026. **Selected diagnostic browser adapter.** The browser page owns one canvas and its `wgpu` surface; the existing V1 `FrameHost` remains the sole fixed-step simulation and prepared-render owner. The browser uses its serial execution route and the same four scene passes plus the surface presentation pass. No browser gameplay implementation or second world is introduced. The pinned `wgpu 30.0.1` WebGPU backend and `wasm-bindgen` canvas binding follow the [wgpu web example](https://wgpu.rs/doc/wgpu/documentation/platforms/web/index.html) and [Wasm browser guide](https://wasm-bindgen.github.io/wasm-bindgen/examples/request-animation-frame.html).

An animation callback samples a monotonic browser timestamp, advances the host once, acquires a surface only when a tick is due and an in-flight target slot is available, and presents only after the host confirms a surface pass. Failed acquisition drops the optional view while the world still advances. Lost/outdated or suboptimal surfaces are reconfigured after existing GPU packets finish; zero-size canvases defer acquisition. A hidden tab pauses admission. On visibility return, already queued updates drain in bounded host calls before the shared clock resumes from a fresh time origin. RAF timestamps may precede a same-frame `performance.now()` lifecycle sample; the adapter clamps that ordering difference and counts it. A visible callback delay beyond the clock queue limit produces an explicit `overload` report with refused tick count; the browser records that refusal, drains accepted work and resumes from the current time. The native diagnostics retain fail-fast overload policy. No refused wall-time tick is represented as a committed world update.

The adapter preallocates its 600-sample diagnostic buffer; callback work does not create a new game or shader. Browser `web-time` supplies CPU phase measurements because this Wasm target's `std::time::Instant` is unsupported. GPU timestamps are requested only when the adapter exposes them. The first gate is 600 presented Chrome WebGPU frames with source tick, CPU tick/encode, all five GPU pass times, zero hidden-time catch-up and explicit overload/resize probes. This diagnostic does not qualify a shipping browser profile, cooked source delivery, visual acceptance, sustained pacing, surface/device loss or non-Chrome browsers.
