# A5 decision: share image history across one connection

4 November 2026. **Selected and running in the local 128-interest slice.** The [four-partition result](../../evidence/v1-workload/A5-FOUR-PARTITION-2026-11-04.md) qualifies this specific fixture, not full-image repair or real transport. This refines the [A5 wire/session decision](A5-STATE-DELTA-SESSION.md) under [C13](../CONTRACTS.md). Multiplying the earlier 16-candidate/16-client ring by four partitions would reserve about 128 KiB of image history per peer before bases, scratch and packets, even if three partitions never change.

One connection owns four partition states and one sender candidate ring plus one client admitted-image ring, each with 16 slots. A record carries connection-wide image ID, partition/generation, tick and its complete 32-actor quantized image. Each partition keeps its own immutable confirmed sender base, initial client base, current client base and scratch. The one client datagram sequence owner is shared by `InputBatch` and `StateAck`; a separate server datagram sequence covers all four partitions. Baseline image IDs 1–4 are unique within each epoch; later samples use one checked monotonic allocator for the connection. An ACK can promote only a matching retained candidate with both newer image ID and tick for that partition. The client protects its currently referenced base outside the ring. Expired unknown ACKs are counted and ignored without mutation. Missing bases or exhausted required history request reliable full-image repair or disconnect; that recovery remains a separate gate.

**Cost account.** A complete 32-actor image is roughly 1 KiB at the current 24-byte visual pose plus wire identity. Two shared 16-slot histories cost roughly 32 KiB per connection, plus partition base/initial/active/received/scratch and packet slots. The measured four-peer combined fixture retains 273,184 bytes of visual backing storage, excluding allocator metadata, world and input/controller state; this is below a per-partition-ring layout's roughly 0.7 MiB but above the initial 0.2 MiB estimate because partition state and 32-packet lanes matter. With four active partitions publishing every three world ticks and a 2–4-tick link in each direction, at most about 12 image candidates await feedback; a 16-slot ring covers that controlled fixture. A 32-packet lane covers two overlapping 16-packet publication batches. These are fixture capacities, not general Internet bounds.

The first 128-interest workload places four controlled moving actors and 124 unchanged static actors in four sorted partitions. One W1 projection per partition is shared across identical peer interests. Unchanged groups send no datagrams unless an earlier divergent image may have reached a client; a zero-record correction then continues until an ACK proves quiescence. Interest membership changes stage all four images before mutation and switch generation for same-epoch observers; a new connection epoch resets its sequences. The 600-tick run, a four-active-partition ring stress and change→return/lost-ACK checks pass. This probes sparse interest and per-connection pool cost, but its externally staged baseline, synthetic 10k scene and missing exact result group cannot qualify the 64-kbit/s total downstream target. After V1, the network track follows with full-image repair, encoded lifecycle and exact controller/result closure.
