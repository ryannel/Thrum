# A5 decision: shared controller replay for the V1 conditioned game

4 November 2026. **Selected for the first four-peer V1 prediction slice.** This narrows [the input-timing decision](A5-INPUT-TIMING-RECONCILIATION.md) to the current 10k world, whose controlled actors have no collision or external resolve commands. [C02/C13](../CONTRACTS.md) still give W1 the only gameplay authority. Confirmed state and speculative controller state have separate owners. A future collision provider, authoritative teleport or game rule change must expand the captured closure or disable this predictor; a position-only rollback would be incomplete.

## Rule and history

Extract the current W1 controller calculation into one pure rule: validated held axes plus ordered impulses/damage derive velocity and health, then one fixed-step integration derives position. W1's input and simulate stages call those same calculations; the client gets an immutable rule configuration copied from the running world. Replay validates finite normalized axes, action count and numeric results before mutating a speculative state. Missing input holds the last axes and never repeats one-shot actions. A reconnect changes the binding/epoch and discards the branch before a new baseline.

Each client owns 64 tick-indexed records with each authored input's exact `Origin` and speculative complete controller state: binding, pose, velocity, health and held axes. The predictor first canonicalizes each authored axis through the same quantize/dequantize rule as the input wire, then stores that decoded value; raw UI values remain outside replay. Otherwise fractional axes would drift from W1's decoded controls. Complete groups from the existing delayed return lane update confirmed state first. A committed origin must match the authored record for that tick; a mismatch sheds speculation, while a missing result is counted even if held movement looks identical. This identity comparison is not reliable result delivery or application ACK. If the speculative state recorded at the group's tick matches within 2 mm for pose and 0.1 mm/s for velocity, with exact binding/health/canonical held axes, continue the current branch. Fixed `dt` does not promise cross-platform bit identity. Otherwise restore the complete confirmed controller at that tick and replay authored inputs through the latest local horizon; count correction distance and replay steps. No predicted value, effect or save commits authority. Missing history or incompatible binding discards the branch and presents confirmed state. The fixture's local horizon is authored target tick `now + 5`, so it includes the newest local control. With 2–4 ticks of ordered result delay, one correction needs at most 7–9 replay steps. This revises the earlier eight-step fixture cap to **nine** with one **shared 1 ms replay budget per presented frame** across all peers; the complete branch falls back to confirmed state on exhaustion. Broader partial-frame replay remains future work. Direct local input reaches the speculative branch at authoring, before W1 receives it.

## Cost and qualification

Four clients × 64 inline records bound the history without per-tick allocation; the largest replay is four clients × nine controller steps at one delivery instant. Store exact authored actions inline up to the fixture's eight-action admission cap, avoiding per-slot `Vec` owners. Reserve no 10k-world snapshots or collision state. The previous 600-tick complete run had a 35.24 ms Divan median, 134 setup/teardown allocations and zero allocations over 500 warmed ticks; these are the comparison baseline, not a predicted speed result.

Qualify with the same four-peer 600-tick 10k world and 100 ms RTT/20 ms jitter/2% loss conditioner. Check a matched branch, a fractional-axis and action wire-canonical case, a dropped-input correction against the independent authority trace, invalid action/axis refusal without mutation, a forced shared-budget fallback, and a unit-level incompatible-binding fallback. Measure replay count, maximum steps, correction distance, full-run time, retained history size and the warmed allocation assertion. An integrated reconnect must later reset both the confirmed owner and prediction branch from a new baseline; the current confirmed consumer refuses an epoch change. Render/effect history invalidation on a correction beyond 2 mm is also a later visible-host gate. Acknowledged state deltas, result/ACK retention, real transport, collision prediction and browser/phone multiplayer remain open.
