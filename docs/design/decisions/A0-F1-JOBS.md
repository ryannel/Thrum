# A0 decision: F1 runtime jobs and tick schedule

3 November 2026. **Status: selected graph semantics; executor implementation to measure in A1/A3.** `thrum-jobs` is a build-input owner, not the runtime job system. F1 owns one typed CPU graph over W1 systems and extraction. The authoritative tick follows `input → simulate → resolve → publish`; physics, AI and timers run every tick even without a discrete action. Each system declares component reads/writes plus named external resources. Conflicting writes or read/write pairs create ordering edges. An explicit stage edge always wins. No system can publish a partially resolved tick.

Native execution uses a long-lived work-stealing pool with `Send + Sync` systems, bounded task queues and priority classes for simulation, extraction and background work. [Rayon's pool/scoped work](https://docs.rs/rayon/latest/rayon/struct.ThreadPool.html) is the initial implementation candidate; compare it with a small dedicated executor only if actual contention or latency requires it. Parallel-for partitions dense component ranges into coarse chunks sized by measured work, not one task per entity. Main-thread device/window tasks are explicit graph nodes and cannot run on workers. Render extraction may overlap the next simulation tick only from a committed, retained endpoint; it never reads mutable W1 columns.

The same graph has a deterministic serial executor for headless tests and the first browser Wasm profile. Threaded Wasm is an optional later tier with its own browser isolation, workers and memory qualification. Parallel execution need not produce identical floating-point reduction order unless a game declares deterministic reduction; authoritative results must use an explicit stable order or serial reduction. Jobs can be cancelled before publication, but an accepted tick is committed exactly once. Failure faults the affected authority or presentation owner according to C4, without inventing a second world.

A1 measures graph validation and 10k-entity serial/native tick cost. A3 measures worker wakeup, contention, sim/extract overlap and allocation count after warmup. The initial acceptance gates are no heap allocations on the steady tick, no unbounded task fan-out, p99 tick latency within the V1 budget on a named desktop and phone, and no divergence between serial and parallel authoritative results. The existing two-stage headless scheduler is superseded only when this schedule runs and its regression tests pass.
