# V1 bounded in-flight frame host

4 November 2026. **Selected first offscreen frame schedule; native Metal diagnostic run.** This applies [C02](../CONTRACTS.md#c02-time-and-committed-state--f1-coordinator-w1-world), [C05](../CONTRACTS.md#c05-assets-streaming-and-retirement--f4-with-w2-v1-and-p7) and [C06](../CONTRACTS.md#c06-gpu-execution-and-lifetime--v1) to the running 10k scene. The fixed-step world remains the only simulation authority. This host is a serial executor for committed ticks and GPU submissions; a future platform adapter supplies its device, surface and event loop.

## Ownership and schedule

One prepared renderer owns immutable pipelines and a queue-ordered instance table. The host owns three generation-bound target/timestamp slots. Each slot moves through `free → rendering → resolving → free`; the optional timestamp resolve uses a later submission after render completion because same-submission resolution previously produced stale Metal counters. The queue callback only signals completion; the host polls, validates pass names, and publishes one CPU/GPU report for that submitted tick. A disabled or failed timing readback yields a counted missing measurement while the rendered frame still completes. A device polling fault remains a device fault requiring generation recreation.

Every callback first polls completion without waiting, then advances the shared clock. A due tick commits exactly once even if all three view slots are occupied. On ring pressure, the optional view is skipped and counted; no extraction, instance upload or GPU packet is made for it. The next submitted view extracts the latest committed endpoint. A skipped adjacent sample invalidates prior-position history, so it cannot silently borrow a nonadjacent tick for motion. The scene's GPU instance writes and submissions share one queue in order. The host keeps target/timestamp owners until their completion/readback, while the simulation never borrows an in-flight target or waits on a GPU fence.

Completed reports use a preallocated three-entry queue, sorted by world tick. A caller that does not drain it loses the oldest diagnostic report with a counter, never a world update. A report is delivered only after any older pending frame, preserving profiler chronology. Capture uses a separate temporary target outside the timed callback. Async worker-owned `SnapshotLease` and `RenderPacket`, surface replacement and device-loss recreation remain the next integration work; this first path has a serial extraction before submission.

## Cost and qualification

Three 640×360 targets retain about 34.5 MiB of logical depth/colour texels: two 1024² D32 Sun maps plus one Rgba16Float scene, one Rgba8Unorm output and one D32 depth attachment per slot. This is GPU logical storage, not process RSS or driver allocation. The three timing batches add small query/readback buffers. Frame callbacks allocate inside wgpu command/submission/timing machinery; the zero steady-allocation guarantee remains on the authoritative tick. The bounded ring trades that fixed residency for no per-frame GPU wait and explicit view shedding under pressure. The slot count is a first profile point, not a universal cap; tune it against actual platform latency and memory.

The [Metal run](../../evidence/render/V1-BOUNDED-FRAMES-2026-11-04.md) exercised 600 completed frames twice with zero dropped views/results/timing faults and full callback CPU p95 of 1.151/2.409 ms. It does not prove macOS surface pacing, Chrome/iPhone runtime or sustained frame-budget qualification. Rejection conditions for the next slice: a callback blocks on ordinary render/timing completion, a skipped view changes the committed tick sequence, a GPU packet frees before completion, a stale target/history is reused after generation change, or the event-loop path hides sustained view drops.
