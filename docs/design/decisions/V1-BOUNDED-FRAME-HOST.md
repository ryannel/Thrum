## Selected ownership and schedule

The platform owns the display link and surface generation. The engine host owns the fixed-step clock, game driver, two GPU slots and completion order. A generic boundary lends a committed page for game extraction into an owned render packet; game schema, rules, `InputFrame` validation and scene mapping stay outside the engine. One native worker owns host and queue. Optional display targets use a lossy mailbox; continuous axes may coalesce, but discrete actions use an ordered bounded FIFO with retry/backpressure. Resize and device controls use a reliable generation channel. Browser execution remains serial.

An independent monotonic wake admits due ticks without display callbacks. Local hidden play pauses/resumes from a fresh origin; network/dedicated authority continues. The worker uses actual now for ticks; future display target only sets alpha, clamped to committed endpoints. It samples the packet, updates view/lights/shadows and encodes. A separate bounded surface task may block on acquire; the host worker polls its generation-tagged lease without waiting, appends output only on match, submits or drops the view, and resumes tick service. No drawable or GPU fence wait blocks authority. Reused pixels retain sample time; history advances only after submission. Replay, product, resize and device changes invalidate histories; a full ring sheds views.

The surface task owns acquire and reconfigure; the host worker owns a transferred lease through submit/present/drop acknowledgement. Reliable resize/device control waits for old leases to return before reconfigure and generation advance; authority ticks continue. The host checks generation, device and extent and rejects stale leases/results. macOS targets `NSView.displayLinkWithTarget:selector:` and `targetTimestamp` in the pinned Xcode SDK; iOS uses its scene link, browser `requestAnimationFrame`. Convert callback and target times to one clock. Display cadence is independent of 60 Hz world updates; replace the timer wake before G3b closes.

## Cost and proof

At 10k/1.5k movers, 600 paired native first/half-tick samples cost 104.0/182.2 and 99.2/185.3 µs CPU encode p50/p95; each median GPU sum is about 0.28 ms. The optimized late submit still makes 125 UI-thread Rust allocations/16.7 KB per frame. Moving host/queue/surface work should remove those UI allocations; measure both threads and reject hidden growth. Two 640×360 slots retain roughly 23 MiB of logical texels, excluding driver residency.

Proof order: move the one game host off the UI thread and verify tick/input parity under mailbox pressure; use a real display-link target; test overlapping submissions and lifecycle invalidation; then move the generic coordinator into the engine. G3b requires 120 Hz ProMotion interval p99 within 1 ms, measured input-to-photon latency, zero steady UI-thread allocations and no lost ticks. The occluded window cannot prove cadence or latency.
