# G3 decision draft: executing render graph

4 November 2026. **Draft for independent review; G3 implementation has not begun.** C04, C06, C07, C12 and the [hardware-native decision](HARDWARE-NATIVE-ENGINE.md) govern this graph. One `FrameHost` in `thrum-render` consumes a leased committed G2 endpoint and a per-frame `ViewPacket`; the graph cannot read or mutate the authoritative world. The platform owns the adapter, surface and display link. The renderer owns GPU resources and execution. A game supplies mesh/material/product handles and view intent, never pass internals. No standalone fixture binary is added: the synthetic scene remains a content configuration of `examples/v1-game`.

## Closure and execution

The platform constructs one immutable `DeviceCapabilities` record per adapter generation, including backend/vendor/driver, features and limits, tile and memory traits, display/HDR, CPU SIMD/core classes, thermal and IO providers. It supplies that record to graph closure. Passes cannot probe the device privately; raw Metal access is isolated behind one backend module. Registry digest, recipe and shader variant enter profiling and cache identity. A device reset creates a new generation and closes a new graph before drawing.

Setup declares resource descriptors (2D, 3D, cube and array textures; buffers), pass reads/writes, clear values, persistence class, required capabilities, queue class and a `record` closure. Closures receive checked resource views, a command encoder/compute or render pass, and immutable frame data; they cannot allocate graph resources, query capabilities or retain transient views. Closure selects one recipe and builds the portable fallback at the same barrier. Portable uses forward+, GPU culling and indirect draws within WebGPU limits. Apple tile configures the same logical inputs/outputs as merged tile-friendly passes, memoryless depth/intermediates where supported and a measured raw-Metal escape hatch only where wgpu cannot express the win. The browser selects portable. Android tile and desktop-high remain post-V1; capability and resource declarations must be able to express them without changing game or frame APIs. Future sea/cloud consumers need compute-before-fragment, mipmapped arrays, 3D noise, wrapping and ping-pong histories, and async-compute-eligible passes; their implementation remains parked until after G7.

The compiler topologically orders passes, rejects missing producers and cycles, culls outputs with no same-frame consumer **unless** they declare present, readback or future-history publication, and computes first/last use for each transient. A published Hi-Z pyramid is therefore a live root even when its consumer runs next frame. The executor reuses compatible physical allocations from a generation-scoped transient pool; aliasing requires disjoint lifetimes, matching format/dimensions/sample count/usage and no outstanding submission lease. It derives load/store operations: first use clears or initializes; later use loads only when a prior producer exists; last use discards unless external/persistent/history/readback needs storage. It derives Apple memoryless eligibility from full in-pass lifetime and backend support, never an authored promise; depth needed for Hi-Z must be stored or resolved. Dynamic resolution and resize create a new pool generation; old resources retire after GPU completion. Pass-local timestamps are automatic around every render and compute pass, with unavailable/failed queries reported as absent, not fabricated zero. Passes may declare an epoch dependency or a bounded time-slice cadence; a skipped pass reuses a compatible committed history or an authored neutral resource, with age/reset telemetry and no uninitialized read. A quality governor may adjust cadence but never the simulation tick.

## Frame contract and hardware readiness

Every view carries jittered and unjittered projection, current and previous view-projection, C07 motion vectors, reversed-Z `Depth32Float`, reactive/transparency mask, exposure, camera cut and explicit history reset. Optional albedo/normal/roughness/hit-distance guides use the same source tick and view generation. Render scale is separate from native output extent. Own TAAU and MetalFX consume the same contract in G4; the graph produces correct history even before those providers ship. History compatibility keys include epoch, view, visual revision, surface generation/resize and recipe; source tick is sample metadata, not a key. Nonadjacent samples reset or use a separately qualified reprojection path; ordinary adjacent ticks retain history.

The G3 mesh arena uses stable logical mesh handles and nonmoving backing spans reserved for the lifetime of a future acceleration structure; replacement allocates a new span and retires the old after dependent submissions. A bindless material table has one shader-visible layout for raster, compute and eventual hit shaders. G1 dirty structural/component sets become explicit GPU upload and future acceleration-structure refit/rebuild inputs; G3 does not build ray tracing. The upload owner tracks the last **applied** `SnapshotId`, not the last extracted page: adjacent pages use dirty sets, while a skipped page triggers accumulated deltas or a complete reconciliation against the latest leased endpoint, including despawns and visual changes. GPU frustum and hierarchical-Z occlusion culling write compact visible instances and indirect draw commands. Occlusion can lag or be unavailable; a frustum-only path remains correct and counts its extra work. No CPU per-object draw loop is accepted as the 10k path.

Pipelines are compiled at graph closure. Live handles are keyed by adapter generation; persisted blobs use a stable compatibility fingerprint of adapter/driver/backend, feature and limit subset, recipe, compiler/cache format, shader source/specialization, layout and render formats. The on-disk cache is versioned and integrity-checked; a miss or invalid cache recompiles before the first draw and cannot change scene output. A two-day G3 spike decides **WGSL with Naga specialization** versus **Slang via passthrough** using required variant count, compile/cache time, Apple tile feature reach, portable/WebGPU output and cross-backend maintenance. No shader-source migration occurs until that comparison is recorded; either choice preserves the same material ABI and portable fallback.

## Cost and proof

The hot path performs no graph compilation, shader compilation, private capability probing or per-object CPU draw submission. Reuse command/resource arrays and bounded upload rings. Measure graph closure, cache hit/miss, transient peak bytes and aliases, pass GPU timestamps, culling work, draw count and CPU encode time in the one game at 10k. On the same physical iPhone, Apple tile must improve GPU time or bandwidth by at least 10% over portable with image difference inside the declared tolerance; both recipes remain measured from G3 onward. Verify load/store and aliasing under resize, device loss, skipped/timed passes, occlusion invalidation and held G2 page leases. An independent review covers the G2 publication, game content, C07 coordinates/time and platform surface seams before implementation.
