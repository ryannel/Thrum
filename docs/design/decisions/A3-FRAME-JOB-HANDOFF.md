# A3 decision: committed frame work on native workers

4 November 2026. **Selected schedule and ownership; executor implementation and device cost open.** This refines [F1 jobs](A0-F1-JOBS.md), [A2 extraction](A2-RENDER-EXTRACTION.md), [the bounded frame host](V1-BOUNDED-FRAME-HOST.md) and [C02/C06](../CONTRACTS.md). The 10k V1 host already has a preallocated W1 visual read-model page whose `Arc` lease survives later ticks. The next step is to consume that page on a native worker while W1 remains free to advance, without making the renderer another simulation authority. F1 must own one run-level typed plan: it composes the existing validated four-system W1 `Schedule` as an authoritative subgraph with visual capture, extraction and device nodes. The first worker proof may execute only this subgraph plus extraction; A3 stays open until the host actually compiles the combined dependencies and the serial/native executors consume that same plan. A standalone extraction queue with its own ordering rules does not satisfy the one-graph gate.

## Selected handoff

The dependency chain is `input → simulate → resolve → publish W1 tick → copy visual page → extract CPU columns → map/pack instance edits → main-thread upload/encode/submit → GPU completion/timestamps`. The copy is a committed read-model publication, never an alias of mutable hecs storage. The worker owns a `VisualSnapshotLease` and the reusable `RenderExtractor` for one extraction. It returns an owned CPU result with source `(epoch,tick)`, dropped-sample report and extraction duration; it drops the W1 lease before sending the result. The host applies the result to its sole prepared scene and queue, then recycles the extractor. GPU target/timing slots remain host-owned through fence/readback. No worker calls `wgpu` or touches a surface. The host admits at most one extraction in flight for this view, with a finite ready slot; a newer complete tick supersedes only over-horizon unsubmitted optional work. World ticks and command ordering never wait for extraction or a GPU fence.

Native execution starts with a private long-lived [Rayon 1.12 pool](https://docs.rs/rayon/latest/rayon/struct.ThreadPool.html), one bounded extraction job per view, and a completion wake to the platform event loop. The Mac surface is acquired **after** the CPU result is ready **and** a GPU slot is free, avoiding a held drawable while the worker runs. Both extraction completion and the existing surface worker's acquisition result must wake winit; each wake may submit a ready result even when the fixed clock reports zero due updates. A completed result can therefore submit before another world tick without a mandatory one-tick delay. The first browser Wasm and headless profile walks the same declared dependencies serially in the callback, without a thread or wake. This is an executor choice at host construction, not two gameplay implementations. Native workers may prepare cooked visual candidates in a later node, but GPU preparation and publication retain their current owner/barrier rules.

Each task and result carries world epoch/tick and visual generation. Before upload, the host rejects a wrong epoch or retired visual generation; an older same-epoch result remains usable within a configured **two-tick visual-age horizon**, with its age reported. A result beyond that horizon is dropped and counted, then the returned extractor is used to synchronously refresh the latest committed page on the next presentation opportunity. Every successful prepared-target replacement invalidates the extractor's prior pose history before its next use; if the extractor is still worker-owned, the old result is discarded and the reset happens when it returns. This prevents a new generation from matching old poses solely by world tick and per-row selector. While a worker remains late, the host may re-render its last prepared scene with temporal history invalidated and a stale-pose counter, rather than starving the surface; this never changes W1. An exhausted visual-page pool or busy worker drops the optional request with telemetry and retries the latest committed tick on the next opportunity. A worker result that fails presentation validation degrades/counts rather than faulting W1. Device loss retires GPU packet owners and cancels unsubmitted view work; the world follows its platform pause policy. On host drop, an outstanding task owns its page and extractor until it finishes; no slot is reused early. A task panic is a programming defect, not a recovery protocol. Explicit `capture_pixels()` may wait up to two seconds for a worker-owned extractor, separately from its existing ten-second GPU wait. On worker timeout it returns an error outside the tick callback; the task retains the extractor/page until completion, and a later host call may collect and recycle them. The world remains unchanged.

## Cost and qualification

At 10k visuals, three W1 pages reserve about 1.44 MB logical CPU payload. The measured page copy is 32.52 µs median; isolated A2 extraction was 99.70 µs, and the W1 tick was 44.41 µs on an M3 Max in separate local runs. The **maximum** overlap of one extraction with one tick is therefore about one tick's 44 µs before worker wake, handoff and cache effects; these figures do not establish a speedup. Moving the two preallocated extractor frames between host and worker avoids a second 10k copy. The worker must not clone the page rows or allocate a new extractor/packet buffer per frame. Measure worker dispatch-to-start, extraction, completion-to-submit, retained bytes, Rust allocations by thread, skipped views and 600-frame p50/p95/max on the named Metal host. Compare serial/native ABBA under matched load, and keep serial execution for a profile where worker overhead or control latency outweighs overlap. The V1 tick remains zero steady-allocation; worker/packet allocations get a separate explicit count rather than being hidden by that assertion.

Reject this design if a tick waits on a worker, a result reads mutable W1 storage, a wrong-generation or over-horizon result reaches the GPU, a dropped frame reuses adjacent history, a surface is held across worker execution, a ready packet waits for the next world tick solely because of a missing wake, or steady worker dispatch causes unbounded allocation/queue growth. The first proof must include same-tick and catch-up rendering, an intentionally delayed worker, page-pool exhaustion, host shutdown with work in flight, visual generation replacement, serial/native image and authoritative-state comparison, and a persistent slow-worker case that continues presenting with explicit visual age. Browser and iPhone runtime, full packet GPU staging/resource leases, priority classes, and generic game-system parallelism remain separate V1 gates.
