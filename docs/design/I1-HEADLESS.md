# I1 headless authority: selected slice and qualification

1 November 2026. This is the governing design for the bounded I1 executable slice. It implements the first game-owned rule and in-memory local/replica path, not source admission, a network codec, a general ECS, device shells or the full R4 match. The full [foundation](FOUNDATION-SPEC.md), [network](NETWORK-SPEC.md) and [C4 contracts](CONTRACTS.md) remain the destination.

**2 November 2026 direction:** The prior whole-process hard memory admission target is retired. The implemented pool and protected-host proofs remain useful optional bounded profiles and lifetime/accounting evidence, but the general native engine and game rules need no global byte ceiling or precharged game-work allowance. Continue measuring actual CPU, allocation count, retained bytes and process RSS under representative local/multiplayer workloads; use pressure response, retention policy and targeted optimization to stay light and fast. This changes the intended general capability, not the historical results of the bounded-profile tests. See the [decision record](../evidence/i1-headless/MEMORY-DIRECTION-2026-11-02.md).

## Selected interaction and contract map

One preloaded world contains a controlled actor, a collectible and a door. The game owns `Collect` and `Open` rule decisions: collection requires proximity and an available item; opening requires ownership of that item and a closed door. The engine owns world identity, the fixed tick, permission/sequence/timing admission, committed results, event IDs and publication. A standalone connection and an in-memory match connection submit the same typed actions to the same rule. A replica receives a complete baseline and atomic groups with full changed object state, lifecycle, action results and events. A duplicate cannot cause a second collection or event. No presentation, transport or persistence participates in the decision.

| I1 obligation | Owner and C4 contract | Observable rejection |
| --- | --- | --- |
| Fresh local world epoch, checked slot/generation, stable object ID | W1/F3, C01 | stale handle and duplicate stable ID fail |
| Exclusive 60 Hz authority step and immutable committed read model | F1/W1, C02 | old snapshot changes or partial step appears |
| Controlled actor, typed game legality, one committed effect/result | P6/F1, C03/C13 | unauthorized, duplicate, late or stale-epoch input changes state |
| Baseline and atomic full-state lifecycle/result group | N1/W1, C13 | spawn visible before usable state; invalid group partially applies |
| Bounded work and honest evidence | F1/T2, C12 | unbounded pending input or claimed device performance from headless timing |

This slice uses caller-supplied fresh 128-bit local session/world/match IDs; the future host generates them. Match and local session identities are distinct types. A connection epoch and sequence are checked before a command enters the authority. Timing follows the selected `nextTick` 18-past/2-future and `timed` 6-past/12-future admission windows, with timed one-shots over two ticks late rejected. Pending future input may leave a sequence gap while a later due input resolves; group results identify each resolved sequence and a contiguous watermark. The in-memory baseline carries outstanding results, matching event IDs and an event cursor. The initial fixture had one controlled peer; the later [two-player in-memory fixture](../evidence/i1-headless/TWO-PEER.md) exercises independent peers and a slow replica. I2n, after V1, adds the exact wire envelope, bounded reliable queues, wire result acknowledgement/resync, interest and compatibility manifests. Disconnect/reconnect uses a new epoch and baseline, with no automatic replay of uncertain one-shots.

The [finite ordinary host profile](../evidence/i1-headless/ORDINARY-PEER-PROFILE.md)
selects a maximum cumulative count of controlled `PeerId` rows per local or
in-memory match. It refuses an overfull initial authority and any fresh ID
after the count is reached, before authority queue or sequence work. The
replicated host requires a new baseline for same-ID reconnect; no retirement
API reclaims a slot. The local host allows the authority's newer-epoch
same-ID reconnect without consuming another slot. Unrestricted constructors
remain prototype paths; this profile does not provide N1 socket, spectator,
projection or queue-byte ownership.

The [selected inline slow-peer probe](../evidence/i1-headless/SLOW-PEER-PROJECTION-PROBE.md)
now tests the next owner boundary without adding a public N1 API. A local
authority's complete committed group is copied into a per-peer owned typed
projection before the callback publication and snapshot are released. The
selected counter/event/rejection values contain no indirect W1 owner; generic
game values do not gain that property from `Clone`. One slow peer retains
complete groups for more than eight changed ticks while a fast replica applies
and acknowledges its groups. An entry/byte/age-limited private queue refuses
new slow inputs before authority sequencing once it needs a replacement
baseline. This tests the intended N1 partition, not a wire codec, remote ACK,
general schema closure or the production queue. I2n must own those mechanisms
and preserve results, mandatory events and lifecycle through resync/close.

## Representation and cost account

Select a dense slot table with a free list, generation check and stable-ID index for the finite preloaded I1 world. The `hecs` 0.11.2 private ordinary-component store remains selected for the broader W1 capability; this slice does not have heterogeneous component queries or enough dependency need to add it. Replacing the slot payload with the selected private store must preserve the public identity/barrier interface and be qualified with its actual license, dependency, Wasm and target costs before I2b. Do not expose a backend entity or Rust `TypeId` as durable/wire identity.

The exclusive authority writes slots in place. A 32-slot immutable read-model page is copied only if touched since the last publication; unchanged pages share an immutable root with earlier snapshots. An unchanged tick shares the root in O(1) work; a changed tick copies `ceil(N/32)` page references and up to `32 × D` object records for `D` dirty pages. The world index and free list cost O(N) retained memory and O(1) expected stable lookup; ordered action work is O(A log A) in the bounded pending set, with O(1) ordinary slot reads. Replica confirmed-object lookup is hash indexed; prototype validation uses a temporary ordered duplicate-ID set, while sealed live groups validate the producer's sorted IDs in one scan. Full baseline is O(N) records once. A live in-memory group carries O(C + R + E) full changed records, results and events per tick; I2n must batch at its 20 Hz cadence and independently account for wire bytes, fan-out, acknowledgement and queues. Snapshot pages use owned clones, so no mutable world array aliases a reader. An `Arc` lease keeps old pages alive; retained page bytes grow with the number of concurrently leased changed pages. Authority admits at most eight live tick bundles and backpressures before mutation if they remain leased. Consumer cancellation and host overload policy remain required before a general runtime profile is qualified; a hard whole-process byte admission gate is no longer a general-runtime requirement.

Alternatives: full world copy each tick moves O(N) objects even for one changed object; a persistent tree reduces reference copying but adds nodes/branches and allocations to a small finite world; a universal ECS query planner is premature. Dirty-page copying is chosen for low churn and explicit lifetime. A 25% uniformly distributed churn case will touch almost every page; its measured cost may justify a different page size or selected side store before that workload is supported. Rejected actions avoid page copies. Publication is a commit boundary: read-only rule `decide` and `prepare` produce complete edits; the authority validates and applies each decision in canonical order, and publishes only after the whole tick succeeds. A panic or invalid prepared batch after mutation permanently faults this authority; there is no generic rollback or external effect reversal.

The first page storage used an `Arc` slice, which required relocating each built Vec buffer. The intermediate `Arc<Vec<_>>` kept the buffer in place and halved the width of each root page reference; [repeated local cost runs](../evidence/i1-headless/PAGE-LAYOUT.md) supported that step. The charged owner now keeps an exact-length boxed slice inside an `Arc` with its lifetime charge. This removes retained spare capacity and preserves thin root page references, while retaining a separate data and owner allocation. Its [local charged-path measurements](../evidence/i1-headless/CHARGED-PAGES.md) are not a controlled whole-engine comparison. A fixed inline page was rejected because unrestricted game entity size could overflow the stack. This layout is private to W1 and does not change the game-facing state semantics.

The critical path measured here is input admission → authority tick/decision/commit → immutable publication → replica admission. Count attempted/committed/rejected inputs, dirty pages, object copies, full group records and retained snapshot bytes. Measure repeated small reads and no-op ticks as well as high churn. Workload cases are 64, 4,096 and 16,384 objects, with zero, 1% and 25% changed objects per tick, plus typed actions over the small game. These are stress fixtures, not new product population limits. The game fixture checks exact outcomes/events; the scale fixture compares every final replica object with authority state. Record p50/p95/p99/max per-stage elapsed, allocation/byte counts where observable, and run-to-run noise. The [idle replica path](../evidence/i1-headless/IDLE-REPLICA.md) avoids temporary progress and validation maps for a complete unchanged group with identical peer watermarks; a [changed-only group](../evidence/i1-headless/CHANGED-PROGRESS.md) can also reuse peer progress when it carries no results and requires no gap normalization, while still validating its changes. One host's headless timings cannot certify Mac/Windows/browser/phone frame budgets, lifecycle or the real I2n network.

## Proof queue and status

1. Verify stale handles, ID reuse, epoch mismatch and old immutable snapshots. Reject a design that resurrects a retired identity or aliases mutable state.
2. Run the game-owned collect/open sequence through local and replica roles, then two controlled peers in one match. Inject unauthorized, duplicate, late and old-epoch input, a pending timed gap, a slow replica and a malformed spawn group. Reject any duplicate effect, missing result or partial replica state.
3. Run the declared scale/churn fixture with stage timings and byte/work counts, retaining exact build and command. Investigate recurring cost and tails, then record the selected path's limits. Device targets, actual WSS, durable outcome recovery and mobile shells remain separately unqualified.

## Bounded host-clock slice

The next F1 seam is a headless fixed-step clock driven by a host-supplied monotonic timestamp, separate from display callbacks and the authoritative rule. Its selected default is 60 world updates per second; `tick_hz` is configurable, and presenting at 30/60/120/240 Hz never changes the number of due world updates. Integer nanosecond accumulation with a fractional-tick remainder avoids cumulative rounding from a rounded 16.67 ms period. One callback performs no heap allocation in the clock itself. After a callback, the clock exposes the exact next due delay from its integer fractional remainder; platform schedulers may wake at that deadline instead of polling at an unrelated fixed interval. A queued tick has zero due delay and may be retried at a bounded platform pace, while a stopped empty clock has no world deadline. This is an advisory wake time, not a separate clock or a guarantee that the OS fires on time. Its recurring work is O(1) time accounting plus O(K) attempted steps, where `K` is capped by the configured four-per-call safety limit, an eight-tick queue and a host-supplied CPU admission count. The host must derive that count from a measured/bounded tick cost and its callback reserve; the clock alone cannot preempt a slow rule callback or prove a device frame deadline.

The caller's step callback commits one authority update or leaves it unchanged on an expected, retryable error. Only successful steps retire due work. A blocked snapshot publication retains the due tick and retries without replaying an earlier successful action. A terminal game-contract fault instead stops the host; its partially processed tick is never retried. When elapsed active time exceeds remaining queue capacity, the clock enters explicit local overload, reports the due ticks refused at that transition, stops accumulating world time and drains already admitted ticks. Resume requires an empty queue and a fresh monotonic origin. Pause also stops accumulation and allows only previously admitted ticks to drain. A remote authority must use its N1 session-overload policy rather than silently applying this local stop-time policy. The clock owns no render rate cap, transport queue or game rule.

This clock slice is implemented and locally tested against the game-owned authority; [running evidence](../evidence/i1-headless/QUALIFICATION.md) records its cost and limits. A later native headless host callback and the initial authority/replica stage validation are qualified below. The general F1 system registry, typed component views, platform event adapters and full host package remain separate work. Whole-process publication bytes, native phone shells and actual multiplayer transport are also unqualified by the clock fixture.

## Native headless callback and initial stage plan

The bounded headless host owns one `TickClock`, one `Authority`, and optionally one in-memory `Replica`. It prepares a typed two-stage schedule once: authority state mutation/publication precedes replica admission. Validation rejects missing or backward dependencies, cycles, unordered conflicting access and cross-role world access; the selected rule stays inside the one exclusive authority stage and follows the same game-owned `decide`/`prepare` path as direct calls. Local publications and replica-admitted results/events return to the caller. The caller explicitly acknowledges handled outcomes; until then, bounded retained-result capacity applies. A newly hosted replica returns its baseline outcomes at construction. This is an I1 stage plan, not a general F1 component-system registry.

The host receives real monotonic `Instant` callback times. A configured callback time budget, other-work reserve and conservative complete-tick cost bound determine the admitted tick count once at construction. The clock's four-per-callback and eight-queued caps still apply. Each committed tick checks actual elapsed wall time against the budget **after** the other-work reserve and stops further catch-up if spent; the callback then enters explicit overload and closes input admission. A replica rejection after authority commit is terminal for this host, because that tick cannot be retried. The measured headless fixture uses a 120 Hz native callback loop, two controlled peers, 60 Hz authority and in-memory replica; [evidence](../evidence/i1-headless/HOST.md) includes callback cadence, per-callback service time, actual submit-to-confirmed-result latency and injected slow-callback overload. This proves the initial hosted clock path, not device frame pacing, mobile lifecycle or online session service.

A separate [sealed charged callback](../evidence/i1-headless/CHARGED-HOST.md) now runs the same two-stage schedule with charged group/outcome owners and a finite charged local replica. Before sequencing a new hosted action, it protects conservative **object-slot** headroom for every queued action and the candidate, based on the game-wide maximum spawns per action. Duplicate answers precede the check. A full object profile can refuse an otherwise harmless action if that action's declaration permits a spawn; such refusal occurs before input admission, while previously accepted inputs and idle ticks continue. A defensive post-admission headroom failure is terminal, not retryable. Before activation, the host primes a charged peer-watermark owner and reserves a [finite idle delivery floor](../evidence/i1-headless/IDLE-DELIVERY-FLOOR.md) for eight independent callback buffers. The public read-only collection keeps one permit through its consuming iterator. Clean two-peer ticks advance under full competing pool contention until all eight callback permits are held; an exhausted permit returns explicit retryable backpressure before the authority step. Charged per-peer [completed-history storage](../evidence/i1-headless/COMPLETED-HISTORY.md) now grows before new input sequence admission, so accepted pending actions have a history slot ready. A sorted [charged peer registry](../evidence/i1-headless/PEER-REGISTRY.md) preserves canonical multiplayer order without uncharged tree nodes. This is not yet a whole-byte execution credit: replica progress scratch and future output bytes still need admission. The changed-tick local callback cost is recorded separately from the earlier real 120 Hz slow-callback qualification.

## Two controlled peers in one in-memory match

The two-player fixture keeps one game-owned rule and one authoritative world. Distinct peer IDs, connection epochs and controlled actors share that authority; the peer map supplies independent sequence, pending, result and watermark state. Simultaneous attempts to collect one item are resolved in the authority's canonical peer order, so one effect commits and the other receives a game rejection. This fixture also delivers several complete tick groups late to a replica, then verifies the same final state and joined baseline. Its [correctness and cost record](../evidence/i1-headless/TWO-PEER.md) measures two accepted actions per tick in a separate small counter workload. It proves in-memory peer separation and ordered admission, not encoded WSS, four-player latency, network backpressure or durable outcome recovery.

## Publication-memory admission gate

This section records the optional bounded-profile design and its historical proofs. It is no longer a general-runtime completion gate; the general engine's low-memory work follows measurements and pressure response.

In the optional bounded publication profile, the shared pool charges each unique retained immutable page and root allocation once across all worlds and readers, plus retained full-state groups, results and events. Summing `Snapshot::logical_bytes` is invalid because shared pages would be charged repeatedly while owned game payloads and group copies would be missed. Admission must reserve a conservative peak **before** any rule commit mutates the world; a slow required reader returns backpressure without reusing its pages. Release must follow actual last-owner retirement, including a replica or view that holds an older snapshot.

The current `Entity: Clone` and `World::get_mut` allow game-owned values with arbitrary heap growth. `prepare` now returns validated edit batches, but their count and payload size are not yet admitted. A hard byte cap cannot be inferred from `size_of::<Entity>()` or current dirty flags. The earlier strict-profile target declares finite state, input, structural and output bounds and expresses authoritative writes as bounded prepared commands. An unchecked maximum in a trait is insufficient; owned variable-size payloads use admission-managed containers or immutable products whose allocation and last-owner charge are enforced. The unbounded `Clone` path remains available to ordinary native rules; its actual cost needs measurement in representative games. The prepared commands preserve one game-owned decision rule, exact action outcomes and atomic replica groups. A `Copy`-only state would simplify a finite proof but unnecessarily narrow the reusable engine. Idle-tick admission must stay O(1), and conservative reservations must be visible in cost evidence.

In the optional bounded profile, the shared pool owns a count and byte limit. Before the **first** rule commit of a tick, the host reserves a conservative whole-tick peak for every due input and the authority's ordered outputs, including the in-memory replica's required admission capacity. Decisions still run in canonical order against preceding committed effects: `Collect` then `Open` in one tick and competing peer collections retain their existing outcomes. A normal capacity refusal leaves the tick, pending inputs and state unchanged. The bound accounts for peak slot high-water, dirty pages and root buffers even if spawn/despawn commands cancel before publication, plus changed-record groups, events, results and retained input history. A rule exceeding its declared command bound is a terminal contract violation, never a silent over-budget publication. Reservation is O(1) in world size on an idle tick and does not scan old readers.

Each unique immutable allocation carries one lifetime charge shared by its owners and released at actual last-owner retirement. Count and byte reservations are separate: a no-op tick still has a distinct leased tick bundle, even if all pages are shared, so an old reader cannot evade the eight-bundle limit. The budgeted construction and `try_baseline` paths reserve initial/deep-copy peak outside a tick; budgeted group copying is fallible and charged rather than using unrestricted `StateGroup::clone`. When a replica admits a group, charges on owned entity payloads move with those values into replica state, while the group-buffer charge ends with that buffer and the results/events buffer charge follows returned outcomes. Replica map growth is reserved before mutation. Pending input's payload charge moves into completed duplicate-history retention and releases only after acknowledgement, expiry or reconnect. The in-memory host reserves for both authority and required replica before commit, so expected replica capacity refusal cannot occur after a successful authority tick. A remote peer has its own admission and queue policy; it cannot stall server authority. Invalid replica data remains a separate terminal fault.

The checked atomic reservation arithmetic is implemented and tested. Prepared world edits validate an ordered batch before ordinary invalid edits can mutate the world, including checked handles and transient slot growth. The [world proof](../evidence/i1-headless/PREPARED-EDITS.md) and [rule-boundary proof](../evidence/i1-headless/PREPARED-RULE.md) cover the selected read-only preparation path and its terminal fault isolation. An [immutable byte product](../evidence/i1-headless/PUBLICATION-BYTES.md) reserves its logical payload and owner bytes before copying, or spends an existing tick reservation, then shares one lifetime charge across clones. A nonempty product performs two allocations at creation, one for bytes and one for the shared owner; cloning performs an atomic reference increment and content equality scans the bytes. Its caller-owned source and allocator metadata are outside this logical charge. The I1 fixture shows a charged action surviving pending and completed duplicate history until acknowledgement, but does not require all game input payloads to use charged storage. Immutable world pages and roots now own [unique lifetime charges](../evidence/i1-headless/CHARGED-PAGES.md), shared across old readers and two worlds using one pool. The selected boxed buffers have exact retained lengths; a conservative reservation covers possible staging overlap. A [constant-time precommit bound](../evidence/i1-headless/PRECOMMIT-PAGE-BOUND.md) covers page/root growth from a declared maximum edit and spawn count, including a net-zero lifecycle. The [charged authority bridge](../evidence/i1-headless/CHARGED-AUTHORITY.md) now connects this snapshot primitive to construction and pre-edit page/root admission. Mutable world indexes, arbitrary `Clone` payloads, groups, outcomes, baselines and replica allocations remain outside this pool's enforced scope. Do not promote a partial page-byte counter as whole-process memory qualification.

The proof fixture shares one pool across at least two authorities, holds old readers while state grows, forces a rejected tick before mutation, then releases readers and shows recovery. It also performs 65 spawn/despawn pairs before a publication, tests deep baseline/group copying, retained large action payloads, and a replica that keeps changed objects and outcomes after consuming a group. It checks sequential same-tick rules and a competing peer decision at the budget boundary. Compare charged unique bytes, actual owned allocation scope and count limits. Reject the gate if it mutates before budget refusal, double-charges shared pages, misses transient slot/root or retained payload bytes, releases capacity before the final owner, or changes multiplayer outcomes. The [read-only design challenge](../evidence/i1-headless/MEMORY-DESIGN-REVIEW.md) records why these cases are required. These fixtures qualify the selected strict profile only; the general low-footprint work in the [work list](../BUILD-PLAN.md) needs representative whole-game measurements.

### Prepared rule boundary implemented; byte admission pending

The authority now uses read-only `prepare(&World, Change)` to return complete `WorldEdit` replacements and an optional event payload. It applies each returned batch through the world's validated edit path, then assigns event/result identities. The next action decides and prepares against earlier canonical effects, including another peer's action; a rejected action has no edits or event. One game-owned rule implementation serves standalone and match authorities. No world mutation or event emission occurs during `prepare`. An invalid prepared batch returns terminal `StepError::TerminalGameContract`. The authority is poisoned before tick mutation, so an unwind caught by the caller is also terminal. Its failed tick emits no snapshot, event or result; `try_baseline`, input admission and acknowledgement refuse the faulted instance. The host faults rather than replaying it. If a prior tick succeeded in the same catch-up callback, the callback delivers that publication with an explicit terminal fault. Snapshot backpressure remains retryable before mutation.

`PreparedEdits` holds zero, one or two edits inline and uses an owned vector for larger batches. The one-edit path avoids a validation collection; the two-edit path validates with inline bookkeeping and was measured through the complete authority and replica flow. An optional finite admitted game profile must cap actual edits, spawns and inline `size_of::<Entity>()` per action before application. Arbitrarily large inline state can increase stack pressure, and arbitrary `Entity: Clone` or output payloads remain outside the byte proof. The bounded host calculates a conservative page/root peak from those bounds and all due inputs before its first edit, then includes group, result, event, input-history and required replica peaks in one reservation. Exceeding a declared bound will be a terminal contract fault. See the [rule-boundary qualification](../evidence/i1-headless/PREPARED-RULE.md).

### Charged snapshot authority bridge, partial gate

The bounded bridge now connects the shared pool to authority construction and each tick's snapshot pages. A charged constructor reserves the tick-zero page/root peak before its initial publication, and records an explicit maximum edit and spawn count per due action. Before any tick mutation, it counts due actions, checks the products of those bounds, computes the world's constant-time conservative page/root peak and tries one process-shared reservation. Capacity refusal leaves tick, inputs and world unchanged for retry. Each actual prepared batch must fit its declared counts; a violation faults the authority. The final page/root publication spends the reservation; an unexpectedly insufficient bound after mutation is terminal. A one-edit action in a small world can reserve one page and one root while unchanged ticks need no new snapshot bytes. The shared pool arbitrates competing worlds and old readers by unique allocation ownership.

This [tested bridge](../evidence/i1-headless/CHARGED-AUTHORITY.md) covers only snapshot owners in the optional bounded profile: the due-input scan is proportional to pending actions, but idle work is independent of world size. The maximum counts are trusted game-contract declarations and currently do not constrain allocation during `prepare`. Mutable world slots/indexes, results/events, full-state groups, baselines, replica maps and arbitrary game payloads are still outside the charged scope. A fuller strict profile would need to charge them before claiming complete owner-byte admission; the general low-footprint item instead needs workload measurements. Rejection criteria for the bridge are mutation on pool refusal, a retry after a declared-bound violation, a charged world silently using uncharged publication, or release while an old snapshot reader remains.

### Whole-tick byte gate: bounded profile and owner plan

The selected optional strict profile is finite and uses the same game rule path. The authority continues to call one typed `decide`/`prepare` implementation for standalone and match play. An admitted value must use an engine-owned structural representation: scalar/fixed-array inline fields and explicit tagged records, plus charged immutable owners for variable data. Arbitrary game `Copy` is insufficient because it can contain external references or pointers; arbitrary `Clone` can allocate even for a `Copy` type. The engine controls duplication of inline fields without invoking game `Clone`, and checks that every charged product belongs to the authority pool before retaining it. Typed game-facing views must preserve that closed storage representation; their access cost is part of qualification. The prototype remains available for unqualified games. Once a world enters the qualified path, game code writes only through prepared edits and charged product constructors; the unrestricted `World::get_mut` prototype escape hatch cannot bypass the gate. A budgeted rule context must be available to both `decide` and `prepare`: rejection values from `decide` are retained outputs, while a successful `Change` is temporary rule work. The context enforces per-action edit, spawn, new payload, event and retained-output limits. Private game scratch outside engine-owned products needs a separate game work budget and is not counted as publication-pool memory. The first storage proof uses a private-field `PublicationRecord<const INLINE, const BLOBS>` containing only `[u8; INLINE]` and `[Option<PublicationBytes>; BLOBS]`. Its constructor checks all payload owners against one pool; its engine-controlled clone copies bytes and shares existing charged owners. The sealed closed-authority entry path scans initial slots once and checks every prepared state before applying the batch; foreign owners or states above selected inline-byte, payload-slot and per-payload-byte limits fault the authority without a partial edit. An idle tick performs no value scan, and the per-action scan is linear only in prepared states and payload slots. The final shared owner determines payload release. A typed game-facing projection, bounded action and temporary work, charged output/history buffers and complete pre-edit admission still need proof before claiming complete owner-byte admission for that optional profile. The first fixture verifies both fixed state and a charged variable payload without changing authority semantics.

The sealed entry path also selects separate closed limits for action, event and game-rejection values. It checks their type shapes at construction. A new action is checked for pool provenance and per-payload size before entering the pending map or consuming a sequence; a game rejection is checked before retaining an outcome, and a prepared event before any world edit. Exact duplicate lookup precedes new-action validation because it retains no incoming value. These checks prevent a wrong-pool or oversized value from entering authority history, while pending/history container bytes, output buffers and game-callback allocations still await the whole-tick gate.

The selected qualified group representation is a by-value identity/tick header with separately shared, charged columns for changes, results, events and peer watermarks. A nonempty column owns a private `Vec<T>` with a separately enforced logical fill limit and its single charge behind an `Arc`; cloning the group shares column owners instead of deep-cloning records. An empty column has no allocation. Rust guarantees `Vec::with_capacity(n)` requests storage for exactly `n` elements from the allocator, although the allocator may provide unused surplus. Preflight first reserves checked `n × size_of::<T>()` plus the shared-owner/header charge for every required column, then allocates before the first edit. The private wrapper never fills past `n`, grows, shrinks, converts or deep-clones the vector, so allocator-supplied surplus remains allocator slack rather than engine-admitted capacity. Every candidate column keeps its charge during construction and unwinding; a unique `IntoIter` keeps the charge until its final value or iterator drops. This safe representation avoids initialization of unused slots and needs no unsafe-code exception. The logical cap excludes allocator metadata, allocator-supplied slack, game-private work and the pool's one fixed admission-control Arc; it admits the selected engine-owned dynamic buffers. The authority may reuse one charged watermark owner across idle ticks until peer progress changes, avoiding a per-tick peer-list copy. This qualified group is a different storage wrapper around the same lifecycle/result schema and rule path; the current public `StateGroup` with deep `Vec` cloning remains an unqualified prototype and cannot cross the qualified gate.

The [live authority group proof](../evidence/i1-headless/CHARGED-TICK.md) implements that pre-edit column reservation and shares a cached watermark owner across steady clean ticks. The [fixed-slot output-credit proof](../evidence/i1-headless/OUTPUT-CREDITS.md) gives the same `GameRules::decide` and `prepare` callbacks a borrowed `RuleContext` in both local and multiplayer authorities.
