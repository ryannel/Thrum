# I1 headless authority: selected slice and qualification

1 November 2026. This is the governing design for the bounded I1 executable slice. It implements the first game-owned rule and in-memory local/replica path, not source admission, a network codec, a general ECS, device shells or the full R4 match. The full [foundation](FOUNDATION-SPEC.md), [network](NETWORK-SPEC.md) and [C4 contracts](CONTRACTS.md) remain the destination.

## Selected interaction and contract map

One preloaded world contains a controlled actor, a collectible and a door. The game owns `Collect` and `Open` rule decisions: collection requires proximity and an available item; opening requires ownership of that item and a closed door. The engine owns world identity, the fixed tick, permission/sequence/timing admission, committed results, event IDs and publication. A standalone connection and an in-memory match connection submit the same typed actions to the same rule. A replica receives a complete baseline and atomic groups with full changed object state, lifecycle, action results and events. A duplicate cannot cause a second collection or event. No presentation, transport or persistence participates in the decision.

| I1 obligation | Owner and C4 contract | Observable rejection |
| --- | --- | --- |
| Fresh local world epoch, checked slot/generation, stable object ID | W1/F3, C01 | stale handle and duplicate stable ID fail |
| Exclusive 60 Hz authority step and immutable committed read model | F1/W1, C02 | old snapshot changes or partial step appears |
| Controlled actor, typed game legality, one committed effect/result | P6/F1, C03/C13 | unauthorized, duplicate, late or stale-epoch input changes state |
| Baseline and atomic full-state lifecycle/result group | N1/W1, C13 | spawn visible before usable state; invalid group partially applies |
| Bounded work and honest evidence | F1/T2, C12 | unbounded pending input or claimed device performance from headless timing |

This slice uses caller-supplied fresh 128-bit local session/world/match IDs; the future host generates them. Match and local session identities are distinct types. A connection epoch and sequence are checked before a command enters the authority. Timing follows the selected `nextTick` 18-past/2-future and `timed` 6-past/12-future admission windows, with timed one-shots over two ticks late rejected. Pending future input may leave a sequence gap while a later due input resolves; group results identify each resolved sequence and a contiguous watermark. The in-memory baseline carries outstanding results, matching event IDs and an event cursor. The initial fixture had one controlled peer; the later [two-player in-memory fixture](../evidence/i1-headless/TWO-PEER.md) exercises independent peers and a slow replica. I2n adds the exact wire envelope, bounded reliable queues, wire result acknowledgement/resync, interest and compatibility manifests. Disconnect/reconnect uses a new epoch and baseline, with no automatic replay of uncertain one-shots.

## Representation and cost account

Select a dense slot table with a free list, generation check and stable-ID index for the finite preloaded I1 world. The `hecs` 0.11.2 private ordinary-component store remains selected for the broader W1 capability; this slice does not have heterogeneous component queries or enough dependency need to add it. Replacing the slot payload with the selected private store must preserve the public identity/barrier interface and be qualified with its actual license, dependency, Wasm and target costs before I2b. Do not expose a backend entity or Rust `TypeId` as durable/wire identity.

The exclusive authority writes slots in place. A 32-slot immutable read-model page is copied only if touched since the last publication; unchanged pages share an immutable root with earlier snapshots. An unchanged tick shares the root in O(1) work; a changed tick copies `ceil(N/32)` page references and up to `32 × D` object records for `D` dirty pages. The world index and free list cost O(N) retained memory and O(1) expected stable lookup; ordered action work is O(A log A) in the bounded pending set, with O(1) ordinary slot reads. Replica confirmed-object lookup is hash indexed; validation uses a temporary ordered duplicate-ID set. Full baseline is O(N) records once. A live in-memory group carries O(C + R + E) full changed records, results and events per tick; I2n must batch at its 20 Hz cadence and independently account for wire bytes, fan-out, acknowledgement and queues. Snapshot pages use owned clones, so no mutable world array aliases a reader. An `Arc` lease keeps old pages alive; retained page bytes grow with the number of concurrently leased changed pages. Authority admits at most eight live tick bundles and backpressures before mutation if they remain leased. Whole-process byte admission, consumer cancellation and host overload policy remain required before a general runtime profile is qualified.

Alternatives: full world copy each tick moves O(N) objects even for one changed object; a persistent tree reduces reference copying but adds nodes/branches and allocations to a small finite world; a universal ECS query planner is premature. Dirty-page copying is chosen for low churn and explicit lifetime. A 25% uniformly distributed churn case will touch almost every page; its measured cost may justify a different page size or selected side store before that workload is supported. Rejected actions avoid page copies. Publication is a commit boundary: read-only rule `decide` and `prepare` produce complete edits; the authority validates and applies each decision in canonical order, and publishes only after the whole tick succeeds. A panic or invalid prepared batch after mutation permanently faults this authority; there is no generic rollback or external effect reversal.

The first page storage used an `Arc` slice, which required relocating each built Vec buffer. The intermediate `Arc<Vec<_>>` kept the buffer in place and halved the width of each root page reference; [repeated local cost runs](../evidence/i1-headless/PAGE-LAYOUT.md) supported that step. The charged owner now keeps an exact-length boxed slice inside an `Arc` with its lifetime charge. This removes retained spare capacity and preserves thin root page references, while retaining a separate data and owner allocation. Its [local charged-path measurements](../evidence/i1-headless/CHARGED-PAGES.md) are not a controlled whole-engine comparison. A fixed inline page was rejected because unrestricted game entity size could overflow the stack. This layout is private to W1 and does not change the game-facing state semantics.

The critical path measured here is input admission → authority tick/decision/commit → immutable publication → replica admission. Count attempted/committed/rejected inputs, dirty pages, object copies, full group records and retained snapshot bytes. Measure repeated small reads and no-op ticks as well as high churn. Workload cases are 64, 4,096 and 16,384 objects, with zero, 1% and 25% changed objects per tick, plus typed actions over the small game. These are stress fixtures, not new product population limits. The game fixture checks exact outcomes/events; the scale fixture compares every final replica object with authority state. Record p50/p95/p99/max per-stage elapsed, allocation/byte counts where observable, and run-to-run noise. The [idle replica path](../evidence/i1-headless/IDLE-REPLICA.md) avoids temporary progress and validation maps for a complete unchanged group with identical peer watermarks; other groups retain full validation. One host's headless timings cannot certify Mac/Windows/browser/phone frame budgets, lifecycle or the real I2n network.

## Proof queue and status

1. Verify stale handles, ID reuse, epoch mismatch and old immutable snapshots. Reject a design that resurrects a retired identity or aliases mutable state.
2. Run the game-owned collect/open sequence through local and replica roles, then two controlled peers in one match. Inject unauthorized, duplicate, late and old-epoch input, a pending timed gap, a slow replica and a malformed spawn group. Reject any duplicate effect, missing result or partial replica state.
3. Run the declared scale/churn fixture with stage timings and byte/work counts, retaining exact build and command. Investigate recurring cost and tails, then record the selected path's limits. Device targets, actual WSS, durable outcome recovery and mobile shells remain separately unqualified.

## Bounded host-clock slice

The next F1 seam is a headless fixed-step clock driven by a host-supplied monotonic timestamp, separate from display callbacks and the authoritative rule. Its selected default is 60 world updates per second; `tick_hz` is configurable, and presenting at 30/60/120/240 Hz never changes the number of due world updates. Integer nanosecond accumulation with a fractional-tick remainder avoids cumulative rounding from a rounded 16.67 ms period. One callback performs no heap allocation in the clock itself. Its recurring work is O(1) time accounting plus O(K) attempted steps, where `K` is capped by the configured four-per-call safety limit, an eight-tick queue and a host-supplied CPU admission count. The host must derive that count from a measured/bounded tick cost and its callback reserve; the clock alone cannot preempt a slow rule callback or prove a device frame deadline.

The caller's step callback commits one authority update or leaves it unchanged on an expected, retryable error. Only successful steps retire due work. A blocked snapshot publication retains the due tick and retries without replaying an earlier successful action. A terminal game-contract fault instead stops the host; its partially processed tick is never retried. When elapsed active time exceeds remaining queue capacity, the clock enters explicit local overload, reports the due ticks refused at that transition, stops accumulating world time and drains already admitted ticks. Resume requires an empty queue and a fresh monotonic origin. Pause also stops accumulation and allows only previously admitted ticks to drain. A remote authority must use its N1 session-overload policy rather than silently applying this local stop-time policy. The clock owns no render rate cap, transport queue or game rule.

This clock slice is implemented and locally tested against the game-owned authority; [running evidence](../evidence/i1-headless/QUALIFICATION.md) records its cost and limits. A later native headless host callback and the initial authority/replica stage validation are qualified below. The general F1 system registry, typed component views, platform event adapters and full host package remain separate work. Whole-process publication bytes, native phone shells and actual multiplayer transport are also unqualified by the clock fixture.

## Native headless callback and initial stage plan

The bounded headless host owns one `TickClock`, one `Authority`, and optionally one in-memory `Replica`. It prepares a typed two-stage schedule once: authority state mutation/publication precedes replica admission. Validation rejects missing or backward dependencies, cycles, unordered conflicting access and cross-role world access; the selected rule stays inside the one exclusive authority stage and follows the same game-owned `decide`/`prepare` path as direct calls. Local publications and replica-admitted results/events return to the caller. The caller explicitly acknowledges handled outcomes; until then, bounded retained-result capacity applies. A newly hosted replica returns its baseline outcomes at construction. This is an I1 stage plan, not a general F1 component-system registry.

The host receives real monotonic `Instant` callback times. A configured callback time budget, other-work reserve and conservative complete-tick cost bound determine the admitted tick count once at construction. The clock's four-per-callback and eight-queued caps still apply. Each committed tick checks actual elapsed wall time against the budget **after** the other-work reserve and stops further catch-up if spent; the callback then enters explicit overload and closes input admission. A replica rejection after authority commit is terminal for this host, because that tick cannot be retried. The measured headless fixture uses a 120 Hz native callback loop, two controlled peers, 60 Hz authority and in-memory replica; [evidence](../evidence/i1-headless/HOST.md) includes callback cadence, per-callback service time, actual submit-to-confirmed-result latency and injected slow-callback overload. This proves the initial hosted clock path, not device frame pacing, mobile lifecycle or online session service.

## Two controlled peers in one in-memory match

The two-player fixture keeps one game-owned rule and one authoritative world. Distinct peer IDs, connection epochs and controlled actors share that authority; the peer map supplies independent sequence, pending, result and watermark state. Simultaneous attempts to collect one item are resolved in the authority's canonical peer order, so one effect commits and the other receives a game rejection. This fixture also delivers several complete tick groups late to a replica, then verifies the same final state and joined baseline. Its [correctness and cost record](../evidence/i1-headless/TWO-PEER.md) measures two accepted actions per tick in a separate small counter workload. It proves in-memory peer separation and ordered admission, not encoded WSS, four-player latency, network backpressure or durable outcome recovery.

## Publication-memory admission gate

The process-wide publication cap must charge each unique retained immutable page and root allocation once across all worlds and readers, plus retained full-state groups, results and events. Summing `Snapshot::logical_bytes` is invalid because shared pages would be charged repeatedly while owned game payloads and group copies would be missed. Admission must reserve a conservative peak **before** any rule commit mutates the world; a slow required reader returns backpressure without reusing its pages. Release must follow actual last-owner retirement, including a replica or view that holds an older snapshot.

The current `Entity: Clone` and `World::get_mut` allow game-owned values with arbitrary heap growth. `prepare` now returns validated edit batches, but their count and payload size are not yet admitted. A hard byte cap cannot be inferred from `size_of::<Entity>()` or current dirty flags. **Selected target for the next implementation:** an admitted game profile declares finite state, input, structural and output bounds and expresses authoritative writes as bounded prepared commands. An unchecked maximum in a trait is insufficient; owned variable-size payloads use admission-managed containers or immutable products whose allocation and last-owner charge are enforced. The general unbounded `Clone` path remains a local prototype, not a budget-qualified path. The prepared commands preserve one game-owned decision rule, exact action outcomes and atomic replica groups. A `Copy`-only state would simplify a finite proof but unnecessarily narrow the reusable engine. Idle-tick admission must stay O(1), and conservative reservations must be visible in cost evidence.

The shared pool owns a count and byte limit. Before the **first** rule commit of a tick, the host reserves a conservative whole-tick peak for every due input and the authority's ordered outputs, including the in-memory replica's required admission capacity. Decisions still run in canonical order against preceding committed effects: `Collect` then `Open` in one tick and competing peer collections retain their existing outcomes. A normal capacity refusal leaves the tick, pending inputs and state unchanged. The bound accounts for peak slot high-water, dirty pages and root buffers even if spawn/despawn commands cancel before publication, plus changed-record groups, events, results and retained input history. A rule exceeding its declared command bound is a terminal contract violation, never a silent over-budget publication. Reservation is O(1) in world size on an idle tick and does not scan old readers.

Each unique immutable allocation carries one lifetime charge shared by its owners and released at actual last-owner retirement. Count and byte reservations are separate: a no-op tick still has a distinct leased tick bundle, even if all pages are shared, so an old reader cannot evade the eight-bundle limit. The budgeted construction and `try_baseline` paths reserve initial/deep-copy peak outside a tick; budgeted group copying is fallible and charged rather than using unrestricted `StateGroup::clone`. When a replica admits a group, charges on owned entity payloads move with those values into replica state, while the group-buffer charge ends with that buffer and the results/events buffer charge follows returned outcomes. Replica map growth is reserved before mutation. Pending input's payload charge moves into completed duplicate-history retention and releases only after acknowledgement, expiry or reconnect. The in-memory host reserves for both authority and required replica before commit, so expected replica capacity refusal cannot occur after a successful authority tick. A remote peer has its own admission and queue policy; it cannot stall server authority. Invalid replica data remains a separate terminal fault.

The checked atomic reservation arithmetic is implemented and tested. Prepared world edits validate an ordered batch before ordinary invalid edits can mutate the world, including checked handles and transient slot growth. The [world proof](../evidence/i1-headless/PREPARED-EDITS.md) and [rule-boundary proof](../evidence/i1-headless/PREPARED-RULE.md) cover the selected read-only preparation path and its terminal fault isolation. An [immutable byte product](../evidence/i1-headless/PUBLICATION-BYTES.md) reserves its logical payload and owner bytes before copying, or spends an existing tick reservation, then shares one lifetime charge across clones. A nonempty product performs two allocations at creation, one for bytes and one for the shared owner; cloning performs an atomic reference increment and content equality scans the bytes. Its caller-owned source and allocator metadata are outside this logical charge. The I1 fixture shows a charged action surviving pending and completed duplicate history until acknowledgement, but does not require all game input payloads to use charged storage. Immutable world pages and roots now own [unique lifetime charges](../evidence/i1-headless/CHARGED-PAGES.md), shared across old readers and two worlds using one pool. The selected boxed buffers have exact retained lengths; a conservative reservation covers possible staging overlap. A [constant-time precommit bound](../evidence/i1-headless/PRECOMMIT-PAGE-BOUND.md) covers page/root growth from a declared maximum edit and spawn count, including a net-zero lifecycle. The [charged authority bridge](../evidence/i1-headless/CHARGED-AUTHORITY.md) now connects this snapshot primitive to construction and pre-edit page/root admission. Mutable world indexes, arbitrary `Clone` payloads, groups, outcomes, baselines and replica allocations remain outside this pool's enforced scope. Do not promote a partial page-byte counter as whole-process memory qualification.

The proof fixture shares one pool across at least two authorities, holds old readers while state grows, forces a rejected tick before mutation, then releases readers and shows recovery. It also performs 65 spawn/despawn pairs before a publication, tests deep baseline/group copying, retained large action payloads, and a replica that keeps changed objects and outcomes after consuming a group. It checks sequential same-tick rules and a competing peer decision at the budget boundary. Compare charged unique bytes, actual owned allocation scope and count limits. Reject the gate if it mutates before budget refusal, double-charges shared pages, misses transient slot/root or retained payload bytes, releases capacity before the final owner, or changes multiplayer outcomes. The [read-only design challenge](../evidence/i1-headless/MEMORY-DESIGN-REVIEW.md) records why these cases are required. Until this is implemented and measured, the memory box in the [work list](../BUILD-PLAN.md) stays open.

### Prepared rule boundary implemented; byte admission pending

The authority now uses read-only `prepare(&World, Change)` to return complete `WorldEdit` replacements and an optional event payload. It applies each returned batch through the world's validated edit path, then assigns event/result identities. The next action decides and prepares against earlier canonical effects, including another peer's action; a rejected action has no edits or event. One game-owned rule implementation serves standalone and match authorities. No world mutation or event emission occurs during `prepare`. An invalid prepared batch returns terminal `StepError::TerminalGameContract`. The authority is poisoned before tick mutation, so an unwind caught by the caller is also terminal. Its failed tick emits no snapshot, event or result; `try_baseline`, input admission and acknowledgement refuse the faulted instance. The host faults rather than replaying it. If a prior tick succeeded in the same catch-up callback, the callback delivers that publication with an explicit terminal fault. Snapshot backpressure remains retryable before mutation.

`PreparedEdits` holds zero, one or two edits inline and uses an owned vector for larger batches. The one-edit path avoids a validation collection; the two-edit path validates with inline bookkeeping and was measured through the complete authority and replica flow. A future finite admitted game profile must cap actual edits, spawns and inline `size_of::<Entity>()` per action before application. Arbitrarily large inline state can increase stack pressure, and arbitrary `Entity: Clone` or output payloads remain outside the byte proof. The host must calculate a conservative page/root peak from those bounds and all due inputs before its first edit, then include group, result, event, input-history and required replica peaks in one reservation. Exceeding a declared bound will be a terminal contract fault. See the [rule-boundary qualification](../evidence/i1-headless/PREPARED-RULE.md).

### Charged snapshot authority bridge, partial gate

The bounded bridge now connects the shared pool to authority construction and each tick's snapshot pages. A charged constructor reserves the tick-zero page/root peak before its initial publication, and records an explicit maximum edit and spawn count per due action. Before any tick mutation, it counts due actions, checks the products of those bounds, computes the world's constant-time conservative page/root peak and tries one process-shared reservation. Capacity refusal leaves tick, inputs and world unchanged for retry. Each actual prepared batch must fit its declared counts; a violation faults the authority. The final page/root publication spends the reservation; an unexpectedly insufficient bound after mutation is terminal. A one-edit action in a small world can reserve one page and one root while unchanged ticks need no new snapshot bytes. The shared pool arbitrates competing worlds and old readers by unique allocation ownership.

This [tested bridge](../evidence/i1-headless/CHARGED-AUTHORITY.md) is narrower than the whole-process gate: the due-input scan is proportional to pending actions, but idle work is independent of world size. The maximum counts are trusted game-contract declarations and currently do not constrain allocation during `prepare`. Mutable world slots/indexes, results/events, full-state groups, baselines, replica maps and arbitrary game payloads are still outside the charged scope. The full admitted profile must bound and charge them before the parent memory item closes. Rejection criteria for the bridge are mutation on pool refusal, a retry after a declared-bound violation, a charged world silently using uncharged publication, or release while an old snapshot reader remains.

### Whole-tick byte gate: bounded profile and owner plan

The next design target is a finite I1 profile, not a second game rule path. The authority continues to call one typed `decide`/`prepare` implementation for standalone and match play. An admitted value must use an engine-owned structural representation: scalar/fixed-array inline fields and explicit tagged records, plus charged immutable owners for variable data. Arbitrary game `Copy` is insufficient because it can contain external references or pointers; arbitrary `Clone` can allocate even for a `Copy` type. The engine controls duplication of inline fields without invoking game `Clone`, and checks that every charged product belongs to the authority pool before retaining it. Typed game-facing views must preserve that closed storage representation; their access cost is part of qualification. The prototype remains available for unqualified games. Once a world enters the qualified path, game code writes only through prepared edits and charged product constructors; the unrestricted `World::get_mut` prototype escape hatch cannot bypass the gate. A budgeted rule context must be available to both `decide` and `prepare`: rejection values from `decide` are retained outputs, while a successful `Change` is temporary rule work. The context enforces per-action edit, spawn, new payload, event and retained-output limits. Private game scratch outside engine-owned products needs a separate game work budget and is not counted as publication-pool memory. The first storage proof uses a private-field `PublicationRecord<const INLINE, const BLOBS>` containing only `[u8; INLINE]` and `[Option<PublicationBytes>; BLOBS]`. Its constructor checks all payload owners against one pool; its engine-controlled clone copies bytes and shares existing charged owners. The sealed closed-authority entry path scans initial slots once and checks every prepared state before applying the batch; foreign owners or states above selected inline-byte, payload-slot and per-payload-byte limits fault the authority without a partial edit. An idle tick performs no value scan, and the per-action scan is linear only in prepared states and payload slots. The final shared owner determines payload release. A typed game-facing projection, bounded action and temporary work, charged output/history buffers and complete pre-edit admission still need proof before this becomes a general qualified profile. The first fixture verifies both fixed state and a charged variable payload without changing authority semantics.

The sealed entry path also selects separate closed limits for action, event and game-rejection values. It checks their type shapes at construction. A new action is checked for pool provenance and per-payload size before entering the pending map or consuming a sequence; a game rejection is checked before retaining an outcome, and a prepared event before any world edit. Exact duplicate lookup precedes new-action validation because it retains no incoming value. These checks prevent a wrong-pool or oversized value from entering authority history, while pending/history container bytes, output buffers and game-callback allocations still await the whole-tick gate.

| Owner | Capacity/lifetime needed by the admitted path |
| --- | --- |
| Mutable world and authority history | Use fixed-capacity or precharged containers for slots, indexes, free/dirty/change ledgers, a profile-selected maximum peer count and bounded per-peer pending/completed/result progress. Any allowed growth is admitted before a tick; node-based maps with hidden allocation cannot silently grow on the qualified path. Retained input payload products keep their own shared charge until acknowledgement, expiry or reconnect. |
| Immutable snapshots | Keep the implemented unique page/root charges and eight-bundle count limit; also charge each tick bundle lease owner and the bounded lease directory. The pre-edit reservation covers dirty and structural high-water plus staging overlap. |
| Rule and group work | Reserve bounded preparation scratch, complete changed records, results, events and peer watermarks before the first edit. A charged group owns its buffer charges; ordinary `StateGroup::clone` cannot make an uncharged deep copy in the qualified path. |
| Required local replica | Reserve object/progress map growth and validation scratch before authority commit. Transfer changed entity values into confirmed state, and return outcomes with their buffer charge. A malformed group is terminal; expected capacity refusal happens before the authority step. |
| Baseline and host delivery | A fallible baseline reserves its full-state and retained-outcome copies outside the tick. Callback publication storage and leases follow the same pool until the caller releases them. Remote peer queues use separate bounded N1 admission and never pin server snapshots. |

The selected qualified group representation is a by-value identity/tick header with separately shared, charged columns for changes, results, events and peer watermarks. A nonempty column owns a private `Vec<T>` with a separately enforced logical fill limit and its single charge behind an `Arc`; cloning the group shares column owners instead of deep-cloning records. An empty column has no allocation. Rust guarantees `Vec::with_capacity(n)` requests storage for exactly `n` elements from the allocator, although the allocator may provide unused surplus. Preflight first reserves checked `n × size_of::<T>()` plus the shared-owner/header charge for every required column, then allocates before the first edit. The private wrapper never fills past `n`, grows, shrinks, converts or deep-clones the vector, so allocator-supplied surplus remains allocator slack rather than engine-admitted capacity. Every candidate column keeps its charge during construction and unwinding; a unique `IntoIter` keeps the charge until its final value or iterator drops. This safe representation avoids initialization of unused slots and needs no unsafe-code exception. The logical cap excludes allocator metadata and allocator-supplied slack but includes all engine-requested staging and retained storage. The authority may reuse one charged watermark owner across idle ticks until peer progress changes, avoiding a per-tick peer-list copy. This qualified group is a different storage wrapper around the same lifecycle/result schema and rule path; the current public `StateGroup` with deep `Vec` cloning remains an unqualified prototype and cannot cross the qualified gate.

The local replica consumes a qualified group. If a change column has one owner, it may move state values out of the buffer; otherwise it duplicates closed inline values and shares their charged payload handles. Both cases need separately reserved replica index/record space during the overlapping group lifetime. Result and event columns transfer or share their charged owner into the admitted outcome returned to the host, so a host delivery or later clone cannot make uncharged deep copies. A baseline builds the same column form under a separate fallible reservation and never borrows a mutable world slot. If a group fails validation, the replica changes nothing and drops or returns the candidate owners. The [local full-shape clone probe](../evidence/i1-headless/GROUP-OWNER-DESIGN.md) supports sharing even for zero and one change, but does not measure construction or a complete tick. The first implementation proof should exercise one changed record, two peer watermarks, a retained outcome and a slow shared group; compare owner charges and allocations against the current `StateGroup` path before replacing host output. The exact qualified wrapper API, index growth strategy and preflight overlap proof are still open.

For `A` due inputs, `E` maximum total edits, `S` maximum total spawns, `C ≤ E` changed records, `V` maximum events and `P` registered peers, admission must cover the simultaneous peak of snapshot pages/roots, mutable growth, rule scratch, group buffers, completed history, required replica growth and callback delivery. Pre-existing live owners are already charged; one reservation covers only additional overlapping allocations and transfers into charges as owners become live. Input admission must also protect enough execution reserve for every accepted pending tick, including its worst retained result and required replica output, before it consumes a sequence. Retained input/history payloads and other authorities cannot spend that reserve; if it cannot be protected, the input is refused before sequencing. Future-input credits cannot be reused for the current tick and then released: they transfer into each eventual output owner, while credits for still-pending inputs remain reserved. Authority construction or activation must acquire a precharged finite idle lease/delivery floor before accepting any input; failure prevents activation. That floor lets it advance to a future due tick without consuming input credits. If the count-limited required reader never releases a bundle, the host enters explicit overload rather than promising progress through an impossible memory state. Remote queues use a separate bounded N1 resource partition and cannot consume the required local execution reserve. Products shared by several records keep one payload charge, while each record's inline handle storage is counted. Arithmetic and allocation sizes are checked before mutation. A zero-due, clean-world tick remains O(1) in world size and acquires a precharged finite lease/delivery owner without growing the byte pool. Slot acquisition and reference-count work still need measurement. A required reader or replica without capacity causes retryable precommit backpressure; a false game bound or unexpected postcommit allocation failure is terminal.

The qualified pool is a checked logical owner-byte cap across engine-managed retained data and staging, not an exact OS RSS cap or a bound on arbitrary game-private allocation. Three representation choices need a proof before this target is build-ready. `Vec` and map capacities must be made predictable with preallocation or exact-length owners, including their transient conversion overlap; otherwise a conservative logical cap can miss growth. The public charged group/baseline API must prevent unconditional deep clones while letting the replica consume values and return outcomes without double-charging a moved buffer. The lease and output owner strategy must precharge a finite reusable idle set, and input admission must keep future output credits protected across pause and competing authorities. The next proof should first bind these owners in a small complete two-peer tick, including a large charged action payload and a slow old snapshot reader, then fill pending and completed histories to their admitted limits while a competing world and remote queue seek capacity. Every admitted input must still complete or enter explicit reader overload; excess input must be refused before its sequence is consumed. A zero-pending authority must also continue clean idle ticks while another authority and a remote queue use every byte outside its precharged idle floor. The proof then tests baseline reconstruction and replica-held outcomes. Compare idle work, per-action allocations, charged unique bytes and complete callback latency with the current fixtures. The [design challenge](../evidence/i1-headless/WHOLE-TICK-DESIGN-REVIEW.md) records the value, idle-owner and input-liveness corrections. The parent memory box remains open until those choices are implemented and measured.
