# I1 headless authority: selected slice and qualification

1 November 2026. This is the governing design for the bounded I1 executable slice. It implements the first game-owned rule and in-memory local/replica path, not source admission, a network codec, a general ECS, device shells or the full R4 match. The full [foundation](FOUNDATION-SPEC.md), [network](NETWORK-SPEC.md) and [C4 contracts](CONTRACTS.md) remain the destination.

## Selected interaction and contract map

One preloaded world contains a controlled actor, a collectible and a door. The game owns `Collect` and `Open` rule decisions: collection requires proximity and an available item; opening requires ownership of that item and a closed door. The engine owns world identity, the fixed tick, permission/sequence/timing admission, committed results, event IDs and publication. A standalone connection and an in-memory match connection submit the same typed actions to the same rule. A replica receives a complete baseline and atomic groups with full changed object state, lifecycle, action results and events. A duplicate cannot cause a second collection or event. No presentation, transport or persistence participates in the decision.

| I1 obligation | Owner and C4 contract | Observable rejection |
| --- | --- | --- |
| Fresh local world epoch, checked slot/generation, stable object ID | W1/F3, C01 | stale handle and duplicate stable ID fail |
| Exclusive 60 Hz authority step and immutable committed read model | F1/W1, C02 | old snapshot changes or partial step appears |
| Controlled actor, typed game legality, one committed effect/result | P6/F1, C03/C13 | unauthorized, duplicate, late or stale-epoch input changes state |
| Baseline and atomic full-state lifecycle/result group | N1/W1, C13 | spawn visible before usable state; invalid group partially applies |
| Bounded work and honest evidence | F1/T2, C12 | unbounded pending input or claimed device performance from headless timing |

This slice uses caller-supplied fresh 128-bit local session/world/match IDs; the future host generates them. Match and local session identities are distinct types. A connection epoch and sequence are checked before a command enters the authority. Timing follows the selected `nextTick` 18-past/2-future and `timed` 6-past/12-future admission windows, with timed one-shots over two ticks late rejected. Pending future input may leave a sequence gap while a later due input resolves; group results identify each resolved sequence and a contiguous watermark. The in-memory baseline carries outstanding results, matching event IDs and an event cursor. The initial fixture had one controlled peer; the later [two-player in-memory fixture](../evidence/i1-headless/TWO-PEER.md) exercises independent peers and a slow replica. I2n adds the exact wire envelope, bounded reliable queues, wire result acknowledgement/resync, interest and compatibility manifests. Disconnect/reconnect uses a new epoch and baseline, with no automatic replay of uncertain one-shots.

## Representation and cost account

Select a dense slot table with a free list, generation check and stable-ID index for the finite preloaded I1 world. The `hecs` 0.11.2 private ordinary-component store remains selected for the broader W1 capability; this slice does not have heterogeneous component queries or enough dependency need to add it. Replacing the slot payload with the selected private store must preserve the public identity/barrier interface and be qualified with its actual license, dependency, Wasm and target costs before I2b. Do not expose a backend entity or Rust `TypeId` as durable/wire identity.

The exclusive authority writes slots in place. A 32-slot immutable read-model page is copied only if touched since the last publication; unchanged pages share an immutable root with earlier snapshots. An unchanged tick shares the root in O(1) work; a changed tick copies `ceil(N/32)` page references and up to `32 × D` object records for `D` dirty pages. The world index and free list cost O(N) retained memory and O(1) expected stable lookup; ordered action work is O(A log A) in the bounded pending set, with O(1) ordinary slot reads. Replica confirmed-object lookup is hash indexed; validation uses a temporary ordered duplicate-ID set. Full baseline is O(N) records once. A live in-memory group carries O(C + R + E) full changed records, results and events per tick; I2n must batch at its 20 Hz cadence and independently account for wire bytes, fan-out, acknowledgement and queues. Snapshot pages use owned clones, so no mutable world array aliases a reader. An `Arc` lease keeps old pages alive; retained page bytes grow with the number of concurrently leased changed pages. Authority admits at most eight live tick bundles and backpressures before mutation if they remain leased. Whole-process byte admission, consumer cancellation and host overload policy remain required before a general runtime profile is qualified.

Alternatives: full world copy each tick moves O(N) objects even for one changed object; a persistent tree reduces reference copying but adds nodes/branches and allocations to a small finite world; a universal ECS query planner is premature. Dirty-page copying is chosen for low churn and explicit lifetime. A 25% uniformly distributed churn case will touch almost every page; its measured cost may justify a different page size or selected side store before that workload is supported. Rejected actions avoid page copies. Publication is a commit boundary: rule `decide` receives only `&World`; infallible `commit` runs under exclusive access, and no snapshot/event is emitted until it finishes. A panic after mutation is terminal for this in-memory world; there is no generic rollback or external effect reversal.

The critical path measured here is input admission → authority tick/decision/commit → immutable publication → replica admission. Count attempted/committed/rejected inputs, dirty pages, object copies, full group records and retained snapshot bytes. Measure repeated small reads and no-op ticks as well as high churn. Workload cases are 64, 4,096 and 16,384 objects, with zero, 1% and 25% changed objects per tick, plus typed actions over the small game. These are stress fixtures, not new product population limits. The game fixture checks exact outcomes/events; the scale fixture compares every final replica object with authority state. Record p50/p95/p99/max per-stage elapsed, allocation/byte counts where observable, and run-to-run noise. One host's headless timings cannot certify Mac/Windows/browser/phone frame budgets, lifecycle or the real I2n network.

## Proof queue and status

1. Verify stale handles, ID reuse, epoch mismatch and old immutable snapshots. Reject a design that resurrects a retired identity or aliases mutable state.
2. Run the game-owned collect/open sequence through local and replica roles, then two controlled peers in one match. Inject unauthorized, duplicate, late and old-epoch input, a pending timed gap, a slow replica and a malformed spawn group. Reject any duplicate effect, missing result or partial replica state.
3. Run the declared scale/churn fixture with stage timings and byte/work counts, retaining exact build and command. Investigate recurring cost and tails, then record the selected path's limits. Device targets, actual WSS, durable outcome recovery and mobile shells remain separately unqualified.

## Bounded host-clock slice

The next F1 seam is a headless fixed-step clock driven by a host-supplied monotonic timestamp, separate from display callbacks and the authoritative rule. Its selected default is 60 world updates per second; `tick_hz` is configurable, and presenting at 30/60/120/240 Hz never changes the number of due world updates. Integer nanosecond accumulation with a fractional-tick remainder avoids cumulative rounding from a rounded 16.67 ms period. One callback performs no heap allocation in the clock itself. Its recurring work is O(1) time accounting plus O(K) attempted steps, where `K` is capped by the configured four-per-call safety limit, an eight-tick queue and a host-supplied CPU admission count. The host must derive that count from a measured/bounded tick cost and its callback reserve; the clock alone cannot preempt a slow rule callback or prove a device frame deadline.

The caller's step callback commits one authority update or leaves it unchanged on an expected error. Only successful steps retire due work. A blocked snapshot publication retains the due tick and retries without replaying an earlier successful action. When elapsed active time exceeds remaining queue capacity, the clock enters explicit local overload, reports the due ticks refused at that transition, stops accumulating world time and drains already admitted ticks. Resume requires an empty queue and a fresh monotonic origin. Pause also stops accumulation and allows only previously admitted ticks to drain. A remote authority must use its N1 session-overload policy rather than silently applying this local stop-time policy. The clock owns no render rate cap, transport queue or game rule.

This clock slice is implemented and locally tested against the game-owned authority; [running evidence](../evidence/i1-headless/QUALIFICATION.md) records its cost and limits. A later native headless host callback and the initial authority/replica stage validation are qualified below. The general F1 system registry, typed component views, platform event adapters and full host package remain separate work. Whole-process publication bytes, native phone shells and actual multiplayer transport are also unqualified by the clock fixture.

## Native headless callback and initial stage plan

The bounded headless host owns one `TickClock`, one `Authority`, and optionally one in-memory `Replica`. It prepares a typed two-stage schedule once: authority state mutation/publication precedes replica admission. Validation rejects missing or backward dependencies, cycles, unordered conflicting access and cross-role world access; the selected rule stays inside the one exclusive authority stage and follows the same game-owned `decide`/`commit` path as direct calls. Local publications and replica-admitted results/events return to the caller. The caller explicitly acknowledges handled outcomes; until then, bounded retained-result capacity applies. A newly hosted replica returns its baseline outcomes at construction. This is an I1 stage plan, not a general F1 component-system registry.

The host receives real monotonic `Instant` callback times. A configured callback time budget, other-work reserve and conservative complete-tick cost bound determine the admitted tick count once at construction. The clock's four-per-callback and eight-queued caps still apply. Each committed tick checks actual elapsed wall time against the budget **after** the other-work reserve and stops further catch-up if spent; the callback then enters explicit overload and closes input admission. A replica rejection after authority commit is terminal for this host, because that tick cannot be retried. The measured headless fixture uses a 120 Hz native callback loop, two controlled peers, 60 Hz authority and in-memory replica; [evidence](../evidence/i1-headless/HOST.md) includes callback cadence, per-callback service time, actual submit-to-confirmed-result latency and injected slow-callback overload. This proves the initial hosted clock path, not device frame pacing, mobile lifecycle or online session service.

## Two controlled peers in one in-memory match

The two-player fixture keeps one game-owned rule and one authoritative world. Distinct peer IDs, connection epochs and controlled actors share that authority; the peer map supplies independent sequence, pending, result and watermark state. Simultaneous attempts to collect one item are resolved in the authority's canonical peer order, so one effect commits and the other receives a game rejection. This fixture also delivers several complete tick groups late to a replica, then verifies the same final state and joined baseline. Its [correctness and cost record](../evidence/i1-headless/TWO-PEER.md) measures two accepted actions per tick in a separate small counter workload. It proves in-memory peer separation and ordered admission, not encoded WSS, four-player latency, network backpressure or durable outcome recovery.

## Publication-memory admission gate

The process-wide publication cap must charge each unique retained immutable page and root allocation once across all worlds and readers, plus retained full-state groups, results and events. Summing `Snapshot::logical_bytes` is invalid because shared pages would be charged repeatedly while owned game payloads and group copies would be missed. Admission must reserve a conservative peak **before** any rule commit mutates the world; a slow required reader returns backpressure without reusing its pages. Release must follow actual last-owner retirement, including a replica or view that holds an older snapshot.

The current `Entity: Clone` and `World::get_mut` allow game-owned values with arbitrary heap growth, and `commit` can structurally change the world. A hard byte cap cannot be inferred from `size_of::<Entity>()` or current dirty flags. **Selected target for the next implementation:** an admitted game profile must declare finite state/structural/output bounds and express authoritative writes as a prepared command batch whose maximum publication footprint can be checked before commit. The general unbounded `Clone` path remains a local prototype, not a budget-qualified path. A game-owned heap payload must be stored in a separately admitted immutable product or carry an enforceable bounded footprint; a claimed maximum in a trait without enforcement is insufficient. The prepared batch must preserve one `decide`/commit authority, exact action outcomes and the atomic replica group. It must keep idle-tick admission O(1) and make conservative reservation visible in cost evidence. Do not promote a shallow page-byte counter as whole-process memory qualification.

The shared pool owns a count and byte limit. Its reservation uses a checked process-wide total before any authoritative mutation; page and root allocations, full changed records, retained results/events and baseline/group buffers draw from that reservation. Each unique immutable allocation has one lifetime charge, shared across snapshots and authorities, released by its actual last owner. Count and byte reservations are separate: a no-op tick still has a distinct leased tick bundle, even if it shares all world pages, so an old reader cannot evade the eight-bundle limit. The hot path must not scan every old page or every world to find capacity. A `Copy`-only game state would simplify a finite proof but unnecessarily narrow this reusable engine; an unchecked footprint trait would produce only a promise, not a hard bound. For a new page, build its final allocation directly; do not allocate a temporary empty page and immediately replace it. The current implementation removes that avoidable growth allocation, but does not yet implement the process-wide pool or precommit byte gate.

The proof fixture will share one pool across at least two authorities, hold old readers while state grows, force a rejected tick before mutation, then release readers and show recovery. It will compare charged unique bytes, actual owned allocation scope and count limits, and exercise a replica holding groups. Its rejection conditions are any mutation before budget refusal, double-charged shared pages, an uncharged heap payload/group, or recovery before the actual last owner releases. Until this is implemented and measured, the memory box in the [work list](../BUILD-PLAN.md) stays open.
