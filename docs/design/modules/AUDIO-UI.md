# A1 audio and U1 UI/text/accessibility family

Status: analytically designed target, **provisional** mechanism selection, 31 October 2026. No runtime implementation, measured latency, device certification, accessibility audit or visual review. **V1 scope:** [G6](../../BUILD-PLAN.md#active-gate-order-and-budgets) needs U1 demo controls (text, sliders, toggles and overlays of engine fields bound to typed game parameters) natively and in Chrome, within UI CPU ≤0.05 ms per frame and zero steady allocations; A1 and the rest of U1 are not V1 gates. Scope derives from the [architecture brief](../ARCHITECTURE-BRIEF.md), [shared contracts](../CONTRACTS.md) and [design programme](../DESIGN-PROGRAMME.md); source audit is [here](../research/AUDIO-UI-SOURCES.md). This family serves 3D top-down, isometric, third-person and first-person games across native Mac/PC, browser and iOS/Android. It does not promise a general 2D game framework or MMO voice chat.

## Required experiences and ownership

| Experience | Producer → consumer and owner | Required invariant |
| --- | --- | --- |
| A collision, action or sequence admits one sound | P3/P4/P6 committed cause → P6 event ledger → A1 logical voice → output | One logical admission per event ID; no sound triggered by render frame or visible-particle count. OS interruption can still prevent an admitted sound from being heard. |
| Ambience/music persists across camera changes and streaming | W1/E1/P6 state plus F4 content → A1 emitter/music policy | One clocked soundtrack per output policy; region retirement removes emitter representation only after voice/tail policy. |
| A character hears offscreen activity | W1 positions, P2 listener choice, P3/E1 acoustic query → A1 | V2 camera frustum and occlusion culling are irrelevant to sound eligibility. |
| Two cameras view one world | P2 per-view transforms → A1 explicit listener selection | No accidental two-world advance, duplicate sound or rapid nearest-view listener flip. |
| Accessible menu, text entry and subtitles | Authored UI schema/content → U1 semantic/layout tree → GPU/DOM/native accessibility | The same focused control and label drive pixels, hit tests, keyboard/controller/touch and assistive output. |
| Mobile interruption and return | F1 shell → A1/U1/P1/P7 | No callback on dead device, catch-up burst, repeated transient sound or lost text composition. |

**A1 owns** authored sound cue interpretation, logical emitter and voice state, mix buses, scheduled sample envelopes, spatial presentation and device adapter. P6 owns *cause/event identity*; W1 owns transforms/object lifetime; P2 owns cameras; F1 owns lifecycle and platform clocks; F4 owns cooked asset availability; P7 owns durable game state and replay; V2 owns visual culling. UI sounds can be U1-generated presentation cues with U1-local gesture IDs; gameplay consequences still enter P6 commands. A1's effects are never authoritative game state.

**U1 owns** an authored semantic UI tree, layout, text selection/shaping plan, hit testing, focus, accessibility projections, localization hooks and visual composition. P1 owns raw device normalization and action mapping; U1 gets first chance to consume events in the active focus context, then P1 admits gameplay actions. F1 owns native/browser IME and safe-area notifications. V1 owns GPU execution and device lifetime; U1 contributes draw products/passes without private submission. P2 provides projection/picking data for world-space panels, which remain U1 semantic controls. T1 edits the same schema/operations as game-authored UI, not a private editor mutation path.

## A1 operating model

### Cause, clock and scheduling

The producer emits a committed event `e = (world_epoch, tick, producer_stable_id, local_sequence, kind)` under C03/P6. A1 keeps a bounded consumer cursor plus deduplication keys for the current replay epoch. It records `seen` (ledger consumed), `queued` (accepted by output scheduler), and `rendered/expired` (sample callback progressed past the event or cue deadline) separately. `rendered` is an engine observation, **not proof the OS/device made the sound audible**. A repeated extraction of the same world snapshot never creates a second logical voice. An audio-device generation is separate: rebuilding an output device must not reset event identity. Source IDs and active voice IDs also carry runtime generations so a late asset decode cannot attach to a retired emitter.

The world clock is `t_w(n) = n h`; the device/context clock is `t_a = sample_index / sample_rate`. At each valid transition, F1/A1 establishes an anchor `(n_0, s_0, rate)` and maps a committed event to `s_e = s_0 + round((n_e-n_0) h f_s / rate)`, where `rate` is world-seconds per audio-second (normally 1). A bounded lookahead `L` schedules only admitted events whose assets are ready. Because an event cannot enter A1 before its tick commits, the actual start is `s_start = max(s_e, s_now + Q + safety)` for a device quantum `Q`; the added scheduling delay is recorded. A late transient starts at that earliest safe slot if still perceptually relevant or is dropped by a cue-specific expiry. No retroactive sample playback. This mapping is a design inference; browser `AudioContext.currentTime` and native device callbacks expose different clock/latency details ([Web Audio time](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime)).

Pause is a policy per bus/cue: gameplay one-shots stop admitting; looped ambience/music retain phase or fade/pause; UI confirmation can remain audible while the game is paused. Seek/replay increments a presentation epoch, cancels unstarted scheduled voices, and restores loop/music phase from declared state. The default live-resume rule marks a one-shot already queued before interruption as consumed and does not replay it; one-shots seen during interruption expire or wait only under their authored cue policy. An explicit replay mode may request historical re-audition under a new presentation epoch. A resumed device uses a new anchor at the next valid world tick and resumes retained loops from stored phase, without draining every event emitted during suspension. Durable event cursor/save semantics stay with P6/P7; A1's event-state cache is presentation state, reconstructed from cursor/replay policy. This provides one logical admission per committed event under normal operation, not exactly-once *audible* playback across OS interruption. Browser autoplay gating creates a `NeedsGesture` output state rather than a failed world tick ([browser guidance](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)).

### Voice, mix and spatial path

Cooked cues declare stable clip/stream ID, gain, priority, concurrency group, attenuation range/model, loop region, bus, localization variant and late-event expiry. At admission A1 creates a **logical voice** even when it cannot allocate a physical mixer voice. Each update ranks logical voices by audibility/priority with stable tie-breaking and hysteresis; up to `V_phys` voices render. A virtual looping voice continues phase and can re-enter at the correct offset; an expired one-shot retires. Per-group limits prevent a burst of nearly identical impacts from consuming every slot. Voice stealing uses a short gain ramp to avoid discontinuities. Priority cannot make an inaudible event authoritative; subtitles/haptics are separate consumers of the same cause.

Mix topology is source → spatial/filter node → category bus (effects, ambience, music, voice, UI) → master limiter/output. Bus gains, mute, ducking and side-chain policy are explicit and smoothly ramped; user volume preferences are durable settings, not a hidden engine singleton. Game-authored music state/tempo and transition rules run on the audio clock with quantized sample or beat boundaries. A1 may own a modest wet/dry reverb send but must declare CPU and tail lifetime. No GPU/readback dependency is permitted in the audio callback. The callback reads preallocated command/audio buffers and bounded DSP state; decode, file/network access, heap churn, waiting on locks and physics raycasts occur elsewhere ([Android callback guidance](https://developer.android.com/games/sdk/oboe/low-latency-audio)). A queue overflow reports a bounded dropped/deferred count, retaining higher-priority commands under deterministic admission rules; it cannot grow without limit.

For a point emitter at distance `r`, choose authored `r_min>0`, `r_max>r_min` and bounded inverse attenuation such as `g_d(r)=1/(1+k(max(r,r_min)-r_min))` for `r<r_max`, with a short smooth fade to zero at the limit. `k`/distances are cue parameters, not physical truth. Directional cones multiply a bounded directivity gain. Relative velocity may drive capped doppler, but camera interpolation alone cannot induce a speed change; use time-consistent world/listener velocities. Spatialization quality selects stereo pan or HRTF only when output/device/CPU support it. Stereo UI/music are non-spatial unless authored otherwise. miniaudio documents these primitive controls, not this policy ([manual](https://miniaud.io/docs/manual/)).

Occlusion is a **separate acoustic visibility query**, budgeted by perceptual importance and generation. Baseline: P3/W2 supplies coarse solid/portal geometry and material acoustic classes; A1 requests at most `R` ray/portal samples per emitter/listener update, obtains an occlusion fraction `o∈[0,1]` and combines `g_occ = 1-o(1-g_blocked)` with a bounded low-pass cutoff. Treat the result as a smoothed approximation, not an exact wave solver. At cell boundaries, unknown or stale geometry returns `unknown`; policy uses previous valid value briefly then a conservative authored fallback, never "open air" by accident. Query interval `Δt` gives a worst-case reaction delay of roughly `Δt + query latency`; fast door/portal changes can request an immediate prioritized refresh. Optional room/portal sends add early-reflection/reverb approximations, with authored room boundaries and crossfade; full diffraction/convolution is not a baseline promise. Acoustic source state and ray budget do not depend on camera visibility. Reverb tails may outlive emitter cell retirement under an explicit tail cap and lease.

**Multiple views:** a physical output mix has one selected local listener rig by default: the owning local player/primary interactive view's P2 pose, with optional authored ear offset and short transitions on camera cuts. Secondary map/editor/reflection views contribute no independent listener. Split-screen with two audible players is an explicit separate policy: weighted two-listener sum with per-source energy normalization or two device outputs, plus increased voice/query cost; it cannot inherit miniaudio's closest-listener default without a design choice. A camera cut can reposition the listener at a declared boundary with a short spatial crossfade; it never schedules the same event twice.

### Content, lifecycle, platform path and cost

F4 cooks small transients as decoded resident buffers and long music/ambience as compressed streams with decode ahead. Audio product records codec, channels, sample rate, loop points, loudness/peak metadata, trim and dependency hash. Decode/cache leases include source generation; region activation may admit gameplay with a named silent/placeholder cue when sound is optional, but a required spoken instruction blocks or exposes an accessible text fallback. Stream starvation produces silence/fade and telemetry; it never stalls the callback. Seek can be async and returns pending until its decode window is ready. Resampling occurs outside or in bounded DSP and changes on route/sample-rate rebuild. Source retirement waits for in-flight callbacks and tails, then releases F4 lease.

Candidate substrate: **provisionally** use a native low-level device plus mature mixer/resource primitives, with miniaudio as the primary candidate after a pinned FFI, callback and mobile-shell audit; browser baseline can use a Web Audio graph for buffered/streamed playback without mandatory `SharedArrayBuffer`. The same cue, scheduling, voice and bus semantics must be implemented in both adapters; sample-identical DSP is not promised. CPAL is a credible Rust-native device alternative but leaves mixer/streaming ownership to us; Kira's upstream desktop focus and Wasm streaming limit make it a poor sole provider ([source comparison](../research/AUDIO-UI-SOURCES.md)). If a single Wasm native mixer is later desired, its AudioWorklet/atomic deployment profile must be separately qualified, not silently imposed on the public website.

Let `f_s` be device sample rate, `Q` callback frames, `C` output channels, `V_phys` active voices and `K_dsp` bounded DSP work per sample. Callback deadline is `Q/f_s`; work is approximately `O(Q(C+V_phys+K_dsp))`, with no unbounded sort/query/allocations in that thread. Control work is `O(V_log log V_phys + R)` per update if voice ranking uses a bounded heap; spatial queries are separately budgeted. Buffer memory is approximately `Σ(decoded_frames_i·channels_i·bytes_per_sample) + Σ(stream_ring_bytes_i) + O(Q C + V_phys state)`. Peak includes old/new route buffers and F4 decode staging. `Q=128` at 48 kHz is about 2.67 ms, **an illustrative arithmetic deadline, not a guaranteed device quantum or measured latency**. Output latency includes queued buffers, OS route and device path; Bluetooth may dominate. Platform targets and xrun limits need device qualification.

`AudioOff` removes device, decode/stream jobs, mixers, voice queries and retained effect tails. P6 event production remains if gameplay, subtitles, haptics or replay needs it; A1 consumes no resources. `SpatialOff` retains non-spatial audio and suppresses listener/occlusion work. `AcousticsOff` supplies an explicit unoccluded/default-room input and releases query/reverb resources. Live changes reserve overlapping buffers, fade at a sample boundary, then retire prior device generation. Device interruption, Android focus loss/ducking, iOS route removal, browser hidden tab and app suspend transition through `Active → Ducking/Interrupted/NeedsGesture → Restoring → Active`; only F1/OS can report the event, A1 decides gain/clock response. Route changes may alter sample rate/buffer size. On failure, gameplay remains operational with visible captions/status and a retryable audio state; it never blocks world advancement. iOS interruption/resume and Android focus behavior require dedicated shell bridges ([Apple](https://developer.apple.com/documentation/AVFAudio/handling-audio-interruptions), [Android](https://developer.android.com/media/optimize/audio-focus)).

## U1 operating model

### Authored semantic tree through display

Authored UI records contain stable node ID, role, label/value/help/localization keys, style/layout constraints, interaction/actions, tab/focus order, visibility and per-platform presentation hints. F3 versions fields; T1 edits via typed operations with validation and revision preconditions. A game package supplies data binding and action commands; U1 does not own inventory/quest/combat state. Runtime reconciliation builds one semantic tree with node generations, then derives: (1) layout boxes and clipping, (2) hit-test index, (3) paint/display list, (4) accessibility tree. All four use the same visible/focusable node revision, preventing a control whose drawn or accessible bounds disagree with click targets. A hidden menu retires its focus and accessibility nodes; focus moves to a defined successor.

Layout uses a retained tree with measure → constraint resolution → arrange. Rects use logical device-independent units; F1 supplies viewport size, DPI/text scale, orientation and safe-area insets. Anchors/flex/grid-style constraints are sufficient for HUD, menus, subtitles and split-screen viewports; avoid unconstrained cyclic size dependencies by rejecting them at authoring/validation. Percent sizes are resolved from a known parent content box; intrinsic text measure is cached by content/font/style/width/locale revision. Dirty changes propagate to nearest layout root; worst case is `O(N)` nodes, typical cost `O(N_dirty + glyphs_changed)`, explicitly measured rather than assumed. Layout output rounds only at raster edges so hit tests use the same unrounded boxes. For world-space panels, P2 supplies one view projection and depth policy; U1 maps pointer rays to panel-local hit boxes but validates W1 object generation before issuing a P6 command. UI overlay composition is a V1 pass after selected scene/display stages with documented HDR/SDR, tone mapping and clipping order; accessible bounds track the final viewport, not a pre-scale render target.

The paint list groups by clip, layer, texture/font atlas and material while preserving z order. Glyph atlas pages are F4/V1-owned GPU resources leased by U1; cache keys include font revision, glyph ID, size/raster mode and scale bucket. Eviction invalidates paint entries and re-rasterizes asynchronously; a missing glyph uses a visible fallback box with stable advance, not a layout crash. Atlas growth has a byte cap and eviction policy. Renderer device loss rebuilds pages from font assets and shaped runs; semantic tree/focus survive. No per-frame full-tree rebuild is required for an unchanged UI. U1 submits pass declarations; V1 owns allocation, barriers and presentation.

### Text, localization and editing

Text pipeline: resolve localized message and parameters → bidi paragraph levels (UAX #9) → script/language/font runs → grapheme/word segmentation (UAX #29) and line-break opportunities (UAX #14) → HarfBuzz shaping per run → line layout/selection mapping → glyph raster/cache. Shaping receives direction, script, language, font and features; glyph clusters are not equivalent to bytes, Unicode scalar positions or user-perceived graphemes ([HarfBuzz](https://harfbuzz.github.io/getting-started.html), [Unicode](https://www.unicode.org/reports/tr29/)). Pin Unicode data version and font fallback chain in the cooked profile; retain source-to-cluster mapping for caret, selection, hit testing and screen-reader ranges. Font fallback occurs by grapheme/script coverage before shaping; an absent glyph uses a declared fallback font/tofu and reports diagnostics. Localization packages carry message IDs, plural/select rules, locale metadata, line-break tailoring and fonts; missing required strings fail cooking or use a clearly marked development fallback. UI layouts must tolerate expansion, RTL mirroring where appropriate and dynamic type; numbers/dates come from locale-aware formatters, not literal English concatenation.

Editable controls use a dedicated composition state: preedit text and selection are transient, committed text changes only on IME commit, and P1 bindings consumed by that focused control/IME context are suppressed. This does not globally pause the game or suppress unrelated actions unless game policy chooses that behavior. F1's browser/native bridge reports composition updates, cursor rectangle, selection and virtual-keyboard insets; U1 returns a caret rect in platform coordinates. Grapheme-aware movement/deletion, word selection, clipboard and undo are UI operations; password fields redact accessibility values as required by platform policy. On suspend or focus loss, composition is committed/cancelled by the platform-reported outcome, never guessed from a key-up. A native game does not gain correct CJK/RTL input merely by rendering shaped text. Browser baseline should use a real DOM input/textarea as the IME and accessibility anchor; custom canvas pixels can follow its semantic state. A parallel hidden DOM tree requires strict synchronization and testing, so standard DOM controls are preferred for menus/forms where visual design permits.

The [capability survey H04](../CAPABILITY-SURVEY.md) extends production tooling, not this runtime model. U1/F4/T1/T2
should support keyed text extraction/interchange, missing/obsolete-key reports, expansion/pseudo-localization preview
and selected locale-specific voice/art validation. Existing IDs, fallback and cook/residency rules remain authoritative;
a translation service is optional. Languages and supported scripts are selected and qualified, not universally promised.

### Focus, input and accessibility

F1 tags raw keyboard/pointer/touch/controller/IME events with device, window, monotonic time and focus epoch. U1 performs hit test and focus routing first; an event either yields a UI action/consumed result or passes to P1's gameplay map. Pointer capture and gesture arbitration bind to one node generation; node removal cancels capture. A modal traps focus within its semantic subtree and restores it to the trigger or defined successor on close. Keyboard navigation has visible focus and distinct selection state. Controller directional focus uses authored neighbors or spatial geometry with deterministic tie-breaking; no invisible focus target. Touch targets, safe-area insets and virtual-keyboard occlusion are part of layout. Remapping, hold/toggle assistance and sensitivity remain P1 policies; U1 exposes controls to edit those settings without creating separate gameplay commands ([WAI keyboard practices](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)).

The accessibility projection includes role, name, value, state, actions, bounds, order, live-region/caption policy and focus ID. Browser uses DOM/ARIA with native elements where possible. Desktop custom-rendered UI may use AccessKit after adapter/version audit; its overview currently lists macOS, Unix and Windows adapters, so iOS/Android/web cannot be claimed from that page ([AccessKit](https://accesskit.dev/)). iOS requires a UIKit accessibility bridge, Android an accessibility node/provider bridge; both must forward explore-by-touch, focus, actions and text editing. Semantic updates are bounded and coalesced but never omit an important state change. Captions, speaker tags and non-sound cues derive from the same P6 cause/content record as audio, with user settings for scale/contrast/motion/sound. Accessibility metadata is authored and validated before packaging; a runtime bridge cannot invent useful labels.

`UIOff` is valid only for a headless or intentionally interface-free profile; it removes layout/shaping/glyph/paint/accessibility work but retained game command input may still exist through P1. An in-game UI cannot disable accessibility alone to save work while claiming accessible operation. A text-only/server profile can retain semantic output without GPU paint. User settings may switch visual style, scale and locale live via a staged relayout/atlas replacement with peak-memory admission; focus is preserved by stable ID when possible, otherwise moved deliberately. If a font/locale bundle is unavailable, retain the previous locale or show a safe fallback and report failure; do not publish half-relayout. GPU loss does not erase focus, IME state or semantic data.

Let `N` be UI nodes, `G` visible glyphs, `D` dirty nodes, `A` atlas bytes and `H` hit-test entries. Full layout and accessibility projection are `O(N + G)`; dirty updates target `O(D + changed glyphs)` but a root width/locale change can legitimately cause full relayout. Hit testing with a spatial index is `O(log H + overlaps)` plus clip/z checks; worst case `O(H)` under stacked overlays. Paint traffic is roughly `vertices_per_quad·(rect_quads+G)` plus atlas sampling, with overdraw bounded by clipping and authored layer policy. Text shaping and line layout are moved off the render critical path when immutable inputs permit; focus/IME response still has a main-thread deadline. Plan atlas and retained-tree bytes inside F4/V1/U1 peak, including old/new locale/font overlap. These are cost models, not measured budgets.

## Coupled interaction trace

1. On a phone, a player opens an inventory dialog from touch. F1 tags the event; U1 hit tests the button, moves focus into the modal, records an accessibility announcement and consumes the gesture. P1 admits no gameplay fire action. The inventory game package receives a typed P6 command at the next tick.
2. The player closes the dialog and triggers a world interaction. U1 restores focus, P1 resolves the gesture to an action, P6 validates target generation and commits one event ID. P3 contact is already resolved in the same declared tick order. A1 schedules one sound from that ID; a caption consumer publishes corresponding text. V2 may cull the source and a secondary overhead camera may see it, but neither condition duplicates or suppresses the sound.
3. The output mix uses the primary player listener from P2, not the overhead map view. A1 samples the committed emitter pose, P3/W2 acoustic query generation and optional E1 environment. If the next cell's acoustic geometry is not ready, it uses explicit unknown/fallback policy; it never treats an unloaded wall as transparent by default.
4. A call interrupts iOS audio while an asset upload is pending. F1 closes presentation/device admission and reports the audio interruption; A1 fades/stops output, freezes or retires voices per cue and records its new device epoch. P7's periodic checkpoint is authoritative. A1 does not block the world callback, and F4 cannot publish a late decoded clip to a retired source generation.
5. On foreground return, F1 restores surface and audio route, checks whether resumption is permitted, and U1 relayouts for current safe area/keyboard state while preserving stable focus. A1 establishes a fresh device-clock anchor, resumes loop/music phase, skips expired one-shots and keeps the P6 cursor/dedup set. Browser return may remain `NeedsGesture` until user activation. One world clock continues under F1's capped catch-up/pause policy; no audio burst occurs.

## Dependency-ordered commissions and predictions

1. **Freeze shared schemas and state transitions.** F3/P6/P7/F1/P2/U1/A1 owners specify exact event/cursor, cue, UI node/focus, listener and interruption records, including versions and failure states. Reject if a replay, device rebuild or two-view extraction can emit a second transient sound or lose focused control. This is an analytical contract task before building.
2. **Pin implementation candidates and platform matrix.** Audit exact miniaudio/CPAL/Web Audio, HarfBuzz/Unicode/font rasterizer and AccessKit/native bridges against supported OS versions, licenses, Rust FFI, browser isolation/autoplay and mobile app-shell APIs. Choose narrow adapters and record unsupported targets; do not infer native support from a generic upstream list. Reject a candidate that requires a forbidden browser deployment mode for baseline, cannot express safe callback ownership, or cannot expose accessible UI actions on a selected platform.
3. **Implement one complete semantic path with recording fakes first.** A P6 event creates one A1 logical voice/caption through duplicate snapshot extraction, seek and source retirement; U1 focus consumes the input before P1 and preserves identity through relayout. Assert event ID/cursor, phase and focus invariants using deterministic clocks. A fake is sufficient for logic but does not certify audio timing or accessibility bridge behavior.
4. **Integrate real native/web adapters and authored content.** Use one small scene with one offscreen source, a wall/door, one streaming edge, music loop, two views, localized modal/text field, captions and an accessibility tree. Predicted failures to reject: sound disappears with V2 culling; nearest-view flapping; door update exceeds declared acoustic query age; stream underflow blocks callback; Web Audio does not recover from `NeedsGesture`; keyboard/controller/IME actions leak into gameplay; screen reader focus diverges from visual focus.
5. **Qualify complete transitions and budgets.** On this Mac and Chrome for V1, then Windows and iOS/Android devices on rented hardware, record device/OS/browser/version/content hash and sustained p50/p95/p99 callback/frame/input-to-sound times, xruns, memory peaks, atlas churn, stream queue and accessibility behavior. Test suspend, phone call/focus loss, route/sample-rate change, orientation/keyboard safe area, GPU loss and locale switch. Reject if bounded-queue, event-once, focus, restart or accessibility invariants fail; adjust numerical targets only with measured evidence and the whole-scene budget owner. Human listening/readability/accessibility review remains separate from technical pass.

Remaining product choices: minimum devices/browsers, whether split-screen needs simultaneous listeners, exact acoustic quality floor, spoken-dialogue importance, accessibility target level and localization set. These are explicit scope/budget decisions; the baseline above remains coherent without inventing their answers. High-level independent review is recorded in [WHOLE-ENGINE-REVIEW](../WHOLE-ENGINE-REVIEW.md); implementation and platform qualification remain unrun.

## Networked presentation boundary

[N1](NETWORKING.md) supplies confirmed events and explicitly permitted speculative cosmetic keys. A1/U1 reconcile
confirmation/correction without duplicate one-shots; already played sound cannot be undone. A local listener/view
never changes server authority, and a client cannot turn a UI edit into a server save or T1 source operation. Replay,
seek, prediction correction and device interruption have distinct policies. Networking-off retains the ordinary local
path without replication histories. These C11/C13 obligations are selected design, not an implemented network claim.

## Multiplayer outcome consumption

C13/NETWORK-SPEC publish committed action results and event origins with atomic replica state. U1 distinguishes
pending, committed, rejected and uncertain-after-disconnect actions; transport receipt alone never shows success.
A1/V5 reconcile optional speculative cues by origin and deduplicate confirmed event IDs within their bounded retained
history. Reconnect reconstructs ongoing state; historical transient audio is not replayed to invent confirmation.
Already heard sound cannot be undone. Effect deadlines may expire a presentation while authority state remains valid;
result admission and device playback are different acknowledgements. No new audio/UI network authority or private
RPC mechanism is introduced. Source UI/cue edits follow file admission and restart/qualified visual-preview policy.
