# Complete atmosphere scope and interaction account

2 November 2026. Companion to [CLOUDS](CLOUDS.md), [selected mechanisms](CLOUD-PRODUCTION-BASELINE.md) and the
single [checkbox queue](CLOUD-MIGRATION.md). This is a coverage/ownership map, not a second queue or a full-engine pass.

Large engines build an atmosphere from coordinated providers, shared world causes and renderer contracts. No single
cloud technique supplies weather, air, local fog, rain, surface wetness and water dynamics. A convincing complete
image depends on all of them agreeing; a cloud shader alone cannot close the commission. This plan delivers the
following core optical/runtime-weather scope and proves explicit neighbouring-system handoffs.

The absence of full rain/lightning presentation or Moon/stars is a **visible completion boundary**, not an implied
feature supplied by clouds. Core atmosphere acceptance means the included rows pass and all required seams are proved;
it must never be reported as every conceivable weather effect implemented. Scientific climate, snow, tornadoes,
aurora/rainbow/halo optics, unrestricted flight/space and arbitrary cross-provider live migration remain optional.
If a game requires those, add its provider commission and combined-budget gate before claiming that game's complete sky.

## Live storm over water: one causal chain

1. A runtime front command modifies E1 targets at the next commit. Regional controls/wind evolve under the specified
   bounded operator; existing event IDs remain. Authored storm rain flux/lightning activity is an explicit cause,
   not read from cloud opacity. New forcing can arrive after the original scenario ends.
2. Cloud source advects its existing3D optical state once with W plus named internal motion, locally sources/erodes
   matter and transfers cap outflow/ice. It publishes immutable current support/time and invalid correspondence.
3. V3 invalidates affected shadow/voxel-light/ambient/environment products, including offscreen blockers and changed
   fog/geometry dependencies. Current Sun/air inputs and same-source coefficient queries build these products once.
4. Main and independent reflected rays jointly integrate ordered/overlapping air/fog/cloud with correct terminals.
   Surface materials receive clouded ambient/direct light once; V4 reconstructs/displays with proper prior times.
5. Stub rain/lightning/water/surface/audio readers receive the same committed W/flux/event/time. They respond without
   requiring visible cloud pixels. Their actual effect/physics/state operators belong to the named neighbouring owners.
6. A camera cut, main-off or second view changes demand/history, not the front or weather clock. All-off retires optical
   work. Restore/seek/provider replacement follows the explicit checkpoint/epoch policy and never relabels old images.

P4a proves the smallest running chain through optics and stubs before broad family/quality work. P6 adds long-running
forcing changes and complete mixed weather; P8 uses actual neighbouring implementations. Unit tests, a pretty cloud,
a mirror or an individual timing number cannot substitute for this coupled acceptance.

## Selection and confidence boundary

Burning Shores is the leading close-cloud visual comparator, supported by independent reviews and public Nubis³
rendering techniques; no reviewer consensus ranks every complete atmosphere system. Weather responsiveness is a
separate indispensable criterion. The selected runtime3D source is our explicit adaptation and must prove local
morphology and control response early. The production lineage raises confidence in the renderer's mechanisms; it
does not erase the source/art or device risks. Keep the source replaceable without weakening the required profile.
