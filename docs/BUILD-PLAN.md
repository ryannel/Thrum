# Thrum build plan

Updated 5 November 2026. This is the active status page. Git retains earlier plans. [Contracts](design/CONTRACTS.md) own shared invariants; [maturity](design/maturity.json) records implementation, correctness, visuals and device results separately.

## Goal and exit rule

Make one frame fast end to end, then widen. One reusable engine powers `examples/v1-game` with 10,000 entities and 1,000–2,000 movers on this M3 Max and its built-in 120 Hz ProMotion display; Chrome WebGPU runs the portable smoke tier. The game uses cooked meshes/textures, live camera/lights/shadows, GPU culling, reconstruction, EDR, display-link interpolation, hot reload, saves and a profiler. Four rendered peers then run over Quinn through 100 ms RTT, 20 ms jitter and 2% loss at no more than 64 kbit/s per client. The fixed 60 Hz game tick is not an engine ceiling.

**A gate passes only when its fixed real-game rows meet every budget** on the named target, the same game runs through public engine APIs, `./dev check` is green, and an independent reviewer has tried to break the code and raw results. Record p50/p95/p99, allocations and the hot-path profile on one evidence page per gate. The physical iPhone is unavailable: the iPhone 18 Pro simulator proves function, never speed. Label Mac substitutes “proxy”: CPU gets half the iPhone budget on at most two busy frame threads; GPU time at iPhone native resolution ×5 must fit 6.25 ms. iPhone gates may close only as **Mac-qualified, device pending**; the ledger records no iPhone result. At V1 exit, stop with numbers and outstanding device runs. CI remains manual-only by owner decision.

## Active gate order and budgets

- [ ] **G0 — integrity and fixed baselines.** Metal/device tests fail without hardware and run through `./dev check` on Mac; constant assertions become behavioral tests. Put every gate row in a benchmark with an honest baseline, including explicit unsupported rows. Delete the unused mobile shell and old source/cook crates, keep parked scripts out of the check, and guard the iOS runtime dependency tree against SQLite/authoring crates. Report check wall time before/after. Cleanup and GPU-test changes are in progress; the full baseline matrix is open.
- [ ] **G2S — simulation as engine machinery.** Typed `&mut`/shared queries, in-place trusted systems under sparse undo, input validation at admission, dirty-union publication across gaps/rewinds/held pages, previous/current tick pairs, amendable retained inputs and correction replay. Remove game-owned staging, edit, permit and page capture. **S1:** four peers, shuffled movers, one Damage and one SetHealth per tick; tick plus publication p95 ≤25/300 µs at 10k/100k and one more action ≤10% impact. **S2:** rewind eight, amend one input, resimulate and publish p95 ≤100 µs at 10k, full-state equal to straight corrected run. Zero warmed allocations including a 200-spawn burst. Earlier [G2R evidence](evidence/v1-workload/G2R-CONSOLIDATED-2026-11-05.md) covers easier rows and does not qualify this gate.
- [x] **G3a — graph and live scene functionality.** Render, Compute and Copy closures execute in dependency order; scene camera, lights, cascades, reversed-Z `Depth32Float`, indexed draws and GPU previous transforms run. Its former encode-only CPU budget is reopened as the complete-frame G3b row.
- [ ] **G3b — engine frame runtime.** A display link drives macOS/iOS/browser presentation from a target time; simulation and render work run off Apple's main thread, with at most two frames in flight, GPU interpolation, late drawable acquisition and typed lifecycle recovery. Move `FrameHost` into the engine with no game types/pass names. **Budgets:** real 120 Hz ProMotion display, ten-minute present-interval p99 within 1 ms, frame CPU p95 ≤0.3 ms at 10k/1080p with zero allocations on every frame thread, input-to-photon breakdown, and surface/background/device-loss recovery. Mac display qualifies timing; iPhone simulator qualifies only function.
- [ ] **G3t — tile dataflow and Metal boundary.** Direct forward output without post passes, derived memoryless depth and transient motion, mapped upload ring, ≤64 B instances, GPU light binning for every count, separate mirrored range, shared GPU-only targets and one scene/present graph. One registry-selected Metal boundary owns mapped rings, EDR, MetalFX and binary archives with portable fallback. **Budgets:** ≤10 MB screen attachment traffic per 1080p frame confirmed by Metal counters, GPU ≤0.30 ms at 1080p including present, no steady `write_buffer`, ≤5% CPU change from 4→64 lights and ≤5% GPU change for a mirrored row.
- [ ] **G3c — GPU-driven culling.** Compute frustum and Hi-Z, one `draw_indexed_indirect` per mesh/pipeline bucket with GPU-written counts, stable mesh offsets and compute-readable material table. **Budget:** full-visibility 10k GPU time no worse than without culling, with time falling with visibility.
- [ ] **G4 — Apple reconstruction and governor.** MetalFX, EDR and binary archives use the G3t boundary; quality follows GPU/thermal/present evidence. Apple tile must beat portable by ≥10% in GPU time or bandwidth on this Mac within image tolerance, with Metal counters; cold play compiles no pipeline. iPhone comparison remains device pending.
- [ ] **G5 — replace content authoring stack.** Replace `thrum-source`/`thrum-cook` with a small runtime product crate and about 3k lines of stat cache, BLAKE3 file/action CAS, aligned mmap products, glTF meshlets, KTX2 ASTC/BC7, atomic manifest, watcher and dev server. Retain only needed path/JSON/record validation; supersede the SQLite design mandates. **Budgets:** no-change project scan ≤50 ms; one-texture edit visible ≤500 ms without GPU stall; shipping targets link no authoring crates.
- [ ] **G6 — redesign wire, then QUIC.** ≤12-byte packet header with piggybacked ACK bits, relevance/priority under a token bucket, dead-reckoning residuals, repaired unreliable membership, compact input batches, clock sync, remote interpolation and owned-entity prediction. Preserve strict codecs/fuzzing; then add Quinn GSO/GRO and sessions under one link trait/conditioner. **Budgets:** ≤64 kbit/s per client including overhead at 1.5k movers under the conditioner; iPhone reconciliation ≤0.5 ms/snapshot.
- [ ] **G7 — four rendered peers.** Run Mac windows and simulators under the conditioner; qualify Mac Apple tile and portable, Chrome portable smoke, and the [V1 exit](design/BASELINE-SPEC.md). Physical iPhone runs remain device pending.

## Working constraints

Profile before optimising. Each slice reports a before/after hot-path number and net lines per crate; a slower budgeted path stays off main. Zero steady tick/frame allocations are tested. One publication spine, one job graph with serial and core-class-aware execution, and SIMD chosen from the capability registry with a scalar reference. No recipe lands before portable runs through the graph. The game owns schema, rules, scene and assets; engine crates never import game types. Report game lines and engine-side game-type references at each gate. No new fixture binary.

Do not grow design, maturity, evidence or provenance files until V1; correct or shrink them. Evidence is at most one page per gate. Keep the fixed-step clock, checked identities, validate-at-admission authority with a debug/test validator, pipeline closure, temporal history and strict codecs. Use [engine-contributor](../.agents/skills/engine-contributor/SKILL.md), `./dev check` and independent review at each gate. Local commits are checkpoints; do not push without authorization.
