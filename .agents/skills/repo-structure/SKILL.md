# Repository and retention

Use [the layout](../../../docs/REPOSITORY.md) when placing or moving files. Use
[the lifecycle rules](../../../docs/ASSET-LIFECYCLE.md) for asset generation, promotion,
bulk outputs, optimization campaigns and cleanup. Read only the relevant scope.

Keep one canonical design and one selected asset source chain. Scratch work belongs to an identified
task; promotion stages a complete selected delivery and updates explicit consumer pins. Verify retained
sources before deleting owned intermediates. A cleanup command cannot establish recoverability by itself.

Use the real commands in [contributing](../../../CONTRIBUTING.md). Proposed SDK asset/GC operations in
research documents are not installed tooling. Complete authorized placement/promotion/closeout with
normal tools and record exact retained paths and remaining limits. Preserve other workers' active files.
